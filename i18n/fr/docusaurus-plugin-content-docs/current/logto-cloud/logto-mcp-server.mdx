# Logto MCP Server

Logto MCP Server est un serveur [MCP (Model Context Protocol)](https://modelcontextprotocol.io/) distant. Ajoutez l’URL à votre application IA, connectez-vous avec votre compte Logto Cloud et commencez à dialoguer avec Logto.

:::tip
Logto MCP Server est construit avec Logto et [MCP Auth](https://mcp-auth.dev). Si vous souhaitez créer votre propre serveur MCP distant, consultez [Construire votre propre serveur MCP distant](#build-your-own-remote-mcp-server).
:::

## Ce que vous pouvez faire \{#what-you-can-do}

- **Ajoutez l’authentification à votre projet** : L’IA détecte votre framework, crée une application Logto et génère le code d’intégration fonctionnel. Prend en charge plus de 38 frameworks, dont React, Next.js, Vue, Nuxt, SvelteKit, Express, Go, Python, iOS, Android, Flutter, et bien d’autres.
- **Posez des questions sur Logto** : L’IA recherche dans la documentation Logto et vous fournit des réponses avec les sources.

D’autres fonctionnalités arrivent bientôt, notamment la configuration de l’expérience de connexion, la gestion du contrôle d’accès basé sur les rôles (RBAC) et des permissions avec des recommandations de bonnes pratiques, la configuration multi-tenancy pour la création d’applications B2B avec des organisations, et plus encore.

## Comment votre application IA se connecte \{#how-your-ai-application-connects}

Logto MCP Server prend en charge deux méthodes pour qu’une application IA s’identifie lors de la connexion. Vous n’avez rien à créer dans Logto Cloud pour l’une ou l’autre.

- **URL du serveur uniquement (recommandé)** : La plupart des applications IA prennent désormais en charge les [documents de métadonnées d’ID client (CIMD)](/integrate-logto/third-party-applications/dynamic-apps). L’application utilise une URL qu’elle possède comme ID client, et Logto lit le nom de l’application et les URI de redirection à partir de cette URL. Vous saisissez simplement l’URL du serveur `https://mcp.logto.io`.
- **ID client statique** : Pour les applications qui ne prennent pas encore en charge CIMD, saisissez l’ID client OAuth public `mcp-client`. Ce client accepte les URI de redirection loopback (`http://localhost` ou `http://127.0.0.1` avec n’importe quel port).

Si votre application propose les deux options, utilisez uniquement l’URL du serveur. Les connexions existantes utilisant `mcp-client` continueront de fonctionner, vous n’avez donc pas besoin de les reconnecter.

Lorsque vous vous connectez uniquement avec l’URL du serveur, la page de connexion Logto Cloud affiche un écran de consentement avec le nom de l’application et l’hôte de l’URL de son ID client, comme `claude.ai` ou `vscode.dev`. Vérifiez que l’hôte correspond bien à l’application que vous utilisez avant d’autoriser.

## Configuration dans votre application IA \{#set-up-in-your-ai-application}

### Amp \{#amp}

1. Dans [Amp](https://ampcode.com), ouvrez **Personal Settings** > **Integrations & MCP** et cliquez sur **Add MCP Server**.
2. Saisissez le nom `Logto MCP Server` et l’URL du serveur : `https://mcp.logto.io`. Amp détecte automatiquement la méthode d’authentification.
3. Cliquez sur **Connect** et suivez l’invite d’Amp pour vous connecter.
4. Connectez-vous avec votre compte Logto Cloud et autorisez la connexion.

:::tip
Si Amp reste longtemps sur **Detecting Authentication**, cliquez sur **Change** et sélectionnez **OAuth** pour passer la détection automatique. Laissez **OAuth Client ID** et **OAuth Client Secret** sous **Use Your Own OAuth App** vides, puis cliquez sur **Connect** et suivez l’invite de connexion. Amp prend en charge CIMD, vous n’avez donc pas besoin d’enregistrer une application OAuth ni de saisir `mcp-client`.
:::

### Claude Code \{#claude-code}

```bash
claude mcp add --transport http logto https://mcp.logto.io
```

Ensuite, exécutez `/mcp` dans Claude Code, sélectionnez `logto` et suivez le flux de connexion dans le navigateur pour vous authentifier avec votre compte Logto Cloud. Vous pouvez également exécuter `claude mcp login logto` dans votre terminal.

### Claude (web et desktop) \{#claude-web-and-desktop}

1. Ouvrez **Customize** > **Connectors** et cliquez sur **Add custom connector**.
2. Saisissez le nom `Logto MCP Server` et l’URL du serveur MCP distant : `https://mcp.logto.io`. Laissez les paramètres OAuth sous **Advanced settings** vides, puis cliquez sur **Add**.
3. Dans la liste **Connectors**, trouvez **Logto MCP Server** et cliquez sur **Connect**.
4. Vous serez redirigé vers la page de connexion Logto Cloud. Connectez-vous avec votre compte Logto Cloud et autorisez la connexion.

Les connecteurs sont enregistrés dans votre compte Claude, ils sont donc disponibles à la fois sur Claude web et Claude Desktop.

### ChatGPT et Codex \{#chatgpt-and-codex}

1. Dans la barre latérale gauche, ouvrez **Plugins**, puis cliquez sur **Add** > **Add custom MCP server** en haut à droite.
2. Saisissez le nom `Logto MCP Server`. Sous **Connection**, sélectionnez **Server URL** et saisissez `https://mcp.logto.io`.
3. Gardez les paramètres par défaut **Authentification (Authentication)** (**OAuth**) et **Advanced OAuth settings**.
4. Sélectionnez **I understand and want to continue**, puis cliquez sur **Create as a plugin**.
5. Dans la boîte de dialogue **Connect Logto MCP Server**, cliquez sur **Connect Logto MCP Server**. Connectez-vous avec votre compte Logto Cloud et autorisez la connexion.

:::tip
Si **Logto MCP Server** n’apparaît pas sous **Installed** après la connexion, attendez un instant puis cliquez sur le bouton de rafraîchissement en haut à droite de la page **Plugins**.
:::

Vous pouvez également ajouter le serveur avec la CLI Codex :

```bash
codex mcp add logto --url https://mcp.logto.io
codex mcp login logto
```

Une fenêtre de navigateur s’ouvrira. Connectez-vous avec votre compte Logto Cloud pour établir la connexion. L’application desktop ChatGPT, la CLI Codex et l’extension Codex IDE partagent cette configuration.

### Cursor \{#cursor}

Cursor ne prend pas encore en charge CIMD, il utilise donc l’ID client statique.

1. Ouvrez **Customize** > **MCPs**, ou ouvrez `~/.cursor/mcp.json` (global) ou `.cursor/mcp.json` (projet).
2. Ajoutez la configuration suivante :

   ```json
   {
     "mcpServers": {
       "Logto": {
         "url": "https://mcp.logto.io",
         "auth": {
           "CLIENT_ID": "mcp-client",
           "scopes": ["mcp:all"]
         }
       }
     }
   }
   ```

3. Cliquez sur **Connect** à côté du serveur. Une page de connexion Logto Cloud apparaîtra. Connectez-vous avec votre compte Logto Cloud pour établir la connexion.

Connectez-vous depuis l’application desktop Cursor. Le callback web utilisé par Cursor sur le web et Cursor Agents n’est pas pris en charge.

### OpenCode \{#opencode}

1. Ajoutez la configuration suivante à votre fichier `opencode.json` :

   ```json
   {
     "$schema": "https://opencode.ai/config.json",
     "mcp": {
       "Logto": {
         "enabled": true,
         "type": "remote",
         "url": "https://mcp.logto.io"
       }
     }
   }
   ```

2. Exécutez la commande suivante pour vous authentifier :
   ```bash
   opencode mcp auth Logto
   ```
   Notez que `Logto` correspond au nom du serveur MCP dans votre fichier de configuration.

Une fenêtre de navigateur s’ouvrira. Connectez-vous avec votre compte Logto Cloud pour autoriser et établir la connexion.

### VS Code \{#vs-code}

1. Ouvrez la palette de commandes (`Command + Shift + P`), puis sélectionnez **MCP: Add Server...**.
2. Choisissez **HTTP** comme type de serveur.
3. Saisissez l’URL : `https://mcp.logto.io`. Vous pouvez choisir de l’installer dans votre espace de travail pour une meilleure isolation et gestion.
4. Lorsque VS Code demande à s’authentifier, acceptez. Vous serez redirigé vers la page de connexion Logto Cloud. Connectez-vous avec votre compte Logto Cloud pour établir la connexion.

Vous pouvez aussi ajouter le serveur dans `.vscode/mcp.json` ou dans votre `mcp.json` utilisateur :

```json
{
  "servers": {
    "logto": {
      "type": "http",
      "url": "https://mcp.logto.io"
    }
  }
}
```

### Windsurf \{#windsurf}

Windsurf ne documente pas la prise en charge de CIMD, utilisez donc [`mcp-remote`](https://www.npmjs.com/package/mcp-remote) avec l’ID client statique.

1. Ouvrez la palette de commandes (`Command + Shift + P`) et sélectionnez **Windsurf: MCP Marketplace**.
2. Dans la section **Installed MCPs**, cliquez sur l’icône de paramètres à droite pour ouvrir le fichier de configuration MCP.
3. Ajoutez la [configuration](https://docs.windsurf.com/windsurf/cascade/mcp#mcp_config-json) suivante :

   ```json
   {
     "mcpServers": {
       "Logto": {
         "command": "npx",
         "args": [
           "mcp-remote",
           "https://mcp.logto.io",
           "--allow-http",
           "--static-oauth-client-info",
           "{ \"client_id\": \"mcp-client\", \"scope\": \"mcp:all\" }",
           "--resource",
           "https://mcp.logto.io/"
         ]
       }
     }
   }
   ```

Une page de connexion Logto Cloud apparaîtra automatiquement. Connectez-vous avec votre compte Logto Cloud pour établir la connexion.

### Autres clients MCP \{#other-mcp-clients}

Logto MCP Server fonctionne avec tout client MCP prenant en charge l’autorisation OAuth :

- **Si votre client prend en charge CIMD** : Saisissez uniquement l’URL du serveur MCP `https://mcp.logto.io`. Le client découvre tout le reste depuis le serveur.
- **Sinon** : Utilisez la configuration suivante.
  - **URL du serveur MCP :** `https://mcp.logto.io`
  - **ID client OAuth :** `mcp-client` (pas de secret client)
  - **Redirect URI :** une adresse loopback, comme `http://localhost:<port>/callback`
  - **Resource :** `https://mcp.logto.io/` (si votre client l’exige)
  - **Scope :** `mcp:all` (si votre client l’exige)

Logto MCP Server ne prend pas en charge l’enregistrement dynamique de client (DCR). Si vous êtes développeur d’application IA, [publiez un document de métadonnées d’ID client](/integrate-logto/third-party-applications/dynamic-apps#publish-a-client-id-metadata-document) pour votre application, et elle pourra se connecter sans aucune configuration dans Logto. Si cela n’est pas possible, [contactez-nous](https://logto.io/contact) avec les détails de votre application.
