# Vérification par SMS pour MFA

Logto prend en charge la fonctionnalité d’authentification multi-facteurs (MFA) basée sur SMS, qui renforce la sécurité des comptes en envoyant des codes de vérification à usage unique aux numéros de téléphone enregistrés des utilisateurs. Le SMS MFA sert de second facteur d’authentification et peut être combiné avec d’autres facteurs MFA (tels que TOTP, passkeys, codes de secours) pour offrir aux utilisateurs des options flexibles d’authentification à deux facteurs.

## Concepts \{#concepts}

La vérification par SMS, également appelée vérification du numéro de téléphone, est l’une des méthodes MFA les plus accessibles. Elle exploite l’omniprésence des téléphones mobiles pour délivrer des codes de vérification temporaires et à usage unique directement sur les appareils des utilisateurs via des messages texte. Contrairement aux applications d’authentification qui nécessitent l’installation d’un logiciel supplémentaire, le SMS MFA utilise l’infrastructure de messagerie existante, standard sur tous les appareils mobiles, ce qui le rend immédiatement disponible pour les utilisateurs sans aucune configuration préalable.

## Configurer la vérification par SMS pour MFA \{#configure-sms-verification-for-mfa}

**Étape 1 : Configurer le connecteur SMS et les modèles**

1. Accédez à <CloudLink to="/connectors/passwordless">Console > Connecteurs > Connecteurs Email et SMS</CloudLink>
2. Sélectionnez un connecteur SMS approprié (Twilio, SMS Aero, etc.)
3. Configurez les paramètres de connexion.
4. Configurez le modèle SMS pour MFA avec les types d’utilisation dédiés.
   - usageType `MfaVerification` pour la vérification MFA.
   - usageType `BindMfa` pour l’association MFA.
5. Testez la fonctionnalité du connecteur pour garantir la bonne délivrance des messages.
6. Consultez [Connecteurs SMS](/connectors/sms-connectors) pour les instructions de configuration spécifiques au fournisseur.

**Étape 2 : Activer le SMS pour MFA**

1. Accédez à <CloudLink to="/mfa">Console > Authentification multi-facteurs</CloudLink>
2. Activez le facteur "Code de vérification SMS". Il est recommandé d’utiliser le SMS MFA en combinaison avec d’autres facteurs MFA (TOTP, passkeys, codes de secours) pour réduire la dépendance à un seul facteur.
3. Dans **Vérification en 2 étapes Email/SMS**, choisissez quels utilisateurs disposent du SMS MFA. Voir [Qui a le SMS MFA](#who-has-sms-mfa).
4. Configurez votre politique MFA préférée (optionnelle, adaptative ou obligatoire).
5. Enregistrez vos modifications de configuration.

:::note Considérations importantes d’utilisation

1. **Limitation de la méthode de connexion** : Les codes de vérification SMS ne peuvent pas être utilisés simultanément comme [méthode de connexion (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in) et comme facteur MFA (2FA). Choisissez un seul flux d’authentification par implémentation SMS.

2. **Compatibilité de la méthode d’inscription** : Les codes de vérification SMS peuvent être utilisés simultanément comme méthode d’inscription et comme MFA. Logto optimisera le flux d’inscription de l’utilisateur final selon la politique MFA sélectionnée pour éviter de demander deux fois la vérification SMS pour le même numéro.

3. **Compatibilité avec la récupération de mot de passe** : Bien que les codes de vérification SMS puissent être utilisés à la fois pour [Mot de passe oublié](/end-user-flows/sign-up-and-sign-in/reset-password) et pour MFA, cette combinaison est **non recommandée**. Cette configuration réduit l’efficacité de la sécurité MFA, car les utilisateurs pourraient contourner la MFA en utilisant la vérification SMS pour réinitialiser leur mot de passe, puis utiliser le nouveau mot de passe pour l’authentification principale (1FA) suivie de la même méthode SMS pour la vérification MFA.

:::

## Qui a le SMS MFA \{#who-has-sms-mfa}

Les codes SMS MFA sont toujours envoyés au numéro de téléphone principal de l’utilisateur. Le paramètre **Vérification en 2 étapes Email/SMS** sur la page <CloudLink to="/mfa">Authentification multi-facteurs</CloudLink> détermine quels utilisateurs disposent du SMS MFA :

- **Chaque utilisateur avec un email ou numéro de téléphone vérifié** : Chaque utilisateur ayant un numéro de téléphone principal bénéficie du SMS MFA, sans configuration supplémentaire.
- **Seuls les utilisateurs qui l’activent** : Seuls les utilisateurs qui configurent le SMS MFA en bénéficient. Un utilisateur qui s’inscrit avec un numéro de téléphone vérifié n’obtient pas automatiquement le SMS MFA, ce qui vous permet de proposer le SMS comme option MFA sans inscrire tous les utilisateurs. Les utilisateurs le configurent dans le flux de configuration MFA, dans le [Centre de compte](/end-user-flows/account-settings/by-account-center-ui), ou via l’[Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa). Les administrateurs peuvent l’ajouter ou le supprimer pour un utilisateur via le [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management).

Ce paramètre s’applique également à [l’email MFA](/end-user-flows/mfa/email-mfa). Pour en savoir plus sur les valeurs par défaut et ce qui se passe lors d’un changement de mode, consultez [Inscription à l’email et au SMS MFA](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment).

:::note
Avec **Chaque utilisateur avec un email ou numéro de téléphone vérifié**, un utilisateur qui a le SMS MFA uniquement grâce à son numéro principal n’a pas d’enregistrement SMS MFA stocké, il n’apparaît donc pas dans `GET /api/my-account/mfa-verifications`, `GET /api/users/{userId}/mfa-verifications`, ou `user.mfaVerificationFactors` (Revendications JWT personnalisées et Actions `PostSignIn`).
:::

## Flux de configuration du SMS MFA \{#sms-mfa-setup-flows}

L’invite de configuration MFA peut apparaître lors de l’inscription de l’utilisateur ou après la connexion, selon la [politique MFA](/end-user-flows/mfa/configure-mfa#global-mfa-configuration) configurée.

Le flux de configuration du SMS MFA dépend des facteurs suivants :

- **Nombre de facteurs MFA principaux** : S’il existe plusieurs facteurs principaux, l’utilisateur doit en choisir un à configurer. Les facteurs principaux sont les méthodes MFA autres que les codes de secours.
- **Codes de secours activés** : Lorsqu’ils sont activés, les codes de secours sont générés automatiquement après la configuration du facteur MFA principal ; l’utilisateur est invité à les sauvegarder.
- **Configuration de l’identifiant d’inscription** : Le numéro de téléphone a été utilisé comme [identifiant d’inscription](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier) et l’utilisateur l’a déjà vérifié avec un code SMS lors de l’inscription.
  - Avec **Chaque utilisateur avec un email ou numéro de téléphone vérifié**, le système associe automatiquement ce numéro comme facteur MFA et aucune vérification supplémentaire n’est requise. Si d’autres facteurs principaux existent, l’interface affichera une option “Ajouter une autre vérification en 2 étapes” (l’utilisateur peut l’ignorer), ce qui indique clairement que la MFA est activée.
  - Avec **Seuls les utilisateurs qui l’activent**, le numéro de téléphone est proposé comme tout autre facteur, avec le numéro masqué. Lorsque l’utilisateur le choisit, ou s’il s’agit du seul facteur principal, Logto le configure avec la vérification de l’inscription, donc aucun second code n’est envoyé.
- **Données utilisateur existantes** : Lorsqu’un utilisateur existant configure la MFA après s’être connecté, il doit d’abord terminer l’authentification principale puis poursuivre la configuration MFA. Si le compte contient déjà un numéro de téléphone principal vérifié :
  - Avec **Chaque utilisateur avec un email ou numéro de téléphone vérifié**, la configuration se comporte comme dans le cas de l’identifiant d’inscription ci-dessus.
  - Avec **Seuls les utilisateurs qui l’activent**, le numéro de téléphone est proposé avec le numéro masqué. Lorsque l’utilisateur le choisit, ou s’il s’agit du seul facteur principal, Logto envoie un code de vérification à ce numéro, et le SMS MFA est configuré une fois le code saisi.

Voici trois scénarios courants d’association du SMS MFA.

### Scénario 1 : Numéro de téléphone utilisé uniquement pour MFA (Flux typique) \{#scenario-1-phone-number-only-used-for-mfa-typical-flow}

Lorsque le numéro de téléphone n’est pas un des identifiants d’inscription, et uniquement pour la MFA, suivez la séquence de configuration standard :

- S’il n’y a qu’un seul facteur SMS MFA, affichez directement l’interface de configuration pour ce facteur.
- S’il y a plusieurs facteurs MFA principaux, affichez une page de liste “Configurer la MFA” et laissez l’utilisateur choisir le facteur à configurer.

Avec **Seuls les utilisateurs qui l’activent**, le SMS est le seul facteur principal dans ce scénario, donc Logto le configure avec la vérification de l’inscription de la même manière.

### Scénario 3 : Numéro vérifié mais plusieurs facteurs principaux disponibles \{#scenario-3-phone-verified-but-multiple-primary-factors-available}

Si le numéro de téléphone a été vérifié à l’inscription (comme identifiant d’inscription) mais que le compte dispose de plusieurs facteurs MFA principaux (par exemple, SMS plus passkeys ou applications d’authentification), l’interface invitera l’utilisateur avec “Ajouter une autre vérification en 2 étapes”. L’utilisateur peut choisir d’ajouter un autre facteur ou passer ; l’invite indique également que la MFA est déjà activée.

Avec **Seuls les utilisateurs qui l’activent**, l’utilisateur choisit d’abord un facteur dans la liste. L’invite “Ajouter une autre vérification en 2 étapes” apparaît lorsque l’utilisateur vient de configurer le SMS, l’email ou une passkey de connexion comme seul facteur.

## Flux de vérification du SMS MFA \{#sms-mfa-verification-flows}

Lorsqu’un utilisateur ayant activé le SMS MFA se connecte, après avoir terminé avec succès l’authentification principale (1FA), il sera invité à vérifier son identité à l’aide du code de vérification SMS comme second facteur d’authentification (2FA).

Si plusieurs facteurs MFA sont disponibles, Logto ouvre directement le facteur de plus haute priorité selon l’ordre fixe spécifié dans [Configurer la MFA](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) (Passkey, Application d’authentification OTP, Code de vérification SMS, Code de vérification email, Codes de secours). Lorsqu’un autre facteur comme l’application d’authentification OTP est proposé en premier, les utilisateurs peuvent cliquer sur **Essayer une autre méthode de vérification** pour ouvrir la liste de sélection et choisir le code de vérification SMS à la place.

## Gestion des erreurs \{#error-handling}

1. **Numéro de téléphone non associé**

   - Code d’erreur : `session.mfa.mfa_factor_not_enabled`
   - Traitement : Inviter l’utilisateur à associer d’abord un numéro de téléphone

2. **Code de vérification incorrect**

   - Code d’erreur : `verification_code.code_mismatch`
   - Traitement : Demander à l’utilisateur de ressaisir, limiter le nombre de tentatives

3. **Code de vérification expiré**

   - Code d’erreur : `verification_code.expired`
   - Traitement : Inviter l’utilisateur à demander un nouveau code de vérification

4. **Limite de fréquence d’envoi dépassée**
   - Codes d’erreur : `request.message_rate_limited` (limite de fréquence d’envoi par destinataire Logto) ou `connector.rate_limit_exceeded` (limite de fréquence du connecteur SMS)
   - Traitement : Afficher le temps d’attente, limiter les renvois
