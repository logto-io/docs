# Vérification par e-mail pour MFA

Logto prend en charge la fonctionnalité d’authentification multi-facteurs (MFA) basée sur l’e-mail, qui améliore la sécurité des comptes en envoyant des codes de vérification à usage unique aux adresses e-mail enregistrées des utilisateurs. L’e-mail MFA sert de second facteur d’authentification et peut être combiné avec d’autres facteurs MFA (tels que TOTP, passkeys, codes de secours) pour offrir aux utilisateurs des options flexibles d’authentification à deux facteurs.

## Concepts \{#concepts}

La vérification par e-mail est l’une des méthodes MFA les plus universellement accessibles. Elle exploite la disponibilité généralisée des comptes e-mail pour délivrer des codes de vérification temporaires et à usage unique directement dans la boîte de réception des utilisateurs. Contrairement aux applications d’authentification qui nécessitent l’installation de logiciels supplémentaires, l’e-mail MFA utilise l’infrastructure e-mail existante, déjà accessible à pratiquement tous les utilisateurs d’Internet via des navigateurs web, des clients e-mail ou des applications mobiles. Cela la rend immédiatement disponible pour les utilisateurs sans exigence matérielle particulière ni configuration supplémentaire, à part disposer d’un compte e-mail.

## Configurer la vérification par e-mail pour MFA \{#configure-email-verification-for-mfa}

**Étape 1 : Configurer le connecteur e-mail et les modèles**

1. Accédez à <CloudLink to="/connectors/passwordless">Console > Connecteurs > Connecteurs e-mail et SMS</CloudLink>
2. Sélectionnez un connecteur e-mail approprié (SendGrid, Mailgun, etc.)
3. Configurez les paramètres de connexion.
4. Configurez le [modèle d’e-mail](/connectors/email-connectors/email-templates) pour MFA avec les types d’utilisation dédiés :

   - usageType `MfaVerification` pour la vérification MFA.
   - usageType `BindMfa` pour l’association MFA.
   - Astuce : [Logto Email Service](/connectors/email-connectors/built-in-email-service) fournit des modèles d’e-mail intégrés.

5. Consultez [Connecteurs e-mail](/connectors/email-connectors) pour les instructions de configuration spécifiques au fournisseur.

**Étape 2 : Activer l’e-mail pour MFA**

1. Accédez à <CloudLink to="/mfa">Console > Authentification multi-facteurs</CloudLink>
2. Activez le facteur "Code de vérification par e-mail". Il est recommandé d’utiliser l’e-mail MFA en combinaison avec d’autres facteurs MFA (TOTP, passkeys, SMS, codes de secours) pour réduire la dépendance à un seul facteur.
3. Dans **Vérification en 2 étapes par e-mail/SMS**, choisissez quels utilisateurs disposent de l’e-mail MFA. Voir [Qui a l’e-mail MFA](#who-has-email-mfa).
4. Configurez votre politique MFA préférée (optionnelle, adaptative ou obligatoire)
5. Enregistrez vos modifications de configuration

:::note Considérations importantes d’utilisation

1. **Limitation de la méthode de connexion** : Les codes de vérification par e-mail ne peuvent pas être utilisés simultanément comme [méthode de connexion (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in) et comme facteur MFA (2FA). Choisissez un seul flux d’authentification par implémentation e-mail.

2. **Compatibilité de la méthode d’inscription** : Les codes de vérification par e-mail peuvent être utilisés simultanément comme méthode d’inscription et comme MFA. Logto optimisera le flux d’inscription utilisateur final selon la politique MFA sélectionnée afin d’éviter de demander deux fois la vérification e-mail pour la même adresse.

3. **Compatibilité de la récupération de mot de passe** : Bien que les codes de vérification par e-mail puissent être utilisés simultanément pour [Mot de passe oublié](/end-user-flows/sign-up-and-sign-in/reset-password) et pour MFA, cette combinaison est **non recommandée**. Cette configuration réduit l’efficacité de la sécurité MFA, car les utilisateurs pourraient potentiellement contourner la MFA en utilisant la vérification e-mail du mot de passe oublié pour réinitialiser leur mot de passe, puis utiliser le nouveau mot de passe pour l’authentification principale (1FA) suivie de la même méthode e-mail pour la vérification MFA.

:::

## Qui a l’e-mail MFA \{#who-has-email-mfa}

Les codes MFA par e-mail sont toujours envoyés à l’adresse e-mail principale de l’utilisateur. Le paramètre **Vérification en 2 étapes par e-mail/SMS** sur la page <CloudLink to="/mfa">Authentification multi-facteurs</CloudLink> détermine quels utilisateurs disposent de l’e-mail MFA :

- **Chaque utilisateur avec une adresse e-mail ou un numéro de téléphone vérifié** : Chaque utilisateur ayant une adresse e-mail principale dispose de l’e-mail MFA, sans configuration préalable.
- **Seuls les utilisateurs qui l’ont configuré** : Seuls les utilisateurs ayant configuré l’e-mail MFA en bénéficient. Un utilisateur qui s’inscrit avec une adresse e-mail vérifiée n’obtient pas automatiquement l’e-mail MFA, ce qui vous permet de proposer l’e-mail comme option MFA sans inscrire tous les utilisateurs. Les utilisateurs le configurent dans le flux de configuration MFA, dans le [Centre de compte](/end-user-flows/account-settings/by-account-center-ui), ou via l’[Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa). Les administrateurs peuvent l’ajouter ou le supprimer pour un utilisateur via le [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management).

Ce paramètre s’applique également au [SMS MFA](/end-user-flows/mfa/sms-mfa). Pour en savoir plus sur les valeurs par défaut et ce qui se passe lors du changement de mode, voir [Inscription à l’e-mail et au SMS MFA](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment).

:::note
Avec **Chaque utilisateur avec une adresse e-mail ou un numéro de téléphone vérifié**, un utilisateur qui dispose de l’e-mail MFA uniquement grâce à son adresse e-mail principale n’a pas d’enregistrement MFA e-mail stocké, il n’apparaît donc pas dans `GET /api/my-account/mfa-verifications`, `GET /api/users/{userId}/mfa-verifications`, ou `user.mfaVerificationFactors` (Revendications JWT personnalisées et Actions `PostSignIn`).
:::

## Flux de configuration de l’e-mail MFA \{#email-mfa-setup-flows}

L’invite de configuration MFA peut apparaître lors de l’inscription de l’utilisateur ou après la connexion, selon la [politique MFA](/end-user-flows/mfa/configure-mfa#global-mfa-configuration) configurée.

Le flux de configuration de l’e-mail MFA est influencé par les facteurs suivants :

- **Nombre de facteurs MFA principaux** : S’il existe plusieurs facteurs principaux, l’utilisateur doit en choisir un à configurer. Les facteurs principaux sont les méthodes MFA autres que les codes de secours.
- **Codes de secours activés** : Lorsqu’ils sont activés, les codes de secours sont générés automatiquement après la configuration du facteur MFA principal ; l’utilisateur est invité à les sauvegarder.
- **Configuration de l’identifiant d’inscription** : L’adresse e-mail a été utilisée comme [identifiant d’inscription](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier) et l’utilisateur l’a déjà vérifiée avec un code de vérification e-mail lors de l’inscription.
  - Avec **Chaque utilisateur avec une adresse e-mail ou un numéro de téléphone vérifié**, le système associe automatiquement cet e-mail comme facteur MFA et aucune vérification supplémentaire n’est requise. Si d’autres facteurs principaux existent, l’interface affichera une option "Ajouter une autre vérification en 2 étapes" (l’utilisateur peut l’ignorer), ce qui indique clairement que la MFA est activée.
  - Avec **Seuls les utilisateurs qui l’ont configuré**, l’e-mail est proposé comme tout autre facteur, avec l’adresse masquée. Lorsque l’utilisateur le choisit, ou s’il s’agit du seul facteur principal, Logto le configure avec la vérification de l’inscription, donc aucun second code n’est envoyé.
- **Données utilisateur existantes** : Lorsqu’un utilisateur existant configure la MFA après s’être connecté, il doit d’abord effectuer l’authentification principale puis poursuivre la configuration MFA. Si le compte contient déjà une adresse e-mail principale vérifiée :
  - Avec **Chaque utilisateur avec une adresse e-mail ou un numéro de téléphone vérifié**, la configuration se comporte comme dans le cas de l’identifiant d’inscription ci-dessus.
  - Avec **Seuls les utilisateurs qui l’ont configuré**, l’e-mail est proposé avec l’adresse masquée. Lorsque l’utilisateur le choisit, ou s’il s’agit du seul facteur principal, Logto envoie un code de vérification à cette adresse, et l’e-mail MFA est configuré une fois que l’utilisateur saisit le code.

Voici trois scénarios courants d’association de l’e-mail MFA.

### Scénario 1 : Adresse e-mail utilisée uniquement pour MFA (Flux typique) \{#scenario-1-email-address-only-used-for-mfa-typical-flow}

Lorsque l’adresse e-mail n’est pas l’un des identifiants d’inscription, et uniquement pour la MFA, suivez la séquence de configuration standard :

- S’il n’y a qu’un seul facteur e-mail MFA, affichez directement l’interface de configuration pour ce facteur.
- S’il existe plusieurs facteurs MFA principaux, affichez une page de liste "Configurer la MFA" et laissez l’utilisateur choisir le facteur à configurer.

Avec **Seuls les utilisateurs qui l’ont configuré**, l’e-mail est le seul facteur principal dans ce scénario, donc Logto le configure avec la vérification de l’inscription de la même manière.

### Scénario 3 : E-mail vérifié mais plusieurs facteurs principaux disponibles \{#scenario-3-email-verified-but-multiple-primary-factors-available}

Si l’adresse e-mail a été vérifiée à l’inscription (comme identifiant d’inscription) mais que le compte dispose de plusieurs facteurs MFA principaux (par exemple, e-mail plus passkeys ou applications d’authentification), l’interface invitera l’utilisateur avec "Ajouter une autre vérification en 2 étapes". L’utilisateur peut choisir d’ajouter un autre facteur ou d’ignorer ; l’invite indique également que la MFA est déjà activée.

Avec **Seuls les utilisateurs qui l’ont configuré**, l’utilisateur choisit d’abord un facteur dans la liste. L’invite "Ajouter une autre vérification en 2 étapes" apparaît lorsque l’utilisateur vient de configurer l’e-mail, le SMS ou une passkey de connexion comme seul facteur.

## Flux de vérification e-mail MFA \{#email-mfa-verification-flows}

Lorsqu’un utilisateur ayant activé l’e-mail MFA se connecte, après avoir réussi l’authentification principale (1FA), il sera invité à vérifier son identité à l’aide du code de vérification e-mail comme second facteur d’authentification (2FA).

Si plusieurs facteurs MFA sont disponibles, Logto ouvre directement le facteur de priorité la plus élevée selon l’ordre fixe spécifié dans [Configurer la MFA](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) (Passkey, Application d’authentification OTP, Code de vérification SMS, Code de vérification e-mail, Codes de secours). Lorsqu’un autre facteur comme l’application d’authentification OTP est proposé en premier, les utilisateurs peuvent cliquer sur **Essayer une autre méthode de vérification** pour ouvrir la liste de sélection et choisir le code de vérification e-mail à la place.

## Gestion des erreurs \{#error-handling}

1. **Adresse e-mail non associée**

   - Code d’erreur : `session.mfa.mfa_factor_not_enabled`
   - Traitement : Inviter l’utilisateur à associer d’abord une adresse e-mail

2. **Code de vérification incorrect**

   - Code d’erreur : `verification_code.code_mismatch`
   - Traitement : Demander à l’utilisateur de ressaisir, limiter le nombre de tentatives

3. **Code de vérification expiré**

   - Code d’erreur : `verification_code.expired`
   - Traitement : Inviter l’utilisateur à demander un nouveau code de vérification

4. **Limite de fréquence d’envoi dépassée**
   - Codes d’erreur : `request.message_rate_limited` (limite de fréquence d’envoi par destinataire Logto) ou `connector.rate_limit_exceeded` (limite de fréquence du connecteur e-mail)
   - Traitement : Afficher le temps d’attente, limiter les renvois
