Par défaut, Logto envoie les requêtes d’authentification SAML (AuthnRequests) non signées. Si votre fournisseur d’identité (IdP) exige des requêtes d’authentification signées, Logto peut les signer avec un certificat de fournisseur de service (SP) généré. La signature est entièrement contrôlée par le paramètre **Signer la requête d’authentification** du connecteur — Logto ne lit pas le drapeau `WantAuthnRequestsSigned` dans les métadonnées de l’IdP.

Procédez dans cet ordre pour éviter toute interruption de connexion :

1. Dans l’onglet `Connexion` du connecteur, trouvez la section **Certificat de signature de la requête** et cliquez sur **Générer une nouvelle clé**. La première clé est activée automatiquement ; les clés générées ultérieurement sont mises en attente comme inactives pour la rotation.
2. Téléchargez le certificat de la clé active et enregistrez-le auprès de votre IdP.
3. Activez **Signer la requête d’authentification** et enregistrez. L’activation nécessite une clé de signature active — l’enregistrement sans clé active est refusé.
4. Si votre IdP dispose d’une option distincte pour exiger ou vérifier les requêtes signées, activez-la maintenant, puis testez le flux de connexion.

:::warning
Gardez les deux côtés synchronisés. Activer **Signer la requête d’authentification** avant que le certificat ne soit enregistré — ou exiger la vérification côté IdP avant que Logto ne signe — bloque la connexion via cette liaison jusqu’à ce que l’autre côté soit à jour. Les IdP qui ne vérifient pas les signatures de requête ignorent simplement la signature.
:::

La gestion des clés fonctionne indépendamment du bouton d’activation :

- Au maximum une seule clé est **active**, et la clé active signe chaque requête. Les opérations sur les clés (générer, activer, désactiver, supprimer) prennent effet immédiatement.
- Pour faire une rotation de certificats sans interruption : générez une nouvelle clé (mise en attente comme inactive), enregistrez son certificat auprès de votre IdP, puis activez-la — la clé précédente est automatiquement désactivée et peut être supprimée ensuite.
- La clé active ne peut pas être supprimée, et elle ne peut pas être désactivée tant que **Signer la requête d’authentification** est activé — désactivez d’abord la signature.
- Désactiver le bouton conserve toutes les clés, donc la réactivation reprend la signature avec le même certificat — aucune modification côté IdP n’est nécessaire.

Logto signe les requêtes avec RSA-SHA256 par défaut. Pour utiliser RSA-SHA512, définissez `requestSignatureAlgorithm` sur `http://www.w3.org/2001/04/xmldsig-more#rsa-sha512` dans la configuration du connecteur via la Management API Logto.
