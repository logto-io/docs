# Passkeys (WebAuthn)

[Passkey](https://auth.wiki/passkey) มอบทางเลือกที่ปลอดภัยและใช้งานง่ายกว่ารหัสผ่านแบบเดิม ด้วยการใช้การเข้ารหัสแบบกุญแจสาธารณะ (public-key cryptography) passkey จะเพิ่มความปลอดภัยโดยเชื่อมโยงอุปกรณ์ของผู้ใช้ โดเมนของบริการ และรหัสผู้ใช้ (user ID) เข้าด้วยกัน ช่วยป้องกันการโจมตีแบบ phishing และรหัสผ่าน รองรับการใช้งานกับอุปกรณ์หรือเบราว์เซอร์ต่าง ๆ และให้ผู้ใช้ยืนยันตัวตนด้วยไบโอเมตริกซ์หรือฟีเจอร์ความปลอดภัยของฮาร์ดแวร์ได้อย่างสะดวก [WebAuthn](https://auth.wiki/webauthn) ให้ API สำหรับเว็บไซต์เพื่อใช้งาน passkey

Logto รองรับ passkeys (WebAuthn) ทั้งสำหรับ [การยืนยันตัวตนหลายปัจจัย (MFA)](/end-user-flows/mfa/configure-mfa) และ [การลงชื่อเข้าใช้ด้วย passkey](/end-user-flows/sign-up-and-sign-in/passkey-sign-in) โดยสามารถใช้ WebAuthn credential เดียวกันได้ทั้งสองกรณี ขึ้นอยู่กับการตั้งค่าของ tenant ของคุณ

## แนวคิด \{#concepts}

ลูกค้ามักจะรู้จัก Passkeys มากกว่า WebAuthn แล้วทั้งสองอย่างนี้เกี่ยวข้องกันอย่างไร และใช้งานอย่างไร? มาทำความเข้าใจแนวคิดเหล่านี้กัน:

- **Passkeys**: Passkey คือ credential ที่ใช้มาตรฐาน FIDO และต้านทาน phishing เพื่อทดแทนรหัสผ่าน ใช้การเข้ารหัสแบบกุญแจสาธารณะ-ส่วนตัว (asymmetric public-key cryptography) เพื่อความปลอดภัยที่สูงขึ้น อาจอยู่ในรูปแบบฮาร์ดแวร์โทเค็นหรือกุญแจความปลอดภัย เช่น อุปกรณ์ USB หรือ Bluetooth เนื่องจาก “Passkeys” เป็นวิธีการยืนยันตัวตนที่แสดงต่อผู้ใช้ จึงควรใช้คำนี้ในฝั่ง client ของผลิตภัณฑ์คุณ
- **WebAuthn**: เป็น JavaScript API ที่พัฒนาโดย W3C และ FIDO Alliance เพื่อให้เว็บแอปพลิเคชันสามารถยืนยันตัวตนตามมาตรฐาน FIDO2 ได้ Passkeys เป็นหนึ่งในวิธีการยืนยันตัวตนที่ WebAuthn รองรับ ใน Logto Console เราจะเรียกการเชื่อมต่อนี้อย่างเป็นทางการว่า “WebAuthn”

WebAuthn มีตัวเลือกตัวตรวจสอบ (authenticator) หลากหลายให้ผู้ใช้เลือก แบ่งเป็น 2 ประเภทสำหรับการใช้งานในเครื่องและบนคลาวด์:

- **Platform authenticator (Internal authenticator)**: ผูกกับระบบปฏิบัติการของอุปกรณ์เดียว เช่น คอมพิวเตอร์ แล็ปท็อป โทรศัพท์ หรือแท็บเล็ตที่ผู้ใช้ลงชื่อเข้าใช้ ใช้งานได้เฉพาะบนอุปกรณ์นั้นโดยใช้ไบโอเมตริกซ์หรือรหัสผ่านอุปกรณ์ เช่น iCloud Keychain ที่ยืนยันด้วย Touch ID, Face ID หรือรหัสผ่านอุปกรณ์บน macOS หรือ iOS; Windows Hello ที่ยืนยันด้วยใบหน้า ลายนิ้วมือ หรือ PIN
- **Roaming authenticator (External authenticator, Cross-platform authenticator)**: เป็นอุปกรณ์หรือแอปพลิเคชันแยกต่างหากที่พกพาได้ เช่น กุญแจความปลอดภัยฮาร์ดแวร์หรือสมาร์ทโฟน ต้องเชื่อมต่ออุปกรณ์ผ่าน USB หรือเปิด NFC/Bluetooth ตัว roaming authenticator ไม่จำกัดเฉพาะอุปกรณ์หรือเบราว์เซอร์เดียว ให้ความยืดหยุ่นมากกว่า

หากต้องการเจาะลึกหลักการและกระบวนการของ WebAuthn สามารถอ่านได้ที่บล็อกของเรา: [WebAuthn and Passkeys 101](https://blog.logto.io/web-authn-and-passkey-101/) และ [สิ่งที่ควรรู้ก่อนเชื่อมต่อ WebAuthn](https://blog.logto.io/webauthn-base-knowledge/)

## ตั้งค่าการตรวจสอบ passkeys สำหรับ MFA \{#configure-passkeys-verification-for-mfa}

1. ไปที่ <CloudLink to="/mfa">Console > การยืนยันตัวตนหลายปัจจัย (Multi-factor authentication)</CloudLink>
2. เปิดใช้งานปัจจัย “Passkeys (WebAuthn)” แนะนำให้ใช้ Passkeys ร่วมกับปัจจัย MFA อื่น ๆ (TOTP, SMS, รหัสสำรอง) เพื่อลดความเสี่ยงจากการพึ่งพาปัจจัยเดียว
3. กำหนดนโยบาย MFA ที่ต้องการ (บังคับใช้หรือไม่บังคับ)
4. บันทึกการเปลี่ยนแปลงการตั้งค่า

:::tip
หากผู้ใช้เดียวกันลงชื่อเข้าใช้ด้วย [passkey sign-in](/end-user-flows/sign-up-and-sign-in/passkey-sign-in) Logto จะข้ามขั้นตอนตรวจสอบ MFA แยกต่างหาก เพราะการลงชื่อเข้าใช้ด้วย passkey ถือว่าผ่านการตรวจสอบ WebAuthn แล้ว
:::

:::note ให้ความสำคัญกับข้อจำกัด

ควรตระหนักถึงข้อจำกัดบางประการเมื่อใช้งาน WebAuthn:

1. **ข้อจำกัดด้านแพลตฟอร์มและเบราว์เซอร์**: ปัจจุบัน Logto ยังไม่รองรับ WebAuthn สำหรับแอปพลิเคชัน native และการรองรับ WebAuthn authenticator ขึ้นอยู่กับเบราว์เซอร์และอุปกรณ์ ([ตรวจสอบรายการ](https://caniuse.com/?search=webauthn)) ดังนั้น WebAuthn จึงไม่ใช่ตัวเลือกเดียวสำหรับการใช้งาน MFA เว้นแต่คุณจะควบคุมได้ว่าเบราว์เซอร์และอุปกรณ์ใดเข้าถึงผลิตภัณฑ์ของคุณ
2. **ข้อจำกัดด้านโดเมน**: การเปลี่ยนโดเมนอาจทำให้ผู้ใช้ไม่สามารถยืนยันตัวตนผ่านบัญชี WebAuthn เดิมได้ Passkeys จะผูกกับโดเมนของหน้าเว็บปัจจุบันและไม่สามารถใช้ข้ามโดเมนได้
3. **ข้อจำกัดด้านอุปกรณ์**: หากผู้ใช้ทำอุปกรณ์หาย อาจสูญเสียการเข้าถึงบัญชี โดยเฉพาะผู้ที่ใช้ Platform Authenticator แบบ “This device” ทางที่ดีควรให้ผู้ใช้มีปัจจัยยืนยันตัวตนมากกว่าหนึ่งอย่าง

:::

## ตั้งค่าการจัดการ passkeys \{#configure-passkeys-management}

คุณสามารถใช้ Account API เพื่อสร้างอินเทอร์เฟซจัดการบัญชีแบบกำหนดเอง ให้ผู้ใช้เพิ่ม ดู เปลี่ยนชื่อ และลบ passkeys ได้ เหมาะสำหรับสร้างศูนย์บัญชีส่วนตัวและรองรับกรณีสำรองข้อมูลข้ามอุปกรณ์

ดูขั้นตอนการใช้งานและ API endpoint ได้ที่ [การตั้งค่าบัญชีด้วย Account API](/end-user-flows/account-settings/by-account-api#link-a-new-webauthn-passkey)

## ส่งออก passkeys \{#export-passkeys}

คุณสามารถส่งออก WebAuthn credentials ที่ Logto เก็บไว้ให้ผู้ใช้แต่ละรายได้ด้วย [Management API](/integrate-logto/interact-with-management-api) ใช้การส่งออกนี้เพื่อย้าย passkeys ไปยังระบบอื่นที่รองรับ WebAuthn บนโดเมนเดียวกัน เพื่อให้ผู้ใช้ยังคงลงชื่อเข้าใช้ด้วย passkey เดิมได้

เรียก [`GET /api/users/{userId}/mfa-verifications`](https://openapi.logto.io/operation/operation-listusermfaverifications) พร้อม query parameter `includeWebAuthnCredentials` เป็น `true`:

```bash
curl "https://[tenant-id].logto.app/api/users/{userId}/mfa-verifications?includeWebAuthnCredentials=true" \
  -H 'authorization: Bearer <management-api-access-token>'
```

แต่ละ WebAuthn entry ใน response จะมี credential ที่จัดเก็บไว้:

```json
[
  {
    "id": "wv9m3k2x7p1q",
    "createdAt": "2026-10-12T08:31:24.000Z",
    "lastUsedAt": "2026-11-02T06:15:09.000Z",
    "type": "WebAuthn",
    "agent": "Mozilla/5.0 (Macintosh) ...",
    "name": "MacBook",
    "rpId": "auth.example.com",
    "credentialId": "Ab3dY0n9Kq2LwX8mR4sT1uV6zE",
    "publicKey": "pQECAyYgASFYIOrE5x...",
    "counter": 0,
    "transports": ["internal", "hybrid"]
  }
]
```

| Field          | คำอธิบาย                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------- |
| `credentialId` | รหัส credential ของ WebAuthn ในรูปแบบ base64url                                                    |
| `publicKey`    | กุญแจสาธารณะของ credential ในรูปแบบ COSE และ base64url                                             |
| `counter`      | ตัวนับลายเซ็นล่าสุด (`signCount`) ที่ Logto พบสำหรับ credential หลาย passkey จะรายงานเป็น `0` เสมอ |
| `transports`   | วิธีการเชื่อมต่อที่ authenticator รายงานขณะลงทะเบียน เช่น `internal`, `hybrid`, หรือ `usb`         |
| `rpId`         | รหัส relying party (โดเมน) ที่ credential ถูกลงทะเบียนไว้                                          |
| `createdAt`    | เวลาที่ credential ถูกลงทะเบียน                                                                    |
| `lastUsedAt`   | เวลาที่ credential ถูกใช้ครั้งล่าสุดเพื่อยืนยันตัวตนผู้ใช้                                         |

หากไม่ใส่ `includeWebAuthnCredentials` ใน request response จะไม่มี `credentialId`, `publicKey`, `counter`, `transports` และ `rpId` ปัจจัย MFA อื่น ๆ จะถูกส่งกลับตามปกติ พารามิเตอร์นี้ใช้ได้กับ Management API แบบ read-only เพราะ credential ID และ public key ไม่สามารถใช้ลงชื่อเข้าใช้ได้

เมื่อคุณนำ credential ไปใช้กับระบบอื่น:

- **ใช้โดเมนเดิม** Passkey จะใช้ได้เฉพาะกับ relying party ID ที่ลงทะเบียนไว้เท่านั้น ระบบอื่นต้องใช้ `rpId` ที่ส่งออกเป็น WebAuthn relying party ID ของตัวเอง ซึ่งหมายถึงต้องให้บริการลงชื่อเข้าใช้บนโดเมนนั้น เช่น [custom domain](/logto-cloud/custom-domain) ของคุณ
- **จัดการ credential ที่ไม่มี `rpId`** Credential ที่ลงทะเบียนก่อน Logto จะบันทึก relying party ID และยังไม่ถูกใช้งานหลังจากนั้น จะไม่มี `rpId` โดย credential เหล่านี้จะผูกกับโดเมนที่ให้บริการหน้าลงชื่อเข้าใช้ขณะลงทะเบียน ซึ่งอาจไม่ใช่ custom domain ปัจจุบันของคุณ
- **แมป user handle** Logto จะลงทะเบียน byte ของ user ID (UTF-8) เป็น WebAuthn `userHandle` สำหรับการลงชื่อเข้าใช้ด้วย passkey authenticator จะส่งค่านี้กลับมา ดังนั้นระบบอื่นต้องแมปกับผู้ใช้ที่ย้ายข้อมูลไป
- **เก็บ counter** บันทึก `counter` เป็นตัวนับลายเซ็นปัจจุบันของ credential เพื่อให้ระบบอื่นสามารถตรวจจับ authenticator ที่ถูกโคลนได้ต่อไป

## ขั้นตอนการตรวจสอบ Passkey \{#passkey-verification-flows}

เมื่อผู้ใช้ตั้งค่า MFA หลายวิธีรวมถึง passkey ระบบจะแนะนำ passkey เป็นวิธีตรวจสอบ MFA หลักบนหน้าจอแรก เพราะปลอดภัยและสะดวกกว่า ผู้ใช้สามารถเปลี่ยนไปใช้วิธีอื่นได้โดยคลิก “ลองวิธีอื่นเพื่อยืนยันตัวตน” ด้านล่าง อ่าน [ตั้งค่า MFA](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) เพื่อดูรายละเอียด

หากผู้ใช้ลงชื่อเข้าใช้ด้วย [passkey sign-in](/end-user-flows/sign-up-and-sign-in/passkey-sign-in) แทนการกรอกปัจจัยแรกแบบอื่น Logto จะไม่ถามหาขั้นตอน MFA เพิ่มเติม เพราะ passkey ถือเป็นปัจจัย MFA แบบ WebAuthn อยู่แล้ว
