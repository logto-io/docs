# การยืนยันอีเมลสำหรับ MFA

Logto รองรับฟังก์ชันการยืนยันตัวตนหลายปัจจัย (MFA) ผ่านอีเมล ซึ่งช่วยเพิ่มความปลอดภัยให้กับบัญชีโดยการส่งรหัสยืนยันแบบใช้ครั้งเดียวไปยังอีเมลที่ลงทะเบียนของผู้ใช้ การยืนยันอีเมลสำหรับ MFA ทำหน้าที่เป็นปัจจัยการยืนยันตัวตนลำดับที่สอง และสามารถใช้ร่วมกับปัจจัย MFA อื่น ๆ (เช่น TOTP, passkeys, รหัสสำรอง) เพื่อมอบตัวเลือกการยืนยันตัวตนสองขั้นตอนที่ยืดหยุ่นให้กับผู้ใช้

## แนวคิด \{#concepts}

การยืนยันอีเมลเป็นหนึ่งในวิธี MFA ที่เข้าถึงได้มากที่สุด โดยอาศัยความแพร่หลายของบัญชีอีเมลในการส่งรหัสยืนยันแบบใช้ครั้งเดียวไปยังกล่องจดหมายของผู้ใช้โดยตรง แตกต่างจากแอปยืนยันตัวตนที่ต้องติดตั้งซอฟต์แวร์เพิ่มเติม MFA ผ่านอีเมลใช้โครงสร้างพื้นฐานอีเมลที่มีอยู่แล้วซึ่งผู้ใช้อินเทอร์เน็ตแทบทุกคนเข้าถึงได้ผ่านเว็บเบราว์เซอร์ โปรแกรมอีเมล หรือแอปมือถือ ทำให้ผู้ใช้สามารถใช้งานได้ทันทีโดยไม่ต้องมีฮาร์ดแวร์พิเศษหรือการตั้งค่าเพิ่มเติมนอกจากมีบัญชีอีเมล

## ตั้งค่าการยืนยันอีเมลสำหรับ MFA \{#configure-email-verification-for-mfa}

**ขั้นตอนที่ 1: ตั้งค่าตัวเชื่อมต่ออีเมลและเทมเพลต**

1. ไปที่ <CloudLink to="/connectors/passwordless">Console > Connectors > Email and SMS connectors</CloudLink>
2. เลือกตัวเชื่อมต่ออีเมลที่เหมาะสม (SendGrid, Mailgun ฯลฯ)
3. กำหนดค่าพารามิเตอร์การเชื่อมต่อ
4. ตั้งค่า [เทมเพลตอีเมล](/connectors/email-connectors/email-templates) สำหรับ MFA โดยใช้ประเภทการใช้งานเฉพาะ:

   - `MfaVerification` usageType สำหรับการยืนยัน MFA
   - `BindMfa` usageType สำหรับการผูก MFA
   - เคล็ดลับ: [Logto Email Service](/connectors/email-connectors/built-in-email-service) มีเทมเพลตอีเมลสำเร็จรูปให้ใช้งาน

5. ดูรายละเอียดการตั้งค่าเฉพาะผู้ให้บริการได้ที่ [Email connectors](/connectors/email-connectors)

**ขั้นตอนที่ 2: เปิดใช้งานอีเมลสำหรับ MFA**

1. ไปที่ <CloudLink to="/mfa">Console > Multi-factor authentication</CloudLink>
2. เปิดใช้งานปัจจัย "Email verification code" แนะนำให้ใช้อีเมล MFA ร่วมกับปัจจัย MFA อื่น ๆ (TOTP, passkeys, SMS, รหัสสำรอง) เพื่อลดการพึ่งพาปัจจัยเดียว
3. ใน **Email/SMS 2-step verification** เลือกว่าผู้ใช้กลุ่มใดจะมีอีเมล MFA ดู [ใครมีอีเมล MFA](#who-has-email-mfa)
4. กำหนดนโยบาย MFA ที่ต้องการ (optional, adaptive หรือ mandatory)
5. บันทึกการเปลี่ยนแปลงการตั้งค่า

:::note ข้อควรพิจารณาในการใช้งานที่สำคัญ

1. **ข้อจำกัดวิธีลงชื่อเข้าใช้**: รหัสยืนยันอีเมลไม่สามารถใช้เป็นทั้ง [วิธีลงชื่อเข้าใช้ (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in) และปัจจัย MFA (2FA) พร้อมกันได้ ให้เลือก flow การยืนยันตัวตนแบบเดียวต่อการใช้งานอีเมลแต่ละครั้ง

2. **ความเข้ากันได้กับวิธีสมัครสมาชิก**: รหัสยืนยันอีเมลสามารถใช้เป็นทั้งวิธีสมัครสมาชิกและ MFA พร้อมกันได้ Logto จะปรับปรุง flow การลงทะเบียนของผู้ใช้ปลายทางตามนโยบาย MFA ที่เลือกเพื่อหลีกเลี่ยงการยืนยันอีเมลซ้ำสำหรับอีเมลเดียวกัน

3. **ความเข้ากันได้กับการกู้คืนรหัสผ่าน**: แม้ว่ารหัสยืนยันอีเมลจะสามารถใช้กับทั้ง [ลืมรหัสผ่าน](/end-user-flows/sign-up-and-sign-in/reset-password) และ MFA พร้อมกันได้ แต่ **ไม่แนะนำ** การตั้งค่านี้ เพราะจะลดประสิทธิภาพความปลอดภัยของ MFA เนื่องจากผู้ใช้อาจข้าม MFA ได้โดยใช้การยืนยันอีเมลสำหรับลืมรหัสผ่านเพื่อรีเซ็ตรหัสผ่าน แล้วใช้รหัสผ่านใหม่สำหรับการยืนยันตัวตนหลัก (1FA) ตามด้วยวิธีอีเมลเดิมสำหรับ MFA

:::

## ใครมีอีเมล MFA \{#who-has-email-mfa}

รหัส MFA ทางอีเมลจะถูกส่งไปยังอีเมลหลักของผู้ใช้เสมอ การตั้งค่า **Email/SMS 2-step verification** ในหน้า <CloudLink to="/mfa">Multi-factor authentication</CloudLink> จะกำหนดว่าผู้ใช้กลุ่มใดจะมีอีเมล MFA:

- **ผู้ใช้ทุกคนที่มีอีเมลหรือเบอร์โทรศัพท์ที่ยืนยันแล้ว**: ผู้ใช้ทุกคนที่มีอีเมลหลักจะมีอีเมล MFA โดยไม่ต้องตั้งค่า
- **เฉพาะผู้ใช้ที่ตั้งค่าเอง**: เฉพาะผู้ใช้ที่ตั้งค่าอีเมล MFA เท่านั้นที่จะมี ผู้ใช้ที่สมัครด้วยอีเมลที่ยืนยันแล้วจะไม่ได้อีเมล MFA โดยอัตโนมัติ คุณจึงสามารถเสนออีเมลเป็นหนึ่งในตัวเลือก MFA โดยไม่ต้องลงทะเบียนให้ทุกคน ผู้ใช้สามารถตั้งค่าได้ใน flow ตั้งค่า MFA, ใน [Account Center](/end-user-flows/account-settings/by-account-center-ui) หรือผ่าน [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa) ผู้ดูแลระบบสามารถเพิ่มหรือลบให้ผู้ใช้แต่ละรายผ่าน [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management)

การตั้งค่านี้ใช้กับ [SMS MFA](/end-user-flows/mfa/sms-mfa) ด้วย ดูค่าเริ่มต้นและผลกระทบเมื่อเปลี่ยนโหมดได้ที่ [การลงทะเบียน Email และ SMS MFA](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment)

:::note
สำหรับ **ผู้ใช้ทุกคนที่มีอีเมลหรือเบอร์โทรศัพท์ที่ยืนยันแล้ว** ผู้ใช้ที่มีอีเมล MFA เพียงเพราะมีอีเมลหลักจะไม่มีบันทึก MFA อีเมลในระบบ ดังนั้นจะไม่ปรากฏใน `GET /api/my-account/mfa-verifications`, `GET /api/users/{userId}/mfa-verifications` หรือ `user.mfaVerificationFactors` (Custom JWT claims และ `PostSignIn` Actions)
:::

## ขั้นตอนการตั้งค่าอีเมล MFA \{#email-mfa-setup-flows}

หน้าตั้งค่า MFA อาจปรากฏระหว่างการลงทะเบียนผู้ใช้หรือหลังลงชื่อเข้าใช้ ขึ้นอยู่กับ [นโยบาย MFA](/end-user-flows/mfa/configure-mfa#global-mfa-configuration) ที่คุณตั้งค่าไว้

flow การตั้งค่าอีเมล MFA จะได้รับผลกระทบจากปัจจัยต่อไปนี้:

- **จำนวนปัจจัย MFA หลัก**: หากมีปัจจัยหลักหลายตัว ผู้ใช้ต้องเลือกหนึ่งตัวเพื่อกำหนดค่า ปัจจัยหลักคือวิธี MFA ที่ไม่ใช่รหัสสำรอง
- **เปิดใช้งานรหัสสำรอง**: เมื่อเปิดใช้งาน รหัสสำรองจะถูกสร้างอัตโนมัติหลังจากตั้งค่าปัจจัย MFA หลัก ผู้ใช้จะถูกแจ้งให้บันทึก
- **การตั้งค่าตัวระบุสมัครสมาชิก**: อีเมลถูกใช้เป็น [ตัวระบุสมัครสมาชิก](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier) และผู้ใช้ได้ยืนยันแล้วด้วยรหัสอีเมลระหว่างลงทะเบียน
  - สำหรับ **ผู้ใช้ทุกคนที่มีอีเมลหรือเบอร์โทรศัพท์ที่ยืนยันแล้ว** ระบบจะผูกอีเมลนั้นเป็นปัจจัย MFA โดยอัตโนมัติและไม่ต้องยืนยันซ้ำ หากมีปัจจัยหลักอื่น UI จะแสดงตัวเลือก "เพิ่มการยืนยัน 2 ขั้นตอน" (ผู้ใช้อาจข้ามได้) ซึ่งแสดงชัดเจนว่าเปิดใช้ MFA แล้ว
  - สำหรับ **เฉพาะผู้ใช้ที่ตั้งค่าเอง** อีเมลจะถูกเสนอเหมือนปัจจัยอื่น ๆ พร้อมที่อยู่ที่ถูกปิดบัง เมื่อผู้ใช้เลือก หรือเมื่อเป็นปัจจัยหลักเดียว Logto จะตั้งค่าด้วยการยืนยันจากการลงทะเบียนโดยไม่ส่งรหัสซ้ำ
- **ข้อมูลผู้ใช้ที่มีอยู่**: เมื่อผู้ใช้ที่มีอยู่ตั้งค่า MFA หลังลงชื่อเข้าใช้ ต้องยืนยันตัวตนหลักก่อนแล้วจึงตั้งค่า MFA หากบัญชีมีอีเมลหลักที่ยืนยันแล้ว:
  - สำหรับ **ผู้ใช้ทุกคนที่มีอีเมลหรือเบอร์โทรศัพท์ที่ยืนยันแล้ว** การตั้งค่าจะเหมือนกรณีตัวระบุสมัครสมาชิกข้างต้น
  - สำหรับ **เฉพาะผู้ใช้ที่ตั้งค่าเอง** อีเมลจะถูกเสนอพร้อมที่อยู่ที่ถูกปิดบัง เมื่อผู้ใช้เลือก หรือเมื่อเป็นปัจจัยหลักเดียว Logto จะส่งรหัสยืนยันไปยังอีเมลนั้น และจะตั้งค่า MFA อีเมลเมื่อผู้ใช้กรอกรหัส

ด้านล่างคือตัวอย่างสถานการณ์การผูก MFA อีเมลที่พบบ่อย 3 แบบ

### สถานการณ์ที่ 1: ใช้อีเมลสำหรับ MFA เท่านั้น (flow ทั่วไป) \{#scenario-1-email-address-only-used-for-mfa-typical-flow}

- หากมีปัจจัย MFA อีเมลเพียงตัวเดียว ให้แสดง UI ตั้งค่าสำหรับปัจจัยนั้นโดยตรง

สำหรับ **เฉพาะผู้ใช้ที่ตั้งค่าเอง** ผู้ใช้จะเลือกปัจจัยจากรายการก่อน ข้อความ "เพิ่มการยืนยัน 2 ขั้นตอน" จะปรากฏเมื่อผู้ใช้เพิ่งตั้งค่าอีเมล, SMS หรือ passkey สำหรับลงชื่อเข้าใช้เป็นปัจจัยเดียว

## ขั้นตอนการยืนยัน MFA อีเมล \{#email-mfa-verification-flows}

เมื่อผู้ใช้ที่เปิดใช้งาน MFA อีเมลลงชื่อเข้าใช้ หลังจากผ่านการยืนยันตัวตนหลัก (1FA) แล้ว จะถูกขอให้ยืนยันตัวตนด้วยรหัสยืนยันอีเมลเป็นปัจจัยที่สอง (2FA)

หากมีปัจจัย MFA หลายตัว Logto จะเปิดปัจจัยที่มีลำดับความสำคัญสูงสุดโดยตรงตามลำดับที่กำหนดไว้ใน [Configure MFA](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) (Passkey, Authenticator app OTP, รหัสยืนยัน SMS, รหัสยืนยันอีเมล, รหัสสำรอง) หากปัจจัยอื่นเช่น Authenticator app OTP ถูกแสดงก่อน ผู้ใช้สามารถคลิก **ลองวิธีอื่นเพื่อยืนยัน** เพื่อเปิดรายการเลือกและเลือกใช้รหัสยืนยันอีเมลแทน

## การจัดการข้อผิดพลาด \{#error-handling}

1. **ยังไม่ได้ผูกอีเมล**

   - รหัสข้อผิดพลาด: `session.mfa.mfa_factor_not_enabled`
   - วิธีจัดการ: แนะนำผู้ใช้ให้ผูกอีเมลก่อน

2. **รหัสยืนยันไม่ถูกต้อง**

   - รหัสข้อผิดพลาด: `verification_code.code_mismatch`
   - วิธีจัดการ: แจ้งให้ผู้ใช้กรอกใหม่ จำกัดจำนวนครั้งที่ลอง

3. **รหัสยืนยันหมดอายุ**

   - รหัสข้อผิดพลาด: `verification_code.expired`
   - วิธีจัดการ: แจ้งให้ผู้ใช้ขอรหัสใหม่

4. **เกินขีดจำกัดการส่ง**
   - รหัสข้อผิดพลาด: `request.message_rate_limited` (Logto จำกัดอัตราการส่งต่อผู้รับ) หรือ `connector.rate_limit_exceeded` (ขีดจำกัดอัตราการส่งของตัวเชื่อมต่ออีเมล)
   - วิธีจัดการ: แสดงเวลารอ จำกัดการส่งซ้ำ
