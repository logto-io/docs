# การยืนยันตัวตนหลายปัจจัย (MFA)

## MFA คืออะไร? \{#what-is-mfa}

[การยืนยันตัวตนหลายปัจจัย (MFA)](https://auth.wiki/mfa) เป็นวิธีการรักษาความปลอดภัยที่เพิ่มชั้นการป้องกันระหว่างกระบวนการเข้าสู่ระบบ โดยผู้ใช้ต้องแสดงข้อมูลยืนยันตัวตนหลายรายการเพื่อยืนยันเอกลักษณ์ดิจิทัลของตน

มีประเภทของการยืนยันตัวตนหลักสองแบบ:

- **SFA/1FA (การยืนยันตัวตนปัจจัยเดียว; Single-Factor Authentication)**: เป็นวิธีเข้าสู่ระบบขั้นต้น โดยทั่วไปต้องใช้ [ชื่อผู้ใช้/อีเมล/โทรศัพท์และรหัสผ่าน](/end-user-flows/sign-up-and-sign-in/sign-in) หรือ [เข้าสู่ระบบโซเชียล](/end-user-flows/sign-up-and-sign-in/social-sign-in)
- **MFA/2FA (การยืนยันตัวตนหลายปัจจัย/สองปัจจัย; Multi-Factor Authentication/Two-Factor Authentication)**: MFA กำหนดให้ต้องมีวิธีการตรวจสอบอย่างน้อยสองแบบที่แตกต่างกันในการเข้าถึงบัญชีของคุณ ซึ่งช่วยเสริมความปลอดภัยจากการเข้าถึงโดยไม่ได้รับอนุญาตอย่างมีประสิทธิภาพ

ปัจจัยการยืนยันตัวตนคือมาตรการที่ใช้ตรวจสอบตัวตนของคุณ โดยมีปัจจัยหลากหลายที่แบ่งตามคุณลักษณะให้เลือกใช้:

| ประเภท      | ความหมาย       | ปัจจัยการตรวจสอบ (ที่ Logto รองรับ)                                                 |
| ----------- | -------------- | ----------------------------------------------------------------------------------- |
| ความรู้     | สิ่งที่คุณรู้  | รหัสผ่าน, รหัสยืนยันอีเมล, และรหัสสำรอง                                             |
| การครอบครอง | สิ่งที่คุณมี   | รหัสยืนยัน SMS, รหัส OTP จากแอป Authenticator, รหัส OTP จากฮาร์ดแวร์ (Security key) |
| ลักษณะเฉพาะ | สิ่งที่คุณเป็น | ไบโอเมตริกซ์ เช่น ลายนิ้วมือ, Face ID                                               |

ในกระบวนการ MFA ขั้นตอนการยืนยันตัวตนที่สองต้องใช้ปัจจัยที่มีคุณลักษณะแตกต่างจากขั้นตอนแรก (ความรู้/การครอบครอง/ลักษณะเฉพาะ) ตัวอย่างเช่น การใช้ “รหัสผ่าน (ความรู้)” เป็นปัจจัยแรก และ “รหัส OTP จากแอป Authenticator (การครอบครอง)” เป็นปัจจัยที่สอง จะช่วยลดความเสี่ยงจากการโจมตีได้อย่างมีประสิทธิภาพ

## ทำไมเราต้องใช้ MFA? \{#why-do-we-need-an-mfa}

MFA เป็นมาตรการรักษาความปลอดภัยที่สำคัญ โดยเฉพาะสำหรับบริการ B2B และ B2E และได้รับการนำไปใช้อย่างแพร่หลายในยุคดิจิทัลปัจจุบันด้วยเหตุผลหลายประการ:

- **การแฮ็กบัญชี**: การเข้าถึงบัญชีโดยไม่ได้รับอนุญาตยังคงเป็นภัยคุกคามด้านความปลอดภัยที่สำคัญ อย่างไรก็ตาม MFA ให้การป้องกันที่แข็งแกร่ง สามารถป้องกันการแฮ็กบัญชีได้ถึง 99.9% โดยเฉพาะจากการรั่วไหลของรหัสผ่าน ถือเป็นการเสริมความปลอดภัยที่คุ้มค่า นอกเหนือจากกลยุทธ์อื่น ๆ เช่น การเข้าสู่ระบบแบบไม่ใช้รหัสผ่าน นโยบายรหัสผ่านที่เข้มงวด ตัวจัดการรหัสผ่าน และมาตรการป้องกันการโจมตี
- **การนำ SaaS มาใช้**: หลายองค์กรเริ่มนำ MFA มาใช้มากขึ้นเพื่อปกป้องพนักงานและข้อมูล/ทรัพย์สินสำคัญของบริษัท จากผลสำรวจของ LastPass พบว่า 57% ของธุรกิจทั่วโลกใช้ MFA แล้ว เพิ่มขึ้น 12% จากปีก่อนหน้า
- **การปฏิบัติตามข้อกำหนด**: MFA ช่วยให้องค์กรปฏิบัติตามข้อกำหนดด้านการคุ้มครองข้อมูล เช่น GDPR และ NIST เพื่อความปลอดภัยของข้อมูลผู้ใช้

## การรองรับของ Logto \{#logto-support}

Logto ทำให้การเปิดใช้งาน MFA เป็นเรื่องง่ายด้วยการสลับเปิด/ปิดเพียงคลิกเดียว โดยไม่ต้องตั้งค่าซับซ้อน เริ่มต้นด้วยคู่มือ [การเปิดใช้งานปัจจัยการตรวจสอบ](/end-user-flows/mfa/configure-mfa)

**ปัจจัย MFA ที่รองรับ**:

- [Passkeys (WebAuthn)](/end-user-flows/mfa/webauthn): ใช้ Security key หรือการยืนยันตัวตนด้วยไบโอเมตริกซ์เพื่อประสบการณ์แบบไม่ใช้รหัสผ่าน
- [รหัส OTP จากแอป Authenticator](/end-user-flows/mfa/authenticator-app-otp): ใช้รหัสผ่านแบบใช้ครั้งเดียวตามเวลา (TOTP) ที่สร้างโดยแอป Authenticator เช่น Google Authenticator หรือ Authy
- [การยืนยัน SMS](/end-user-flows/mfa/sms-mfa): ใช้ข้อความ SMS เพื่อส่งรหัสใช้ครั้งเดียว (รหัสยืนยัน) สำหรับการยืนยันตัวตน
- [การยืนยันอีเมล](/end-user-flows/mfa/email-mfa): ใช้อีเมลเพื่อส่งรหัสใช้ครั้งเดียว (รหัสยืนยัน) สำหรับการยืนยันตัวตน
- [รหัสสำรอง](/end-user-flows/mfa/backup-codes): สร้างรหัสสำรองแบบใช้ครั้งเดียวสำหรับกรณีฉุกเฉิน

**ความสามารถ MFA ที่เกี่ยวข้อง**:

- [อุปกรณ์ที่เชื่อถือได้](/end-user-flows/mfa/trusted-devices): ให้ผู้ใช้ข้ามการถาม MFA ซ้ำ ๆ บนเบราว์เซอร์ที่เชื่อถือได้ด้วยข้อมูลรับรองที่มีอายุจำกัดและสามารถเพิกถอนได้ ผู้ใช้เลือกเปิดใช้งานในหน้า **เชื่อถืออุปกรณ์นี้ (Trust this device)** แยกต่างหากเมื่อสิ้นสุดกระบวนการลงชื่อเข้าใช้หรือสมัครใช้งานที่เข้าเงื่อนไข
