# การยืนยันตัวตนหลายปัจจัย (MFA)

## MFA คืออะไร? \{#what-is-mfa}

[การยืนยันตัวตนหลายปัจจัย (MFA)](https://auth.wiki/mfa) เป็นวิธีการรักษาความปลอดภัยที่เพิ่มชั้นการป้องกันพิเศษในระหว่างกระบวนการเข้าสู่ระบบ โดยผู้ใช้ต้องแสดงข้อมูลยืนยันตัวตนหลายรายการเพื่อยืนยันอัตลักษณ์ดิจิทัลของตน

มีประเภทของการยืนยันตัวตนหลักสองแบบ:

- **SFA/1FA (การยืนยันตัวตนปัจจัยเดียว; Single-Factor Authentication)**: เป็นวิธีเข้าสู่ระบบขั้นต้น โดยทั่วไปจะใช้ [ชื่อผู้ใช้/อีเมล/เบอร์โทรศัพท์และรหัสผ่าน](/end-user-flows/sign-up-and-sign-in/sign-in) หรือ [เข้าสู่ระบบโซเชียล](/end-user-flows/sign-up-and-sign-in/social-sign-in)
- **MFA/2FA (การยืนยันตัวตนหลายปัจจัย/สองปัจจัย; Multi-Factor Authentication/Two-Factor Authentication)**: MFA กำหนดให้ต้องมีวิธีการตรวจสอบอย่างน้อยสองวิธีที่แตกต่างกันในการเข้าถึงบัญชีของคุณ ซึ่งช่วยเสริมความแข็งแกร่งในการป้องกันการเข้าถึงโดยไม่ได้รับอนุญาต

ปัจจัยการยืนยันตัวตนคือมาตรการที่ใช้ตรวจสอบตัวตนของคุณ โดยมีปัจจัยหลายประเภทที่จัดกลุ่มตามคุณลักษณะให้เลือกใช้:

| ประเภท     | ความหมาย       | ปัจจัยการตรวจสอบ (ที่ Logto รองรับ)                                                 |
| ---------- | -------------- | ----------------------------------------------------------------------------------- |
| Knowledge  | สิ่งที่คุณรู้  | รหัสผ่าน, รหัสยืนยันอีเมล, และรหัสสำรอง                                             |
| Possession | สิ่งที่คุณมี   | รหัสยืนยัน SMS, รหัส OTP จากแอป Authenticator, รหัส OTP จากฮาร์ดแวร์ (Security key) |
| Inherence  | สิ่งที่คุณเป็น | ไบโอเมตริกซ์ เช่น ลายนิ้วมือ, Face ID                                               |

ในกระบวนการ MFA การใช้ปัจจัยที่สองจากหมวดคุณลักษณะที่แตกต่างจากปัจจัยแรก (Knowledge / Possession / Inherence) จะช่วยเพิ่มความปลอดภัยต่อการถูกเจาะผ่านช่องทางเดียว โปรดทราบว่า Logto ไม่ได้บังคับให้ใช้หมวดคุณลักษณะที่แตกต่างกันระหว่าง 1FA และ 2FA; เพียงแต่ห้ามใช้วิธีรหัสยืนยันอีเมลหรือ SMS ซ้ำทั้งเป็นวิธีเข้าสู่ระบบ (1FA) และเป็นปัจจัย MFA (2FA)

## ทำไมเราต้องใช้ MFA? \{#why-do-we-need-an-mfa}

MFA เป็นมาตรการรักษาความปลอดภัยที่สำคัญ โดยเฉพาะสำหรับบริการ B2B และ B2E ซึ่งได้รับการนำไปใช้อย่างแพร่หลายในยุคดิจิทัลปัจจุบันด้วยเหตุผลหลายประการ:

- **การแฮ็กบัญชี**: การเข้าถึงบัญชีโดยไม่ได้รับอนุญาตยังคงเป็นภัยคุกคามด้านความปลอดภัยที่สำคัญ อย่างไรก็ตาม MFA ให้การป้องกันที่แข็งแกร่ง สามารถป้องกันการแฮ็กบัญชีได้ถึง 99.9% โดยเฉพาะกรณีที่เกิดจากการรั่วไหลของรหัสผ่าน ถือเป็นการเพิ่มความปลอดภัยที่คุ้มค่า เสริมด้วยกลยุทธ์อื่น เช่น การเข้าสู่ระบบแบบไม่ใช้รหัสผ่าน นโยบายรหัสผ่านที่แข็งแรง ตัวจัดการรหัสผ่าน และมาตรการป้องกันการโจมตี
- **การนำ SaaS มาใช้**: หลายองค์กรเริ่มนำ MFA มาใช้มากขึ้นเพื่อปกป้องพนักงานและข้อมูลสำคัญของบริษัท จากผลสำรวจของ LastPass พบว่า 57% ของธุรกิจทั่วโลกใช้ MFA แล้ว เพิ่มขึ้น 12% จากปีก่อนหน้า
- **การปฏิบัติตามข้อกำหนด**: MFA ช่วยให้องค์กรปฏิบัติตามข้อกำหนดด้านการคุ้มครองข้อมูล เช่น GDPR และ NIST เพื่อให้มั่นใจว่าข้อมูลผู้ใช้ปลอดภัย

## การรองรับของ Logto \{#logto-support}

Logto ทำให้การเปิดใช้งาน MFA ง่ายขึ้นด้วยการสลับเปิด-ปิดเพียงคลิกเดียว โดยไม่ต้องตั้งค่าซับซ้อน เริ่มต้นได้จากคู่มือ [การเปิดใช้งานปัจจัยการตรวจสอบ](/end-user-flows/mfa/configure-mfa)

**ปัจจัย MFA ที่รองรับ**:

- [Passkeys (WebAuthn)](/end-user-flows/mfa/webauthn): ใช้ security key หรือการยืนยันตัวตนด้วยไบโอเมตริกซ์เพื่อประสบการณ์แบบไม่ใช้รหัสผ่าน
- [รหัส OTP จากแอป Authenticator](/end-user-flows/mfa/authenticator-app-otp): ใช้รหัสผ่านแบบใช้ครั้งเดียวตามเวลา (TOTP) ที่สร้างโดยแอป Authenticator เช่น Google Authenticator หรือ Authy
- [การยืนยันผ่าน SMS](/end-user-flows/mfa/sms-mfa): ใช้ข้อความ SMS ส่งรหัสแบบใช้ครั้งเดียว (รหัสยืนยัน) เพื่อยืนยันตัวตน
- [การยืนยันผ่านอีเมล](/end-user-flows/mfa/email-mfa): ใช้อีเมลส่งรหัสแบบใช้ครั้งเดียว (รหัสยืนยัน) เพื่อยืนยันตัวตน
- [รหัสสำรอง](/end-user-flows/mfa/backup-codes): สร้างรหัสสำรองแบบใช้ครั้งเดียวสำหรับกรณีฉุกเฉิน

**นโยบาย MFA และการควบคุมการเข้าสู่ระบบ**:

- [ตั้งค่า MFA](/end-user-flows/mfa/configure-mfa): กำหนดนโยบาย MFA ระดับโกลบอล องค์กร และรายผู้ใช้ ข้อเสนอแนะปัจจัย และกฎของ flow การเข้าสู่ระบบ
- [อุปกรณ์ที่เชื่อถือได้](/end-user-flows/mfa/trusted-devices): ให้ผู้ใช้ข้ามการถาม MFA ซ้ำบนเบราว์เซอร์ที่เชื่อถือได้ด้วย credential ที่มีอายุจำกัดและเพิกถอนได้ ผู้ใช้เลือกเปิดใช้งานในหน้า **Trust this device** แยกต่างหากเมื่อจบ flow การเข้าสู่ระบบหรือสมัครสมาชิกที่เข้าเงื่อนไข
- [Adaptive MFA](/end-user-flows/mfa/adaptive-mfa): แจ้งขอ MFA ระหว่างเข้าสู่ระบบเฉพาะเมื่อกฎความเสี่ยงในตัวถูกกระตุ้น
