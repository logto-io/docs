# การยืนยันตัวตนหลายปัจจัย (MFA)

## MFA คืออะไร? \{#what-is-mfa}

[การยืนยันตัวตนหลายปัจจัย (MFA)](https://auth.wiki/mfa) เป็นวิธีการรักษาความปลอดภัยที่เพิ่มชั้นการป้องกันพิเศษระหว่างกระบวนการเข้าสู่ระบบ โดยผู้ใช้ต้องแสดงข้อมูลยืนยันตัวตนหลายรายการเพื่อยืนยันอัตลักษณ์ดิจิทัลของตน

มีประเภทของการยืนยันตัวตนหลักสองแบบ:

- **SFA/1FA (การยืนยันตัวตนปัจจัยเดียว; Single-Factor Authentication)**: เป็นวิธีเข้าสู่ระบบเบื้องต้น โดยทั่วไปจะใช้ [ชื่อผู้ใช้/อีเมล/เบอร์โทรศัพท์และรหัสผ่าน](/end-user-flows/sign-up-and-sign-in/sign-in) หรือ [เข้าสู่ระบบโซเชียล](/end-user-flows/sign-up-and-sign-in/social-sign-in)
- **MFA/2FA (การยืนยันตัวตนหลายปัจจัย/สองปัจจัย; Multi-Factor Authentication/Two-Factor Authentication)**: MFA กำหนดให้ต้องมีวิธีการยืนยันตัวตนอย่างน้อยสองแบบที่แตกต่างกันในการเข้าถึงบัญชีของคุณ ซึ่งช่วยเสริมความปลอดภัยจากการเข้าถึงโดยไม่ได้รับอนุญาตอย่างมีประสิทธิภาพ

ปัจจัยการยืนยันตัวตนคือมาตรการที่ใช้ตรวจสอบตัวตนของคุณ โดยมีปัจจัยหลายประเภทที่แบ่งตามคุณลักษณะให้เลือกใช้:

| ประเภท     | ความหมาย       | ปัจจัยการยืนยัน (ที่ Logto รองรับ)                                             |
| ---------- | -------------- | ------------------------------------------------------------------------------ |
| Knowledge  | สิ่งที่คุณรู้  | รหัสผ่าน, รหัสยืนยันทางอีเมล, และรหัสสำรอง                                     |
| Possession | สิ่งที่คุณมี   | รหัสยืนยันทาง SMS, รหัส OTP จากแอป Authenticator, ฮาร์ดแวร์ OTP (Security key) |
| Inherence  | สิ่งที่คุณเป็น | ไบโอเมตริกซ์ เช่น ลายนิ้วมือ, Face ID                                          |

ในกระบวนการ MFA การใช้ปัจจัยที่สองจากหมวดคุณลักษณะที่แตกต่างจากปัจจัยแรก (Knowledge / Possession / Inherence) จะช่วยเพิ่มความปลอดภัยจากการถูกเจาะช่องทางเดียว โปรดทราบว่า Logto ไม่ได้บังคับให้ใช้หมวดคุณลักษณะแตกต่างกันระหว่าง 1FA และ 2FA; เพียงแต่ห้ามใช้วิธีรหัสยืนยันทางอีเมลหรือ SMS ซ้ำทั้งเป็นวิธีเข้าสู่ระบบ (1FA) และเป็นปัจจัย MFA (2FA)

## ทำไมเราต้องใช้ MFA? \{#why-do-we-need-an-mfa}

MFA เป็นมาตรการรักษาความปลอดภัยที่สำคัญ โดยเฉพาะสำหรับบริการ B2B และ B2E ปัจจุบันมีการนำไปใช้กันอย่างแพร่หลายในโลกดิจิทัลด้วยเหตุผลหลายประการ:

- **การแฮ็กบัญชี**: การเข้าถึงบัญชีโดยไม่ได้รับอนุญาตยังคงเป็นภัยคุกคามด้านความปลอดภัยที่สำคัญ อย่างไรก็ตาม MFA ให้การป้องกันที่แข็งแกร่ง สามารถป้องกันการแฮ็กบัญชีได้ถึง 99.9% โดยเฉพาะกรณีที่เกิดจากการรั่วไหลของรหัสผ่าน ถือเป็นการเสริมความปลอดภัยที่คุ้มค่า นอกจากนี้ยังควรใช้ร่วมกับกลยุทธ์อื่น เช่น การเข้าสู่ระบบแบบไม่ใช้รหัสผ่าน นโยบายรหัสผ่านที่รัดกุม ตัวจัดการรหัสผ่าน และมาตรการป้องกันการโจมตี
- **การนำ SaaS ไปใช้**: หลายองค์กรเริ่มนำ MFA มาใช้มากขึ้นเพื่อปกป้องพนักงานและข้อมูลสำคัญของบริษัท จากผลสำรวจของ LastPass พบว่า 57% ของธุรกิจทั่วโลกใช้ MFA แล้ว เพิ่มขึ้น 12% จากปีก่อนหน้า
- **การปฏิบัติตามข้อกำหนด**: MFA ช่วยให้องค์กรปฏิบัติตามข้อกำหนดด้านการคุ้มครองข้อมูล เช่น GDPR และ NIST เพื่อให้มั่นใจว่าข้อมูลผู้ใช้ปลอดภัย

## การรองรับของ Logto \{#logto-support}

Logto ทำให้การเปิดใช้งาน MFA เป็นเรื่องง่ายด้วยการสลับเปิด-ปิดเพียงคลิกเดียว โดยไม่ต้องตั้งค่าซับซ้อน เริ่มต้นได้จากคู่มือ [การเปิดใช้งานปัจจัยการยืนยันตัวตน](/end-user-flows/mfa/configure-mfa)

**ปัจจัย MFA ที่รองรับ**:

- [Passkeys (WebAuthn)](/end-user-flows/mfa/webauthn): ใช้ security key หรือการยืนยันตัวตนด้วยไบโอเมตริกซ์เพื่อประสบการณ์แบบไม่ใช้รหัสผ่าน
- [รหัส OTP จากแอป Authenticator](/end-user-flows/mfa/authenticator-app-otp): ใช้รหัสผ่านแบบใช้ครั้งเดียวตามเวลา (TOTP) ที่สร้างโดยแอป Authenticator เช่น Google Authenticator หรือ Authy
- [การยืนยันทาง SMS](/end-user-flows/mfa/sms-mfa): ใช้ข้อความ SMS ส่งรหัสแบบใช้ครั้งเดียว (รหัสยืนยัน) เพื่อยืนยันตัวตน
- [การยืนยันทางอีเมล](/end-user-flows/mfa/email-mfa): ใช้อีเมลส่งรหัสแบบใช้ครั้งเดียว (รหัสยืนยัน) เพื่อยืนยันตัวตน
- [รหัสสำรอง](/end-user-flows/mfa/backup-codes): สร้างรหัสสำรองแบบใช้ครั้งเดียวสำหรับกรณีฉุกเฉิน

**ความสามารถ MFA ที่เกี่ยวข้อง**:

- [อุปกรณ์ที่เชื่อถือได้](/end-user-flows/mfa/trusted-devices): ให้ผู้ใช้ข้ามการถาม MFA ซ้ำบนเบราว์เซอร์ที่เชื่อถือได้ด้วยข้อมูลรับรองที่มีอายุจำกัดและเพิกถอนได้ ผู้ใช้เลือกเปิดใช้งานในหน้า **เชื่อถืออุปกรณ์นี้ (Trust this device)** แยกต่างหากเมื่อสิ้นสุดกระบวนการลงชื่อเข้าใช้หรือสมัครใช้งานที่รองรับ
