# ไลเซนส์แบบ self-hosted

ไลเซนส์แบบ self-hosted คือคีย์ที่ลงลายเซ็นต์ซึ่งปลดล็อกฟีเจอร์แบบชำระเงินของ [แผน Logto self-hosted](https://logto.io/self-hosted-plans) บน Logto OSS instance ของคุณเอง หากไม่มีไลเซนส์ Logto OSS จะทำงานเหมือนเดิมทุกประการ

:::note
ไลเซนส์นี้ใช้สำหรับ Logto OSS แบบ self-hosted เท่านั้น บน Logto Cloud ฟีเจอร์จะเป็นส่วนหนึ่งของ [แผนของ tenant ของคุณ](/logto-cloud/billing-and-pricing) และ endpoint สำหรับไลเซนส์จะไม่สามารถใช้งานได้
:::

## ไลเซนส์ปลดล็อกอะไรบ้าง \{#what-a-license-unlocks}

ไลเซนส์ Self-hosted Pro จะปลดล็อกฟีเจอร์ดังต่อไปนี้บน instance ของคุณ:

| ฟีเจอร์                                                                 | ไม่มีไลเซนส์                  | มีไลเซนส์                                                                                           |
| ----------------------------------------------------------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------- |
| [ซ่อนแบรนด์ Logto](/customization/match-your-brand#hide-logto-branding) | "Powered by Logto" จะแสดงเสมอ | คุณสามารถซ่อนได้                                                                                    |
| [Bring your UI](/customization/bring-your-ui) และ custom CSP sources    | ไม่สามารถใช้งานได้            | อัปโหลด UI ลงชื่อเข้าใช้ของคุณเองไปยัง [พื้นที่จัดเก็บของคุณเอง](#set-up-storage-for-bring-your-ui) |
| สมาชิก Console และการเชิญ                                               | ไม่สามารถใช้งานได้            | เชิญสมาชิกเข้าสู่ Console และจัดการบทบาทใน **Tenant Settings > Members**                            |
| MFA บังคับสำหรับ Console                                                | MFA เป็นตัวเลือกเท่านั้น      | กำหนดให้สมาชิก Console ทุกคนต้องตั้งค่า MFA ใน **Tenant Settings > Settings**                       |
| [SAML apps](/integrate-logto/saml-app)                                  | สูงสุด 3 SAML apps            | ไม่จำกัดจำนวน SAML apps                                                                             |

ฟีเจอร์ที่ไม่อยู่ในรายการนี้จะไม่ได้รับผลกระทบจากไลเซนส์

## ขอรับไลเซนส์ \{#get-a-license}

ขอรับไลเซนส์ผ่าน [หน้ารายละเอียดแผน self-hosted](https://logto.io/self-hosted-plans) จากนั้น Logto จะให้คีย์สองชุดสำหรับไลเซนส์เดียวกัน:

- **Production key**: ใช้สำหรับการใช้งานจริงที่ครอบคลุมโดยการสมัครสมาชิกของคุณ เว้นแต่ในใบสั่งซื้อจะระบุเป็นอย่างอื่น การสมัครสมาชิกแต่ละรายการจะครอบคลุมการใช้งานจริงหนึ่ง deployment
- **Non-production key**: ใช้สำหรับการพัฒนา ทดสอบ และ staging ที่สนับสนุน deployment จริงเดียวกัน โดย deployment เหล่านี้ต้องไม่ให้บริการทราฟฟิกจริง

ทั้งสองคีย์ปลดล็อกฟีเจอร์และโควตาเดียวกัน การมีสองคีย์ไม่ได้ให้สิทธิ์ในการรัน production deployment สองชุด การใช้งานของคุณอยู่ภายใต้ [ข้อตกลงการสมัครสมาชิก Self-hosted](https://logto.io/terms/self-hosted) และใบสั่งซื้อของคุณ

คีย์ที่คุณติดตั้งจะบอก Logto ว่าเป็น deployment ประเภทใด Logto จะไม่ตรวจสอบทางเทคนิค ดังนั้นควรติดตั้งคีย์ที่ตรงกับ deployment

## ติดตั้งไลเซนส์ \{#install-a-license}

คุณสามารถติดตั้งไลเซนส์ใน Console หรือผ่าน Management API ไม่ว่าทางใด Logto จะตรวจสอบลายเซ็นต์บน instance ของคุณก่อนบันทึกคีย์ และจะปฏิเสธคีย์ที่ไม่ถูกต้อง ถูกแก้ไข หรือหมดอายุแล้ว

### ใน Console \{#in-console}

1. ไปที่ **Console > Tenant Settings > License**
2. วางคีย์ไลเซนส์ของคุณแล้วคลิก **Install license**

เมื่อติดตั้งแล้ว หน้าจะโชว์รายละเอียดของไลเซนส์ หากต้องการเปลี่ยนคีย์ เช่น จาก non-production เป็น production หรือเป็นคีย์ที่ออกใหม่ ให้คลิก **Replace license**

### ใช้ Management API \{#using-the-management-api}

ส่งคีย์ไปที่ `PUT /api/systems/license` พร้อม access token สำหรับ [Logto Management API](/integrate-logto/interact-with-management-api):

```bash
curl -X PUT 'https://your-logto-endpoint/api/systems/license' \
  -H 'Authorization: Bearer <access_token>' \
  -H 'Content-Type: application/json' \
  -d '{ "license": "<your_license_key>" }'
```

หากสำเร็จจะได้ `204 No Content` หากล้มเหลวจะได้:

- `400` และ `license.invalid_key` หากคีย์ไม่ได้ลงลายเซ็นต์โดย Logto หรือถูกแก้ไข
- `400` และ `license.expired_key` หากคีย์หมดอายุแล้ว ให้ขอคีย์ใหม่และติดตั้งอีกครั้ง
- `501` หาก Logto ของคุณรันอยู่บน Logto Cloud

เพื่อตรวจสอบไลเซนส์ที่ติดตั้งอยู่ ส่ง `GET /api/systems/license` จะได้ข้อมูลแผน, สภาพแวดล้อม, สิทธิ์, วันหมดอายุ และสถานะ refresh ของไลเซนส์ โดยจะไม่คืนคีย์ไลเซนส์เอง และจะคืน `404` หากยังไม่มีไลเซนส์ ดู [Management API reference](https://openapi.logto.io) สำหรับ schema คำขอและคำตอบฉบับเต็ม

### หลาย instance \{#multiple-instances}

ไลเซนส์จะถูกเก็บในฐานข้อมูล Logto ของคุณ ดังนั้นคุณติดตั้งเพียงครั้งเดียวสำหรับ Logto ทุก instance ที่ใช้ฐานข้อมูลเดียวกัน

## การรีเฟรชและช่วงผ่อนผัน \{#refresh-and-grace-period}

Logto ตรวจสอบลายเซ็นต์ไลเซนส์ในเครื่อง ดังนั้นการลงชื่อเข้าใช้แอปของคุณจะไม่ขึ้นกับการเชื่อมต่อกับ Logto และการรีเฟรชที่ล้มเหลวจะไม่บล็อกทราฟฟิกการลงชื่อเข้าใช้

เพื่อรับการต่ออายุและการยกเลิก instance ของคุณจะเช็คอินกับ Logto Cloud:

- **เช็คอินรายสัปดาห์** เมื่อการรีเฟรชครั้งล่าสุดเกิน 7 วัน Logto จะรีเฟรชไลเซนส์เบื้องหลังขณะจัดการคำขอ หากล้มเหลวจะลองใหม่ในภายหลัง สูงสุดชั่วโมงละครั้ง ไลเซนส์ที่เพิ่งติดตั้งจะรีเฟรชทันที
- **ผ่อนผัน 30 วัน** หากการรีเฟรชล้มเหลว เช่น instance ของคุณไม่สามารถเชื่อมต่ออินเทอร์เน็ต ฟีเจอร์จะยังคงทำงานต่อไปอีก 30 วันหลังจากรีเฟรชล่าสุด หลังจากนั้น instance ของคุณจะกลับสู่ค่า OSS เริ่มต้น
- **รีเฟรชถูกปฏิเสธ** หาก Logto ปฏิเสธการรีเฟรชไลเซนส์ เช่น การสมัครสมาชิกถูกยกเลิก หน้าไลเซนส์จะแสดงเหตุผล ช่วงผ่อนผันยังคงนับจากรีเฟรชล่าสุด

การรีเฟรชเป็น HTTPS outbound จาก instance ของคุณไปที่ `https://cloud.logto.io` หาก instance ของคุณอยู่หลัง firewall ให้อนุญาตปลายทางนี้

### ข้อมูลที่ instance ของคุณส่ง \{#what-your-instance-sends}

คำขอรีเฟรชจะมีเพียง:

- คีย์ไลเซนส์ของคุณ ซึ่งระบุไลเซนส์ด้วย `licenseId`
- `deploymentId`: ตัวระบุสุ่มที่สร้างขึ้นเมื่อคุณติดตั้งไลเซนส์ครั้งแรก เก็บในฐานข้อมูลของคุณ ใช้ร่วมกันทุก instance ที่ใช้ฐานข้อมูลเดียวกัน และไม่เปลี่ยน แม้คุณจะเปลี่ยนไลเซนส์
- เวอร์ชัน Logto
- จำนวนการใช้งานของ deployment: ผู้ใช้ที่ใช้งานต่อเดือน, โทเค็นการเข้าถึงต่อเดือน, และจำนวน tenant เว้นแต่คุณจะ [ปิดการรายงานการใช้งาน](#turn-off-usage-reporting)

จำนวนการใช้งานเป็นยอดรวมเท่านั้นและไม่มีข้อมูลส่วนบุคคล Logto จะไม่เก็บ hostname, domain, การตั้งค่าหรือข้อมูลอื่นใดจาก instance ของคุณ Logto ใช้ข้อมูลนี้เพื่อให้ไลเซนส์ของคุณเป็นปัจจุบันและเปรียบเทียบกับ [ขีดจำกัดการใช้งาน](#usage-limits) ของแผนคุณ ดูข้อ 10.2 ของ [ข้อตกลงการสมัครสมาชิก Self-hosted](https://logto.io/terms/self-hosted) พฤติกรรมนี้เป็นโอเพ่นซอร์ส ดู [`LicenseReader.ts`](https://github.com/logto-io/logto/blob/master/packages/core/src/license/LicenseReader.ts)

### ปิดการรายงานการใช้งาน \{#turn-off-usage-reporting}

ตั้ง environment variable นี้บน **ทุก** Logto instance ที่ใช้ฐานข้อมูลเดียวกัน เพราะ instance ใดก็อาจเป็นผู้รีเฟรช:

```bash
SELF_HOSTED_LICENSE_USAGE_REPORTING_DISABLED=1
```

การรีเฟรชจะยังคงทำงานโดยไม่มีจำนวนการใช้งาน และ Console จะยังเตือนเมื่อเกินขีดจำกัด

## ขีดจำกัดการใช้งาน \{#usage-limits}

แต่ละแผนมีขีดจำกัดการใช้งาน ซึ่งจะไม่ถูกบังคับใช้: หากเกินขีดจำกัดจะไม่บล็อกการลงชื่อเข้าใช้หรือปิดฟีเจอร์ใด ๆ Console จะแสดงแบนเนอร์แทน

| เมตริก                   | Production key                                   | Non-production key |
| ------------------------ | ------------------------------------------------ | ------------------ |
| ผู้ใช้ที่ใช้งานต่อเดือน  | 50,000 สำหรับ Self-hosted Pro หรือดูในใบสั่งซื้อ | ไม่จำกัด           |
| Production deployments   | 1                                                | ไม่จำกัด           |
| โทเค็นการเข้าถึงต่อเดือน | ไม่จำกัด                                         | 50,000             |

Production deployment จะนับว่า active หากรีเฟรชไลเซนส์ใน 15 วันที่ผ่านมา

หากเกินขีดจำกัด ติดต่อ Logto ภายใน 30 วันเพื่ออัปเกรดแผนหรือปรับลดการใช้งาน ตามที่ระบุในข้อ 4.2 ของ [ข้อตกลงการสมัครสมาชิก Self-hosted](https://logto.io/terms/self-hosted)

### ขอรับ usage statement \{#get-a-usage-statement}

หาก Logto ขอ usage statement ให้ส่ง `GET /api/systems/license/usage-statement` พร้อม access token สำหรับ [Logto Management API](/integrate-logto/interact-with-management-api) จะได้จำนวนผู้ใช้ที่ใช้งานและโทเค็นการเข้าถึงในแต่ละเดือนย้อนหลัง 12 เดือน อ่านจากฐานข้อมูลของคุณ

## การหมดอายุของไลเซนส์ \{#license-expiration}

ไลเซนส์ครอบคลุมระยะเวลา 1 ปี และวันที่ **Expires on** คือวันสิ้นสุดระยะเวลานั้น

- **เมื่อคุณต่ออายุ** ไม่ต้องทำอะไรบน instance ของคุณ รีเฟรชครั้งถัดไปหลังต่ออายุจะเปลี่ยนคีย์ที่ติดตั้งเป็นคีย์ใหม่ที่หมดอายุอีกหนึ่งปี เป็นเรื่องปกติที่หน้าจะแสดงวันที่เพิ่งหมดอายุไปไม่กี่วันระหว่างรอการรีเฟรช และฟีเจอร์จะยังใช้งานได้ในช่วงนี้
- **เมื่อคุณไม่ต่ออายุ** การรีเฟรชจะถูกปฏิเสธหลังสิ้นสุดระยะเวลา ฟีเจอร์จะยังคงทำงานจนสิ้นสุดช่วงผ่อนผัน 30 วัน จากนั้น instance ของคุณจะกลับสู่ค่า OSS เริ่มต้นเหมือนไม่มีไลเซนส์ หน้าไลเซนส์จะแสดงแบนเนอร์อธิบายและวันที่จะเกิดเหตุการณ์นี้
- **หากคุณถึงสิ้นสุดช่วงผ่อนผัน** ให้ติดตั้งคีย์ใหม่เพื่อปลดล็อกฟีเจอร์อีกครั้ง ติดต่อ Logto ผ่านช่องทางที่คุณใช้ขอไลเซนส์หากต้องการ

### จะเกิดอะไรขึ้นเมื่อฟีเจอร์ถูกปิด \{#what-happens-when-features-are-turned-off}

การกลับสู่ค่า OSS เริ่มต้นจะไม่ลบสิ่งที่คุณสร้างไว้ด้วยไลเซนส์:

- **ซ่อนแบรนด์ Logto**: เครื่องหมาย "Powered by Logto" จะแสดงอีกครั้ง การตั้งค่าของคุณจะถูกเก็บไว้และนำกลับมาใช้หากติดตั้งไลเซนส์ใหม่
- **SAML apps**: แอปที่เกิน 3 จะยังคงอยู่ แต่คุณไม่สามารถสร้างใหม่จนกว่าจะต่ำกว่าขีดจำกัด
- **MFA บังคับ**: คุณสามารถปิดได้เสมอ แต่ไม่สามารถเปิดใหม่ได้หากไม่มีไลเซนส์
- **Bring your UI, custom CSP, และการเชิญ Console**: คุณไม่สามารถเปลี่ยนแปลงใหม่ที่ต้องใช้ฟีเจอร์นี้ แต่ข้อมูลเดิมจะถูกเก็บไว้

## ตั้งค่าพื้นที่จัดเก็บสำหรับ Bring your UI \{#set-up-storage-for-bring-your-ui}

บน Logto Cloud ไฟล์ Bring your UI จะถูกโฮสต์โดย Logto แต่บน instance ของคุณเอง ไฟล์จะถูกเก็บใน object storage ที่คุณตั้งค่า Logto จะ unzip ไฟล์ที่คุณอัปโหลดและเก็บไว้ที่นั่น และให้บริการไฟล์จากที่นั่น

ตั้งค่า `experienceBlobsProvider` ใน system config ด้วยโครงสร้าง JSON เดียวกับ [file storage provider](/logto-oss/file-storage-provider) เช่น สำหรับ S3-compatible storage:

```bash
pnpm logto db system set experienceBlobsProvider '{"provider":"S3Storage","accessKeyId":"my-access-key-id","accessSecretKey":"my-secret-access-key","bucket":"logto-sie","endpoint":"https://s3.us-east-2.amazonaws.com"}'
```

รีสตาร์ท Logto หลังเปลี่ยน config จากนั้นทำตาม [Bring your UI](/customization/bring-your-ui#upload-your-custom-ui-assets) เพื่ออัปโหลดไฟล์ใน Console

## อีเมลเชิญสมาชิก Console \{#invitation-emails-for-console-members}

การเชิญ Console จะถูกส่งทางอีเมลผ่าน email connector ของ tenant หลักของคุณ ตรวจสอบให้แน่ใจว่าคุณได้ [ตั้งค่า email connector](/connectors/email-connectors) แล้วก่อนเชิญสมาชิก
