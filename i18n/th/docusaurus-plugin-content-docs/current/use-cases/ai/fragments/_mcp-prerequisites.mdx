## ข้อกำหนดเบื้องต้น \{#prerequisites}

- [Logto Cloud](https://cloud.logto.io) (หรือแบบ self-hosted) tenant
- สภาพแวดล้อม Node.js >= 20

### ทำความเข้าใจสถาปัตยกรรม \{#understanding-the-architecture}

- **เซิร์ฟเวอร์ MCP**: เซิร์ฟเวอร์ที่เปิดเผยเครื่องมือและทรัพยากรให้กับไคลเอนต์ MCP โดยอิงตาม [MCP specification ล่าสุด](https://modelcontextprotocol.io/specification/latest/basic/authorization) จะทำหน้าที่เป็น resource server ของ OAuth 2.0 ที่ตรวจสอบโทเค็นการเข้าถึง (access token) ที่ออกโดย Logto
- **ไคลเอนต์ MCP**: ไคลเอนต์ที่ใช้เริ่มต้น flow การยืนยันตัวตนและทดสอบการเชื่อมต่อ {<b>{props.isThirdParty ? 'AI agent ของบุคคลที่สามจะถูกใช้เป็นไคลเอนต์ในคู่มือนี้' : "เราจะใช้ VS Code (ซึ่งรองรับ MCP ในตัว) เป็นไคลเอนต์ในคู่มือนี้"}</b>}
- **Logto**: ทำหน้าที่เป็นผู้ให้บริการ OpenID Connect (authorization server) จัดการข้อมูลระบุตัวตนของผู้ใช้ และออกโทเค็นการเข้าถึง JWT ที่ผูกกับผู้รับ (audience-bound) สำหรับเซิร์ฟเวอร์ MCP ของคุณ

ไดอะแกรมลำดับ (sequence diagram) ที่ไม่เป็นทางการนี้แสดงภาพรวมของกระบวนการทั้งหมด:

    participant Logto as Logto<br/>(authorization server)

    Server->>Client: 401 ไม่ได้รับอนุญาต (WWW-Authenticate)
    Client->>Server: ดึง metadata ของทรัพยากรที่ป้องกันไว้<br/>(/.well-known/oauth-protected-resource)
    Server->>Client: ส่งคืน metadata พร้อมข้อมูล authorization server

    Logto->>Client: ส่งคืนการตั้งค่า OpenID Connect

    Server->>Server: ตรวจสอบ access token กับ JWKS ของ Logto<br/>(ลายเซ็น, ผู้ออก, ผู้รับ, วันหมดอายุ)
    Server->>Client: ส่งคืนผลลัพธ์ของเครื่องมือ`}
