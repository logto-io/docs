# Verificação SMS para MFA

O Logto oferece suporte à autenticação multifatorial (MFA) baseada em SMS, que aumenta a segurança da conta enviando códigos de verificação únicos para os números de telefone registrados dos usuários. O SMS MFA serve como um segundo fator de autenticação e pode ser combinado com outros fatores de MFA (como TOTP, passkeys, códigos de backup) para fornecer aos usuários opções flexíveis de autenticação em dois fatores.

## Conceitos \{#concepts}

A verificação por SMS, também chamada de verificação de número de telefone, é um dos métodos de MFA mais acessíveis. Ela aproveita a ubiquidade dos celulares para entregar códigos de verificação temporários e únicos diretamente aos dispositivos dos usuários via mensagens de texto. Diferente dos autenticadores baseados em aplicativos, que exigem instalação de software adicional, o SMS MFA utiliza a infraestrutura de mensagens já existente em todo dispositivo móvel, tornando-o imediatamente disponível aos usuários sem necessidade de configuração.

## Configurar verificação SMS para MFA \{#configure-sms-verification-for-mfa}

**Passo 1: Configure o conector SMS e os templates**

1. Navegue até <CloudLink to="/connectors/passwordless">Console > Conectores > Conectores de Email e SMS</CloudLink>
2. Selecione um conector SMS apropriado (Twilio, SMS Aero, etc.)
3. Configure os parâmetros de conexão.
4. Configure o template SMS para MFA com os tipos de uso dedicados.
   - `MfaVerification` usageType para verificação de MFA.
   - `BindMfa` usageType para vinculação de MFA.
5. Teste a funcionalidade do conector para garantir a entrega correta das mensagens
6. Consulte [Conectores SMS](/connectors/sms-connectors) para instruções de configuração específicas do provedor

**Passo 2: Ative SMS para MFA**

1. Navegue até <CloudLink to="/mfa">Console > Autenticação multifatorial</CloudLink>
2. Ative o fator "Código de verificação SMS". Recomenda-se usar SMS MFA em combinação com outros fatores de MFA (TOTP, passkeys, códigos de backup) para reduzir a dependência de um único fator.
3. Em **Verificação em 2 etapas por Email/SMS**, escolha quais usuários terão SMS MFA. Veja [Quem tem SMS MFA](#who-has-sms-mfa).
4. Configure sua política de MFA preferida (opcional, adaptativa ou obrigatória)
5. Salve as alterações de configuração

:::note Considerações importantes de uso

1. **Limitação do método de login**: Códigos de verificação SMS não podem ser usados simultaneamente como [método de login (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in) e como fator de MFA (2FA). Escolha um fluxo de autenticação por implementação de SMS.

2. **Compatibilidade com método de cadastro**: Códigos de verificação SMS podem ser usados simultaneamente como método de cadastro e como MFA. O Logto otimizará o fluxo de registro do usuário final com base na política de MFA selecionada para evitar exigir verificação SMS duas vezes para o mesmo número.

3. **Compatibilidade com recuperação de senha**: Embora códigos de verificação SMS possam ser usados simultaneamente para [Esqueci a senha](/end-user-flows/sign-up-and-sign-in/reset-password) e MFA, essa combinação **não é recomendada**. Essa configuração reduz a eficácia da segurança do MFA, pois usuários poderiam potencialmente contornar o MFA usando a verificação SMS de "esqueci a senha" para redefinir a senha, depois usar a nova senha para autenticação primária (1FA) seguida do mesmo método SMS para verificação MFA.

:::

## Quem tem SMS MFA \{#who-has-sms-mfa}

Os códigos SMS MFA são sempre enviados para o número de telefone principal do usuário. A configuração **Verificação em 2 etapas por Email/SMS** na página <CloudLink to="/mfa">Autenticação multifatorial</CloudLink> decide quais usuários terão SMS MFA:

- **Todo usuário com email ou telefone verificado**: Todo usuário com número de telefone principal tem SMS MFA, sem precisar configurar.
- **Apenas usuários que configurarem**: Apenas usuários que configurarem o SMS MFA terão acesso. Um usuário que se cadastrar com número de telefone verificado não recebe SMS MFA automaticamente, assim você pode oferecer SMS como uma opção de MFA sem inscrever todos os usuários. Os usuários configuram no fluxo de configuração de MFA, no [Account Center](/end-user-flows/account-settings/by-account-center-ui), ou via [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa). Administradores podem adicionar ou remover para um usuário via [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management).

A configuração também se aplica ao [email MFA](/end-user-flows/mfa/email-mfa). Para saber sobre os padrões e o que acontece ao trocar de modo, veja [Inscrição em Email e SMS MFA](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment).

:::note
Com **Todo usuário com email ou telefone verificado**, um usuário que tem SMS MFA apenas por causa do número de telefone principal não possui registro armazenado de SMS MFA, então não aparece em `GET /api/my-account/mfa-verifications`, `GET /api/users/{userId}/mfa-verifications` ou `user.mfaVerificationFactors` (Reivindicações JWT personalizadas e Ações `PostSignIn`).
:::

## Fluxos de configuração do SMS MFA \{#sms-mfa-setup-flows}

O prompt de configuração de MFA pode aparecer durante o registro do usuário ou após o login, dependendo da [política de MFA](/end-user-flows/mfa/configure-mfa#global-mfa-configuration) configurada.

O fluxo de configuração do SMS MFA é afetado pelos seguintes fatores:

- **Quantidade de fatores primários de MFA**: Se houver múltiplos fatores primários, o usuário deve escolher um para configurar. Fatores primários são métodos de MFA diferentes de códigos de backup.
- **Códigos de backup ativados**: Quando ativados, os códigos de backup são gerados automaticamente após a configuração do fator primário de MFA; o usuário é solicitado a salvá-los.
- **Configuração do identificador de cadastro**: O número de telefone foi usado como [identificador de cadastro](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier) e o usuário já o verificou com código SMS durante o registro.
  - Com **Todo usuário com email ou telefone verificado**, o sistema vinculará automaticamente esse número como fator de MFA e nenhuma verificação adicional será necessária. Se existirem outros fatores primários, a interface mostrará a opção “Adicionar outra verificação em 2 etapas” (o usuário pode pular), indicando claramente que o MFA está ativado.
  - Com **Apenas usuários que configurarem**, o número de telefone é oferecido como qualquer outro fator, com o número mascarado. Quando o usuário escolhe, ou quando é o único fator primário, o Logto configura usando a verificação do registro, sem enviar um segundo código.
- **Dados existentes do usuário**: Quando um usuário existente configura MFA após o login, ele deve primeiro concluir a autenticação primária e então prosseguir com a configuração do MFA. Se a conta já contém um número de telefone principal verificado:
  - Com **Todo usuário com email ou telefone verificado**, a configuração se comporta da mesma forma que o caso do identificador de cadastro acima.
  - Com **Apenas usuários que configurarem**, o número de telefone é oferecido com o número mascarado. Quando o usuário escolhe, ou quando é o único fator primário, o Logto envia um código de verificação para esse número, e o SMS MFA é configurado quando o usuário digita o código.

Abaixo estão três cenários comuns de vinculação do SMS MFA.

### Cenário 1: Número de telefone usado apenas para MFA (Fluxo típico) \{#scenario-1-phone-number-only-used-for-mfa-typical-flow}

Quando o número de telefone não é um dos identificadores de cadastro, e apenas para MFA, siga a sequência padrão de configuração:

- Se houver apenas um fator SMS MFA, mostre a interface de configuração diretamente para esse fator.
- Se houver múltiplos fatores primários de MFA, mostre uma página de lista "Configurar MFA" e deixe o usuário escolher qual fator configurar.

Com **Apenas usuários que configurarem**, o SMS é o único fator primário neste cenário, então o Logto configura usando a verificação do registro da mesma forma.

### Cenário 3: Telefone verificado mas múltiplos fatores primários disponíveis \{#scenario-3-phone-verified-but-multiple-primary-factors-available}

Se o número de telefone foi verificado no cadastro (como identificador de cadastro) mas a conta possui múltiplos fatores primários de MFA (ex: SMS mais passkeys ou apps autenticadores), a interface solicitará ao usuário “Adicionar outra verificação em 2 etapas”. O usuário pode escolher adicionar outro fator ou pular; o prompt também comunica que o MFA já está ativado.

Com **Apenas usuários que configurarem**, o usuário primeiro escolhe um fator da lista. O prompt “Adicionar outra verificação em 2 etapas” aparece quando o usuário acabou de configurar SMS, email ou uma passkey de login como único fator.

## Fluxos de verificação do SMS MFA \{#sms-mfa-verification-flows}

Quando um usuário com SMS MFA ativado faz login, após concluir com sucesso a autenticação primária (1FA), ele será solicitado a verificar sua identidade usando o código de verificação SMS como segundo fator de autenticação (2FA).

Se houver múltiplos fatores de MFA disponíveis, o Logto abre diretamente o fator de maior prioridade de acordo com a ordem fixa especificada em [Configurar MFA](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) (Passkey, OTP de app autenticador, Código de verificação SMS, Código de verificação por email, Códigos de backup). Quando outro fator como OTP de app autenticador for solicitado primeiro, os usuários podem clicar em **Tentar outro método de verificação** para abrir a lista de seleção e escolher o código de verificação SMS.

## Tratamento de erros \{#error-handling}

1. **Número de telefone não vinculado**

   - Código de erro: `session.mfa.mfa_factor_not_enabled`
   - Tratamento: Oriente o usuário a vincular o número de telefone primeiro

2. **Código de verificação incorreto**

   - Código de erro: `verification_code.code_mismatch`
   - Tratamento: Solicite ao usuário que digite novamente, limite as tentativas

3. **Código de verificação expirado**

   - Código de erro: `verification_code.expired`
   - Tratamento: Solicite ao usuário que solicite um novo código de verificação

4. **Limite de envio excedido**
   - Códigos de erro: `request.message_rate_limited` (limite de envio por destinatário do Logto) ou `connector.rate_limit_exceeded` (limite do conector SMS)
   - Tratamento: Mostre o tempo de espera, limite o reenvio
