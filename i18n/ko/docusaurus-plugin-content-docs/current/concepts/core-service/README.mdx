# 핵심 서비스

## 소개 \{#introduction}

*핵심 서비스*는 Logto의 주요 역할을 담당하는 모놀리식 서비스입니다. 소스 코드는 [`@logto/core`](https://github.com/logto-io/logto/tree/master/packages/core)에 있습니다.

:::note
*핵심 서비스*와 *SDK core*는 별개의 개념입니다. 차이점은 [SDK 규칙](/developers/sdk-conventions)을 참고하세요.
:::

간단하게 하기 위해, 핵심 서비스는 네 가지 주요 모듈로 나눌 수 있습니다:

<table>
  <thead>
    <tr>
      <td>이름</td>
      <td>설명</td>
      <td>마운트 경로</td>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>OIDC Provider</td>
      <td>[OpenID Provider](https://openid.net/specs/openid-connect-core-1_0.html).</td>
      <td>
        <code>/oidc</code>
      </td>
    </tr>
    <tr>
      <td>Logto API</td>
      <td>Management API, Experience API, Account API.</td>
      <td>
        <code>/api</code>
      </td>
    </tr>
    <tr>
      <td>프론트엔드 프록시</td>
      <td>프론트엔드 프로젝트를 위한 HTTP 프록시 또는 정적 파일 제공.</td>
      <td>
        자세한 내용은 <a href="#frontend-proxies">프론트엔드 프록시</a>를 참고하세요.
      </td>
    </tr>
  </tbody>
</table>

OIDC를 포함한 백엔드 API는 `core` 패키지 내에 구축되어 있으며, 프론트엔드 프록시는 Logto 모노레포 내의 해당 형제 패키지에 의존합니다.

## OIDC Provider \{#oidc-provider}

Logto는 내부적으로 인증받은 [OpenID Connect](https://openid.net/connect/) 구현체인 [node-oidc-provider](https://github.com/panva/node-oidc-provider)를 사용합니다. 이 프로바이더는 `/oidc`에 마운트되어 있으며, 관련 설정과 파일은 [packages/core/src/oidc](https://github.com/logto-io/logto/tree/master/packages/core/src/oidc)에서 확인할 수 있습니다.

OIDC [Userinfo Endpoint](https://openid.net/specs/openid-connect-core-1_0.html#UserInfo)는 `/oidc/me`에 제공 및 마운트되어 있습니다.

:::info
OIDC API를 직접 호출하려면, 헤더에 `Content-Type: application/x-www-form-urlencoded`를 반드시 설정하세요.
:::

## Logto API \{#logto-api}

### Management API \{#management-api}

*Management API*는 Logto 데이터를 관리 및 업데이트하는 API 집합입니다. `admin` 역할을 가진 사용자만 접근할 수 있습니다.

자세한 내용은 [API 참조](https://openapi.logto.io)를 확인하세요.

API를 프로그래밍적으로 사용하려면 [Management API와 상호작용하기](/integrate-logto/interact-with-management-api)를 참고하세요.

### Experience API \{#experience-api}

Experience API는 맞춤형 로그인 인터페이스 상호작용을 지원하는 전용 엔드포인트 집합입니다.

이 API를 통해 개발자는 로그인, 회원가입, 비밀번호 재설정, 소셜 계정 연동, 다단계 인증 (MFA) 등 핵심 인증 (Authentication) 기능을 구현할 수 있습니다. 이러한 기능을 구현하려면, 맞춤형 UI가 Experience API와 상호작용해야 합니다.

사용자 흐름과 구현 세부사항을 더 잘 이해하려면:

- [맞춤형 UI 개발](/customization/bring-your-ui/#develop-your-custom-ui) 가이드를 참고하여 Experience API를 활용한 맞춤형 경험 UI를 만드는 방법을 알아보세요.
- [Experience API 참조](https://openapi.logto.io/group/endpoint-experience)에서 상세한 API 문서를 확인하세요.
- [Experience API 설계 RFC](https://github.com/logto-io/rfcs/blob/master/draft/0004-experience-api.md)를 읽고 기술 사양과 예시를 확인하세요.

### Account API \{#account-api}

Account API는 최종 사용자가 Management API를 거치지 않고 직접 API에 접근할 수 있도록 하는 포괄적인 API 집합입니다. 주요 특징은 다음과 같습니다:

- 직접 접근: Account API를 통해 최종 사용자는 자신의 계정 프로필을 직접 접근 및 관리할 수 있습니다. Management API를 거칠 필요가 없습니다.
- 사용자 프로필 및 아이덴티티 관리: 사용자는 이메일, 전화번호, 비밀번호, 소셜 연결, MFA 요소 등 프로필과 보안 설정을 관리할 수 있으며, 연결된 소셜 및 엔터프라이즈 SSO 연결을 위한 Secret Vault 토큰도 조회할 수 있습니다.
- 글로벌 접근 제어: 관리자는 접근 설정을 전역적으로 완전히 제어할 수 있으며, 각 필드를 맞춤화할 수 있습니다.
- 원활한 인가 (Authorization): 인가가 그 어느 때보다 쉬워졌습니다! `client.getAccessToken()`을 사용하여 OP (Logto)용 불투명 액세스 토큰을 얻고, Authorization 헤더에 `Bearer <access_token>`으로 첨부하세요.

Logto Account API를 활용하면 Logto와 완전히 통합된 프로필 페이지와 같은 맞춤형 계정 관리 시스템을 구축할 수 있습니다.

[Account API로 계정 설정](/end-user-flows/account-settings/by-account-api)을 참고하여 Account API를 활용한 계정 설정 페이지 구축 방법을 알아보세요.

상세한 API 문서는 [Account API 참조](https://openapi.logto.io/group/endpoint-my-account)를 참고하세요.

## 프론트엔드 프록시 \{#frontend-proxies}

*프론트엔드 프록시*는 환경에 따라 프론트엔드 프로젝트를 제공하는 미들웨어 함수입니다:

- 개발 환경에서는 HTTP 요청을 프론트엔드 개발 서버로 프록시합니다.
- 운영 환경에서는 정적 프론트엔드 파일을 직접 제공합니다.

Logto에는 세 가지 프론트엔드 프록시가 있습니다:

  <thead>
    <tr>
      <td>이름</td>
      <td>프론트엔드 패키지</td>
      <td>마운트 경로</td>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Admin Console 프록시</td>
      <td>
        <code>/packages/console</code>
      </td>
      <td>
        <code>/console</code>
      </td>
    </tr>
    <tr>
      <td>Demo app 프록시</td>
      <td>
        <code>/packages/demo-app</code>
      </td>
      <td>
        <code>/demo-app</code>
      </td>
    </tr>
    <tr>
      <td>UI (로그인 경험) 프록시</td>
      <td>
        <code>/packages/ui</code>
      </td>
      <td>
        <code>/</code>
      </td>
    </tr>
  </tbody>
</table>

:::note
UI 프록시는 루트 경로를 사용한다는 점을 알 수 있습니다. 다른 프록시와 달리, UI 프록시는 fallback 프록시로, 다른 프록시와 일치하지 않을 때만 동작합니다.
:::
