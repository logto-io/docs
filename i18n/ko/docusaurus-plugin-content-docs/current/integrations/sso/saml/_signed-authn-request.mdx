기본적으로, Logto는 SAML 인증 요청 (AuthnRequests)을 서명하지 않은 상태로 전송합니다. 만약 아이덴티티 제공자 (IdP)에서 서명된 인증 요청을 요구한다면, Logto는 생성된 서비스 제공자 (SP) 인증서로 요청에 서명할 수 있습니다. 서명 여부는 전적으로 커넥터의 **인증 요청 서명(Sign authentication request)** 설정에 의해 제어됩니다 — Logto는 IdP 메타데이터의 `WantAuthnRequestsSigned` 플래그를 읽지 않습니다.

로그인 중단을 방지하려면 다음 순서로 설정하세요:

1. 커넥터의 `Connection` 탭에서 **요청 서명 인증서(Request signing certificate)** 섹션을 찾고 **새 키 생성(Generate new key)**을 클릭하세요. 첫 번째 키는 자동으로 활성화되며, 이후 생성된 키는 회전을 위해 비활성 상태로 대기합니다.
2. 활성 키의 인증서를 다운로드하여 IdP에 등록하세요.
3. **인증 요청 서명(Sign authentication request)**을 활성화하고 저장하세요. 활성 서명 키가 필요하며, 없을 경우 저장이 거부됩니다.
4. IdP에 서명된 요청을 요구하거나 검증하는 별도의 옵션이 있다면, 지금 활성화한 후 로그인 플로우를 테스트하세요.

:::warning
양쪽 설정을 맞추세요. 인증서가 등록되기 전에 **인증 요청 서명(Sign authentication request)**을 활성화하거나, Logto가 서명하기 전에 IdP에서 검증을 요구하면, 다른 쪽이 따라잡을 때까지 이 연결을 통한 로그인이 중단됩니다. 요청 서명을 검증하지 않는 IdP는 서명을 무시합니다.
:::

키 관리는 토글과 독립적으로 동작합니다:

- 최대 한 개의 키만 **활성(Active)** 상태이며, 활성 키가 모든 요청에 서명합니다. 키 작업(생성, 활성화, 비활성화, 삭제)은 즉시 반영됩니다.
- 다운타임 없이 인증서를 회전하려면: 새 키를 생성(비활성 상태로 대기), 해당 인증서를 IdP에 등록, 그리고 활성화하세요 — 이전 키는 자동으로 비활성화되며 이후 삭제할 수 있습니다.
- 활성 키는 삭제할 수 없으며, **인증 요청 서명(Sign authentication request)**이 활성화된 동안 비활성화할 수 없습니다 — 먼저 서명을 비활성화하세요.
- 토글을 끄면 모든 키가 유지되므로, 다시 활성화하면 동일한 인증서로 서명이 재개됩니다 — IdP 측에서 추가 작업이 필요하지 않습니다.

Logto는 기본적으로 RSA-SHA256으로 요청에 서명합니다. RSA-SHA512를 사용하려면, Logto Management API를 통해 커넥터 설정의 `requestSignatureAlgorithm`을 `http://www.w3.org/2001/04/xmldsig-more#rsa-sha512`로 설정하세요.
