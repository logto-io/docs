# 자체 호스팅 라이선스

자체 호스팅 라이선스는 [Logto 자체 호스팅 플랜](https://logto.io/self-hosted-plans)에서 제공하는 유료 기능을 여러분의 Logto OSS 인스턴스에서 활성화하는 서명된 키입니다. 라이선스가 없으면 Logto OSS는 기존과 동일하게 동작합니다.

:::note
라이선스는 오직 자체 호스팅 Logto OSS에만 해당됩니다. Logto Cloud에서는 기능이 [테넌트 플랜](/logto-cloud/billing-and-pricing)에 포함되어 있으며, 라이선스 엔드포인트는 제공되지 않습니다.
:::

## 라이선스로 활성화되는 기능 \{#what-a-license-unlocks}

Self-hosted Pro 라이선스를 설치하면 인스턴스에서 다음 기능이 활성화됩니다:

| 기능                                                                       | 라이선스 없음                    | 라이선스 있음                                                                          |
| -------------------------------------------------------------------------- | -------------------------------- | -------------------------------------------------------------------------------------- |
| [Logto 브랜딩 숨기기](/customization/match-your-brand#hide-logto-branding) | "Powered by Logto"가 항상 표시됨 | 숨길 수 있습니다.                                                                      |
| [Bring your UI](/customization/bring-your-ui) 및 커스텀 CSP 소스           | 사용 불가                        | [별도의 저장소 설정](#set-up-storage-for-bring-your-ui) 후, 자체 로그인 UI 업로드 가능 |
| Console 멤버 및 초대                                                       | 사용 불가                        | Console에 멤버를 초대하고, **테넌트 설정 > 멤버**에서 역할 관리 가능                   |
| Console의 필수 MFA                                                         | 선택적 MFA만 가능                | 모든 Console 멤버가 MFA를 설정하도록 요구, **테넌트 설정 > 설정**에서 설정             |
| [SAML 앱](/integrate-logto/saml-app)                                       | 최대 3개 SAML 앱                 | SAML 앱 개수 제한 없음                                                                 |

이 목록에 없는 기능은 라이선스에 의해 영향을 받지 않습니다.

## 라이선스 받기 \{#get-a-license}

[자체 호스팅 플랜 페이지](https://logto.io/self-hosted-plans)에서 라이선스를 요청하세요. Logto는 동일한 라이선스에 대해 두 개의 키를 제공합니다:

- **프로덕션 키**: 구독에 포함된 프로덕션 배포에 사용합니다. 별도의 명시가 없다면, 각 구독은 하나의 프로덕션 배포만 허용합니다.
- **비프로덕션 키**: 동일한 프로덕션 배포를 지원하는 개발, 테스트, 스테이징 배포에 사용합니다. 이 배포들은 프로덕션 트래픽을 처리해서는 안 됩니다.

두 키 모두 동일한 기능과 할당량을 활성화합니다. 두 개의 키가 있다고 해서 두 개의 프로덕션 배포를 허용하는 것은 아닙니다. 허용된 사용 범위는 [자체 호스팅 구독 약관](https://logto.io/terms/self-hosted)과 주문서에 의해 결정됩니다.

설치한 키는 Logto에 어떤 유형의 배포인지 알려줍니다. Logto는 이를 기술적으로 검증하지 않으므로, 배포 환경에 맞는 키를 설치하세요.

## 라이선스 설치하기 \{#install-a-license}

Console 또는 Management API를 통해 라이선스를 설치할 수 있습니다. 어떤 방법이든, Logto는 인스턴스에서 키의 서명을 저장 전에 검증하며, 유효하지 않거나 변조되었거나 이미 만료된 키는 거부합니다.

### Console에서 설치하기 \{#in-console}

1. **Console > 테넌트 설정 > 라이선스**로 이동합니다.
2. 라이선스 키를 붙여넣고 **라이선스 설치**를 클릭합니다.

설치가 완료되면, 페이지에 라이선스 상세 정보가 표시됩니다. 예를 들어 비프로덕션 키에서 프로덕션 키로, 또는 새로 발급된 키로 전환하려면 **라이선스 교체**를 클릭하세요.

### Management API 사용하기 \{#using-the-management-api}

[Logto Management API](/integrate-logto/interact-with-management-api)용 액세스 토큰과 함께, 키를 `PUT /api/systems/license`로 전송하세요:

```bash
curl -X PUT 'https://your-logto-endpoint/api/systems/license' \
  -H 'Authorization: Bearer <access_token>' \
  -H 'Content-Type: application/json' \
  -d '{ "license": "<your_license_key>" }'
```

성공 시 `204 No Content`를 반환합니다. 다음과 같은 경우 요청이 실패합니다:

- Logto가 서명하지 않았거나 수정된 키일 경우 `400` 및 `license.invalid_key`
- 만료된 키일 경우 `400` 및 `license.expired_key`. 새 키를 받아 다시 설치하세요.
- Logto가 Logto Cloud에서 실행 중일 경우 `501`

설치된 라이선스 정보를 확인하려면 `GET /api/systems/license`를 전송하세요. 플랜, 환경, 권한, 만료일, 갱신 상태를 반환합니다. 키 자체는 반환하지 않으며, 라이선스가 없으면 `404`를 반환합니다. 전체 요청 및 응답 스키마는 [Management API reference](https://openapi.logto.io)를 참고하세요.

### 여러 인스턴스 \{#multiple-instances}

라이선스는 Logto 데이터베이스에 저장되므로, 동일한 데이터베이스를 공유하는 모든 Logto 인스턴스에 한 번만 설치하면 됩니다.

## 갱신 및 유예 기간 \{#refresh-and-grace-period}

Logto는 라이선스 서명을 로컬에서 검증하므로, 애플리케이션 로그인은 Logto와의 연결에 의존하지 않으며, 갱신 실패로 인해 로그인 트래픽이 차단되는 일은 없습니다.

갱신 및 취소를 반영하기 위해 인스턴스는 Logto Cloud와 체크인을 수행합니다:

- **주간 체크인**: 마지막 성공적 갱신이 7일을 초과하면, Logto는 요청 처리 중 백그라운드에서 라이선스를 갱신합니다. 시도에 실패하면 최대 한 시간에 한 번씩 재시도합니다. 새로 설치된 라이선스는 즉시 갱신됩니다.
- **30일 유예**: 갱신이 실패해도(예: 인스턴스가 인터넷에 접근할 수 없는 경우), 마지막 성공적 갱신 후 30일 동안 기능이 계속 동작합니다. 이후에는 인스턴스가 OSS 기본값으로 돌아갑니다.
- **갱신 거부**: Logto가 라이선스 갱신을 거부하는 경우(예: 구독 취소), 라이선스 페이지에 사유가 표시됩니다. 유예 기간은 마지막 성공적 갱신 시점부터 계산됩니다.

갱신은 인스턴스에서 `https://cloud.logto.io`로의 아웃바운드 HTTPS 요청입니다. 방화벽 뒤에서 실행 중이라면 이 주소를 허용하세요.

### 인스턴스가 전송하는 정보 \{#what-your-instance-sends}

갱신 요청에는 다음 정보만 포함됩니다:

- 라이선스 키(내부적으로 `licenseId`로 식별)
- `deploymentId`: 라이선스 최초 설치 시 생성되는 무작위 식별자. 데이터베이스에 저장되며, 해당 데이터베이스를 사용하는 모든 인스턴스가 공유하고, 라이선스를 교체해도 변경되지 않습니다.
- Logto 버전
- 배포 사용량: 월간 활성 사용자 수, 월간 액세스 토큰 수, 테넌트 수 (단, [사용량 보고 비활성화](#turn-off-usage-reporting) 시 제외)

사용량 정보는 총계만 포함하며, 개인정보는 포함하지 않습니다. Logto는 호스트명, 도메인, 설정, 기타 데이터를 수집하지 않습니다. 이 데이터는 라이선스 유효성 유지 및 [플랜의 사용량 제한](#usage-limits) 비교에만 사용됩니다. 자세한 내용은 [자체 호스팅 구독 약관](https://logto.io/terms/self-hosted) 10.2항을 참고하세요. 동작은 오픈 소스이며, [`LicenseReader.ts`](https://github.com/logto-io/logto/blob/master/packages/core/src/license/LicenseReader.ts)에서 확인할 수 있습니다.

### 사용량 보고 비활성화 \{#turn-off-usage-reporting}

갱신을 실행할 수 있는 **모든** Logto 인스턴스에 아래 환경 변수를 설정하세요(동일 데이터베이스 공유 시):

```bash
SELF_HOSTED_LICENSE_USAGE_REPORTING_DISABLED=1
```

이 경우에도 갱신은 진행되며, Console은 제한 초과 시 경고를 표시합니다.

## 사용량 제한 \{#usage-limits}

각 플랜에는 사용량 제한이 있습니다. 제한을 초과해도 기능이 차단되거나 로그인에 영향을 주지 않습니다. Console에 배너로 안내만 표시됩니다.

| 지표             | 프로덕션 키                                  | 비프로덕션 키 |
| ---------------- | -------------------------------------------- | ------------- |
| 월간 활성 사용자 | Self-hosted Pro는 50,000명, 또는 주문서 기준 | 제한 없음     |
| 프로덕션 배포    | 1                                            | 제한 없음     |
| 월간 액세스 토큰 | 제한 없음                                    | 50,000        |

프로덕션 배포는 최근 15일 내 라이선스 갱신이 이루어진 경우 활성으로 간주됩니다.

제한을 초과한 경우, [자체 호스팅 구독 약관](https://logto.io/terms/self-hosted) 4.2항에 따라 30일 이내에 플랜 업그레이드 또는 사용량 축소를 위해 Logto에 문의하세요.

### 사용량 명세서 받기 \{#get-a-usage-statement}

Logto에서 사용량 명세서를 요청하는 경우, [Logto Management API](/integrate-logto/interact-with-management-api)용 액세스 토큰과 함께 `GET /api/systems/license/usage-statement`를 전송하세요. 최근 12개월간 월간 활성 사용자 및 액세스 토큰 수를 데이터베이스에서 읽어 반환합니다.

## 라이선스 만료 \{#license-expiration}

라이선스는 1년 단위로 적용되며, **만료일**이 해당 기간의 종료일입니다.

- **갱신 시**: 인스턴스에서 별도 조치가 필요 없습니다. 갱신 후 첫 갱신 시, 설치된 키가 새 만료일로 교체됩니다. 갱신 반영까지 며칠간 만료일이 지난 것으로 표시될 수 있으나, 이 기간 동안 기능은 계속 사용 가능합니다.
- **미갱신 시**: 기간 종료 후 갱신이 거부됩니다. 30일 유예 기간까지 기능이 유지되며, 이후에는 라이선스가 없는 OSS 기본값으로 돌아갑니다. 라이선스 페이지에 안내 배너와 적용 예정일이 표시됩니다.
- **유예 기간 종료 시**: 기능을 다시 활성화하려면 새 키를 설치하세요. 라이선스가 필요하다면 기존 문의 채널로 Logto에 연락하세요.

### 기능이 비활성화될 때 \{#what-happens-when-features-are-turned-off}

OSS 기본값으로 돌아가도, 라이선스로 생성한 데이터는 삭제되지 않습니다:

- **Logto 브랜딩 숨기기**: "Powered by Logto" 마크가 다시 표시됩니다. 설정은 저장되어, 라이선스 재설치 시 다시 적용됩니다.
- **SAML 앱**: 3개 초과 앱도 유지되지만, 제한 이하로 줄이기 전까지 새 앱을 만들 수 없습니다.
- **필수 MFA**: 언제든 비활성화할 수 있습니다. 라이선스 없이는 다시 활성화할 수 없습니다.
- **Bring your UI, 커스텀 CSP, Console 초대**: 해당 기능이 필요한 새 변경은 불가하며, 기존 데이터는 유지됩니다.

## Bring your UI용 저장소 설정 \{#set-up-storage-for-bring-your-ui}

Logto Cloud에서는 Bring your UI 자산이 Logto에서 호스팅됩니다. 자체 인스턴스에서는 직접 구성한 오브젝트 스토리지에 저장됩니다. Logto는 업로드된 파일을 압축 해제하여 해당 저장소에 저장하고, 거기서 제공합니다.

`experienceBlobsProvider` 시스템 설정을 [파일 스토리지 프로바이더](/logto-oss/file-storage-provider)와 동일한 JSON 구조로 지정하세요. 예를 들어 S3 호환 스토리지의 경우:

```bash
pnpm logto db system set experienceBlobsProvider '{"provider":"S3Storage","accessKeyId":"my-access-key-id","accessSecretKey":"my-secret-access-key","bucket":"logto-sie","endpoint":"https://s3.us-east-2.amazonaws.com"}'
```

설정 변경 후 Logto를 재시작하세요. 이후 [Bring your UI](/customization/bring-your-ui#upload-your-custom-ui-assets) 안내에 따라 Console에서 자산을 업로드하세요.

## Console 멤버 초대 이메일 \{#invitation-emails-for-console-members}

Console 초대는 기본 테넌트의 이메일 커넥터를 통해 이메일로 발송됩니다. 멤버 초대 전 [이메일 커넥터를 설정](/connectors/email-connectors)했는지 확인하세요.
