# MFA용 이메일 인증

Logto는 사용자의 등록된 이메일 주소로 일회성 인증 코드를 전송하여 계정 보안을 강화하는 이메일 기반 다단계 인증 (MFA, Multi-factor authentication) 기능을 지원합니다. 이메일 MFA는 두 번째 인증 (Authentication) 요소로 작동하며, TOTP, 패스키, 백업 코드 등 다른 MFA 요소와 결합하여 유연한 2단계 인증 옵션을 제공합니다.

## 개념 \{#concepts}

이메일 인증은 가장 보편적으로 접근 가능한 MFA 방법 중 하나입니다. 이메일 계정의 광범위한 보급을 활용하여 임시 일회성 인증 코드를 사용자의 이메일 인박스로 직접 전달합니다. 별도의 소프트웨어 설치가 필요한 앱 기반 인증기와 달리, 이메일 MFA는 이미 거의 모든 인터넷 사용자가 웹 브라우저, 이메일 클라이언트 또는 모바일 앱을 통해 접근할 수 있는 기존 이메일 인프라를 활용합니다. 따라서 이메일 계정만 있으면 별도의 하드웨어나 추가 설정 없이 즉시 사용할 수 있습니다.

## MFA용 이메일 인증 설정하기 \{#configure-email-verification-for-mfa}

**1단계: 이메일 커넥터 및 템플릿 설정**

1. <CloudLink to="/connectors/passwordless">콘솔 > 커넥터 > 이메일 및 SMS 커넥터</CloudLink>로
   이동하세요.
2. 적절한 이메일 커넥터 (SendGrid, Mailgun 등)를 선택하세요.
3. 연결 파라미터를 설정하세요.
4. MFA 전용 사용 유형으로 [이메일 템플릿](/connectors/email-connectors/email-templates)을 설정하세요.

   - MFA 인증용 `MfaVerification` usageType
   - MFA 바인딩용 `BindMfa` usageType
   - 팁: [Logto 이메일 서비스](/connectors/email-connectors/built-in-email-service)는 내장 이메일 템플릿을 제공합니다.

5. 공급자별 설정 방법은 [이메일 커넥터](/connectors/email-connectors)를 참고하세요.

**2단계: MFA용 이메일 활성화**

1. <CloudLink to="/mfa">콘솔 > 다단계 인증</CloudLink>으로 이동하세요.
2. "이메일 인증 코드" 요소를 활성화하세요. 이메일 MFA는 TOTP, 패스키, SMS, 백업 코드 등 다른 MFA 요소와 함께 사용하는 것을 권장합니다. (단일 요소 의존성 감소)
3. **이메일/SMS 2단계 인증**에서 어떤 사용자가 이메일 MFA를 사용할지 선택하세요. [이메일 MFA 대상](#who-has-email-mfa) 참고.
4. 원하는 MFA 정책(선택적, 적응형, 필수)을 설정하세요.
5. 설정 변경 사항을 저장하세요.

:::note 중요 사용 시 고려사항

1. **로그인 방식 제한**: 이메일 인증 코드는 [로그인 방식(1FA)](/end-user-flows/sign-up-and-sign-in/sign-in)과 MFA 요소(2FA)로 동시에 사용할 수 없습니다. 이메일 구현별로 하나의 인증 흐름만 선택하세요.

2. **회원가입 방식 호환성**: 이메일 인증 코드는 회원가입 방식과 MFA에 동시에 사용할 수 있습니다. Logto는 동일 이메일 주소에 대해 중복 인증을 요구하지 않도록 선택한 MFA 정책에 따라 최적화된 최종 사용자 등록 흐름을 제공합니다.

3. **비밀번호 재설정 호환성**: 이메일 인증 코드는 [비밀번호 찾기](/end-user-flows/sign-up-and-sign-in/reset-password)와 MFA에 동시에 사용할 수 있지만, 이 조합은 **권장하지 않습니다**. 이 설정은 MFA 보안 효과를 저하시킬 수 있습니다. 사용자가 비밀번호 찾기 이메일 인증으로 비밀번호를 재설정한 뒤, 새 비밀번호로 1차 인증(1FA)을 하고 동일 이메일 방식으로 MFA 인증을 통과할 수 있기 때문입니다.

:::

## 이메일 MFA 대상 \{#who-has-email-mfa}

이메일 MFA 코드는 항상 사용자의 기본 이메일 주소로 전송됩니다. <CloudLink to="/mfa">다단계 인증</CloudLink> 페이지의 **이메일/SMS 2단계 인증** 설정에 따라 이메일 MFA 대상이 결정됩니다:

- **인증된 이메일 또는 전화번호가 있는 모든 사용자**: 기본 이메일 주소가 있는 모든 사용자는 별도 설정 없이 이메일 MFA를 사용할 수 있습니다.
- **직접 설정한 사용자만**: 이메일 MFA를 직접 설정한 사용자만 사용할 수 있습니다. 인증된 이메일로 회원가입한 사용자도 자동으로 이메일 MFA가 활성화되지 않으므로, 모든 사용자에게 강제하지 않고 옵션으로 제공할 수 있습니다. 사용자는 MFA 설정 흐름, [계정 센터](/end-user-flows/account-settings/by-account-center-ui), 또는 [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa)를 통해 직접 설정할 수 있습니다. 관리자는 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management)를 통해 사용자의 MFA를 추가/삭제할 수 있습니다.

이 설정은 [SMS MFA](/end-user-flows/mfa/sms-mfa)에도 적용됩니다. 기본값 및 모드 전환 시 동작은 [이메일 및 SMS MFA 등록](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment)을 참고하세요.

:::note
**인증된 이메일 또는 전화번호가 있는 모든 사용자** 설정에서는, 기본 이메일 주소만으로 이메일 MFA가 활성화된 사용자는 별도의 이메일 MFA 기록이 저장되지 않으므로, `GET /api/my-account/mfa-verifications`, `GET /api/users/{userId}/mfa-verifications`, 또는 `user.mfaVerificationFactors` (커스텀 JWT 클레임 및 `PostSignIn` 액션)에서 나타나지 않습니다.
:::

## 이메일 MFA 설정 흐름 \{#email-mfa-setup-flows}

MFA 설정 프롬프트는 사용자 등록 시 또는 로그인 후에 표시될 수 있으며, 이는 설정한 [MFA 정책](/end-user-flows/mfa/configure-mfa#global-mfa-configuration)에 따라 달라집니다.

이메일 MFA 설정 흐름에 영향을 주는 요소는 다음과 같습니다:

- **MFA 주요 요소 개수**: 주요 요소가 여러 개라면, 사용자가 하나를 선택해 설정해야 합니다. 주요 요소란 백업 코드를 제외한 MFA 방식입니다.
- **백업 코드 활성화 여부**: 활성화된 경우, 주요 MFA 요소 설정 후 백업 코드가 자동 생성되며, 사용자는 이를 저장하라는 안내를 받습니다.
- **회원가입 식별자 설정**: 이메일 주소가 [회원가입 식별자](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier)로 사용되었고, 사용자가 회원가입 시 이미 이메일 인증 코드를 통해 인증을 마쳤을 경우
  - **인증된 이메일 또는 전화번호가 있는 모든 사용자**에서는 시스템이 해당 이메일을 자동으로 MFA 요소로 바인딩하며 추가 인증이 필요하지 않습니다. 다른 주요 요소가 있다면 UI에 "다른 2단계 인증 추가" 옵션이 표시됩니다(사용자는 건너뛸 수 있음). 이로써 MFA가 활성화되었음을 명확히 안내합니다.
  - **직접 설정한 사용자만**에서는 이메일이 다른 요소와 동일하게 마스킹된 주소로 제공됩니다. 사용자가 이를 선택하거나, 유일한 주요 요소일 경우, Logto는 회원가입 시 인증을 활용해 추가 코드 전송 없이 설정을 완료합니다.
- **기존 사용자 데이터**: 기존 사용자가 로그인 후 MFA를 설정할 때, 먼저 1차 인증을 완료한 뒤 MFA 설정을 진행해야 합니다. 계정에 이미 인증된 기본 이메일 주소가 있다면:
  - **인증된 이메일 또는 전화번호가 있는 모든 사용자**에서는 위 회원가입 식별자 케이스와 동일하게 동작합니다.
  - **직접 설정한 사용자만**에서는 이메일이 마스킹된 주소로 제공됩니다. 사용자가 이를 선택하거나, 유일한 주요 요소일 경우, Logto가 해당 주소로 인증 코드를 전송하고, 사용자가 코드를 입력하면 이메일 MFA가 설정됩니다.

아래는 세 가지 일반적인 이메일 MFA 바인딩 시나리오입니다.

## 이메일 MFA 인증 흐름 \{#email-mfa-verification-flows}

이메일 MFA가 활성화된 사용자가 로그인하면, 1차 인증(1FA)을 성공적으로 완료한 후 두 번째 인증 (Authentication) 요소(2FA)로 이메일 인증 코드를 입력하라는 프롬프트가 표시됩니다.

여러 MFA 요소가 있을 경우, Logto는 [MFA 설정](/end-user-flows/mfa/configure-mfa#mfa-verification-flow)에 명시된 고정 순서(패스키, 인증기 앱 OTP, SMS 인증 코드, 이메일 인증 코드, 백업 코드)에 따라 우선순위가 가장 높은 요소를 바로 엽니다. 인증기 앱 OTP 등 다른 요소가 먼저 표시되면, 사용자는 **다른 인증 방법 시도**를 클릭해 선택 목록을 열고 이메일 인증 코드를 선택할 수 있습니다.

**예시:**

<details>
  <summary>
    로그인: `전화번호 + 비밀번호` | MFA: `이메일 인증 코드 / 인증기 앱 OTP / 백업 코드`
  </summary>

## 오류 처리 \{#error-handling}

1. **이메일 주소 미연결**

   - 오류 코드: `session.mfa.mfa_factor_not_enabled`
   - 처리: 사용자가 먼저 이메일 주소를 연결하도록 안내

2. **잘못된 인증 코드**

   - 오류 코드: `verification_code.code_mismatch`
   - 처리: 재입력 안내, 재시도 횟수 제한

3. **인증 코드 만료**

   - 오류 코드: `verification_code.expired`
   - 처리: 새 인증 코드 요청 안내

4. **전송 속도 제한 초과**
   - 오류 코드: `request.message_rate_limited` (Logto 수신자별 전송 속도 제한) 또는 `connector.rate_limit_exceeded` (이메일 커넥터 속도 제한)
   - 처리: 대기 시간 안내, 재전송 제한
