# 백업 코드

## 개념 \{#concepts}

백업 코드(Recovery code라고도 함)는 MFA를 위한 일회용 코드로, 사용자의 주요 인증 (Authentication) 요소(예: 인증 앱 또는 하드웨어 토큰)를 사용할 수 없을 때 백업 역할을 합니다.

이 코드를 분실하면 계정 복구에 어려움이 생길 수 있습니다. 따라서 백업 코드를 활성화하기 전에 추가 주요 인증 (Authentication) 요소를 먼저 설정하고, 이를 우선적으로 사용하는 것이 권장됩니다.

Logto는 사용자가 추가 인증 (Authentication) 요소를 설정하면 자동으로 10개의 백업 코드를 생성합니다. 각 코드는 한 번만 사용할 수 있습니다. 사용자는 [사전 구축된 Account Center UI](/end-user-flows/account-settings/by-account-center-ui) (`/account/backup-codes/regenerate`), [Account API](/end-user-flows/account-settings/by-account-api#manage-backup-codes)로 구축한 맞춤형 셀프 서비스 인터페이스, 또는 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management)를 사용하는 관리자 도구를 통해 기존 코드를 모두 사용하기 전에 새로운 코드 세트를 재생성할 수 있습니다.

## MFA용 백업 코드 설정 \{#configure-backup-codes-for-mfa}

1. <CloudLink to="/mfa">콘솔 > 다단계 인증 (MFA)</CloudLink>으로 이동하세요.
2. "백업 코드" 요소를 활성화하세요. 백업 코드는 단독 MFA 요소로 사용할 수 없습니다. 백업 코드는 다른 주요 MFA 요소(패스키, 인증 앱, SMS, 이메일)와 함께 사용해야 합니다.
3. 원하는 MFA 정책(선택적, 적응형, 필수)을 설정하세요.
4. 구성 변경 사항을 저장하세요.

## 백업 코드 관리 설정 \{#configure-backup-codes-management}

사용자는 [사전 구축된 Account Center UI](/end-user-flows/account-settings/by-account-center-ui) (`/account/backup-codes/manage` 및 `/account/backup-codes/regenerate`)를 통해 자신의 백업 코드를 확인하고 재생성할 수 있습니다. 또한 Account API를 사용하여 사용자가 백업 코드를 확인, 재생성, 삭제할 수 있는 맞춤형 계정 관리 인터페이스를 구축할 수 있습니다. 이를 통해 사용자는 애플리케이션의 계정 설정에서 직접 복구 옵션을 관리할 수 있습니다.

구현 단계 및 API 엔드포인트에 대한 자세한 내용은 [Account API를 통한 계정 설정](/end-user-flows/account-settings/by-account-api#manage-backup-codes)을 참조하세요.

## 백업 코드 설정 흐름 \{#backup-codes-setup-flows}

백업 코드는 보조 MFA 요소이므로, 주요 MFA 요소가 성공적으로 설정된 후에만 설정할 수 있습니다. 자동 생성된 10개의 백업 코드가 사용자에게 표시되며, 사용자는 이를 안전하게 다운로드 및 복사할 수 있습니다. 사용자는 MFA 설정 과정을 완료하기 위해 백업 코드를 수동으로 확인해야 합니다.

Logto는 **백업 코드**가 활성화되어 있고 사용자가 이미 다른 활성 요소를 가지고 있지만 사용하지 않은 백업 코드가 남아 있지 않은 경우, 로그인 중에 새로운 백업 코드 세트를 생성하고 저장하라는 안내를 표시합니다. 예시:

- 이전에 생성된 모든 백업 코드를 이미 사용한 경우
- 사용자가 주요 MFA 요소를 등록한 후 **백업 코드**를 활성화한 경우

기존 사용자의 로그인 중에는, 사용자가 MFA 챌린지를 검증(또는 패스키로 로그인)한 후에만 이 재안내가 발생합니다. MFA 검증을 건너뛰는 로그인(신뢰된 기기, 저위험 [적응형 MFA](/end-user-flows/mfa/adaptive-mfa) 로그인, 사용자가 건너뛴 **선택적 MFA** 등)에서는 로그인 중에 새로운 백업 코드를 바인딩하라는 안내가 표시되지 않으며, 일반 [엔터프라이즈 SSO](/end-user-flows/enterprise-sso) 로그인의 경우 `acr_values`를 통해 MFA가 명시적으로 요청되지 않는 한 MFA 설정 안내가 생략됩니다.

## 백업 코드 검증 흐름 \{#backup-codes-verification-flow}

백업 코드는 주요 MFA 요소를 사용할 수 없을 때 비상 인증 (Authentication) 수단으로 사용됩니다. 각 코드는 한 번만 사용할 수 있으며, 성공적으로 검증되면 무효화됩니다.

**검증 우선순위:**

- **주요 요소 우선**: 사용자가 다른 MFA 요소를 설정한 경우, 주요 요소(패스키, TOTP, SMS, 이메일)가 먼저 안내됩니다.
- **백업 코드 접근**: 주요 요소를 사용할 수 없는 경우, 사용자는 "다른 방법으로 인증"을 클릭하여 백업 코드로 전환할 수 있습니다.
- **폴백 시나리오**: 모든 주요 요소가 삭제된 경우, 백업 코드만이 유일한 인증 (Authentication) 옵션이 됩니다. 로그인 중 백업 코드로 MFA 인증에 성공하면, Logto는 자동으로 새로운 주요 요소를 설정하라는 안내를 표시합니다.
