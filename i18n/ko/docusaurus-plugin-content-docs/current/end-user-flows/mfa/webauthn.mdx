# 패스키 (Passkeys, WebAuthn)

[패스키 (Passkey)](https://auth.wiki/passkey)는 기존 비밀번호보다 더 안전하고 사용자 친화적인 대안을 제공합니다. 공개키 암호화를 사용하여, 패스키는 사용자의 디바이스, 서비스 도메인, 그리고 사용자 ID를 연결함으로써 피싱 및 비밀번호 공격을 효과적으로 방지합니다. 다양한 디바이스나 브라우저와 호환되며, 사용자가 생체 인증 및 하드웨어 보안 기능을 활용하여 편리하게 인증할 수 있습니다. [WebAuthn](https://auth.wiki/webauthn)은 웹사이트가 패스키를 구현할 수 있도록 API를 제공합니다.

Logto는 [다단계 인증 (MFA)](/end-user-flows/mfa/configure-mfa)와 [패스키 로그인](/end-user-flows/sign-up-and-sign-in/passkey-sign-in) 모두에서 패스키 (WebAuthn)를 지원합니다. 동일한 WebAuthn 자격 증명은 테넌트 설정에 따라 두 곳 모두에서 재사용할 수 있습니다.

## 개념 (Concepts) \{#concepts}

고객들은 일반적으로 WebAuthn보다는 패스키(Passkeys)를 더 잘 알고 있습니다. 그렇다면 이 둘의 관계와 사용 방법은 무엇일까요? 다음 개념을 살펴보세요:

- **패스키 (Passkeys)**: 패스키는 비밀번호를 대체하는 FIDO 기반의 피싱 저항 자격 증명입니다. 비대칭 공개키 암호화를 활용하여 보안을 강화합니다. USB 또는 Bluetooth 장치와 같은 하드웨어 토큰이나 보안 키가 될 수 있습니다. "패스키"는 사용자에게 표시되는 인증 방식이므로, 제품 클라이언트 내에서 사용해야 합니다.
- **WebAuthn**: W3C와 FIDO Alliance가 개발한 JavaScript API로, 웹 애플리케이션 인증을 FIDO2 표준으로 지원합니다. 패스키는 WebAuthn이 지원하는 인증 방식 중 하나입니다. Logto 콘솔에서는 이 통합을 전문적으로 "WebAuthn"이라고 부릅니다.

WebAuthn은 사용자가 선택할 수 있는 다양한 인증기를 제공합니다. 로컬 및 클라우드 용도로 두 가지 유형이 있습니다:

- **플랫폼 인증기 (Platform authenticator, 내부 인증기)**: 단일 및 특정 디바이스 OS(컴퓨터, 노트북, 휴대폰, 태블릿 등)에 연결되어 있습니다. 사용자는 해당 디바이스에서 생체 인증이나 디바이스 암호 등으로 빠르게 인증할 수 있습니다. 예: macOS 또는 iOS에서 Touch ID, Face ID, 디바이스 암호로 인증되는 iCloud Keychain; Windows Hello에서 얼굴 인식, 지문, PIN으로 인증.
- **로밍 인증기 (Roaming authenticator, 외부 인증기, 크로스 플랫폼 인증기)**: 별도의 휴대용 디바이스 또는 소프트웨어 애플리케이션(예: 하드웨어 보안 키, 스마트폰)입니다. USB 연결 또는 NFC, Bluetooth를 활성화해야 합니다. 로밍 인증기는 단일 디바이스나 브라우저에 국한되지 않아 더 큰 유연성을 제공합니다.

WebAuthn의 원리와 과정을 더 깊이 이해하려면, 다음 블로그 글을 참고하세요: [WebAuthn과 패스키 101](https://blog.logto.io/web-authn-and-passkey-101/) 및 [WebAuthn 통합 전 알아야 할 것들](https://blog.logto.io/webauthn-base-knowledge/).

## MFA용 패스키 인증 설정하기 \{#configure-passkeys-verification-for-mfa}

1. <CloudLink to="/mfa">콘솔 > 다단계 인증 (MFA)</CloudLink>로 이동하세요.
2. "패스키 (WebAuthn)" 요소를 활성화하세요. 단일 요소 의존도를 줄이기 위해 패스키를 다른 MFA 요소(TOTP, SMS, 백업 코드)와 함께 사용하는 것을 권장합니다.
3. 원하는 MFA 정책(필수 vs. 선택)을 설정하세요.
4. 설정 변경 사항을 저장하세요.

:::tip
동일한 사용자가 [패스키 로그인](/end-user-flows/sign-up-and-sign-in/passkey-sign-in)으로 로그인하면, Logto는 별도의 MFA 인증 단계를 건너뜁니다. 패스키 로그인이 이미 WebAuthn 기반 인증 요건을 충족하기 때문입니다.
:::

:::note 제한 사항에 주의하세요

WebAuthn을 구현할 때 몇 가지 제한 사항을 반드시 인지해야 합니다:

1. **플랫폼 및 브라우저 제한**: Logto는 현재 네이티브 애플리케이션에 대해 WebAuthn을 지원하지 않습니다. 또한, WebAuthn 인증기의 사용 가능 여부는 브라우저 및 디바이스의 기능에 따라 다릅니다 ([지원 목록 확인](https://caniuse.com/?search=webauthn)). 따라서 WebAuthn은 항상 다단계 인증 (MFA)을 구현하는 유일한 옵션이 아니며, 그렇지 않다면 어떤 브라우저와 디바이스가 제품에 접근할 수 있는지 제어해야 합니다.
2. **도메인 제한**: 도메인이 변경되면 기존 WebAuthn 계정을 통한 사용자 인증이 어려워질 수 있습니다. 패스키는 현재 웹 페이지의 특정 도메인에 바인딩되며, 서로 다른 도메인 간에는 사용할 수 없습니다.
3. **디바이스 제한**: 디바이스를 분실하면, 특히 "이 디바이스" 플랫폼 인증기에 의존하는 경우 계정 접근이 불가능해질 수 있습니다. 인증 접근성을 높이기 위해 사용자에게 둘 이상의 인증 요소를 제공하는 것이 좋습니다.

:::

## 패스키 관리 설정하기 \{#configure-passkeys-management}

Account API를 사용하여 사용자가 패스키를 추가, 조회, 이름 변경, 삭제할 수 있는 맞춤형 계정 관리 인터페이스를 구축할 수 있습니다. 이는 개인화된 계정 센터를 만들거나, 크로스 디바이스 백업 시나리오를 구현할 때 유용합니다.

구체적인 구현 단계와 API 엔드포인트는 [Account API로 계정 설정](/end-user-flows/account-settings/by-account-api#link-a-new-webauthn-passkey)을 참고하세요.

## 패스키 내보내기 \{#export-passkeys}

[Management API](/integrate-logto/interact-with-management-api)를 사용하여 Logto가 저장한 사용자의 WebAuthn 자격 증명을 내보낼 수 있습니다. 내보낸 패스키는 동일한 도메인에서 WebAuthn을 제공하는 다른 시스템으로 이동할 때 사용할 수 있어, 사용자가 기존 패스키로 계속 로그인할 수 있습니다.

[`GET /api/users/{userId}/mfa-verifications`](https://openapi.logto.io/operation/operation-listusermfaverifications) 호출 시 `includeWebAuthnCredentials` 쿼리 파라미터를 `true`로 설정하세요:

```bash
curl "https://[tenant-id].logto.app/api/users/{userId}/mfa-verifications?includeWebAuthnCredentials=true" \
  -H 'authorization: Bearer <management-api-access-token>'
```

응답의 각 WebAuthn 항목에는 저장된 자격 증명이 포함됩니다:

```json
[
  {
    "id": "wv9m3k2x7p1q",
    "createdAt": "2026-10-12T08:31:24.000Z",
    "lastUsedAt": "2026-11-02T06:15:09.000Z",
    "type": "WebAuthn",
    "agent": "Mozilla/5.0 (Macintosh) ...",
    "name": "MacBook",
    "rpId": "auth.example.com",
    "credentialId": "Ab3dY0n9Kq2LwX8mR4sT1uV6zE",
    "publicKey": "pQECAyYgASFYIOrE5x...",
    "counter": 0,
    "transports": ["internal", "hybrid"]
  }
]
```

| 필드           | 설명                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| `credentialId` | WebAuthn 자격 증명 ID, base64url 인코딩.                                                                |
| `publicKey`    | COSE 형식의 자격 증명 공개키, base64url 인코딩.                                                         |
| `counter`      | Logto가 해당 자격 증명에서 마지막으로 본 서명 카운터(`signCount`). 많은 패스키는 항상 `0`을 반환합니다. |
| `transports`   | 등록 시 인증기가 보고한 전송 방식. 예: `internal`, `hybrid`, `usb`.                                     |
| `rpId`         | 자격 증명이 등록된 릴라잉 파티 ID(도메인).                                                              |
| `createdAt`    | 자격 증명이 등록된 시점.                                                                                |
| `lastUsedAt`   | 사용자가 인증에 마지막으로 사용한 시점.                                                                 |

`includeWebAuthnCredentials` 없이 호출하면, 응답에서 `credentialId`, `publicKey`, `counter`, `transports`, `rpId`가 생략됩니다. 다른 MFA 요소는 변경 없이 반환됩니다. 이 파라미터는 읽기 전용 Management API 접근에서도 동작합니다. 자격 증명 ID와 공개키만으로는 로그인을 할 수 없기 때문입니다.

자격 증명을 다른 시스템에 가져올 때:

- **동일한 도메인을 유지하세요.** 패스키는 등록된 릴라잉 파티 ID에서만 동작합니다. 다른 시스템도 내보낸 `rpId`를 WebAuthn 릴라잉 파티 ID로 사용해야 하며, 즉 해당 도메인에서 로그인 서비스를 제공해야 합니다. 예: [커스텀 도메인](/logto-cloud/custom-domain).
- **`rpId`가 없는 자격 증명 처리.** Logto가 릴라잉 파티 ID 기록을 시작하기 전 등록되었고, 이후 사용되지 않은 자격 증명은 `rpId`가 없습니다. 이들은 등록 당시 로그인 페이지를 제공한 도메인에 바인딩되어 있으며, 현재 커스텀 도메인과 다를 수 있습니다.
- **사용자 핸들 매핑.** Logto는 Logto 사용자 ID의 UTF-8 바이트를 WebAuthn `userHandle`로 등록합니다. 패스키 로그인 시 인증기가 이 값을 반환하므로, 다른 시스템에서 마이그레이션된 사용자와 매핑해야 합니다.
- **카운터 유지.** `counter`를 자격 증명의 현재 서명 카운터로 저장하여, 다른 시스템에서도 복제된 인증기를 감지할 수 있도록 해야 합니다.

## 패스키 인증 플로우 \{#passkey-verification-flows}

사용자가 패스키를 포함한 여러 MFA 방식을 설정한 경우, 패스키는 보안성과 편의성 때문에 첫 화면에서 추천 MFA 인증 방식으로 표시됩니다. 사용자는 아래의 "다른 방법으로 인증 시도"를 클릭하여 다른 인증 방식으로 전환할 수 있습니다. 자세한 내용은 [MFA 설정하기](/end-user-flows/mfa/configure-mfa#mfa-verification-flow)를 참고하세요.

사용자가 다른 1차 인증 요소를 입력하는 대신 [패스키 로그인](/end-user-flows/sign-up-and-sign-in/passkey-sign-in)으로 로그인을 완료하면, Logto는 추가 MFA 단계를 요구하지 않습니다. 패스키 자체가 WebAuthn MFA 요소로 간주되기 때문입니다.
