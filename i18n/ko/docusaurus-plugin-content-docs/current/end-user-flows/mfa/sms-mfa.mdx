# MFA용 SMS 인증 (SMS verification for MFA)

Logto는 SMS 기반 다단계 인증 (MFA) 기능을 지원하여, 사용자의 등록된 휴대폰 번호로 일회성 인증 코드를 전송함으로써 계정 보안을 강화합니다. SMS MFA는 두 번째 인증 요소로 사용되며, 다른 MFA 요소(TOTP, 패스키, 백업 코드 등)와 결합하여 유연한 2단계 인증 옵션을 제공합니다.

## 개념 (Concepts) \{#concepts}

SMS 인증, 즉 휴대폰 번호 인증은 가장 접근성이 높은 MFA 방법 중 하나입니다. 이는 휴대폰의 보편성을 활용하여 임시 일회성 인증 코드를 문자 메시지로 사용자의 기기에 직접 전달합니다. 별도의 소프트웨어 설치가 필요한 앱 기반 인증기와 달리, SMS MFA는 모든 모바일 기기에 기본적으로 제공되는 메시징 인프라를 활용하므로, 별도의 설정 없이 즉시 사용자가 이용할 수 있습니다.

## MFA용 SMS 인증 설정하기 \{#configure-sms-verification-for-mfa}

**1단계: SMS 커넥터 및 템플릿 설정**

1. <CloudLink to="/connectors/passwordless">콘솔 > 커넥터 > 이메일 및 SMS 커넥터</CloudLink>로
   이동하세요.
2. 적절한 SMS 커넥터(Twilio, SMS Aero 등)를 선택하세요.
3. 연결 파라미터를 설정하세요.
4. MFA 전용 사용 유형으로 SMS 템플릿을 설정하세요.
   - MFA 인증을 위한 `MfaVerification` usageType
   - MFA 바인딩을 위한 `BindMfa` usageType
5. 커넥터 기능을 테스트하여 메시지 전달이 정상적으로 되는지 확인하세요.
6. 공급자별 설정 방법은 [SMS 커넥터](/connectors/sms-connectors)를 참고하세요.

**2단계: MFA용 SMS 활성화**

1. <CloudLink to="/mfa">콘솔 > 다단계 인증</CloudLink>으로 이동하세요.
2. "SMS 인증 코드" 요소를 활성화하세요. SMS MFA는 다른 MFA 요소(TOTP, 패스키, 백업 코드 등)와 함께 사용하는 것을 권장합니다(단일 요소 의존성 감소).
3. **이메일/SMS 2단계 인증**에서 어떤 사용자가 SMS MFA를 사용할지 선택하세요. [누가 SMS MFA를 사용하는가](#who-has-sms-mfa)를 참고하세요.
4. 원하는 MFA 정책(선택적, 적응형, 필수)을 설정하세요.
5. 구성 변경 사항을 저장하세요.

:::note 중요한 사용 시 고려사항

1. **로그인 방식 제한**: SMS 인증 코드는 [로그인 방식(1FA)](/end-user-flows/sign-up-and-sign-in/sign-in)과 MFA 요소(2FA)로 동시에 사용할 수 없습니다. SMS 구현당 하나의 인증 흐름만 선택하세요.

2. **회원가입 방식 호환성**: SMS 인증 코드는 회원가입 방식과 MFA에 동시에 사용할 수 있습니다. Logto는 선택한 MFA 정책에 따라 동일한 휴대폰 번호에 대해 SMS 인증을 두 번 요구하지 않도록 최적화합니다.

3. **비밀번호 재설정 호환성**: SMS 인증 코드는 [비밀번호 찾기](/end-user-flows/sign-up-and-sign-in/reset-password)와 MFA에 동시에 사용할 수 있지만, 이 조합은 **권장하지 않습니다**. 이 구성은 MFA의 보안 효과를 저하시킬 수 있습니다. 사용자가 비밀번호 찾기 SMS 인증으로 비밀번호를 재설정한 후, 새 비밀번호로 1차 인증(1FA)을 하고 동일한 SMS 방식으로 MFA 인증을 할 수 있기 때문입니다.

:::

## 누가 SMS MFA를 사용하는가 \{#who-has-sms-mfa}

SMS MFA 코드는 항상 사용자의 기본 휴대폰 번호로 전송됩니다. <CloudLink to="/mfa">다단계 인증</CloudLink> 페이지의 **이메일/SMS 2단계 인증** 설정이 어떤 사용자가 SMS MFA를 사용할지 결정합니다:

- **인증된 이메일 또는 휴대폰 번호가 있는 모든 사용자**: 기본 휴대폰 번호가 있는 모든 사용자는 별도의 설정 없이 SMS MFA를 사용합니다.
- **직접 설정한 사용자만**: SMS MFA를 직접 설정한 사용자만 사용합니다. 인증된 휴대폰 번호로 회원가입한 사용자도 자동으로 SMS MFA를 받지 않으므로, 모든 사용자를 등록시키지 않고도 SMS를 MFA 옵션 중 하나로 제공할 수 있습니다. 사용자는 MFA 설정 흐름, [계정 센터](/end-user-flows/account-settings/by-account-center-ui), 또는 [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa)를 통해 직접 설정할 수 있습니다. 관리자는 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management)를 통해 사용자의 SMS MFA를 추가/삭제할 수 있습니다.

이 설정은 [이메일 MFA](/end-user-flows/mfa/email-mfa)에도 적용됩니다. 기본값 및 모드 전환 시 동작은 [이메일 및 SMS MFA 등록](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment)을 참고하세요.

:::note
**인증된 이메일 또는 휴대폰 번호가 있는 모든 사용자** 설정에서는, 기본 휴대폰 번호로 인해 SMS MFA가 활성화된 사용자는 별도의 SMS MFA 기록이 저장되지 않으므로, `GET /api/my-account/mfa-verifications`, `GET /api/users/{userId}/mfa-verifications`, 또는 `user.mfaVerificationFactors`(커스텀 JWT 클레임 및 `PostSignIn` 액션)에서 나타나지 않습니다.
:::

## SMS MFA 설정 흐름 \{#sms-mfa-setup-flows}

MFA 설정 프롬프트는 [MFA 정책](/end-user-flows/mfa/configure-mfa#global-mfa-configuration) 설정에 따라 회원가입 중 또는 로그인 후에 나타날 수 있습니다.

SMS MFA 설정 흐름은 다음 요소에 의해 영향을 받습니다:

- **MFA 주요 요소 개수**: 주요 요소가 여러 개라면, 사용자가 하나를 선택해 설정해야 합니다. 주요 요소란 백업 코드를 제외한 MFA 방식입니다.
- **백업 코드 활성화 여부**: 활성화 시, 주요 MFA 요소 설정 후 백업 코드가 자동 생성되며, 사용자는 이를 저장하라는 안내를 받습니다.
- **회원가입 식별자 구성**: 휴대폰 번호가 [회원가입 식별자](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier)로 사용되었고, 사용자가 회원가입 중 SMS 인증 코드로 이미 인증을 마쳤을 경우
  - **인증된 이메일 또는 휴대폰 번호가 있는 모든 사용자**에서는, 시스템이 해당 번호를 자동으로 MFA 요소로 바인딩하며 추가 인증이 필요하지 않습니다. 다른 주요 요소가 있다면 UI에 "다른 2단계 인증 추가" 옵션이 표시됩니다(사용자는 건너뛸 수 있음). 이로써 MFA가 활성화되었음을 명확히 안내합니다.
  - **직접 설정한 사용자만**에서는, 휴대폰 번호가 다른 요소와 마찬가지로 마스킹된 상태로 제공됩니다. 사용자가 이를 선택하거나, 유일한 주요 요소일 경우, Logto는 회원가입 시 인증을 활용해 추가 코드 없이 설정을 완료합니다.
- **기존 사용자 데이터**: 기존 사용자가 로그인 후 MFA를 설정할 때, 먼저 1차 인증을 완료한 뒤 MFA 설정을 진행해야 합니다. 계정에 이미 인증된 기본 휴대폰 번호가 있다면:
  - **인증된 이메일 또는 휴대폰 번호가 있는 모든 사용자**에서는, 위 회원가입 식별자 케이스와 동일하게 동작합니다.
  - **직접 설정한 사용자만**에서는, 휴대폰 번호가 마스킹된 상태로 제공됩니다. 사용자가 이를 선택하거나 유일한 주요 요소일 경우, Logto가 해당 번호로 인증 코드를 전송하고, 사용자가 코드를 입력하면 SMS MFA가 설정됩니다.

아래는 세 가지 일반적인 SMS MFA 바인딩 시나리오입니다.

## SMS MFA 인증 흐름 \{#sms-mfa-verification-flows}

SMS MFA가 활성화된 사용자가 로그인할 때, 1차 인증(1FA)을 성공적으로 완료한 후, 두 번째 인증 요소(2FA)로 SMS 인증 코드를 입력하라는 프롬프트가 표시됩니다.

여러 MFA 요소가 있을 경우, Logto는 [MFA 설정](/end-user-flows/mfa/configure-mfa#mfa-verification-flow)에 명시된 고정 순서(패스키, 인증기 앱 OTP, SMS 인증 코드, 이메일 인증 코드, 백업 코드)에 따라 우선순위가 가장 높은 요소를 바로 엽니다. 인증기 앱 OTP 등 다른 요소가 먼저 표시될 경우, 사용자는 **다른 인증 방법 시도**를 클릭해 선택 목록을 열고 SMS 인증 코드를 선택할 수 있습니다.

**예시:**

## 오류 처리 \{#error-handling}

1. **휴대폰 번호 미연결**

   - 오류 코드: `session.mfa.mfa_factor_not_enabled`
   - 처리: 사용자가 먼저 휴대폰 번호를 연결하도록 안내

2. **잘못된 인증 코드**

   - 오류 코드: `verification_code.code_mismatch`
   - 처리: 재입력 안내, 재시도 횟수 제한

3. **인증 코드 만료**

   - 오류 코드: `verification_code.expired`
   - 처리: 새 인증 코드 요청 안내

4. **발송 속도 제한 초과**
   - 오류 코드: `request.message_rate_limited`(Logto 수신자별 발송 속도 제한) 또는 `connector.rate_limit_exceeded`(SMS 커넥터 속도 제한)
   - 처리: 대기 시간 안내, 재전송 제한
