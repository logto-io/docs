## 사전 준비 사항 \{#prerequisites}

- [Logto Cloud](https://cloud.logto.io) (또는 자체 호스팅) 테넌트
- Node.js >= 20 환경

### 아키텍처 이해하기 \{#understanding-the-architecture}

- **MCP 서버**: MCP 클라이언트에게 도구와 리소스를 제공하는 서버입니다. [최신 MCP 명세](https://modelcontextprotocol.io/specification/latest/basic/authorization)에 따라, Logto에서 발급한 액세스 토큰 (Access token)을 검증하는 OAuth 2.0 리소스 서버 역할을 합니다.
- **MCP 클라이언트**: 인증 (Authentication) 플로우를 시작하고 통합을 테스트하는 데 사용되는 클라이언트입니다. {<b>{props.isThirdParty ? '이 가이드에서는 서드파티 AI 에이전트를 클라이언트로 사용합니다.' : "이 가이드에서는 VS Code (내장 MCP 지원)를 클라이언트로 사용합니다."}</b>}
- **Logto**: OpenID Connect 제공자 (인가 (Authorization) 서버)로서, 사용자 아이덴티티를 관리하고 MCP 서버를 위한 대상 (Audience) 바인딩된 JWT 액세스 토큰 (Access token)을 발급합니다.

비공식 시퀀스 다이어그램은 전체 프로세스의 흐름을 보여줍니다:

<Mermaid value={`sequenceDiagram
    participant Client as MCP 클라이언트<br/>${props.isThirdParty ? '(서드파티 AI 에이전트)' : '(VS Code)'}
    participant Server as MCP 서버<br/>(리소스 서버)
    participant Logto as Logto<br/>(인가 (Authorization) 서버)

    Client->>Server: MCP 요청 (토큰 없음)
    Server->>Client: 401 인가되지 않음 (WWW-Authenticate)
    Client->>Server: 보호된 리소스 메타데이터 가져오기<br/>(/.well-known/oauth-protected-resource)
    Server->>Client: 인가 (Authorization) 서버 정보가 포함된 메타데이터 반환
    Client->>Logto: 인가 (Authorization) 서버 메타데이터 가져오기
    Logto->>Client: OpenID Connect 구성 반환
    Client->>Logto: 인증 (Authentication)을 위해 Logto로 리디렉션
    Logto->>Logto: 사용자가 인증 (Authentication)
    ${props.isThirdParty ? 'Logto->>Logto: 사용자가 서드파티 AI 에이전트에<br/>스코프 동의 (consent)' : ''}
    Logto->>Client: 인가 코드와 함께 다시 리디렉션
    Client->>Logto: 코드로 액세스 토큰 (Access token) 교환<br/>(resource 파라미터 포함)
    Logto->>Client: 액세스 토큰 (JWT, 대상 바인딩) 반환
    Client->>Server: 액세스 토큰 (Access token)과 함께 MCP 요청
    Server->>Server: Logto의 JWKS로 액세스 토큰 (Access token) 검증<br/>(서명, 발급자, 대상, 만료)
    Server->>Client: 도구 응답 반환`}

/>

:::note
