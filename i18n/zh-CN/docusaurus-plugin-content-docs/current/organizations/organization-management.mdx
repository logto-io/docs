# 管理组织 (Organization)

本节介绍开发者如何通过 Logto Console 或 Logto Management API 管理他们的组织 (Organization)，而不是组织管理员如何在你的应用内自助管理成员。要了解如何开发你的组织体验，请查阅[本指南](/end-user-flows/organization-experience/organization-management)。

## 通过 Logto Console 管理 \{#manage-via-logto-console}

### 创建组织 (Organization) \{#create-an-organization}

导航至 <CloudLink to="/organizations">Console > Organizations</CloudLink> 并点击“创建组织 (Organization)”按钮。

### 基本设置 \{#basic-settings}

你可以配置组织 (Organization) 的基本属性，如名称、描述、Logo、自定义数据等。

### 要求组织成员启用多因素认证 (MFA) \{#require-mfa-for-organization-members}

你可以要求组织 (Organization) 的所有成员启用多因素认证 (MFA)。这是一个安全措施，确保所有成员在访问组织资源时有额外的保护层。

要启用此功能，请进入组织详情页并打开“多因素认证 (MFA)”开关。

:::note

你需要[至少启用一种 MFA 方式](/end-user-flows/mfa)才能使此功能正常工作。

:::

启用后，未配置 MFA 的成员在设置 MFA 之前将无法交换组织令牌。关于组织令牌何时被交换的更多细节，请参阅[授权 (Authorization)](/authorization)。

请注意：

- 此功能仅在交换组织令牌时检查用户是否已配置 MFA（`isMfaRequired`）。登录时的 MFA 提示由租户的 MFA 策略控制：在**可选 MFA**下，将**组织启用 MFA 后提示用户设置 MFA**设置为**下次登录时要求用户设置 MFA（不可跳过）**。当租户级别启用**自适应 MFA**时，Console 会隐藏该组织提示设置，并且对于未触发风险规则的低风险登录，即使是要求 MFA 的组织成员也不会被要求进行 MFA 验证。
- 此功能不会强制用户在交换访问令牌时验证 MFA。
- 此功能不限制用户可以使用哪些 MFA 方式。

### 即时 (Just-in-Time) 供应 \{#just-in-time-provisioning}

[即时 (Just-in-Time) 供应](https://auth.wiki/jit-provisioning)会在用户首次登录应用时自动将其添加到组织 (Organization)。在 Logto 中，这一功能支持[企业单点登录 (SSO)](/end-user-flows/enterprise-sso)和基于邮箱域名的供应。当用户满足特定条件（如通过特定企业 IdP 登录或使用特定域名的邮箱）时，他们会被自动加入组织。

你还可以为首次加入组织的成员设置默认的组织角色 (Role)。

关于即时 (Just-in-Time) 供应的更多细节及设置方法，请参阅[本节](/organizations/just-in-time-provisioning)。

### 管理组织成员 \{#manage-organization-members}

用户可以拥有一个或多个角色 (Role)。在向组织 (Organization) 添加成员时，你可以为多个用户分配角色 (Role)。如果不分配，新增用户将不会获得任何角色 (Role)。

在 <CloudLink to="/users">Console > 用户管理 > 用户详情页</CloudLink>，你可以查看用户属于哪些组织 (Organization) 以及他们拥有的组织角色 (Role)。

### 管理组织 M2M 应用程序 \{#manage-organization-m2m-applications}

机器对机器 (M2M) 应用程序也可以被添加到组织 (Organization)。你可以像为用户分配角色 (Role) 一样，[为机器对机器应用程序分配角色 (Role)](/organizations/understand-how-organizations-work#organization-m2m-application)。

在 <CloudLink to="/applications">Console > 应用程序 > 应用详情页</CloudLink>，你可以查看该应用关联了哪些组织 (Organization) 以及拥有的组织角色 (Role)。

## 通过 Logto Management API 管理 \{#manage-via-logto-management-api}

你在 Logto Console 能做的所有操作，也都可以通过 [Management API](/integrate-logto/interact-with-management-api) 完成，包括但不限于：

1. 创建、删除或编辑组织 (Organization)。
2. 管理组织模板：创建、删除或编辑组织权限 (Permission) 和角色 (Role)。
3. 向组织 (Organization) 添加或移除成员。
4. 分配或移除用户的组织角色 (Role)。
5. 向组织 (Organization) 添加或移除机器对机器应用程序。
6. 分配或移除机器对机器应用程序的组织角色 (Role)。

你还可以查阅本节，了解如何使用 Management API 实现更多组织级体验和管理。[了解更多](/end-user-flows/organization-experience)

完整能力列表请参阅我们的 [API 参考文档](https://openapi.logto.io/group/endpoint-organizations)。

## 组织数据结构 \{#organization-data-structure}

对于每个组织 (Organization)，Logto 会存储以下数据：

### 组织 ID \{#organization-id}

_organization id_ 是每个组织 (Organization) 的唯一标识符。它对于实现组织级登录体验和获取组织令牌非常有用。

### 名称 \{#name}

_name_ 支持组织级登录，并可根据需要集成到组织级产品界面中。

### 描述 \{#description}

_description_ 字段允许你添加文本以帮助识别和标记组织 (Organization)。

### 组织 Logo \{#organization-logos}

为了在登录体验中动态展示客户组织 (Organization) 的 Logo，你可以在组织设置页上传组织 Logo。

详见[组织特定 Logo](/customization/match-your-brand/#organization-specific-branding)。

### 自定义数据 \{#custom-data}

_custom data_ 是一个 JSON 对象，用于存储关于组织 (Organization) 的额外信息。你可以用它存储任何与你的应用相关的附加信息，如组织特定设置或元数据。

### 是否要求 MFA \{#is-mfa-required}

_isMfaRequired_ 表示组织 (Organization) 是否要求其成员在交换组织令牌前已配置 MFA。如果设置为 `true`，Logto 会拒绝为未启用 MFA 的成员颁发组织令牌。对于这些成员的登录 MFA 强制策略由租户的 `organizationRequiredMfaPolicy` 单独控制。

详见[管理组织](/organizations/organization-management#require-mfa-for-organization-members)。

### 创建时间 \{#created-at}

_createdAt_ 是组织 (Organization) 创建时带有时区的时间戳。

### 租户 ID \{#tenant-id}

_tenantId_ 标识该组织 (Organization) 所属的租户。
