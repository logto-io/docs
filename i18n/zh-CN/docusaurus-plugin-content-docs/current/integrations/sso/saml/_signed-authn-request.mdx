默认情况下，Logto 发送的 SAML 认证请求 (AuthnRequests) 是未签名的。如果你的身份提供商 (IdP) 要求认证请求必须签名，Logto 可以使用生成的服务提供者 (SP) 证书对其进行签名。签名完全由连接器的 **签名认证请求 (Sign authentication request)** 设置控制 —— Logto 不会读取 IdP 元数据中的 `WantAuthnRequestsSigned` 标志。

请按以下顺序设置，以避免登录中断：

1. 在连接器的 `Connection` 选项卡中，找到 **请求签名证书 (Request signing certificate)** 部分并点击 **生成新密钥 (Generate new key)**。第一个密钥会自动激活；之后生成的密钥会作为非激活状态用于轮换。
2. 下载激活密钥的证书，并在你的 IdP 上注册。
3. 启用 **签名认证请求 (Sign authentication request)** 并保存。启用时必须有一个激活的签名密钥 —— 没有激活密钥时保存会被拒绝。
4. 如果你的 IdP 有单独的选项来要求或验证签名请求，请现在开启，然后测试登录流程。

:::warning
保持双方同步。在证书注册之前启用 **签名认证请求 (Sign authentication request)** —— 或在 Logto 签名之前在 IdP 端要求验证 —— 都会导致该连接的登录中断，直到另一方跟进。未验证请求签名的 IdP 会直接忽略签名。
:::

密钥管理与开关独立运作：

- 最多只能有一个密钥为 **激活** 状态，激活密钥会为每个请求签名。密钥操作（生成、激活、停用、删除）会立即生效。
- 若要无停机轮换证书：生成新密钥（作为非激活状态），在 IdP 注册其证书，然后激活它 —— 之前的密钥会自动停用，之后可以删除。
- 激活密钥无法被删除，并且在启用 **签名认证请求 (Sign authentication request)** 时无法停用 —— 需先关闭签名功能。
- 关闭开关不会删除任何密钥，因此重新启用时会继续使用同一证书进行签名 —— 无需在 IdP 端重新配置。

Logto 默认使用 RSA-SHA256 对请求进行签名。如需使用 RSA-SHA512，可在连接器配置中通过 Logto Management API 将 `requestSignatureAlgorithm` 设置为 `http://www.w3.org/2001/04/xmldsig-more#rsa-sha512`。
