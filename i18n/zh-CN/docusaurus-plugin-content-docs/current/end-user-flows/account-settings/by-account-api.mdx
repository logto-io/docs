# 通过 Account API 进行账户设置

## 什么是 Logto Account API \{#what-is-logto-account-api}

Logto Account API 是一套全面的 API，允许终端用户直接通过 API 访问，无需经过 Management API。主要亮点如下：

- 直接访问：Account API 让终端用户可以直接访问和管理自己的账户资料，无需通过 Management API 中转。
- 用户资料与身份管理：用户可以管理自己的资料和安全设置，包括邮箱、手机号、密码、社交连接和多因素认证 (MFA) 因素，还可以从 Secret Vault 获取企业单点登录 (SSO) 联邦访问令牌。
- 全局访问控制：管理员拥有对访问设置的完全全局控制，并可自定义每个字段。
- 无缝授权 (Authorization)：授权 (Authorization) 变得前所未有的简单！只需使用 `client.getAccessToken()` 获取 OP (Logto) 的不透明令牌 (Opaque token)，并将其作为 `Bearer <access_token>` 附加到 Authorization 头部即可。

通过 Logto Account API，你可以构建一个与 Logto 完全集成的自定义账户管理系统，比如个人资料页面。

常见的使用场景包括：

- 获取用户资料
- 更新用户资料
- 更新用户密码
- 更新用户身份信息，包括邮箱、手机号和社交连接
- 管理多因素认证 (MFA) 因素（验证方式）
- 管理用户会话
- 管理用户授权应用（授权 (Authorization)）

想了解更多可用 API，请访问 [Logto Account API 参考文档](https://openapi.logto.io/group/endpoint-my-account) 和 [Logto Verification API 参考文档](https://openapi.logto.io/group/endpoint-verifications)。

:::note

SSO 账户查看和账户删除功能目前通过 Logto Management API 提供（Account API 不支持企业 SSO 身份的绑定或解绑，仅支持获取已绑定 SSO 身份的 Secret Vault 令牌）。具体实现细节请参见 [通过 Management API 进行账户设置](/end-user-flows/account-settings/by-management-api)。

:::

## 如何启用 Account API \{#how-to-enable-account-api}

前往 <CloudLink to="/sign-in-experience/account-center">控制台 > 登录与账户 > 账户中心</CloudLink>。

Account API 默认关闭，因此其访问控制是锁定的。切换 **启用 Account API** 开关即可开启。

启用后，可以配置 **近期认证 (Authentication)** 窗口（1 到 120 分钟，默认 10 分钟），以及标识符、资料数据和第三方令牌访问的每字段权限。每个字段支持 `关闭`、`只读` 或 `可编辑`，默认是 `关闭`。

1. **安全字段**：
   - 包括：主邮箱、主手机号、社交身份、密码、Passkey、多因素认证 (MFA)、个人访问令牌。
   - 敏感操作需要来自一方应用的近期用户认证 (Authentication) —— 访问令牌的 `acr` 满足 `urn:logto:acr:1fa`，且在配置的近期认证 (Authentication) 窗口内（详见 [OIDC 提升认证 (Authentication)](/end-user-flows/step-up-authentication#account-api-and-account-center)）。
   - 若要使用 WebAuthn Passkey 作为 MFA，请将前端应用域名添加到 **WebAuthn 相关来源**，以便账户中心和登录体验共享 Passkey。详见 [绑定新的 WebAuthn Passkey](#link-a-new-webauthn-passkey)。
2. **资料字段**：
   - 包括：用户名、姓名、头像、[profile](/user-management/user-data#profile)（其他标准资料属性）和 [自定义数据](/user-management/user-data#custom-data)。
   - 终端用户可直接编辑，`username` 字段除外，也需要近期用户认证 (Authentication)。
3. **Secret Vault**：
   - 对于 OIDC 或 OAuth 社交和企业连接器，Logto [Secret Vault](/secret-vault/federated-token-set) 会在认证 (Authentication) 后安全存储第三方访问令牌和刷新令牌。应用可调用外部 API（如同步 Google 日历事件），无需再次提示用户登录。启用 Account API 后，令牌获取功能自动开放。
4. **会话管理**：
   - 启用后，用户可查看和管理活跃会话，包括设备信息和上次登录时间。用户还可撤销会话，从特定设备登出。
   - 同一个 `Sessions` 字段权限也控制用户授权应用（授权 (Authorization)）API（查看和撤销授权 (Authorization)）。
   - 访问会话和授权 (Authorization) 管理需要与安全字段相同的近期用户认证 (Authentication)。

## 如何访问 Account API \{#how-to-access-account-api}

:::note
为确保访问令牌拥有合适的权限，请在 Logto 配置中正确设置对应的权限 (Scopes)。

例如，调用 `POST /api/my-account/primary-email` API 时，需要配置 `email` 权限；调用 `POST /api/my-account/primary-phone` API 时，需要配置 `phone` 权限。

```ts
import { type LogtoConfig, UserScope } from '@logto/js';

const config: LogtoConfig = {
  // ...其他选项
  // 添加适合你用例的权限 (Scopes)。
  scopes: [
    UserScope.Email, // 用于 `{POST,DELETE} /api/my-account/primary-email` API
    UserScope.Phone, // 用于 `{POST,DELETE} /api/my-account/primary-phone` API
    UserScope.CustomData, // 管理自定义数据
    UserScope.Address, // 管理地址
    UserScope.Identities, // 用于身份和 MFA 相关 API
    UserScope.Profile, // 管理用户资料
    UserScope.Sessions, // 管理用户会话和应用授权 (Authorization)
  ],
};
```

:::

### 获取访问令牌 \{#fetch-an-access-token}

在应用中配置好 SDK 后，可以使用 `client.getAccessToken()` 方法获取访问令牌。该令牌是不透明令牌 (Opaque token)，可用于访问 Account API。

如果你未使用官方 SDK，请在访问令牌授权 (Authorization) 请求 `/oidc/token` 时将 `resource` 设为空。

### 使用访问令牌访问 Account API \{#access-account-api-using-access-token}

与 Account API 交互时，应将访问令牌以 Bearer 格式（`Bearer YOUR_TOKEN`）放在 HTTP 头部的 `Authorization` 字段中。

以下是获取用户账户信息的示例：

```bash
curl https://[tenant-id].logto.app/api/my-account \
  -H 'authorization: Bearer <access_token>'
```

## 管理基础账户信息 \{#manage-basic-account-information}

### 获取用户账户信息 \{#retrieve-user-account-information}

要获取用户数据，可以使用 [`GET /api/my-account`](https://openapi.logto.io/operation/operation-getprofile) 接口。

```bash
curl https://[tenant-id].logto.app/api/my-account \
  -H 'authorization: Bearer <access_token>'
```

响应体示例：

```json
{
  "id": "...",
  "username": "...",
  "name": "...",
  "avatar": "..."
}
```

响应字段可能会根据账户中心设置有所不同。

### 更新基础账户信息 \{#update-basic-account-information}

基础账户信息包括用户名、姓名、头像、自定义数据及其他资料信息。

要更新 **username、name、avatar 和 customData**，可使用 [`PATCH /api/my-account`](https://openapi.logto.io/operation/operation-updateprofile) 接口。

```bash
curl -X PATCH https://[tenant-id].logto.app/api/my-account \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"username":"...","name":"...","avatar":"..."}'
```

要更新其他资料信息，包括 **familyName、givenName、middleName、nickname、profile（个人主页 URL）、website、gender、birthdate、zoneinfo、locale 和 address**，可使用 [`PATCH /api/my-account/profile`](https://openapi.logto.io/operation/operation-updateotherprofile) 接口。

```bash
curl -X PATCH https://[tenant-id].logto.app/api/my-account/profile \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"familyName":"...","givenName":"..."}'
```

## 管理标识符及其他敏感信息 \{#manage-identifiers-and-other-sensitive-information}

出于安全考虑，敏感的 Account API 操作需要来自一方应用的近期用户认证 (Authentication)：访问令牌必须携带 `acr` 满足 `urn:logto:acr:1fa`，且 `auth_time` 在租户的 **近期认证 (Authentication)** 窗口内（默认 600 秒 / 10 分钟，可配置为 60 到 7,200 秒）。

当访问令牌缺少 `urn:logto:acr:1fa` 或已超出窗口时，Account API 会返回 `401 Unauthorized`，并带有 RFC 9470 `WWW-Authenticate` 头（`error="insufficient_user_authentication"`，`acr_values="urn:logto:acr:1fa"`，`max_age="<window>"`）。请使用这些参数发起一次 [OIDC 提升认证 (Authentication)](/end-user-flows/step-up-authentication#account-api-and-account-center) 请求，并用新颁发的访问令牌重试调用。

:::note
绑定**新**邮箱、手机号、社交身份或 WebAuthn Passkey 时，也需要通过 Verification API 验证新标识符或因素的所有权，并在请求体中传递 `newIdentifierVerificationRecordId`，具体见下方各节。
:::

### 更新用户密码 \{#update-users-password}

要更新用户密码，可使用 [`POST /api/my-account/password`](https://openapi.logto.io/operation/operation-updatepassword) 接口。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/password \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"password":"..."}'
```

:::tip
与注册时设置密码一样，通过 Account API 设置的密码也必须符合你在 <CloudLink to="/security/password-policy">控制台 > 安全 > 密码策略</CloudLink> 中配置的 [密码策略](/security/password-policy)。Logto 会返回详细的校验结果和错误信息。
:::

### 更新或绑定新邮箱 \{#update-or-link-new-email}

:::note
使用此方法前，请先[配置邮箱连接器](/connectors/email-connectors/)，并确保已配置 `BindNewIdentifier` 模板。
:::

要更新或绑定新邮箱，需先证明邮箱所有权。

调用 [`POST /api/verifications/verification-code`](https://openapi.logto.io/operation/operation-createverificationbyverificationcode) 接口请求验证码。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/verification-code \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"identifier":{"type":"email","value":"..."}}'
```

你将在响应中获得 `verificationId`，并在邮箱中收到验证码，使用验证码进行验证。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/verification-code/verify \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"identifier":{"type":"email","value":"..."},"verificationId":"...","code":"..."}'
```

验证码验证通过后，可调用 [`PATCH /api/my-account/primary-email`](https://openapi.logto.io/operation/operation-updateprimaryemail) 更新用户邮箱，将 `verificationId` 作为 `newIdentifierVerificationRecordId` 放入请求体。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/primary-email \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"email":"...","newIdentifierVerificationRecordId":"<verification_record_id_from_new_email>"}'
```

:::tip
与注册时收集的邮箱一样，通过 Account API 绑定的邮箱也必须通过你在 <CloudLink to="/security/blocklist">控制台 > 安全 > 黑名单</CloudLink> 配置的 [黑名单](/security/blocklist) 校验。若邮箱违反策略，Logto 会拒绝请求并返回详细错误。
:::

### 移除用户邮箱 \{#remove-the-users-email}

要移除用户邮箱，可使用 [`DELETE /api/my-account/primary-email`](https://openapi.logto.io/operation/operation-deleteprimaryemail) 接口。

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/primary-email \
  -H 'authorization: Bearer <access_token>'
```

### 管理手机号 \{#manage-phone}

:::note
使用此方法前，请先[配置短信连接器](/connectors/sms-connectors/)，并确保已配置 `BindNewIdentifier` 模板。
:::

与更新邮箱类似，可使用 [`PATCH /api/my-account/primary-phone`](https://openapi.logto.io/operation/operation-updateprimaryphone) 接口更新或绑定新手机号。使用 [`DELETE /api/my-account/primary-phone`](https://openapi.logto.io/operation/operation-deleteprimaryphone) 接口移除用户手机号。

### 绑定新的社交连接 \{#link-a-new-social-connection}

要绑定新的社交连接，首先需通过 [`POST /api/verifications/social`](https://openapi.logto.io/operation/operation-createverificationbysocial) 请求授权 (Authorization) URL。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/social \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"connectorId":"...","redirectUri":"...","state":"..."}'
```

- `connectorId`： [社交连接器](/connectors/social-connectors/) 的 ID。
- `redirectUri`：用户授权 (Authorization) 应用后的回调地址，你需在此 URL 上托管网页并捕获回调。
- `state`：用户授权 (Authorization) 应用后返回的状态，是用于防止 CSRF 攻击的随机字符串。

响应中会有 `verificationRecordId`，请保存以备后用。

用户授权 (Authorization) 应用后，你会在 `redirectUri` 收到带有 `state` 参数的回调。然后可使用 [`POST /api/verifications/social/verify`](https://openapi.logto.io/operation/operation-verifyverificationbysocial) 接口验证社交连接。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/social/verify \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"connectorData":"...","verificationRecordId":"..."}'
```

`connectorData` 是用户授权 (Authorization) 应用后社交连接器返回的数据，你需在回调页面解析 `redirectUri` 的查询参数，并将其包装为 JSON 作为 `connectorData` 字段的值。

最后，可使用 [`POST /api/my-account/identities`](https://openapi.logto.io/operation/operation-adduseridentities) 接口绑定社交连接。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/identities \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"newIdentifierVerificationRecordId":"<verification_record_id_from_social>"}'
```

### 移除社交连接 \{#remove-a-social-connection}

要移除社交连接，可使用 [`DELETE /api/my-account/identities`](https://openapi.logto.io/operation/operation-deleteidentity) 接口。

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/identities/[connector_target_id] \
  -H 'authorization: Bearer <access_token>'
```

### 绑定新的 WebAuthn Passkey \{#link-a-new-webauthn-passkey}

:::note
请先[启用 MFA 和 WebAuthn](/end-user-flows/mfa)。
:::

:::note
WebAuthn Passkey 写入接口（`POST /api/my-account/mfa-verifications`，`type: "WebAuthn"`，`PATCH /api/my-account/mfa-verifications/{verificationId}/name`，以及 `DELETE /api/my-account/mfa-verifications/{verificationId}`）受账户中心设置中的 `passkey` 字段控制，若未设置则回退到 `mfa`。读取 `GET /api/my-account/mfa-verifications` 需将 `mfa` 设为 `只读` 或 `可编辑`。
:::

**步骤 1：将前端应用域名添加到相关来源**

WebAuthn Passkey 绑定到特定主机名（RP ID）。只有托管在 RP ID 来源的应用才能注册或认证 (Authentication) 这些 Passkey。

由于你的前端应用与 Logto 认证 (Authentication) 页面域名不同，需配置 **相关来源** 以允许跨域 Passkey 操作。

**Logto 如何确定 RP ID：**

- **默认设置**：仅使用 Logto 默认域名 `https://[tenant-id].logto.app` 时，RP ID 为 `[tenant-id].logto.app`
- **自定义域名**：如配置了 [自定义域名](/logto-cloud/custom-domain) `https://auth.example.com`，RP ID 为 `auth.example.com`

**配置相关来源：**

使用 [`PATCH /api/account-center`](https://openapi.logto.io/operation/operation-updateaccountcentersettings) 接口添加前端应用的来源。例如，账户中心运行在 `https://account.example.com`：

```bash
curl -X PATCH https://[tenant-id].logto.app/api/account-center \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"webauthnRelatedOrigins":["https://account.example.com"]}'
```

:::note

WebAuthn 最多支持 5 个唯一 eTLD+1 标签作为相关来源。eTLD+1（有效顶级域加一级标签）是可注册域名部分。例如：

- `https://example.com`、`https://app.example.com`、`https://auth.example.com` 算作**一个**标签（`example.com`）
- `https://shopping.com`、`https://shopping.co.uk`、`https://shopping.co.jp` 也算作**一个**标签（`shopping`）
- `https://example.com` 和 `https://another.com` 算作**两个**标签

如需支持超过 5 个不同域名作为相关来源，请参考 [Related Origin Requests](https://passkeys.dev/docs/advanced/related-origins/) 文档。

:::

**步骤 2：请求新的注册选项**

使用 [`POST /api/verifications/web-authn/registration`](https://openapi.logto.io/operation/operation-generatewebauthnregistrationoptions) 接口请求注册新 Passkey。Logto 允许每个账户注册多个 Passkey。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/web-authn/registration \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

你会收到如下响应：

```json
{
  "registrationOptions": "...",
  "verificationRecordId": "...",
  "expiresAt": "..."
}
```

**步骤 3：在本地浏览器注册 Passkey**

以 [`@simplewebauthn/browser`](https://simplewebauthn.dev/) 为例，可用 `startRegistration` 方法在本地浏览器注册 Passkey。

```ts
import { startRegistration } from '@simplewebauthn/browser';

// ...
const response = await startRegistration({
  optionsJSON: registrationOptions, // 第 1 步服务器返回的数据
});
// 保存 response 以备后用
```

**步骤 4：验证 Passkey 注册**

使用 [`POST /api/verifications/web-authn/registration/verify`](https://openapi.logto.io/operation/operation-verifywebauthnregistration) 接口验证 Passkey 注册。

此步骤会验证认证器生成的加密签名，确保 Passkey 合法创建且传输过程中未被篡改。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/web-authn/registration/verify \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"payload":"...","verificationRecordId":"..."}'
```

- `payload`：第 2 步本地浏览器返回的响应。
- `verificationRecordId`：第 1 步服务器返回的验证记录 ID。

**步骤 5：绑定 Passkey**

最后，可通过 [`POST /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-addmfaverification) 接口将 Passkey 绑定到用户账户。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"type":"WebAuthn","newIdentifierVerificationRecordId":"..."}'
```

- `type`：MFA 因素类型（`WebAuthn`、`Totp` 或 `BackupCode`，此处用 `WebAuthn`）。
- `newIdentifierVerificationRecordId`：第 2 步服务器返回的验证记录 ID。

### 管理已有 WebAuthn Passkey \{#manage-existing-webauthn-passkeys}

要管理已有 WebAuthn Passkey，可使用 [`GET /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-getmfaverifications) 接口获取当前 Passkey 及其他 MFA 验证因素。

```bash
curl https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>'
```

响应体示例：

```json
[
  {
    "id": "...",
    "type": "WebAuthn",
    "name": "...",
    "agent": "...",
    "createdAt": "...",
    "lastUsedAt": "..."
  }
]
```

- `id`：验证记录 ID。
- `type`：验证类型（`WebAuthn`、`Totp`、`BackupCode`、`EmailVerificationCode` 或 `PhoneVerificationCode`）。仅当用户[设置了邮箱或短信 MFA](#manage-email-and-sms-mfa) 时，才会列出 `EmailVerificationCode` 和 `PhoneVerificationCode`。
- `name`：Passkey 名称，可选字段（`WebAuthn`）。
- `agent`：Passkey 的 user agent（`WebAuthn`）。
- `createdAt`：验证创建时间戳。
- `lastUsedAt`：验证最后使用时间戳，可选字段（`WebAuthn`）。
- `remainCodes`：剩余未用备份码数量，可选字段（`BackupCode`）。

通过 [`PATCH /api/my-account/mfa-verifications/{verificationId}/name`](https://openapi.logto.io/operation/operation-updatemfaverificationname) 接口更新 Passkey 名称：

```bash
curl -X PATCH https://[tenant-id].logto.app/api/my-account/mfa-verifications/{verificationId}/name \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"name":"..."}'
```

通过 [`DELETE /api/my-account/mfa-verifications/{verificationId}`](https://openapi.logto.io/operation/operation-deletemfaverification) 接口删除 Passkey：

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/mfa-verifications/{verificationId} \
  -H 'authorization: Bearer <access_token>'
```

### 绑定新的 TOTP \{#link-a-new-totp}

:::note
请先[启用 MFA 和 TOTP](/end-user-flows/mfa)。
:::

:::note
使用此方法需在[账户中心设置](#how-to-enable-account-api)中启用 `mfa` 字段。
:::

**步骤 1：生成 TOTP 密钥**

使用 [`POST /api/my-account/mfa-verifications/totp-secret/generate`](https://openapi.logto.io/operation/operation-generatetotpsecret) 接口生成 TOTP 密钥。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications/totp-secret/generate \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

响应体示例：

```json
{
  "secret": "..."
}
```

**步骤 2：向用户展示 TOTP 密钥**

用密钥生成二维码或直接展示给用户。用户应将其添加到自己的认证器应用（如 Google Authenticator、Microsoft Authenticator 或 Authy）。

二维码的 URI 格式为：

```
otpauth://totp/[Issuer]:[Account]?secret=[Secret]&issuer=[Issuer]
```

示例：

```
otpauth://totp/YourApp:user@example.com?secret=JBSWY3DPEHPK3PXP&issuer=YourApp
```

**步骤 3：绑定 TOTP 因素**

用户将密钥添加到认证器应用后，需要验证并绑定到账户。使用 [`POST /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-addmfaverification) 接口绑定 TOTP 因素。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"type":"Totp","secret":"..."}'
```

- `type`：必须为 `Totp`。
- `secret`：第 1 步生成的 TOTP 密钥。

:::note
每个用户只能有一个 TOTP 因素。如已存在 TOTP 因素，重复添加会返回 422 错误。
:::

### 替换已有 TOTP \{#replace-an-existing-totp}

如用户已配置 TOTP 因素，可通过 [`PUT /api/my-account/mfa-verifications/totp`](https://openapi.logto.io/operation/operation-createorreplacetotpmfaverification) 接口替换为新密钥。此操作幂等，会移除旧 TOTP 并绑定新密钥。

:::note
使用此方法需在[账户中心设置](#how-to-enable-account-api)中启用 `mfa` 字段。
:::

**步骤 1：生成新 TOTP 密钥**

使用 [`POST /api/my-account/mfa-verifications/totp-secret/generate`](https://openapi.logto.io/operation/operation-generatetotpsecret) 接口生成新密钥，并按 [绑定新的 TOTP](#link-a-new-totp) 展示给用户。

**步骤 2：替换 TOTP 因素**

```bash
curl -X PUT https://[tenant-id].logto.app/api/my-account/mfa-verifications/totp \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"secret":"...","code":"..."}'
```

- `secret`：第 1 步生成的新 TOTP 密钥。
- `code`：用新密钥生成的 TOTP 验证码，用于确认绑定。

### 管理邮箱和短信 MFA \{#manage-email-and-sms-mfa}

:::note
请先[启用 MFA 及邮箱或短信验证码因素](/end-user-flows/mfa)。
:::

:::note
使用此方法需在[账户中心设置](#how-to-enable-account-api)中启用 `mfa` 字段。
:::

邮箱和短信 MFA 验证码会发送到用户主邮箱和主手机号。设置因素会记录用户选择了该方式；地址本身通过 [更新或绑定新邮箱](#update-or-link-new-email) 和 [管理手机号](#manage-phone) 管理。

用户是否需要设置这些因素取决于 [邮箱和短信 MFA 注册](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment) 设置。选择 **仅设置的用户** 时，只有设置过的用户可用作 MFA；选择 **所有有已验证邮箱或手机号的用户** 时，设置也会被记录，方便后续切换模式时保留因素。

**设置邮箱或短信 MFA**

使用 [`POST /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-addmfaverification) 接口：

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"type":"EmailVerificationCode"}'
```

- `type`：邮箱 MFA 用 `EmailVerificationCode`，短信 MFA 用 `PhoneVerificationCode`。

:::note

- 邮箱 MFA 需有主邮箱，短信 MFA 需有主手机号，否则请求返回 422 错误。
- 每个用户每种因素只能设置一次，重复设置会返回 422 错误。

:::

**移除邮箱或短信 MFA**

使用 [`GET /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-getmfaverifications) 接口查找 `type` 为 `EmailVerificationCode` 或 `PhoneVerificationCode` 的验证记录，然后用 [`DELETE /api/my-account/mfa-verifications/{verificationId}`](https://openapi.logto.io/operation/operation-deletemfaverification) 接口删除：

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/mfa-verifications/{verificationId} \
  -H 'authorization: Bearer <access_token>'
```

移除因素不会影响用户主邮箱或主手机号。

### 管理备份码 \{#manage-backup-codes}

:::note
请先[启用 MFA 和备份码](/end-user-flows/mfa)。
:::

:::note
使用此方法需在[账户中心设置](#how-to-enable-account-api)中启用 `mfa` 字段。
:::

**步骤 1：生成新备份码**

使用 [`POST /api/my-account/mfa-verifications/backup-codes/generate`](https://openapi.logto.io/operation/operation-generatemyaccountbackupcodes) 接口生成一组新的 10 个备份码。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications/backup-codes/generate \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

响应体示例：

```json
{
  "codes": ["...", "...", "..."]
}
```

**步骤 2：向用户展示备份码**

在绑定备份码前，必须将其展示给用户，并提示：

- 立即下载或抄写这些备份码
- 妥善保管
- 每个备份码只能使用一次
- 这些备份码是丢失主 MFA 方法后的最后保障

建议以清晰、易复制的格式展示，并提供下载选项（如文本文件或 PDF）。

**步骤 3：绑定备份码到用户账户**

使用 [`POST /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-addmfaverification) 接口将备份码绑定到用户账户。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"type":"BackupCode","codes":["...","...","..."]}'
```

- `type`：必须为 `BackupCode`。
- `codes`：上一步生成的备份码数组。

:::note

- 每个用户一次只能有一组备份码。如全部用完，需重新生成并绑定新备份码。
- 备份码不能作为唯一 MFA 因素。用户必须配置认证器应用（`Totp`）或 Passkey（`WebAuthn`）；仅有邮箱或短信验证码不满足要求。
- 每个备份码只能使用一次。

:::

**查看已有备份码**

要查看已有备份码及其使用状态，使用 [`GET /api/my-account/mfa-verifications/backup-codes`](https://openapi.logto.io/operation/operation-getbackupcodes) 接口：

```bash
curl https://[tenant-id].logto.app/api/my-account/mfa-verifications/backup-codes \
  -H 'authorization: Bearer <access_token>'
```

响应体示例：

```json
{
  "codes": [
    {
      "code": "...",
      "usedAt": null
    },
    {
      "code": "...",
      "usedAt": "2024-01-15T10:30:00.000Z"
    }
  ]
}
```

- `code`：备份码。
- `usedAt`：备份码使用时间戳，未使用为 `null`。

### 管理两步验证设置 \{#manage-2-step-verification-settings}

:::note
使用这些方法需在[账户中心设置](#how-to-enable-account-api)中启用 `mfa` 字段。
:::

终端用户可为账户开启或关闭两步验证。常见场景如用户已配置 MFA 因素（如 Passkey），但只想用于登录而非额外验证 —— 关闭两步验证后，登录时可跳过 MFA 提示，同时保留 MFA 因素。该功能由每个用户的 `skipMfaOnSignIn` 设置控制。

**获取当前 MFA 设置**

使用 [`GET /api/my-account/mfa-settings`](https://openapi.logto.io/operation/operation-getmfasettings) 接口获取用户当前两步验证设置。

```bash
curl https://[tenant-id].logto.app/api/my-account/mfa-settings \
  -H 'authorization: Bearer <access_token>'
```

响应体示例：

```json
{
  "skipMfaOnSignIn": false,
  "enabled": true,
  "required": false
}
```

- `skipMfaOnSignIn`：用户是否选择登录时跳过 MFA 验证提示。
- `enabled`（可选）：用户是否启用 MFA 验证（对该字段引入前创建的旧账户为 `undefined`，Logto 在存在可用因素时视为已启用）。
- `required`（只读）：MFA 是否被租户策略（包括**强制**和**自适应 MFA**不可跳过策略）、用户或组织要求，此时 `skipMfaOnSignIn` 和 `enabled: false` 无效。

**更新 MFA 设置**

要启用或关闭两步验证，使用 [`PATCH /api/my-account/mfa-settings`](https://openapi.logto.io/operation/operation-updatemfasettings) 接口。

```bash
curl -X PATCH https://[tenant-id].logto.app/api/my-account/mfa-settings \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"skipMfaOnSignIn":true}'
```

- `skipMfaOnSignIn`：设为 `true` 表示登录时跳过两步验证提示，`false` 表示启用。
- `enabled`（可选）：设为 `true` 或 `false` 更新用户是否启用 MFA 验证。响应会包含更新后的 `skipMfaOnSignIn`、`enabled` 和只读的 `required` 字段。

:::note
`skipMfaOnSignIn` 和 `enabled: false` 仅在 MFA 策略为**可选**且用户或组织未被要求 MFA（通过 `organizationRequiredMfaPolicy`）时生效。如 MFA 为**强制**，或用户/组织被要求 MFA，则两者均被忽略，强制 MFA（`required` 为 `true`）。在**自适应 MFA**下，`required` 也为 `true`，两者被忽略，仅在风险规则触发时提示 MFA 验证。
:::

### 管理用户会话 \{#manage-user-sessions}

**列出活跃会话**

要列出用户活跃会话，可使用 [`GET /api/my-account/sessions`](https://openapi.logto.io/operation/operation-getsessions) 接口。

:::note

- 访问该接口需 `UserScope.Sessions` 权限。
- 账户中心设置中的 `Sessions` 字段需设为 `只读` 或 `可编辑`。

:::

```bash
curl https://[tenant-id].logto.app/api/my-account/sessions \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

**按会话 ID 撤销会话**

要撤销指定会话，使用 [`DELETE /api/my-account/sessions/{sessionId}`](https://openapi.logto.io/operation/operation-deletesessionbyid) 接口。

:::note

- 访问该接口需 `UserScope.Sessions` 权限。
- 账户中心设置中的 `Sessions` 字段需设为 `可编辑`。
  :::

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/sessions/{sessionId} \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

可选查询参数：

- `revokeGrantsTarget`：可选，指定撤销会话时要撤销的授权 (Authorization) 目标。可选值：
  - `all`：撤销该会话下所有授权 (Authorization)。
  - `firstParty`：仅撤销该会话下的一方应用授权 (Authorization)。（推荐大多数场景，撤销自有应用访问，保留第三方应用授权 (Authorization)，提升用户体验。）
  - 未指定：默认行为为撤销不含 `offline_access` 权限的授权 (Authorization)，通常即撤销该会话下的非刷新令牌授权 (Authorization)。

### 管理用户授权应用（授权 (Authorization)）\{manage-user-authorized-apps-grants} \{#manage-user-authorized-apps-grants}

当用户需要在账户设置页面查看和撤销已授权应用时，可使用用户授权应用（授权 (Authorization)）API。

:::note

- 应用授权 (Authorization) API 与会话 API 共享同一权限模型。
- 需 `UserScope.Sessions` 权限。
- 账户中心设置中的 `Sessions` 字段需启用：
  - `只读` 或 `可编辑` 可列出授权 (Authorization)。
  - `可编辑` 可撤销授权 (Authorization)。

:::

**列出当前用户活跃授权 (Authorization)**

要列出当前用户的活跃授权 (Authorization)，使用 [`GET /api/my-account/grants`](https://openapi.logto.io/operation/operation-getgrants) 接口。

```bash
curl https://[tenant-id].logto.app/api/my-account/grants \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

可选查询参数：

- `appType=firstParty`：仅返回一方应用授权 (Authorization)。
- `appType=thirdParty`：仅返回第三方应用授权 (Authorization)。
- 不传 `appType`：返回所有活跃授权 (Authorization)。

```bash
curl "https://[tenant-id].logto.app/api/my-account/grants?appType=thirdParty" \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

**按授权 (Authorization) ID 撤销应用授权 (Authorization)**

要撤销指定应用授权 (Authorization)，使用 [`DELETE /api/my-account/grants/{grantId}`](https://openapi.logto.io/operation/operation-deletegrantbyid) 接口。

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/grants/{grantId} \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

撤销授权 (Authorization) 后，该授权 (Authorization) 下已颁发的不透明令牌 (Opaque token) 和刷新令牌 (Refresh token) 均会失效。
