# 密码钥匙（Passkeys，WebAuthn）

[密码钥匙（Passkey）](https://auth.wiki/passkey) 为传统密码提供了一种更安全且用户友好的替代方案。通过使用公钥加密，密码钥匙提升了安全性，将用户设备、服务域名和用户 ID 绑定在一起，有效防止钓鱼和密码攻击。兼容多种设备或浏览器，并允许用户使用生物识别和硬件安全特性实现便捷的认证 (Authentication)。[WebAuthn](https://auth.wiki/webauthn) 提供了 API，使网站能够实现密码钥匙功能。

Logto 支持在 [多因素认证 (MFA)](/end-user-flows/mfa/configure-mfa) 和 [密码钥匙登录](/end-user-flows/sign-up-and-sign-in/passkey-sign-in) 中使用密码钥匙（WebAuthn）。同一个底层 WebAuthn 凭证可以在这两处复用，具体取决于你的租户配置。

## 概念 \{#concepts}

客户通常了解的是密码钥匙（Passkeys），而不是 WebAuthn，那么它们之间是什么关系，如何使用？让我们来探讨这些概念：

- **密码钥匙（Passkeys）**：密码钥匙是一种基于 FIDO、抗钓鱼的凭证，用于替代密码。它利用非对称公钥加密技术提升安全性。可以是硬件令牌或安全密钥，如 USB 或蓝牙设备。由于“密码钥匙”是展示给用户的认证 (Authentication) 方式，建议在你的产品客户端中使用该术语。
- **WebAuthn**：它是由 W3C 和 FIDO 联盟开发的 JavaScript API，使 Web 应用能够采用 FIDO2 标准进行认证 (Authentication)。密码钥匙是 WebAuthn 支持的认证 (Authentication) 方式之一。在 Logto 控制台中，我们专业地将这种集成称为“WebAuthn”。

WebAuthn 为用户提供了多样的认证器选择，分为本地和云端两种类型：

- **平台认证器（内部认证器）**：绑定于单一且特定的设备操作系统，如电脑、笔记本、手机或平板，用户通过这些设备登录。它仅在该设备上通过生物识别或设备密码等方式进行授权，因此认证 (Authentication) 速度很快。例如，macOS 或 iOS 上通过 Touch ID、Face ID 或设备密码验证的 iCloud 钥匙串；Windows Hello 通过人脸识别、指纹或 PIN 验证。
- **漫游认证器（外部认证器，跨平台认证器）**：是独立的便携设备或软件应用，如硬件安全密钥或智能手机。需要通过 USB 连接或保持 NFC、蓝牙开启。漫游认证器不受限于单一设备或浏览器，提供更高的灵活性。

想深入了解 WebAuthn 的原理和流程，可以参考我们的博客：[WebAuthn 和密码钥匙 101](https://blog.logto.io/web-authn-and-passkey-101/) 以及 [集成 WebAuthn 前你应该知道的事](https://blog.logto.io/webauthn-base-knowledge/)。

## 配置密码钥匙用于 MFA 验证 \{#configure-passkeys-verification-for-mfa}

1. 进入 <CloudLink to="/mfa">控制台 > 多因素认证 (MFA)</CloudLink>
2. 启用“密码钥匙（Passkeys，WebAuthn）”因子。建议与其他 MFA 因子（TOTP、短信、备份码）组合使用，减少对单一因子的依赖。
3. 配置你偏好的 MFA 策略（必需或可选）
4. 保存你的配置更改

:::tip
如果同一用户使用 [密码钥匙登录](/end-user-flows/sign-up-and-sign-in/passkey-sign-in)，Logto 会跳过单独的 MFA 验证步骤。密码钥匙登录已满足基于 WebAuthn 的验证要求。
:::

:::note 注意限制

在实现 WebAuthn 时，需注意以下一些限制：

1. **平台和浏览器限制**：Logto 目前不支持原生应用的 WebAuthn。此外，WebAuthn 认证器的可用性取决于浏览器和设备能力（[查看支持列表](https://caniuse.com/?search=webauthn)）。因此，WebAuthn 并不是实现多因素认证 (MFA) 的唯一选项，除非你能控制哪些浏览器和设备可以访问你的产品。
2. **域名限制**：更换域名会阻碍用户通过现有 WebAuthn 账户进行验证。密码钥匙绑定于当前网页的特定域名，不能跨域使用。
3. **设备限制**：丢失设备可能导致用户无法访问账户，尤其是依赖“此设备”平台认证器的用户。为提升认证 (Authentication) 可用性，建议为用户提供多种认证 (Authentication) 因子。

:::

## 配置密码钥匙管理 \{#configure-passkeys-management}

你可以使用 Account API 构建自定义账户管理界面，让用户添加、查看、重命名和移除他们的密码钥匙。这对于打造个性化账户中心和实现跨设备备份场景非常有用。

详细的实现步骤和 API 接口，请参见 [通过 Account API 进行账户设置](/end-user-flows/account-settings/by-account-api#link-a-new-webauthn-passkey)。

## 导出密码钥匙 \{#export-passkeys}

你可以通过 [Management API](/integrate-logto/interact-with-management-api) 导出 Logto 为用户存储的 WebAuthn 凭证。导出后可将密码钥匙迁移到同一域名下支持 WebAuthn 的其他系统，用户即可继续使用现有密码钥匙登录。

调用 [`GET /api/users/{userId}/mfa-verifications`](https://openapi.logto.io/operation/operation-listusermfaverifications) 并将 `includeWebAuthnCredentials` 查询参数设为 `true`：

```bash
curl "https://[tenant-id].logto.app/api/users/{userId}/mfa-verifications?includeWebAuthnCredentials=true" \
  -H 'authorization: Bearer <management-api-access-token>'
```

响应中的每个 WebAuthn 条目都包含存储的凭证：

```json
[
  {
    "id": "wv9m3k2x7p1q",
    "createdAt": "2026-10-12T08:31:24.000Z",
    "lastUsedAt": "2026-11-02T06:15:09.000Z",
    "type": "WebAuthn",
    "agent": "Mozilla/5.0 (Macintosh) ...",
    "name": "MacBook",
    "rpId": "auth.example.com",
    "credentialId": "Ab3dY0n9Kq2LwX8mR4sT1uV6zE",
    "publicKey": "pQECAyYgASFYIOrE5x...",
    "counter": 0,
    "transports": ["internal", "hybrid"]
  }
]
```

| 字段           | 说明                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| `credentialId` | WebAuthn 凭证 ID，base64url 编码。                                            |
| `publicKey`    | COSE 格式的凭证公钥，base64url 编码。                                         |
| `counter`      | Logto 记录的该凭证的最后签名计数（`signCount`）。许多密码钥匙始终报告为 `0`。 |
| `transports`   | 注册时认证器报告的传输方式，如 `internal`、`hybrid` 或 `usb`。                |
| `rpId`         | 注册凭证时的依赖方 ID（域名）。                                               |
| `createdAt`    | 凭证注册时间。                                                                |
| `lastUsedAt`   | 凭证最后一次用于验证用户的时间。                                              |

如果不带 `includeWebAuthnCredentials`，响应将省略 `credentialId`、`publicKey`、`counter`、`transports` 和 `rpId` 字段。其他 MFA 因子保持不变。该参数也适用于只读 Management API 访问，因为凭证 ID 和公钥无法用于登录。

当你将凭证导入到其他系统时：

- **保持相同域名。** 密码钥匙仅适用于注册时的依赖方 ID。其他系统必须使用导出的 `rpId` 作为 WebAuthn 依赖方 ID，即在该域名下提供登录服务，如你的 [自定义域名](/logto-cloud/custom-domain)。
- **处理无 `rpId` 的凭证。** 在 Logto 开始记录依赖方 ID 之前注册且未再次使用的凭证没有 `rpId`。它们绑定于注册时提供登录页面的域名，可能不是你当前的自定义域名。
- **映射用户句柄。** Logto 将 Logto 用户 ID 的 UTF-8 字节注册为 WebAuthn 的 `userHandle`。对于密码钥匙登录，认证器会返回该值，因此其他系统必须将其映射到迁移后的用户。
- **保持计数器。** 将 `counter` 作为凭证当前签名计数器存储，以便其他系统继续检测克隆认证器。

## 密码钥匙设置流程 \{#passkey-setup-flows}

## 密码钥匙验证流程 \{#passkey-verification-flows}

当用户设置了包括密码钥匙在内的多种 MFA 方式时，密码钥匙会因其更高的安全性和便捷性，在首屏作为推荐的 MFA 验证方式展示。用户可点击下方“尝试其他方式验证”切换到其他验证方式。阅读 [配置 MFA](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) 了解更多。

如果用户通过 [密码钥匙登录](/end-user-flows/sign-up-and-sign-in/passkey-sign-in) 完成登录，而不是输入其他第一因子，Logto 不会再要求额外的 MFA 步骤。这是因为密码钥匙本身已被视为 WebAuthn MFA 因子。
