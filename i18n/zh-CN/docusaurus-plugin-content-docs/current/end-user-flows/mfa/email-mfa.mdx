# 用于多因素认证 (MFA) 的邮箱验证

Logto 支持基于邮箱的多因素认证 (MFA) 功能，通过向用户注册邮箱发送一次性验证码来增强账户安全性。邮箱 MFA 作为第二认证 (Authentication) 因子，可以与其他 MFA 因子（如 TOTP、通行密钥、备用验证码）结合，为用户提供灵活的双因素认证 (Authentication) 选项。

## 概念 \{#concepts}

邮箱验证是最普及的 MFA 方法之一。它利用邮箱账户的广泛可用性，将临时的一次性验证码直接发送到用户的邮箱收件箱。与需要额外安装软件的应用认证器不同，邮箱 MFA 利用现有的邮箱基础设施，几乎所有互联网用户都可以通过网页浏览器、邮箱客户端或移动应用访问。这使得邮箱 MFA 对用户来说无需特殊硬件或额外设置，只要有邮箱账户即可立即使用。

## 配置用于 MFA 的邮箱验证 \{#configure-email-verification-for-mfa}

**步骤 1：配置邮箱连接器和模板**

1. 进入 <CloudLink to="/connectors/passwordless">控制台 > 连接器 > 邮箱和短信连接器</CloudLink>
2. 选择合适的邮箱连接器（SendGrid、Mailgun 等）
3. 配置连接参数。
4. 为 MFA 设置 [邮箱模板](/connectors/email-connectors/email-templates) 并指定专用的 usageType：

   - `MfaVerification` 用于 MFA 验证。
   - `BindMfa` 用于绑定 MFA。
   - 提示：[Logto 邮箱服务](/connectors/email-connectors/built-in-email-service) 提供内置邮箱模板。

5. 参考 [邮箱连接器](/connectors/email-connectors) 获取不同服务商的详细配置说明

**步骤 2：启用邮箱 MFA**

1. 进入 <CloudLink to="/mfa">控制台 > 多因素认证 (MFA)</CloudLink>
2. 启用“邮箱验证码”因子。建议将邮箱 MFA 与其他 MFA 因子（TOTP、通行密钥、短信、备用验证码）结合使用，以降低单一因子的依赖。
3. 在 **邮箱/短信两步验证** 中，选择哪些用户拥有邮箱 MFA。详见 [哪些用户有邮箱 MFA](#who-has-email-mfa)。
4. 配置你偏好的 MFA 策略（可选、自适应或强制）
5. 保存配置更改

:::note 重要使用注意事项

1. **登录方式限制**：邮箱验证码不能同时作为 [登录方式 (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in) 和 MFA 因子 (2FA) 使用。每个邮箱实现请选择一种认证 (Authentication) 流程。

2. **注册方式兼容性**：邮箱验证码可以同时用于注册方式和 MFA。Logto 会根据你选择的 MFA 策略优化终端用户注册流程，避免对同一邮箱地址重复要求邮箱验证。

3. **找回密码兼容性**：虽然邮箱验证码可以同时用于 [忘记密码](/end-user-flows/sign-up-and-sign-in/reset-password) 和 MFA，但**不推荐**这样配置。此配置会降低 MFA 的安全性，因为用户可能通过忘记密码邮箱验证重置密码，然后用新密码完成主认证 (1FA)，再用同一邮箱方式进行 MFA 验证，从而绕过 MFA。

:::

## 哪些用户有邮箱 MFA \{#who-has-email-mfa}

邮箱 MFA 验证码始终发送到用户的主邮箱地址。<CloudLink to="/mfa">多因素认证 (MFA)</CloudLink> 页面上的 **邮箱/短信两步验证** 设置决定哪些用户拥有邮箱 MFA：

- **所有有已验证邮箱或手机号的用户**：所有有主邮箱地址的用户都自动拥有邮箱 MFA，无需单独设置。
- **仅设置过的用户**：只有主动设置邮箱 MFA 的用户才拥有邮箱 MFA。用已验证邮箱注册的用户不会自动获得邮箱 MFA，因此你可以将邮箱作为 MFA 选项之一，而无需让每个用户都注册。用户可在 MFA 设置流程、[账户中心](/end-user-flows/account-settings/by-account-center-ui) 或通过 [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa) 设置。管理员可通过 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 为用户添加或移除邮箱 MFA。

该设置同样适用于 [短信 MFA](/end-user-flows/mfa/sms-mfa)。关于默认值及切换模式时的行为，详见 [邮箱和短信 MFA 注册](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment)。

:::note
当选择 **所有有已验证邮箱或手机号的用户** 时，仅因主邮箱地址而拥有邮箱 MFA 的用户不会有存储的邮箱 MFA 记录，因此不会出现在 `GET /api/my-account/mfa-verifications`、`GET /api/users/{userId}/mfa-verifications` 或 `user.mfaVerificationFactors`（自定义 JWT 声明和 `PostSignIn` Actions）中。
:::

## 邮箱 MFA 设置流程 \{#email-mfa-setup-flows}

MFA 设置提示可在用户注册时或登录后出现，具体取决于你配置的 [MFA 策略](/end-user-flows/mfa/configure-mfa#global-mfa-configuration)。

邮箱 MFA 设置流程受以下因素影响：

- **主 MFA 因子数量**：如有多个主因子，用户需选择一个进行配置。主因子指除备用验证码外的 MFA 方法。
- **启用备用验证码**：启用后，主 MFA 因子配置完成后会自动生成备用验证码，并提示用户保存。
- **注册标识符配置**：邮箱地址作为 [注册标识符](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier) 使用，且用户在注册时已通过邮箱验证码验证。
  - 选择 **所有有已验证邮箱或手机号的用户** 时，系统会自动将该邮箱绑定为 MFA 因子，无需再次验证。如有其他主因子，界面会显示“添加另一项两步验证”选项（用户可跳过），同时明确提示 MFA 已启用。
  - 选择 **仅设置过的用户** 时，邮箱与其他因子一样作为选项，地址会被遮掩。当用户选择邮箱，或邮箱是唯一主因子时，Logto 会用注册时的验证直接设置，无需再次发送验证码。
- **已有用户数据**：已有用户登录后设置 MFA，需先完成主认证 (Authentication)，再进行 MFA 设置。如账户已有已验证主邮箱地址：
  - 选择 **所有有已验证邮箱或手机号的用户** 时，设置流程与上述注册标识符场景一致。
  - 选择 **仅设置过的用户** 时，邮箱作为选项显示，地址会被遮掩。当用户选择邮箱，或邮箱是唯一主因子时，Logto 会向该地址发送验证码，用户输入后完成邮箱 MFA 设置。

以下是三种常见邮箱 MFA 绑定场景。

### 场景 1：邮箱地址仅用于 MFA（典型流程） \{#scenario-1-email-address-only-used-for-mfa-typical-flow}

当邮箱地址不是注册标识符，仅用于 MFA 时，按标准设置流程操作：

- 仅有一个邮箱 MFA 因子时，直接显示该因子的设置界面。
- 有多个主 MFA 因子时，显示“MFA 设置”列表页，让用户选择要配置的因子。

## 邮箱 MFA 验证流程 \{#email-mfa-verification-flows}

启用邮箱 MFA 的用户登录时，完成主认证 (Authentication)（1FA）后，会被提示使用邮箱验证码作为第二认证 (Authentication) 因子（2FA）验证身份。

如有多个 MFA 因子，Logto 会根据 [MFA 配置](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) 中指定的固定顺序（通行密钥、认证器应用 OTP、短信验证码、邮箱验证码、备用验证码）直接打开优先级最高的因子。当优先提示如认证器应用 OTP 时，用户可点击 **尝试其他验证方式** 打开选择列表，选择邮箱验证码。

## 错误处理 \{#error-handling}

1. **邮箱地址未绑定**

   - 错误码：`session.mfa.mfa_factor_not_enabled`
   - 处理方式：引导用户先绑定邮箱地址

2. **验证码错误**

   - 错误码：`verification_code.code_mismatch`
   - 处理方式：提示用户重新输入，限制重试次数

3. **验证码已过期**

   - 错误码：`verification_code.expired`
   - 处理方式：提示用户重新获取验证码

4. **发送频率超限**
   - 错误码：`request.message_rate_limited`（Logto 单用户发送频率限制）或 `connector.rate_limit_exceeded`（邮箱连接器频率限制）
   - 处理方式：显示等待时间，限制重复发送
