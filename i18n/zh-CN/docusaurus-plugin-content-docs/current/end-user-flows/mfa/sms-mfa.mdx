# 用于多因素认证 (MFA) 的短信验证

Logto 支持基于短信的多因素认证 (MFA) 功能，通过向用户注册的手机号发送一次性验证码来增强账户安全性。短信 MFA 作为第二认证 (Authentication) 因子，可以与其他 MFA 因子（如 TOTP、通行密钥、备用码）结合，为用户提供灵活的双因素认证 (Authentication) 选项。

## 概念 \{#concepts}

短信验证，也称为手机号验证，是最易用的 MFA 方法之一。它利用手机的普及性，通过短信将临时的一次性验证码直接发送到用户设备。与需要额外安装软件的基于应用的认证器不同，短信 MFA 利用每部手机都自带的消息基础设施，无需任何设置即可立即为用户提供服务。

## 配置用于 MFA 的短信验证 \{#configure-sms-verification-for-mfa}

**步骤 1：配置短信连接器和模板**

1. 进入 <CloudLink to="/connectors/passwordless">控制台 > 连接器 > 邮件和短信连接器</CloudLink>
2. 选择合适的短信连接器（Twilio、SMS Aero 等）
3. 配置连接参数。
4. 为 MFA 设置专用用途类型的短信模板。
   - `MfaVerification` 用于验证 MFA。
   - `BindMfa` 用于绑定 MFA。
5. 测试连接器功能，确保消息能够正常发送
6. 参考 [短信连接器](/connectors/sms-connectors) 获取特定服务商的设置说明

**步骤 2：启用短信 MFA**

1. 进入 <CloudLink to="/mfa">控制台 > 多因素认证 (MFA)</CloudLink>
2. 启用“短信验证码”因子。建议将短信 MFA 与其他 MFA 因子（TOTP、通行密钥、备用码）结合使用，以降低对单一因子的依赖。
3. 在 **邮件/短信两步验证** 中，选择哪些用户拥有短信 MFA。详见 [哪些用户有短信 MFA](#who-has-sms-mfa)。
4. 配置你偏好的 MFA 策略（可选、自适应或强制）
5. 保存你的配置更改

:::note 重要使用注意事项

1. **登录方式限制**：短信验证码不能同时作为[登录方式 (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in)和 MFA 因子 (2FA) 使用。每个短信实现请选择一种认证 (Authentication) 流程。

2. **注册方式兼容性**：短信验证码可以同时用于注册方式和 MFA。Logto 会根据你选择的 MFA 策略优化终端用户注册流程，避免对同一手机号重复要求短信验证。

3. **密码找回兼容性**：虽然短信验证码可以同时用于[忘记密码](/end-user-flows/sign-up-and-sign-in/reset-password)和 MFA，但**不推荐**这种组合。此配置会降低 MFA 的安全性，因为用户可能通过忘记密码短信验证重置密码，然后用新密码进行主认证 (1FA)，再用同一短信方式进行 MFA 验证，从而绕过 MFA。

:::

## 哪些用户有短信 MFA \{#who-has-sms-mfa}

短信 MFA 验证码始终发送到用户的主手机号。<CloudLink to="/mfa">多因素认证 (MFA)</CloudLink> 页面上的 **邮件/短信两步验证** 设置决定了哪些用户拥有短信 MFA：

- **所有拥有已验证邮箱或手机号的用户**：所有拥有主手机号的用户都自动拥有短信 MFA，无需单独设置。
- **仅设置了的用户**：只有主动设置了短信 MFA 的用户才拥有。用已验证手机号注册的用户不会自动获得短信 MFA，因此你可以将短信作为 MFA 选项之一，而无需让每个用户都启用。用户可在 MFA 设置流程、[账户中心](/end-user-flows/account-settings/by-account-center-ui)或通过 [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa) 设置。管理员可通过 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 为用户添加或移除。

该设置同样适用于 [邮件 MFA](/end-user-flows/mfa/email-mfa)。要了解默认值及切换模式时的行为，请参见 [邮件和短信 MFA 注册](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment)。

:::note
当选择 **所有拥有已验证邮箱或手机号的用户** 时，仅因主手机号而拥有短信 MFA 的用户不会有存储的短信 MFA 记录，因此不会出现在 `GET /api/my-account/mfa-verifications`、`GET /api/users/{userId}/mfa-verifications` 或 `user.mfaVerificationFactors`（自定义 JWT 声明和 `PostSignIn` Actions）中。
:::

## 短信 MFA 设置流程 \{#sms-mfa-setup-flows}

MFA 设置提示可能出现在用户注册期间或登录后，具体取决于你配置的 [MFA 策略](/end-user-flows/mfa/configure-mfa#global-mfa-configuration)。

短信 MFA 设置流程受以下因素影响：

- **主 MFA 因子数量**：如有多个主因子，用户需选择一个进行配置。主因子指除备用码外的 MFA 方法。
- **启用备用码**：启用后，主 MFA 因子配置完成后会自动生成备用码，并提示用户保存。
- **注册标识符配置**：手机号作为[注册标识符](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier)使用，并在注册时已通过短信验证码验证。
  - 选择 **所有拥有已验证邮箱或手机号的用户** 时，系统会自动将该号码绑定为 MFA 因子，无需再次验证。如有其他主因子，界面会显示“添加另一项两步验证”选项（用户可跳过），同时明确提示 MFA 已启用。
  - 选择 **仅设置了的用户** 时，手机号与其他因子一样以掩码方式展示。用户选择后，或当其为唯一主因子时，Logto 会用注册时的验证直接设置，无需再次发送验证码。
- **已有用户数据**：已有用户在登录后设置 MFA 时，需先完成主认证 (Authentication)，再进行 MFA 设置。如账户已包含已验证的主手机号：
  - 选择 **所有拥有已验证邮箱或手机号的用户** 时，设置流程与上述注册标识符场景一致。
  - 选择 **仅设置了的用户** 时，手机号以掩码方式展示。用户选择后，或当其为唯一主因子时，Logto 会向该号码发送验证码，用户输入后即完成短信 MFA 设置。

以下是三种常见的短信 MFA 绑定场景。

### 场景 1：手机号仅用于 MFA（典型流程） \{#scenario-1-phone-number-only-used-for-mfa-typical-flow}

- 如仅有一个短信 MFA 因子，直接展示该因子的设置界面。
- 如有多个主 MFA 因子，展示“MFA 设置”列表页，让用户选择要配置的因子。

## 短信 MFA 验证流程 \{#sms-mfa-verification-flows}

启用短信 MFA 的用户登录时，完成主认证 (Authentication)（1FA）后，会被提示使用短信验证码作为第二认证 (Authentication) 因子（2FA）验证身份。

如有多个 MFA 因子可用，Logto 会按照 [配置 MFA](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) 中指定的固定顺序（通行密钥、认证器应用 OTP、短信验证码、邮箱验证码、备用码）直接打开优先级最高的因子。当优先提示如认证器应用 OTP 时，用户可点击 **尝试其他验证方式** 打开选择列表，选择短信验证码。

## 错误处理 \{#error-handling}

1. **手机号未绑定**

   - 错误码：`session.mfa.mfa_factor_not_enabled`
   - 处理方式：引导用户先绑定手机号

2. **验证码错误**

   - 错误码：`verification_code.code_mismatch`
   - 处理方式：提示用户重新输入，限制重试次数

3. **验证码已过期**

   - 错误码：`verification_code.expired`
   - 处理方式：提示用户重新获取验证码

4. **发送频率超限**
   - 错误码：`request.message_rate_limited`（Logto 单用户发送频率限制）或 `connector.rate_limit_exceeded`（短信连接器频率限制）
   - 处理方式：显示等待时间，限制重复发送
