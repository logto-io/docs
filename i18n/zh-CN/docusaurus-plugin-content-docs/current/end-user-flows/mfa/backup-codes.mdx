# 备份码

## 概念 \{#concepts}

备份码，也称为恢复码，是用于多因素认证 (MFA) 的一次性使用码，当用户的主要认证 (Authentication) 因素（如身份验证器应用或硬件令牌）不可用时，作为备选方案。

丢失备份码可能导致账户恢复困难。因此，建议在启用备份码前先设置一个额外的主要认证 (Authentication) 因素，并优先使用主要因素。

Logto 会在用户配置了额外因素后自动为其生成 10 个备份码。每个备份码仅能使用一次。用户可以通过 [预构建的账户中心界面](/end-user-flows/account-settings/by-account-center-ui)（`/account/backup-codes/regenerate`）、使用 [Account API](/end-user-flows/account-settings/by-account-api#manage-backup-codes) 构建的自助界面，或通过 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 的管理工具，在用完所有现有备份码前重新生成一组新的备份码。

## 为 MFA 配置备份码 \{#configure-backup-codes-for-mfa}

1. 进入 <CloudLink to="/mfa">控制台 > 多因素认证 (MFA)</CloudLink>
2. 启用“备份码”因素。备份码不能作为唯一的 MFA 因素，必须与其他主要 MFA 因素（通行密钥、身份验证器应用、短信、电子邮件）组合使用。
3. 配置你偏好的 MFA 策略（可选、自适应或强制）
4. 保存你的配置更改

## 配置备份码管理 \{#configure-backup-codes-management}

用户可以通过 [预构建的账户中心界面](/end-user-flows/account-settings/by-account-center-ui)（`/account/backup-codes/manage` 和 `/account/backup-codes/regenerate`）查看和重新生成他们的备份码。你也可以使用 Account API 构建自定义账户管理界面，让用户可以查看、重新生成和移除他们的备份码。这使用户能够直接在你的应用账户设置中管理他们的恢复选项。

有关详细的实现步骤和 API 端点，请参阅 [通过 Account API 管理账户设置](/end-user-flows/account-settings/by-account-api#manage-backup-codes)。

## 备份码设置流程 \{#backup-codes-setup-flows}

由于备份码是二级 MFA 因素，只有在成功配置了主要 MFA 因素后才能设置。系统会为用户显示一组自动生成的 10 个备份码，用户可以安全地下载和复制。用户必须手动确认备份码，才能完成 MFA 设置流程。

如果已启用**备份码**且用户已有其他激活因素但没有剩余未使用的备份码，Logto 会在登录时提示用户生成并保存一组新的备份码，例如：

- 之前生成的所有备份码已被使用。
- 你在用户已注册主要 MFA 因素后才启用了**备份码**。

在现有用户登录时，只有在用户验证了 MFA 挑战（或使用通行密钥登录）后才会重新提示；跳过 MFA 验证的登录（如受信任设备、低风险 [自适应 MFA](/end-user-flows/mfa/adaptive-mfa) 登录或用户跳过的**可选 MFA**）不会在登录过程中提示绑定新备份码，正常的 [企业单点登录 (SSO)](/end-user-flows/enterprise-sso) 登录也会跳过 MFA 设置提示，除非通过 `acr_values` 明确请求 MFA。

## 备份码验证流程 \{#backup-codes-verification-flow}

当主要 MFA 因素不可用时，备份码可作为紧急认证 (Authentication) 方式。每个备份码只能使用一次，验证成功后即失效。

**验证优先级：**

- **优先使用主要因素**：当用户配置了其他 MFA 因素时，系统会优先提示主要因素（通行密钥、TOTP、短信、电子邮件）。
- **切换到备份码**：如果主要因素不可用，用户可以点击“尝试其他验证方式”切换到备份码。
- **兜底场景**：如果所有主要因素都被删除，备份码成为唯一的验证选项。用户在登录时通过备份码成功完成 MFA 验证后，Logto 会自动提示用户设置新的主要因素。
