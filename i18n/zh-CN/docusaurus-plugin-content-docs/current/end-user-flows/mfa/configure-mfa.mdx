# 配置多因素认证 (MFA)

## 在 Logto 中配置 MFA 设置 \{#configure-mfa-settings-in-logto}

Logto 提供灵活的多因素认证 (MFA) 配置选项，以满足不同的安全需求。你可以为所有用户在全局层面配置 MFA，或针对多租户应用按组织 (Organization) 启用。

### 全局 MFA 配置 \{#global-mfa-configuration}

按照以下步骤在用户的 Logto 登录流程中启用 MFA：

1. 进入：<CloudLink to="/mfa">控制台 > 多因素认证</CloudLink>。
2. 为你的用户启用支持的验证因子。
   1. 主因子：
      - [Passkeys (WebAuthn)](/end-user-flows/mfa/webauthn)：高安全性的选项，适用于支持设备生物识别或安全密钥等的 Web 产品，确保强大的保护。
      - [Authenticator App OTP](/end-user-flows/mfa/authenticator-app-otp)：最常见且被广泛接受的方法。使用如 Google Authenticator 或 Authy 等认证器应用生成的基于时间的一次性密码 (TOTP)。
      - [短信验证](/end-user-flows/mfa/sms-mfa)：通过短信向用户注册的手机号发送一次性验证码，适合喜欢基于手机认证 (Authentication) 且无需额外应用的用户。
      - [邮箱验证](/end-user-flows/mfa/email-mfa)：通过向用户注册邮箱发送一次性验证码，适用于所有平台和设备的用户。
   2. 备份因子：
      - [备份码](/end-user-flows/mfa/backup-codes)：当用户无法验证上述任何主因子时，作为备选方案。启用此选项可降低用户访问的阻力。
   3. 如果启用了短信或邮箱验证，请在 **邮箱/短信两步验证** 中选择哪些用户拥有此功能。详见 [邮箱和短信 MFA 注册](#email-and-sms-mfa-enrollment)。
3. 从下拉菜单中选择 **要求 MFA** 策略。该策略控制用户在登录时必须完成 MFA 的时机：
   - **可选 MFA** (_Optional MFA: 让用户自行选择是否为其账户安全启用 MFA_)：让用户自行决定是否为其账户安全启用 MFA。用户可以在登录时跳过 MFA 设置，稍后通过自助账户设置页面进行设置。[了解更多](/end-user-flows/account-settings/) 关于实现用户账户设置页面。
   - **自适应 MFA** (_Adaptive MFA: 仅在登录存在风险时要求 MFA，例如新国家/长时间未登录_)：仅在登录行为异常时应用 MFA，使低风险登录流程更顺畅，而可疑登录则需额外验证。Logto 会评估内置的上下文风险规则（新国家、地理速度、长时间未登录、不可信 IP 信号）来做出判断。此模式依赖于你已启用的 MFA 设置（至少需启用一个 MFA 因子），适用于终端用户登录流程，不依赖设备指纹。详见 [自适应 MFA](/end-user-flows/mfa/adaptive-mfa) 了解规则阈值、边缘头部前置条件和 Webhook 详情。
   - **强制 MFA** (_Mandatory MFA: 要求所有用户每次登录都完成 MFA_)：要求所有用户每次登录都完成 MFA。未设置 MFA 的用户必须先完成设置才能继续。
   - 选择 **可选 MFA** 时，可配置 **MFA 设置提示** 策略：
     - **不提示用户设置 MFA**：用户在登录或注册时不会被提示设置 MFA。
     - **在注册时提示用户设置 MFA（可跳过，一次性提示）**：新用户在注册时会被提示设置 MFA，已有用户将在下次登录时看到提示。用户可跳过此步骤，且不会再次出现。
     - **在注册后下次登录时提示用户设置 MFA（可跳过，一次性提示）**：新用户将在注册后的下次登录时被提示设置 MFA，已有用户将在下次登录时看到提示。用户可跳过此步骤，且不会再次出现。
   - 选择 **自适应 MFA** 时，仅支持两种不可跳过的 **MFA 设置提示** 策略（**不提示用户设置 MFA** 不可用）：
     - **在注册时提示用户设置 MFA（不可跳过）**：新用户必须在注册时完成 MFA 设置，已有未设置 MFA 的用户必须在下次登录时完成。
     - **在注册后下次登录时提示用户设置 MFA（不可跳过）**：新用户必须在注册后的下次登录时完成 MFA 设置，已有未设置 MFA 的用户必须在下次登录时完成。

当选择 **可选 MFA** 并启用设置提示（`在注册时提示用户设置 MFA（可跳过，一次性提示）` 或 `在注册后下次登录时提示用户设置 MFA（可跳过，一次性提示）`）时，Logto 首先会显示一个名为 `开启两步验证` 的启用 MFA 确认页面。用户可以选择 `开启两步验证` 继续绑定 MFA，或跳过提示并完成当前登录或注册流程而不启用 MFA。在 **自适应 MFA** 或 **强制 MFA** 下，用户会直接进入 MFA 因子绑定流程，不会看到 `开启两步验证` 确认页面。

:::tip
如果你需要在用户跳过 MFA 注册后再次提示，请重置其跳过状态，这样下次登录时会再次出现设置界面。管理员可使用 Management API（`PATCH /api/users/{userId}/logto-configs`），开发者在自助流程中可调用 Account API（`PATCH /api/my-account/logto-configs`）。[Management API 参考](https://openapi.logto.io/operation/operation-updateuserlogtoconfigs) · [Account API 参考](https://openapi.logto.io/operation/operation-updatelogtoconfig)
:::

### 邮箱和短信 MFA 注册 \{#email-and-sms-mfa-enrollment}

邮箱和短信验证码会发送到用户的主邮箱地址和主手机号。**邮箱/短信两步验证** 设置决定哪些用户拥有这些因子。该设置在启用短信或邮箱验证码因子时出现，并同时适用于两者。

- **所有拥有已验证邮箱或手机号的用户**：所有拥有主邮箱地址的用户都自动拥有邮箱 MFA，所有拥有主手机号的用户都自动拥有短信 MFA，无需单独设置。用已验证邮箱或手机号注册的用户已拥有该因子。
- **仅已设置的用户**：只有在设置后（通过 MFA 设置流程中验证验证码、在 [账户中心](/end-user-flows/account-settings/by-account-center-ui) 或通过 [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa) 设置，或管理员通过 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 添加）用户才拥有邮箱或短信 MFA。仅拥有已验证邮箱或手机号并不会自动启用 MFA，因此你可以将邮箱或短信作为 MFA 选项之一，与认证器应用和 passkey 并列，而无需让每个用户都注册。

新租户默认使用 **仅已设置的用户**。早期创建的租户会保留 **所有拥有已验证邮箱或手机号的用户**，直到你更改为止。在 Management API 中，该设置为 [登录体验](https://openapi.logto.io/operation/operation-updatesigninexp) 的 `mfa.verificationCodeEnrollment`，取值为 `Implicit` 和 `Explicit`。由于更新 `mfa` 会替换整个对象，更新时省略 `verificationCodeEnrollment` 会将其重置为 `Implicit`。

Logto 会记录每次邮箱或短信 MFA 的设置，无论哪种模式。记录的是选择而非地址：当用户更换或移除主邮箱或手机号时记录仍在，用户没有主邮箱或手机号时会被忽略。如果用户之后添加新地址，则再次生效。

**切换模式**

切换立即生效且不会更改任何用户数据。控制台会要求你确认。

- **切换为仅已设置的用户**：未设置邮箱或短信 MFA 的用户将不再计入 MFA。仅以邮箱或手机号为唯一因子的用户将被视为未启用 MFA：登录时不会被要求验证，只有在 MFA 策略要求或提示时才需设置。Logto 不会自动为任何人注册。若需为特定用户保留邮箱或短信 MFA，请在切换前通过 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 添加。
- **切换为所有拥有已验证邮箱或手机号的用户**：所有拥有主邮箱地址或手机号的用户再次拥有邮箱或短信 MFA，包括未设置过的用户。

### 组织 (Organization) 级 MFA 配置 \{#organization-level-mfa-configuration}

对于支持 [组织 (Organizations)](/organizations) 的多租户架构产品，大多数情况下你无需对所有用户强制要求 MFA。你可以按组织 (Organization) 启用 MFA，根据每个客户的需求定制要求。入门请参考 [为组织成员要求 MFA](/organizations/organization-management#require-mfa-for-organization-members)。

当在 **要求 MFA** 下拉菜单中选择 **可选 MFA** 时，控制台会显示 **组织启用 MFA 后对用户的 MFA 设置提示** 设置。将其设置为 **在下次登录时提示用户设置 MFA（不可跳过）**，这样要求 MFA 的组织成员将在下次登录时被强制提示完成 MFA 设置，且无法跳过。（该设置在选择 **自适应 MFA** 或 **强制 MFA** 时在控制台中隐藏且不会保存。）

在 **自适应 MFA** 下，未触发任何风险规则的低风险登录不会被要求 MFA 验证，即使用户已启用每用户 **要求 MFA 设置** 或属于启用 `isMfaRequired` 的组织。

### 建议添加另一个 MFA 因子 \{#suggest-adding-another-mfa-factor}

在 <CloudLink to="/mfa">控制台 > 多因素认证</CloudLink> 中，**建议添加另一个 MFA 因子** 开关（默认启用；由登录体验 API 的 `mfa.skipAdditionalBindingSuggestion` 控制）会在以下情况下提示用户在注册或登录时添加另一个 MFA 因子：

- 用户唯一的 MFA 因子是其用于登录的邮箱、手机号或 passkey，且
- 至少还有一个其他 MFA 因子已为租户启用。

用户可以跳过此提示。跳过后，Logto 会在用户的 `logtoConfig` 上持久化 `mfa.additionalBindingSuggestionSkipped: true`，后续登录不会再次出现该提示。你可以通过 [Account API](/end-user-flows/account-settings/by-account-api) 更新或重置该标志（`PATCH /api/my-account/logto-configs`，内容为 `{ "mfa": { "additionalBindingSuggestionSkipped": false } }`；注意 `GET /api/my-account/logto-configs` 和 `GET /api/users/{userId}/logto-configs` 不返回该字段）。

### 每用户 MFA 要求 \{#per-user-mfa-requirement}

管理员可以为单个用户强制要求 MFA 设置，无论租户的 **可选 MFA** 提示设置如何：

- **在控制台**：打开 <CloudLink to="/users">控制台 > 用户管理</CloudLink>，选择用户，在 **多因素认证** 部分启用 **要求 MFA 设置**。
- **通过 Management API**：调用 `PATCH /api/users/{userId}/logto-configs`，内容为 `{ "mfa": { "required": true } }`（通过 `GET /api/users/{userId}/logto-configs` 读取）。详见 [通过 Management API 管理账户设置](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management)。

终端用户无法通过 Account API（`PATCH /api/my-account/logto-configs`）修改 `mfa.required`；对于自助客户端，该字段在 `GET /api/my-account/mfa-settings` 中只读暴露为 `required`。

当每用户 `mfa.required` 为 `true` 时，用户必须在完成登录前设置至少一个 MFA 因子，且无法跳过设置。在 **可选 MFA** 下，即使用户启用了 `skipMfaOnSignIn` 或设置了 `enabled: false`，登录时也必须进行 MFA 验证。在 **自适应 MFA** 下，未触发任何风险规则的低风险登录仍不会被要求 MFA 验证。

## MFA 用户流程 \{#mfa-user-flow}

### MFA 设置流程 \{#mfa-set-up-flow}

启用 MFA 后，用户在登录和注册时可能会被提示设置 MFA。仅在 **要求 MFA** 策略选择 **可选 MFA** 时，用户才可跳过此设置流程。

1. **访问登录或注册页面**：用户进入登录或注册页面。
2. **完成登录或注册**：用户在登录或注册流程中完成身份验证。
   - 若选择了带设置提示的 **可选 MFA**，Logto 首先显示 `开启两步验证` 确认页面，用户可跳过 MFA 设置或点击 `开启两步验证` 继续。
   - 在 **自适应 MFA** 或 **强制 MFA** 下，用户直接进入 MFA 因子绑定流程，不会看到 `开启两步验证` 页面，且无法跳过设置。
3. **设置 MFA 主因子**：用户被提示设置主 MFA 因子（passkey、认证器应用 OTP、短信码或邮箱码）。
   - 若启用了多个主因子，用户可选择偏好选项。
   - 若主因子与注册标识符相同（如短信或邮箱），则已预验证，用户无需再次验证：
     - 对于 **所有拥有已验证邮箱或手机号的用户**，该因子已属于用户，用户直接进入下一步（如“添加另一个两步验证”或“保存你的备份因子”）。
     - 对于 **仅已设置的用户**，该因子与其他因子一样提供，设置时不会再次发送验证码。详见 [邮箱和短信 MFA 注册](#email-and-sms-mfa-enrollment)。
   - 若在 **要求 MFA** 策略中选择了 **可选 MFA**，用户可通过点击“跳过”按钮跳过此步骤。
4. **设置 MFA 备份因子**：若启用了 **备份码**，用户在成功配置主认证因子后会被提示保存备份码。系统会自动生成备份码，用户可下载并安全保存。用户需手动确认备份码以完成 MFA 设置流程。

### MFA 验证流程 \{#mfa-verification-flow}

已设置 MFA 的用户在登录时会被提示使用已配置的 MFA 因子进行身份验证。验证因子取决于 Logto 的 MFA 配置和用户设置。

如果用户使用 [passkey 登录](/end-user-flows/sign-up-and-sign-in/passkey-sign-in)，Logto 会跳过单独的 MFA 验证步骤。因为用于登录的 passkey 本身就是 WebAuthn MFA 因子。

- 若用户仅有一个可用 MFA 因子，将直接验证该因子。
- 若用户有多个可用 MFA 因子，Logto 会按固定优先级顺序排列，并直接打开第一个可用因子：
  1. **Passkey (WebAuthn)**
  2. **认证器应用 OTP (TOTP)**
  3. **短信验证码**
  4. **邮箱验证码**
  5. **备份码**
- 当有两个或以上 MFA 因子可用时，验证页面会显示 **尝试其他验证方式** 链接，用户可打开方法选择列表，切换到其他可用因子（如启用时也包括一次性备份码）。

### 登录绑定规则与豁免 \{#sign-in-binding-rules-and-exemptions}

设计 MFA 流程时请注意以下行为：

- **备份码重新提示**：启用 **备份码** 且用户已有其他激活的 MFA 因子时，若所有已生成的备份码已用完或在用户初次注册后才启用 **备份码**，Logto 会在登录时提示用户生成并保存新一组备份码。
- **登录时绑定新因子需已验证因子**：在用户已有 MFA 因子的 `SignIn` 交互中，绑定新因子（包括保存重新生成的备份码或响应“建议添加另一个 MFA 因子”提示）需先完成一次 MFA 验证挑战（或通过 passkey 登录或企业 SSO 登录）。跳过 MFA 验证的登录（如 [受信任设备](/end-user-flows/mfa/trusted-devices)、未触发风险规则的低风险 [自适应 MFA](/end-user-flows/mfa/adaptive-mfa) 登录、用户跳过的 **可选 MFA**（`skipMfaOnSignIn` / `enabled: false`））无法在该登录流程中绑定新 MFA 因子。此类会话中的用户可稍后通过账户中心或 [Account API](/end-user-flows/account-settings/by-account-api) 添加因子。
- **企业 SSO 豁免**：通过 [企业 SSO](/end-user-flows/enterprise-sso) 登录或注册会跳过租户 MFA 验证和 MFA 设置提示（除非客户端通过 `acr_values` 明确请求 MFA，如 `urn:logto:acr:mfa`）。
- **忘记密码豁免**：[忘记密码](/end-user-flows/sign-up-and-sign-in/reset-password) 流程会跳过 MFA 验证和 MFA 设置提示。

## MFA 管理 \{#mfa-management}

除了登录/注册时的初始设置外，用户还可以通过自助账户中心管理其 MFA 设置。这样用户可根据需要绑定或解绑 MFA 因子，灵活管理安全性。

### 构建账户中心 \{#building-an-account-center}

你可以使用 Logto 的 [Account API](/end-user-flows/account-settings/by-account-api) 构建完整的账户中心，允许用户：

- **绑定新 MFA 因子**：添加额外的认证器应用、passkey 或重新生成备份码
- **解绑已有 MFA 因子**：移除不再使用的 MFA 方法
- **查看当前 MFA 状态**：查看当前已配置的 MFA 因子

### 登录后 MFA 设置提示 \{#post-login-mfa-setup-prompts}

对于初始注册时不要求 MFA 的应用，你可以实现智能提示以鼓励用户设置 MFA：

- **条件提示**：根据用户行为或账户价值显示 MFA 设置建议
- **安全仪表盘**：显示安全分数，启用 MFA 后分数提升
- **渐进式引导**：将 MFA 设置作为渐进式安全提升流程的一部分

了解更多关于如何用 [Account API](/end-user-flows/account-settings/by-account-api) 实现这些模式。

### 在控制台管理用户 MFA \{#manage-users-mfa-in-console}

在 <CloudLink to="/user">控制台 > 用户管理</CloudLink> 中，管理员可高效管理用户 MFA 设置：

- **查看用户 MFA 状态**：检查每个用户已启用哪些 MFA 因子。提示会标记仅因用户拥有已验证邮箱或手机号而计入的邮箱或短信因子，以及用户设置但因因子被禁用而不计入的因子。
- **移除用户 MFA**：逐个移除已存储的 MFA 因子。隐式邮箱或短信验证码行无法直接从此表移除，启用 passkey 登录时，passkey (WebAuthn) 行在此处无移除按钮，需在同一用户详情页的 **Passkeys** 部分管理。

如需为用户添加邮箱或短信 MFA，请使用 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management)。

### 常见问题 \{#faqs}

<details>
<summary>
### 管理员移除用户现有 MFA 因子后会发生什么？ \{#what-happens-when-administrators-remove-users-existing-mfa-factors}
</summary>
当管理员移除用户所有主 MFA 因子（passkey、认证器应用 OTP、短信或邮箱）后，用户下次登录时会出现以下场景：

**场景 1：无 MFA 因子剩余**

- 若不存在任何 MFA 因子（包括无备份码），且 [MFA 策略](#global-mfa-configuration) 要求 MFA，用户将被允许无 MFA 验证直接登录，并会立即被提示重新设置 MFA。

**场景 2：仍有备份码**

- 若仍有备份码可用，用户必须先在登录时通过备份码验证。
- 备份码验证成功后，用户会被提示设置新的主 MFA 因子。
- 用户是否可跳过此设置取决于你配置的 MFA 策略。
- 这种方式可防止用户在无主因子的情况下被锁定账户。

 </details>
