# Kerndienst

## Einführung \{#introduction}

_Der Kerndienst_ ist ein monolithischer Dienst für kritische Logto-Aufgaben. Der Quellcode befindet sich in [`@logto/core`](https://github.com/logto-io/logto/tree/master/packages/core).

:::note
_Kerndienst_ und _SDK core_ sind zwei verschiedene Konzepte. Siehe [SDK-Konvention](/developers/sdk-conventions) für die Unterschiede.
:::

Zur Vereinfachung unterteilen wir den Kerndienst in vier Hauptmodule:

<table>
  <thead>
    <tr>
      <td>Name</td>
      <td>Beschreibung</td>
      <td>Mount-Pfad</td>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>OIDC-Provider</td>
      <td>Ein [OpenID Provider](https://openid.net/specs/openid-connect-core-1_0.html).</td>
      <td>
        <code>/oidc</code>
      </td>
    </tr>
    <tr>
      <td>Logto API</td>
      <td>Management API, Experience API und Account API.</td>
      <td>
        <code>/api</code>
      </td>
    </tr>
    <tr>
      <td>Frontend-Proxys</td>
      <td>HTTP-Proxys oder statische Dateiauslieferung für Frontend-Projekte.</td>
      <td>
        Siehe <a href="#frontend-proxies">Frontend-Proxys</a> für Details.
      </td>
    </tr>
  </tbody>
</table>

Backend-APIs, einschließlich OIDC, sind im `core`-Paket implementiert, während Frontend-Proxys von den entsprechenden Schwesterpaketen im Logto-Monorepo abhängen.

## OIDC-Provider \{#oidc-provider}

Logto verwendet die großartige zertifizierte [OpenID Connect](https://openid.net/connect/)-Implementierung [node-oidc-provider](https://github.com/panva/node-oidc-provider) im Hintergrund. Der Provider ist unter `/oidc` eingebunden, und du kannst die zugehörigen Konfigurationen und Dateien in [packages/core/src/oidc](https://github.com/logto-io/logto/tree/master/packages/core/src/oidc) einsehen.

Der OIDC [Userinfo Endpoint](https://openid.net/specs/openid-connect-core-1_0.html#UserInfo) ist verfügbar und unter `/oidc/me` eingebunden.

:::info
Wenn du OIDC-APIs direkt aufrufen möchtest, denke daran, den Header `Content-Type: application/x-www-form-urlencoded` zu setzen.
:::

## Logto API \{#logto-api}

### Management API \{#management-api}

_Management API_ ist eine Sammlung von APIs, die Logto-Daten verwalten und aktualisieren. Nur Benutzer mit der `admin`-Rolle haben Zugriff darauf.

Gehe zu den [API-Referenzen](https://openapi.logto.io), um die Details zu sehen.

Um programmgesteuert auf die API zuzugreifen, siehe [Mit Management API interagieren](/integrate-logto/interact-with-management-api).

### Experience API \{#experience-api}

Experience API ist eine Sammlung dedizierter Endpunkte, die benutzerdefinierte Interaktionen mit der Anmeldeoberfläche unterstützen.

Diese APIs ermöglichen es Entwicklern, zentrale Authentifizierungsfunktionen wie Anmeldung, Registrierung, Passwortzurücksetzung, Social-Account-Verknüpfung und Multi-Faktor-Authentifizierung (MFA) zu implementieren. Um diese Funktionen zu realisieren, muss deine benutzerdefinierte UI mit der Experience API interagieren.

Um die Benutzerflüsse und Implementierungsdetails besser zu verstehen:

- Sieh dir die Anleitung [Entwickle deine eigene UI](/customization/bring-your-ui/#develop-your-custom-ui) an, um zu erfahren, wie du die Experience API für deine eigene Experience-UI nutzt
- Sieh in die [Experience API Referenzen](https://openapi.logto.io/group/endpoint-experience) für detaillierte API-Dokumentation
- Lies das [Experience API Design RFC](https://github.com/logto-io/rfcs/blob/master/draft/0004-experience-api.md) für tiefgehende technische Spezifikationen und Beispiele

### Account API \{#account-api}

Account API ist eine umfassende Sammlung von APIs, die Endbenutzern direkten API-Zugriff ermöglichen, ohne die Management API durchlaufen zu müssen. Hier die Highlights:

- Direkter Zugriff: Die Account API ermöglicht es Endbenutzern, direkt auf ihr eigenes Profil zuzugreifen und dieses zu verwalten, ohne die Management API zu benötigen.
- Verwaltung von Benutzerprofilen und Identitäten: Benutzer können ihre Profile und Sicherheitseinstellungen verwalten, einschließlich E-Mail, Telefon, Passwort, Social-Verbindungen und MFA-Faktoren, sowie Secret Vault Tokens für verknüpfte Social- und Enterprise-SSO-Verbindungen abrufen.
- Globale Zugriffskontrolle: Der Admin hat vollständige, globale Kontrolle über die Zugriffseinstellungen und kann jedes Feld individuell anpassen.
- Nahtlose Autorisierung: Autorisieren ist einfacher denn je! Verwende einfach `client.getAccessToken()`, um ein opakes Zugangstoken für OP (Logto) zu erhalten, und füge es dem Authorization-Header als `Bearer <access_token>` hinzu.

Mit der Logto Account API kannst du ein individuelles Kontoverwaltungssystem wie eine Profilseite erstellen, das vollständig mit Logto integriert ist.

Sieh dir [Kontoeinstellungen per Account API](/end-user-flows/account-settings/by-account-api) an, um zu erfahren, wie du die Account API für deine eigene Kontoeinstellungsseite nutzen kannst.

Siehe [Account API Referenzen](https://openapi.logto.io/group/endpoint-my-account) für detaillierte API-Dokumentation.

## Frontend-Proxys \{#frontend-proxies}

Ein _Frontend-Proxy_ ist eine Middleware-Funktion, die ein Frontend-Projekt abhängig von der Umgebung bereitstellt:

- Im Entwicklungsmodus werden HTTP-Anfragen an den Frontend-Dev-Server weitergeleitet.
- Im Produktionsmodus werden statische Frontend-Dateien direkt ausgeliefert.

Logto hat drei Frontend-Proxys:

:::
