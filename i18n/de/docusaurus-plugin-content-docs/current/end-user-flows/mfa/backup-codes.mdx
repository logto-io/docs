# Backup-Codes

## Konzepte \{#concepts}

Backup-Codes, auch bekannt als Wiederherstellungscode, sind Einmalcodes für die Multi-Faktor-Authentifizierung (MFA) und dienen als Backup, falls die primären Authentifizierungsfaktoren des Benutzers (z. B. Authenticator-App oder Hardware-Token) nicht verfügbar sind.

Der Verlust dieser Codes kann zu Herausforderungen bei der Kontowiederherstellung führen. Daher wird empfohlen, vor der Aktivierung von Backup-Codes einen zusätzlichen primären Faktor einzurichten und diesem Priorität einzuräumen.

Logto generiert automatisch 10 Backup-Codes für Benutzer, sobald sie einen zusätzlichen Faktor konfigurieren. Jeder Code ist nur einmal verwendbar. Benutzer können über die [vorgefertigte Account Center UI](/end-user-flows/account-settings/by-account-center-ui) (`/account/backup-codes/regenerate`), eine benutzerdefinierte Self-Service-Oberfläche mit der [Account API](/end-user-flows/account-settings/by-account-api#manage-backup-codes) oder Admin-Tools mit der [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) ein neues Set von Codes generieren, bevor alle bestehenden Codes aufgebraucht sind.

## Backup-Codes für MFA konfigurieren \{#configure-backup-codes-for-mfa}

1. Navigiere zu <CloudLink to="/mfa">Konsole > Multi-Faktor-Authentifizierung</CloudLink>
2. Aktiviere den Faktor "Backup-Codes". Backup-Codes können nicht als einziger MFA-Faktor verwendet werden. Es ist erforderlich, Backup-Codes in Kombination mit anderen primären MFA-Faktoren (Passkeys, Authenticator-App, SMS, E-Mail) zu nutzen.
3. Konfiguriere deine bevorzugte MFA-Richtlinie (optional, adaptiv oder verpflichtend)
4. Speichere deine Konfigurationsänderungen

## Verwaltung der Backup-Codes konfigurieren \{#configure-backup-codes-management}

Benutzer können ihre Backup-Codes über die [vorgefertigte Account Center UI](/end-user-flows/account-settings/by-account-center-ui) (`/account/backup-codes/manage` und `/account/backup-codes/regenerate`) einsehen und regenerieren. Du kannst auch die Account API verwenden, um benutzerdefinierte Account-Management-Oberflächen zu erstellen, in denen Benutzer ihre Backup-Codes anzeigen, regenerieren und entfernen können. So können Benutzer ihre Wiederherstellungsoptionen direkt in den Kontoeinstellungen deiner Anwendung verwalten.

Für detaillierte Implementierungsschritte und API-Endpunkte siehe [Kontoeinstellungen per Account API](/end-user-flows/account-settings/by-account-api#manage-backup-codes).

## Backup-Codes Einrichtungsablauf \{#backup-codes-setup-flows}

Da Backup-Codes ein sekundärer MFA-Faktor sind, können sie erst eingerichtet werden, nachdem ein primärer MFA-Faktor erfolgreich konfiguriert wurde. Eine Gruppe von 10 automatisch generierten Backup-Codes wird dem Benutzer angezeigt, die er sicher herunterladen und kopieren kann. Der Benutzer muss die Backup-Codes manuell bestätigen, um den MFA-Einrichtungsprozess abzuschließen.

Logto fordert den Benutzer außerdem während der Anmeldung auf, eine neue Gruppe von Backup-Codes zu generieren und zu speichern, wenn **Backup-Codes** aktiviert sind und der Benutzer bereits einen anderen aktiven Faktor, aber keine verbleibenden ungenutzten Backup-Codes hat – zum Beispiel:

- Alle zuvor generierten Backup-Codes wurden verwendet.
- Du hast **Backup-Codes** aktiviert, nachdem der Benutzer bereits seinen primären MFA-Faktor eingerichtet hatte.

Während der Anmeldung eines bestehenden Benutzers erfolgt diese erneute Aufforderung erst, nachdem der Benutzer eine MFA-Herausforderung verifiziert hat (oder sich mit einem Passkey anmeldet); Anmeldungen, die die MFA-Überprüfung umgehen (wie ein vertrauenswürdiges Gerät, eine risikoarme [Adaptive MFA](/end-user-flows/mfa/adaptive-mfa)-Anmeldung oder vom Benutzer übersprungene **optionale MFA**), fordern nicht zur Bindung neuer Backup-Codes während der Anmeldung auf, und normale [Enterprise SSO](/end-user-flows/enterprise-sso)-Anmeldungen überspringen MFA-Einrichtungsaufforderungen, es sei denn, MFA wird explizit über `acr_values` angefordert.

## Backup-Codes Verifizierungsablauf \{#backup-codes-verification-flow}

Backup-Codes dienen als Notfall-Authentifizierung, wenn primäre MFA-Faktoren nicht verfügbar sind. Jeder Code kann nur einmal verwendet werden und wird nach erfolgreicher Verifizierung ungültig.

**Verifizierungspriorität:**

- **Zuerst primäre Faktoren**: Wenn Benutzer andere MFA-Faktoren konfiguriert haben, werden primäre Faktoren (Passkeys, TOTP, SMS, E-Mail) zuerst abgefragt.
- **Zugriff auf Backup-Codes**: Benutzer können auf Backup-Codes umschalten, indem sie auf „Andere Methode zur Verifizierung versuchen“ klicken, falls primäre Faktoren nicht verfügbar sind.
- **Fallback-Szenario**: Wenn alle primären Faktoren gelöscht wurden, sind Backup-Codes die einzige Verifizierungsoption. Nach erfolgreicher MFA-Verifizierung per Backup-Codes während der Anmeldung fordert Logto Benutzer automatisch auf, einen neuen primären Faktor einzurichten.
