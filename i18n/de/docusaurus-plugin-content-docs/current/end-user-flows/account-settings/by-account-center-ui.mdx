# Kontoeinstellungen mit dem vorgefertigten Account Center UI

## Was ist das vorgefertigte Account Center UI \{#what-is-the-prebuilt-account-center-ui}

Logto stellt ein vorgefertigtes Account Center UI bereit, das gebrauchsfertige Seiten für Endnutzer bietet, um ihre Kontoeinstellungen zu verwalten. Dieses vorgefertigte UI wird von Logto gehostet und übernimmt gängige Aufgaben der Kontoverwaltung, darunter:

- Anzeigen und Bearbeiten des Benutzerprofils (Name, Avatar und benutzerdefinierte Profilfelder)
- Aktualisieren der E-Mail-Adresse und Telefonnummer
- Aktualisieren des Benutzernamens
- Festlegen oder Aktualisieren des Passworts
- Verwalten sozialer Verbindungen (Verknüpfen und Trennen sozialer Konten)
- Verwalten von MFA-Einstellungen (TOTP-Authenticator-App, Passkeys, Backup-Codes)
- Aktivieren oder Deaktivieren der 2-Schritt-Verifizierung
- Verwalten aktiver Sitzungen und autorisierter Apps

Das vorgefertigte Account Center UI ist so konzipiert, dass es nahtlos mit deiner Anwendung zusammenarbeitet und ein konsistentes Nutzererlebnis bietet, ohne dass du eigene Seiten zur Kontoverwaltung erstellen musst.

## Vorteile der Nutzung des vorgefertigten UI \{#benefits-of-using-the-prebuilt-ui}

- **Kein Entwicklungsaufwand**: Gebrauchsbereite Seiten, die sofort funktionieren
- **Konsistentes Erlebnis**: Entspricht dem Look & Feel der Logto-Anmeldeerfahrung
- **Integrierte Sicherheit**: Alle Verifizierungsabläufe und Sicherheitsmaßnahmen werden automatisch gehandhabt
- **Immer aktuell**: Neue Funktionen und Sicherheitsverbesserungen stehen automatisch zur Verfügung

## Verfügbare Seiten \{#available-pages}

Das vorgefertigte Account Center UI stellt die folgenden Seiten bereit, die alle unter dem Pfad `/account` deines Logto-Tenant-Endpunkts erreichbar sind:

| Pfad                                 | Beschreibung                                                           |
| ------------------------------------ | ---------------------------------------------------------------------- |
| `/account/profile`                   | Benutzerprofilseite (Name, Avatar und benutzerdefinierte Profilfelder) |
| `/account/security`                  | Sicherheits-Hub (2-Schritt-Verifizierung, soziale Konten, Sitzungen)   |
| `/account/email`                     | Primäre E-Mail-Adresse aktualisieren oder entfernen                    |
| `/account/phone`                     | Primäre Telefonnummer aktualisieren oder entfernen                     |
| `/account/username`                  | Benutzernamen aktualisieren                                            |
| `/account/password`                  | Passwort festlegen oder aktualisieren                                  |
| `/account/passkey/add`               | Neuen Passkey hinzufügen (WebAuthn)                                    |
| `/account/passkey/manage`            | Vorhandene Passkeys anzeigen und verwalten                             |
| `/account/authenticator-app`         | TOTP-Authenticator-App einrichten                                      |
| `/account/authenticator-app/replace` | Bestehende TOTP-Authenticator-App ersetzen                             |
| `/account/backup-codes/generate`     | Neue Backup-Codes generieren                                           |
| `/account/backup-codes/manage`       | Backup-Codes anzeigen und verwalten                                    |

Wenn dein Tenant-Endpunkt zum Beispiel `https://example.logto.app` ist, wäre die Seite zum Aktualisieren der E-Mail unter `https://example.logto.app/account/email` erreichbar.

## So verwendest du das vorgefertigte UI \{#how-to-use-the-prebuilt-ui}

### Schritt 1: Account API aktivieren \{#step-1-enable-account-api}

Das vorgefertigte Account Center UI basiert auf der Account API. Navigiere zu <CloudLink to="/sign-in-experience/account-center">Konsole > Anmeldung & Konto > Account Center</CloudLink> und aktiviere die Account API.

Konfiguriere die Feldberechtigungen nach deinen Anforderungen:

- Setze Felder auf `Edit`, damit Nutzer sie bearbeiten können
- Setze Felder auf `ReadOnly`, wenn Nutzer sie nur ansehen dürfen
- Setze Felder auf `Off`, um sie vollständig auszublenden

#### Profilfelder konfigurieren \{#configure-profile-fields}

Das Account Center zeigt eine **Profil**-Seite, auf der Endnutzer ihre Profilinformationen einsehen und verwalten können. Um zu steuern, welche Profilfelder auf dieser Seite erscheinen:

1. Stelle sicher, dass die Berechtigung für die Felder **Name**, **Avatar**, **Profil** oder **Benutzerdefinierte Daten** in den Bereichen Account-Sicherheit / Benutzerprofil auf `Edit` oder `ReadOnly` gesetzt ist.
2. Füge im Bereich **Vorgefertigtes UI integrieren** die Profilfelder hinzu, die du aus dem Profilfeld-Selektor anzeigen möchtest. Diese Felder stammen aus demselben Katalog wie bei [Benutzerprofil erfassen](/end-user-flows/collect-user-profile) — jedes dort definierte Feld kann auch im Account Center angezeigt werden.
3. Ziehe die Felder per Drag & Drop in die gewünschte Reihenfolge.

Nur Felder, die sowohl in den Profilfeldern gelistet sind **und** deren entsprechende Feldberechtigung nicht auf `Off` steht, erscheinen auf der Profilseite.

### Schritt 2: Von deiner Anwendung auf die vorgefertigten Seiten verlinken \{#step-2-link-to-prebuilt-pages}

Um das vorgefertigte Account Center UI zu nutzen, musst du Nutzer aus deiner Anwendung zu den entsprechenden Logto-Seiten weiterleiten. Es gibt zwei Ansätze:

#### Ansatz A: Direktverlinkung mit Redirect-Parameter \{#approach-a-direct-linking}

Füge in deiner Anwendung Links ein, die Nutzer auf die vorgefertigten Seiten weiterleiten. Füge einen `redirect`-Query-Parameter hinzu, um Nutzer nach Abschluss der Aktion zurück zu deiner App zu bringen:

```
https://[tenant-id].logto.app/account/email?redirect=https://your-app.com/settings
```

Wenn Nutzer ihre E-Mail aktualisiert haben, werden sie zurück zu `https://your-app.com/settings` geleitet. Nutzer, die die Seite mit dem Zurück-Button verlassen, kehren ebenfalls zu dieser URL zurück.

#### Ansatz B: Einbettung in deinen Kontoeinstellungs-Flow \{#approach-b-embedding}

Du kannst die vorgefertigten Seiten in deinen bestehenden Kontoeinstellungs-Workflow integrieren:

1. Zeige auf der Kontoeinstellungsseite deiner App die aktuellen Informationen des Nutzers an
2. Biete "Bearbeiten"- oder "Aktualisieren"-Buttons, die auf die entsprechenden vorgefertigten Seiten verlinken
3. Nach Abschluss oder Abbruch der Aktion wird der Nutzer zurück zu deiner App geleitet

Beispielimplementierung:

```tsx
function AccountSettings() {
  const tenantEndpoint = 'https://example.logto.app';
  const redirectUrl = encodeURIComponent(window.location.href);

  return (
    <div>
      <h2>Kontoeinstellungen</h2>

      <div>
        <span>E-Mail: user@example.com</span>
        <a href={`${tenantEndpoint}/account/email?redirect=${redirectUrl}`}>E-Mail aktualisieren</a>
      </div>

      <div>
        <span>Passwort: ••••••••</span>
        <a href={`${tenantEndpoint}/account/password?redirect=${redirectUrl}`}>Passwort ändern</a>
      </div>

      <div>
        <span>MFA: Nicht konfiguriert</span>
        <a href={`${tenantEndpoint}/account/authenticator-app?redirect=${redirectUrl}`}>
          Authenticator einrichten
        </a>
      </div>
    </div>
  );
}
```

### Schritt 3: Rückkehr zu deiner App behandeln \{#step-3-handle-success-redirects}

Nutzer kehren sowohl nach Abschluss einer Aktion als auch beim Verlassen mit dem Zurück-Button zu deiner `redirect`-URL zurück, und die URL ist in beiden Fällen identisch. Behandle die Rückkehr daher nicht als Beweis für eine erfolgreiche Änderung; hole stattdessen die aktuellen Nutzerdaten ab, zum Beispiel mit der [Account API](/end-user-flows/account-settings/by-account-api).

Um dem Nutzer eine abgeschlossene Aktion zu bestätigen, füge `show_success=true` zur Account Center URL hinzu. Das Account Center zeigt dann nach der Aktion eine eigene Erfolgsseite an und kehrt zu deiner `redirect`-URL zurück, wenn der Nutzer auf **Fertig** klickt:

```
https://[tenant-id].logto.app/account/password?redirect=https://your-app.com/settings&show_success=true
```

## Unterstützte URL-Parameter \{#supported-url-parameters}

Du kannst die folgenden Query-Parameter an jede Account Center URL anhängen, um das Erlebnis anzupassen:

| Parameter      | Beschreibung                                                                                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `redirect`     | Die absolute URL, zu der der Nutzer nach Abschluss der Aktion oder beim Verlassen mit dem Zurück-Button zurückgeleitet wird. Es werden nur `http(s)`-URLs akzeptiert.                                                          |
| `show_success` | Wenn auf `true` gesetzt, zeigt das Account Center nach der Aktion eine Erfolgsseite an und kehrt zu deiner `redirect`-URL zurück, wenn der Nutzer auf **Fertig** klickt. Ohne diesen Parameter kehrt der Nutzer sofort zurück. |
| `identifier`   | Füllt das Eingabefeld für den Bezeichner auf der Zielseite (`/account/email`, `/account/phone`, `/account/username`) vorab aus. Nützlich für Deep-Links aus deiner App, wenn du den Nutzerbezeichner bereits kennst.           |
| `ui_locales`   | Durch Leerzeichen getrennte Liste von BCP-47-Sprachtags (z. B. `fr-CA fr en`), die die Sprache des Account Center UI steuert. Wird ausgelassen, wird auf die Browsersprache des Nutzers zurückgegriffen.                       |

Beispiel — Deep-Link zur E-Mail-Aktualisierungsseite mit vorausgefüllter aktueller E-Mail und französischer UI:

```
https://[tenant-id].logto.app/account/email?identifier=user@example.com&ui_locales=fr&redirect=https://your-app.com/settings
```

:::note
Der Wert von `identifier` wird vor der Weiterleitung zur Anmeldung im Session Storage gespeichert und von der Zielseite einmalig ausgelesen.
:::

## Link zur Kontolöschung \{#account-deletion-link}

Das Account Center übernimmt die Kontolöschung nicht direkt. Stattdessen kannst du eine **Kontolöschungs-URL** konfigurieren, die auf deinen eigenen Löschungs-Flow verweist (typischerweise gestützt durch die [Management API](/end-user-flows/account-settings/by-management-api)). Ist sie konfiguriert, erscheint ein Eintrag **Konto löschen** auf der Sicherheitsseite des Account Centers und verlinkt den Nutzer auf deine URL.

Um sie zu konfigurieren, navigiere zu <CloudLink to="/sign-in-experience/account-center">Konsole > Anmeldung & Konto > Account Center</CloudLink> und setze das Feld **Kontolöschungs-URL**. Du kannst sie auch über die Management API aktualisieren:

```bash
curl -X PATCH https://[tenant-id].logto.app/api/account-center \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"deleteAccountUrl":"https://your-app.com/delete-account"}'
```

Lasse das Feld leer (oder setze `deleteAccountUrl` auf `null`), um den Eintrag zur Kontolöschung auszublenden.

## Callback-URL für soziale Verbindungen \{#social-connection-callback-url}

Das Verknüpfen eines sozialen Kontos aus dem Account Center verwendet die Callback-URL des Connectors:

```
https://[your-tenant-endpoint]/callback/{connectorId}
```

Dabei ist `{connectorId}` die ID des sozialen Connectors. Dies ist die **Callback-URI**, die auf der Connector-Detailseite in <CloudLink to="/connectors/social">Konsole > Connectors > Soziale Connectors</CloudLink> angezeigt wird und die du bei deinem sozialen Anbieter registrierst, wenn du den [Connector einrichtest](/connectors/social-connectors/).

## Sicherheitshinweise \{#security-considerations}

Das vorgefertigte Account Center UI enthält integrierte Sicherheitsmaßnahmen:

- **OIDC Step-up-Authentifizierung**: Sensible Änderungen (E-Mail, Telefon, Benutzername, Passwort, soziale Konten, MFA, Sitzungen und vertrauenswürdige Geräte) erfordern eine kürzlich erfolgte Nutzer-Authentifizierung (`urn:logto:acr:1fa` oder stärker) innerhalb des in deinem Tenant konfigurierten **Fensters für kürzliche Authentifizierung** (`10` Minuten standardmäßig, konfigurierbar von `1` bis `120` Minuten in <CloudLink to="/sign-in-experience/account-center">Konsole > Anmeldung & Konto > Account Center</CloudLink>). Wenn sich ein Nutzer gerade mit einer qualifizierenden Methode angemeldet oder registriert hat, erscheint keine zusätzliche Abfrage; wenn die Anmeldung kein `1fa` enthält (z. B. soziale Anmeldung) oder das Fenster überschritten ist, führt das Account Center automatisch die [OIDC Step-up-Authentifizierung](/end-user-flows/step-up-authentication) durch und setzt die ausstehende Aktion fort.
- **Verifizierungscodes**: E-Mail- und Telefonaktualisierungen erfordern Verifizierungscodes, die an die neue Adresse/Nummer gesendet werden
- **Sitzungsvalidierung**: Alle Operationen validieren die Sitzung des Nutzers, um unbefugten Zugriff zu verhindern

## Anpassungsoptionen \{#customization-options}

Das vorgefertigte Account Center UI übernimmt das Branding aus deinen Einstellungen für die Anmeldeerfahrung, einschließlich:

- Logo und Farben
- Dunkel-/Hellmodus
- Spracheinstellungen

### Benutzerdefiniertes CSS \{#custom-css}

Du kannst das Erscheinungsbild des Account Center UI weiter anpassen, indem du benutzerdefiniertes CSS hinzufügst. Navigiere zu <CloudLink to="/sign-in-experience/account-center">Konsole > Anmeldung & Konto > Account Center</CloudLink> und füge dein benutzerdefiniertes CSS im **Custom CSS**-Editor hinzu.

Das vorgefertigte Account Center UI stellt stabile CSS-Klassennamen mit dem Präfix `logto_ac-` für wichtige UI-Elemente (Layout-Container, Seitenüberschriften, Abschnitte, Karten usw.) bereit, um eine gezielte Anpassung zu ermöglichen. So kannst du Standardstile überschreiben, ohne dich um Klassennamenänderungen zwischen Releases sorgen zu müssen.

Beispiel:

```css
/* Logto-Signatur ausblenden */
.logto_ac-logto-signature {
  display: none;
}

/* Sicherheitskarten individuell gestalten */
.logto_ac-security-card {
  border-radius: 12px;
}
```

Wenn du mehr Anpassung benötigst, als das vorgefertigte UI und benutzerdefiniertes CSS bieten, erwäge die Nutzung der [Account API](/end-user-flows/account-settings/by-account-api), um eigene Seiten zur Kontoverwaltung zu erstellen.
