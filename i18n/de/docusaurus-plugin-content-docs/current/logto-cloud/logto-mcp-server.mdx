# Logto MCP Server

Logto MCP Server ist ein entfernter [MCP (Model Context Protocol)](https://modelcontextprotocol.io/) Server. Füge die URL zu deiner KI-Anwendung hinzu, melde dich mit deinem Logto Cloud-Konto an und beginne, mit Logto zu interagieren.

:::tip
Logto MCP Server ist mit Logto und [MCP Auth](https://mcp-auth.dev) gebaut. Wenn du deinen eigenen entfernten MCP-Server bauen möchtest, siehe [Baue deinen eigenen entfernten MCP-Server](#build-your-own-remote-mcp-server).
:::

## Was du tun kannst \{#what-you-can-do}

- **Authentifizierung zu deinem Projekt hinzufügen**: Die KI erkennt dein Framework, erstellt eine Logto-Anwendung und generiert funktionierenden Integrationscode. Unterstützt über 38 Frameworks, darunter React, Next.js, Vue, Nuxt, SvelteKit, Express, Go, Python, iOS, Android, Flutter und mehr.
- **Fragen zu Logto stellen**: Die KI durchsucht die Logto-Dokumentation und gibt dir Antworten mit Quellenangabe.

Weitere Funktionen folgen in Kürze, darunter Konfiguration der Anmeldeerfahrung, RBAC- und Berechtigungsmanagement mit Best-Practice-Anleitungen, Multi-Tenancy-Einrichtung für den Bau von B2B-Apps mit Organisationen und mehr.

## Wie sich deine KI-Anwendung verbindet \{#how-your-ai-application-connects}

Logto MCP Server unterstützt zwei Möglichkeiten, wie sich eine KI-Anwendung beim Anmelden identifizieren kann. Für keine der beiden musst du etwas in Logto Cloud anlegen.

- **Nur Server-URL (empfohlen)**: Die meisten KI-Anwendungen unterstützen inzwischen [Client ID Metadata Documents (CIMD)](/integrate-logto/third-party-applications/dynamic-apps). Die Anwendung verwendet eine URL, die sie besitzt, als ihre Client-ID, und Logto liest den Namen der Anwendung und die Redirect-URIs von dieser URL aus. Du gibst nur die Server-URL `https://mcp.logto.io` ein.
- **Statische Client-ID**: Für Anwendungen, die CIMD noch nicht unterstützen, gib die öffentliche OAuth-Client-ID `mcp-client` ein. Dieser Client akzeptiert Loopback-Redirect-URIs (`http://localhost` oder `http://127.0.0.1` mit beliebigem Port).

Wenn deine Anwendung beide Optionen unterstützt, verwende nur die Server-URL. Bestehende Verbindungen, die `mcp-client` nutzen, funktionieren weiterhin, du musst sie also nicht neu verbinden.

Wenn du dich nur mit der Server-URL verbindest, zeigt die Logto Cloud-Anmeldeseite einen Zustimmungsbildschirm mit dem Namen der Anwendung und dem Host der Client-ID-URL an, wie `claude.ai` oder `vscode.dev`. Überprüfe, ob der Host mit der Anwendung übereinstimmt, die du verwendest, bevor du autorisierst.

## Einrichtung in deiner KI-Anwendung \{#set-up-in-your-ai-application}

### Amp \{#amp}

1. Öffne in [Amp](https://ampcode.com) **Personal Settings** > **Integrations & MCP** und klicke auf **Add MCP Server**.
2. Gib den Namen `Logto MCP Server` und die Server-URL ein: `https://mcp.logto.io`. Amp erkennt die Authentifizierungsmethode automatisch.
3. Klicke auf **Connect** und folge der Aufforderung von Amp, dich anzumelden.
4. Melde dich mit deinem Logto Cloud-Konto an und autorisiere die Verbindung.

:::tip
Wenn Amp lange bei **Detecting Authentication** bleibt, klicke auf **Change** und wähle **OAuth**, um die automatische Authentifizierungserkennung zu überspringen. Lasse **OAuth Client ID** und **OAuth Client Secret** unter **Use Your Own OAuth App** leer, dann klicke auf **Connect** und folge der Anmeldeaufforderung. Amp unterstützt CIMD, daher musst du keine OAuth-App registrieren oder `mcp-client` eingeben.
:::

### Claude Code \{#claude-code}

```bash
claude mcp add --transport http logto https://mcp.logto.io
```

Führe dann `/mcp` in Claude Code aus, wähle `logto` und folge dem Login-Flow im Browser, um dich mit deinem Logto Cloud-Konto zu authentifizieren. Du kannst auch `claude mcp login logto` in deiner Shell ausführen.

### Claude (Web und Desktop) \{#claude-web-and-desktop}

1. Öffne **Customize** > **Connectors** und klicke auf **Add custom connector**.
2. Gib den Namen `Logto MCP Server` und die entfernte MCP-Server-URL ein: `https://mcp.logto.io`. Lasse die OAuth-Einstellungen unter **Advanced settings** leer und klicke auf **Add**.
3. Finde in der **Connectors**-Liste **Logto MCP Server** und klicke auf **Connect**.
4. Du wirst zur Logto Cloud-Anmeldeseite weitergeleitet. Melde dich mit deinem Logto Cloud-Konto an und autorisiere die Verbindung.

Connectors werden in deinem Claude-Konto gespeichert und sind somit sowohl im Web als auch in Claude Desktop verfügbar.

### Codex \{#codex}

```bash
codex mcp add logto --url https://mcp.logto.io
codex mcp login logto
```

Ein Browserfenster öffnet sich. Melde dich mit deinem Logto Cloud-Konto an, um die Verbindung herzustellen. Die ChatGPT-Desktop-App, Codex CLI und die Codex IDE-Erweiterung teilen sich diese Konfiguration.

### Cursor \{#cursor}

Cursor unterstützt CIMD noch nicht, daher wird die statische Client-ID verwendet.

1. Öffne **Customize** > **MCPs** oder öffne `~/.cursor/mcp.json` (global) oder `.cursor/mcp.json` (projektbezogen).
2. Füge folgende Konfiguration hinzu:

   ```json
   {
     "mcpServers": {
       "Logto": {
         "url": "https://mcp.logto.io",
         "auth": {
           "CLIENT_ID": "mcp-client",
           "scopes": ["mcp:all"]
         }
       }
     }
   }
   ```

3. Klicke neben dem Server auf **Connect**. Eine Logto Cloud-Anmeldeseite erscheint. Melde dich mit deinem Logto Cloud-Konto an, um die Verbindung herzustellen.

Melde dich aus der Cursor-Desktop-App an. Der Web-Callback, der von Cursor im Web und von Cursor Agents verwendet wird, wird nicht unterstützt.

### OpenCode \{#opencode}

1. Füge folgende Konfiguration zu deiner `opencode.json`-Datei hinzu:

   ```json
   {
     "$schema": "https://opencode.ai/config.json",
     "mcp": {
       "Logto": {
         "enabled": true,
         "type": "remote",
         "url": "https://mcp.logto.io"
       }
     }
   }
   ```

2. Führe folgenden Befehl aus, um dich zu authentifizieren:
   ```bash
   opencode mcp auth Logto
   ```
   Beachte, dass `Logto` dem MCP-Servernamen in deiner Konfigurationsdatei entspricht.

Ein Browserfenster öffnet sich. Melde dich mit deinem Logto Cloud-Konto an, um zu autorisieren und die Verbindung herzustellen.

### VS Code \{#vs-code}

1. Öffne die Befehlspalette (`Command + Shift + P`) und wähle **MCP: Add Server...**.
2. Wähle **HTTP** als Servertyp.
3. Gib die URL ein: `https://mcp.logto.io`. Du kannst wählen, sie für dein Workspace zu installieren, um bessere Isolierung und Verwaltung zu erhalten.
4. Wenn VS Code nach Authentifizierung fragt, erlaube es. Du wirst zur Logto Cloud-Anmeldeseite weitergeleitet. Melde dich mit deinem Logto Cloud-Konto an, um die Verbindung herzustellen.

Alternativ kannst du den Server zu `.vscode/mcp.json` oder deiner Benutzer-`mcp.json` hinzufügen:

```json
{
  "servers": {
    "logto": {
      "type": "http",
      "url": "https://mcp.logto.io"
    }
  }
}
```

### Windsurf \{#windsurf}

Windsurf dokumentiert keine CIMD-Unterstützung, daher verwende [`mcp-remote`](https://www.npmjs.com/package/mcp-remote) mit der statischen Client-ID.

1. Öffne die Befehlspalette (`Command + Shift + P`) und wähle **Windsurf: MCP Marketplace**.
2. Klicke im Bereich **Installed MCPs** rechts auf das Zahnradsymbol, um die MCP-Konfigurationsdatei zu öffnen.
3. Füge folgende [Konfiguration](https://docs.windsurf.com/windsurf/cascade/mcp#mcp_config-json) hinzu:

   ```json
   {
     "mcpServers": {
       "Logto": {
         "command": "npx",
         "args": [
           "mcp-remote",
           "https://mcp.logto.io",
           "--allow-http",
           "--static-oauth-client-info",
           "{ \"client_id\": \"mcp-client\", \"scope\": \"mcp:all\" }",
           "--resource",
           "https://mcp.logto.io/"
         ]
       }
     }
   }
   ```

Eine Logto Cloud-Anmeldeseite erscheint automatisch. Melde dich mit deinem Logto Cloud-Konto an, um die Verbindung herzustellen.

### Andere MCP-Clients \{#other-mcp-clients}

Logto MCP Server funktioniert mit jedem MCP-Client, der OAuth-Autorisierung unterstützt:

- **Wenn dein Client CIMD unterstützt**: Gib nur die MCP-Server-URL `https://mcp.logto.io` ein. Der Client entdeckt alles Weitere vom Server.
- **Andernfalls**: Verwende folgende Konfiguration.
  - **MCP-Server-URL:** `https://mcp.logto.io`
  - **OAuth-Client-ID:** `mcp-client` (kein Client-Secret)
  - **Redirect-URI:** eine Loopback-Adresse, z. B. `http://localhost:<port>/callback`
  - **Resource:** `https://mcp.logto.io/` (falls dein Client dies benötigt)
  - **Scope:** `mcp:all` (falls dein Client dies benötigt)

Logto MCP Server unterstützt keine Dynamic Client Registration (DCR). Wenn du KI-Anwendungsentwickler bist, [veröffentliche ein Client ID Metadata Document](/integrate-logto/third-party-applications/dynamic-apps#publish-a-client-id-metadata-document) für deine Anwendung, und sie kann sich ohne jegliche Einrichtung in Logto verbinden. Falls das nicht möglich ist, [kontaktiere uns](https://logto.io/contact) mit den Details deiner Anwendung.
