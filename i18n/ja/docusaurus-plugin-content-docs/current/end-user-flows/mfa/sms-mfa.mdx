# MFA のための SMS 認証 (SMS verification for MFA)

Logto は、SMS ベースの多要素認証 (多要素認証 (MFA)) 機能をサポートしており、ユーザーの登録済み電話番号にワンタイム認証コードを送信することでアカウントのセキュリティを強化します。SMS MFA は第 2 の認証 (Authentication) 要素として機能し、他の MFA 要素（TOTP、パスキー、バックアップコードなど）と組み合わせて、柔軟な二要素認証オプションを提供できます。

## 概念 \{#concepts}

SMS 認証 (SMS verification)、または電話番号認証 (Phone Number verification) は、最も利用しやすい MFA 方法の一つです。モバイル端末の普及を活用し、一時的なワンタイム認証コードをテキストメッセージで直接ユーザーのデバイスに配信します。追加のソフトウェアインストールが必要なアプリベースの認証 (Authentication) とは異なり、SMS MFA はすべてのモバイルデバイスに標準搭載されている既存のメッセージングインフラを利用するため、ユーザーは特別な設定なしですぐに利用できます。

## MFA のための SMS 認証 (SMS verification) の設定 \{#configure-sms-verification-for-mfa}

**ステップ 1: SMS コネクターとテンプレートの設定**

{/* prettier-ignore */}
1. <CloudLink to="/connectors/passwordless">コンソール > コネクター > メールおよび SMS コネクター</CloudLink> に移動します
2. 適切な SMS コネクター（Twilio、SMS Aero など）を選択します
3. 接続パラメーターを設定します
4. MFA 用の SMS テンプレートを専用の usageType で設定します
   - MFA 検証用は `MfaVerification` usageType
   - MFA バインド用は `BindMfa` usageType
5. コネクターの動作テストを行い、メッセージが正しく配信されることを確認します
6. プロバイダーごとのセットアップ手順は [SMS コネクター](/connectors/sms-connectors) を参照してください

**ステップ 2: MFA のための SMS を有効化**

1. <CloudLink to="/mfa">コンソール > 多要素認証 (MFA)</CloudLink> に移動します
2. 「SMS 認証コード」要素を有効化します。SMS MFA は他の MFA 要素（TOTP、パスキー、バックアップコードなど）と組み合わせて利用することを推奨します（単一要素依存の低減）。
3. **メール / SMS 2 段階認証** で、どのユーザーが SMS MFA を持つか選択します。[誰が SMS MFA を持つか](#who-has-sms-mfa) を参照してください。
4. 希望する MFA ポリシー（任意、適応型、必須）を設定します
5. 設定変更を保存します

:::note 重要な利用上の注意

1. **サインイン方法の制限**：SMS 認証コードは [サインイン方法 (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in) と MFA 要素 (2FA) の両方として同時に利用できません。SMS 実装ごとに 1 つの認証フローを選択してください。

2. **サインアップ方法の互換性**：SMS 認証コードはサインアップ方法と MFA の両方で同時に利用できます。Logto は選択した MFA ポリシーに基づき、同じ電話番号で 2 回 SMS 認証を要求しないようエンドユーザー登録フローを最適化します。

3. **パスワードリカバリーの互換性**：SMS 認証コードは [パスワードを忘れた場合](/end-user-flows/sign-up-and-sign-in/reset-password) と MFA の両方で同時利用できますが、この組み合わせは **推奨されません**。この設定では、ユーザーがパスワードリセット用の SMS 認証を利用してパスワードを再設定し、その後新しいパスワードで一次認証 (1FA) を行い、同じ SMS 方法で MFA 検証を行うことで MFA を回避できる可能性があり、MFA のセキュリティ効果が低下します。

:::

## 誰が SMS MFA を持つか \{#who-has-sms-mfa}

SMS MFA コードは常にユーザーのプライマリ電話番号に送信されます。<CloudLink to="/mfa">多要素認証 (MFA)</CloudLink> ページの **メール / SMS 2 段階認証** 設定で、どのユーザーが SMS MFA を持つかが決まります：

- **認証済みメールまたは電話番号を持つすべてのユーザー**：プライマリ電話番号を持つすべてのユーザーが、設定不要で SMS MFA を利用できます。
- **設定したユーザーのみ**：SMS MFA を設定したユーザーのみが利用できます。認証済み電話番号でサインアップしたユーザーも自動的に SMS MFA にはなりません。そのため、すべてのユーザーを登録せずに SMS を MFA オプションの一つとして提供できます。ユーザーは MFA セットアップフロー、[アカウントセンター](/end-user-flows/account-settings/by-account-center-ui)、または [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa) で設定できます。管理者は [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) を通じてユーザーごとに追加・削除できます。

この設定は [メール MFA](/end-user-flows/mfa/email-mfa) にも適用されます。デフォルトやモード切替時の挙動については [メール / SMS MFA 登録](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment) を参照してください。

:::note
**認証済みメールまたは電話番号を持つすべてのユーザー** の場合、プライマリ電話番号のみで SMS MFA を持つユーザーには SMS MFA レコードが保存されないため、`GET /api/my-account/mfa-verifications`、`GET /api/users/{userId}/mfa-verifications`、`user.mfaVerificationFactors`（カスタム JWT クレームや `PostSignIn` アクション）には表示されません。
:::

## SMS MFA セットアップフロー \{#sms-mfa-setup-flows}

MFA セットアッププロンプトは、ユーザー登録時またはサインイン後に表示されます（設定した [MFA ポリシー](/end-user-flows/mfa/configure-mfa#global-mfa-configuration) による）。

SMS MFA セットアップフローは以下の要素に影響されます：

- **MFA プライマリ要素の数**：複数のプライマリ要素がある場合、ユーザーはどれを設定するか選択する必要があります。プライマリ要素とは、バックアップコード以外の MFA 方法です。
- **バックアップコードの有効化**：有効化されている場合、プライマリ MFA 要素の設定後に自動的にバックアップコードが生成され、ユーザーに保存を促します。
- **サインアップ識別子の設定**：電話番号が [サインアップ識別子](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier) として使われ、登録時に SMS 認証コードで既に認証されている場合。
  - **認証済みメールまたは電話番号を持つすべてのユーザー** の場合、その番号は自動的に MFA 要素としてバインドされ、追加認証は不要です。他のプライマリ要素がある場合、UI に「2 段階認証を追加」オプションが表示され（スキップ可能）、MFA が有効であることも明示されます。
  - **設定したユーザーのみ** の場合、電話番号は他の要素と同様にマスク表示されます。ユーザーが選択した場合、またはそれが唯一のプライマリ要素の場合、Logto は登録時の認証を利用して設定するため、2 回目のコード送信はありません。
- **既存ユーザーデータ**：既存ユーザーがサインイン後に MFA を設定する場合、まず一次認証を完了し、その後 MFA セットアップに進みます。アカウントに既に認証済みプライマリ電話番号がある場合：
  - **認証済みメールまたは電話番号を持つすべてのユーザー** の場合、サインアップ識別子の場合と同様の挙動です。
  - **設定したユーザーのみ** の場合、電話番号はマスク表示されます。ユーザーが選択した場合、またはそれが唯一のプライマリ要素の場合、その番号に認証コードが送信され、ユーザーが入力すると SMS MFA が設定されます。

以下は、よくある SMS MFA バインドシナリオ 3 例です。

### シナリオ 1: 電話番号を MFA のみに利用（典型的なフロー） \{#scenario-1-phone-number-only-used-for-mfa-typical-flow}

電話番号がサインアップ識別子ではなく、MFA のみで利用する場合、標準のセットアップ手順に従います：

- SMS MFA 要素が 1 つだけの場合、その要素のセットアップ UI を直接表示します。
- 複数のプライマリ MFA 要素がある場合、「MFA を設定」リストページを表示し、ユーザーにどの要素を設定するか選択させます。

**設定したユーザーのみ** の場合も、このシナリオでは SMS が唯一のプライマリ要素となるため、登録時の認証を利用して設定されます。

サインアップ時に電話番号が認証されている（サインアップ識別子）かつアカウントに複数のプライマリ MFA 要素（例：SMS + パスキーや認証アプリ）がある場合、UI で「2 段階認証を追加」プロンプトが表示されます。ユーザーは他の要素を追加するかスキップできます。このプロンプトは MFA が既に有効であることも伝えます。

**設定したユーザーのみ** の場合、ユーザーはまずリストから要素を選択します。SMS、メール、サインインパスキーのみを設定した直後に「2 段階認証を追加」プロンプトが表示されます。

## SMS MFA 認証フロー \{#sms-mfa-verification-flows}

SMS MFA が有効なユーザーがサインインすると、一次認証 (1FA) 完了後、第 2 の認証 (Authentication) 要素 (2FA) として SMS 認証コードによる本人確認が求められます。

複数の MFA 要素が利用可能な場合、Logto は [MFA 設定](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) で定められた固定順（パスキー、認証アプリ OTP、SMS 認証コード、メール認証コード、バックアップコード）に従い、最優先の要素を直接表示します。最初に認証アプリ OTP など他の要素が表示された場合でも、**他の方法で認証する** をクリックして選択リストを開き、SMS 認証コードを選ぶことができます。

**例：**

<details>
  <summary>
    サインイン: `メールアドレス + パスワード` | MFA: `SMS 認証コード / 認証アプリ OTP /
    バックアップコード`
  </summary>

</details>

## エラーハンドリング \{#error-handling}

1. **電話番号がバインドされていない**

   - エラーコード: `session.mfa.mfa_factor_not_enabled`
   - 対応: まず電話番号をバインドするよう案内

2. **認証コードが間違っている**

   - エラーコード: `verification_code.code_mismatch`
   - 対応: 再入力を促し、リトライ回数を制限

3. **認証コードの有効期限切れ**

   - エラーコード: `verification_code.expired`
   - 対応: 新しい認証コードの再送信を促す

4. **送信レート制限超過**
   - エラーコード: `request.message_rate_limited`（Logto の宛先ごとの送信レート制限）または `connector.rate_limit_exceeded`（SMS コネクターのレート制限）
   - 対応: 待機時間を表示し、再送信を制限
