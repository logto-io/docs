# バックアップコード

## 概念 \{#concepts}

バックアップコード（リカバリーコードとも呼ばれます）は、多要素認証 (MFA) のための使い捨てコードであり、ユーザーの主要な認証要素（例：認証アプリやハードウェアトークン）が利用できない場合のバックアップとして機能します。

これらを紛失するとアカウントの復旧が困難になる場合があります。そのため、バックアップコードを有効にする前に追加の主要要素を設定し、優先順位を高くすることを推奨します。

Logto は、ユーザーが追加要素を設定すると自動的に 10 個のバックアップコードを生成します。各コードは一度しか使用できません。ユーザーは [組み込みのアカウントセンター UI](/end-user-flows/account-settings/by-account-center-ui)（`/account/backup-codes/regenerate`）、[Account API](/end-user-flows/account-settings/by-account-api#manage-backup-codes) を使ったカスタムセルフサービスインターフェース、または [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) を利用した管理ツールから、既存のコードをすべて使い切る前に新しいコードセットを再生成できます。

## MFA 用バックアップコードの設定 \{#configure-backup-codes-for-mfa}

1. <CloudLink to="/mfa">コンソール > 多要素認証</CloudLink> に移動します
2. 「バックアップコード」要素を有効にします。バックアップコードは唯一の MFA 要素としては使用できません。他の主要な MFA 要素（パスキー、認証アプリ、SMS、メール）と組み合わせて使用する必要があります。
3. 希望する MFA ポリシー（オプション、適応型、必須）を設定します
4. 設定変更を保存します

## バックアップコード管理の設定 \{#configure-backup-codes-management}

ユーザーは [組み込みのアカウントセンター UI](/end-user-flows/account-settings/by-account-center-ui)（`/account/backup-codes/manage` および `/account/backup-codes/regenerate`）を使用してバックアップコードを表示・再生成できます。また、Account API を利用してカスタムアカウント管理インターフェースを構築し、ユーザーがバックアップコードの表示、再生成、削除を行えるようにすることも可能です。これにより、アプリケーションのアカウント設定画面から直接リカバリーオプションを管理できます。

詳細な実装手順や API エンドポイントについては、[Account API によるアカウント設定](/end-user-flows/account-settings/by-account-api#manage-backup-codes) を参照してください。

## バックアップコード設定フロー \{#backup-codes-setup-flows}

バックアップコードは二次的な MFA 要素であるため、主要な MFA 要素が正常に設定された後にのみセットアップできます。自動生成された 10 個のバックアップコードがユーザーに表示され、ダウンロードや安全なコピーが可能です。ユーザーは MFA 設定プロセスを完了するために、バックアップコードを手動で確認する必要があります。

**バックアップコード**が有効で、ユーザーが他の有効な要素を持っているが未使用のバックアップコードが残っていない場合、Logto はサインイン時に新しいバックアップコードの生成と保存を促します。例えば：

- 以前に生成されたバックアップコードがすべて使用された場合。
- ユーザーが主要な MFA 要素を登録した後に **バックアップコード** を有効にした場合。

既存ユーザーのサインイン時、この再プロンプトはユーザーが MFA チャレンジを検証した後（またはパスキーでサインインした後）にのみ発生します。MFA 検証をバイパスするサインイン（信頼済みデバイス、低リスクの [適応型 MFA](/end-user-flows/mfa/adaptive-mfa) サインイン、またはユーザーがスキップした **オプション MFA** など）では、サインイン途中で新しいバックアップコードのバインドを促しません。また、通常の [エンタープライズシングルサインオン (SSO)](/end-user-flows/enterprise-sso) サインインでは、`acr_values` で MFA が明示的に要求されない限り、MFA 設定プロンプトはスキップされます。

## バックアップコード認証フロー \{#backup-codes-verification-flow}

バックアップコードは、主要な MFA 要素が利用できない場合の緊急認証手段として機能します。各コードは一度しか使用できず、認証に成功すると無効になります。

**認証の優先順位：**

- **まず主要要素**：他の MFA 要素が設定されている場合、主要要素（パスキー、TOTP、SMS、メール）が最初に表示されます。
- **バックアップコードへの切り替え**：主要要素が利用できない場合、「他の方法で認証する」をクリックしてバックアップコードに切り替え可能です。
- **フォールバックシナリオ**：すべての主要要素が削除された場合、バックアップコードが唯一の認証手段となります。サインイン時にバックアップコードで MFA 認証に成功すると、Logto は自動的に新しい主要要素の設定を促します。
