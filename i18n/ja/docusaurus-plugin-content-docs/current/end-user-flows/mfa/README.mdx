# 多要素認証 (Multi-factor authentication)

## MFA とは？ \{#what-is-mfa}

[多要素認証 (MFA)](https://auth.wiki/mfa) は、ログインプロセス中に追加の保護層を加えるセキュリティ手法です。ユーザーはデジタルアイデンティティを確立するために複数の認証情報を提供する必要があります。

認証 (Authentication) には主に 2 種類あります：

- **SFA/1FA (シングルファクター認証)**：これは初期のログイン方法で、通常は [ユーザー名 / メールアドレス / 電話番号とパスワード](/end-user-flows/sign-up-and-sign-in/sign-in) または [ソーシャルログイン](/end-user-flows/sign-up-and-sign-in/social-sign-in) が必要です。
- **MFA/2FA (多要素認証 / 二要素認証)**：MFA ではアカウントにアクセスするために少なくとも 2 つの異なる認証方法が必要となり、不正アクセスに対する防御力が大幅に強化されます。

認証要素とは、アイデンティティを確認するための手段です。属性ごとに分類されたさまざまな要素から選択できます：

| 種類 | 意味               | 認証要素（Logto サポート）                                           |
| ---- | ------------------ | -------------------------------------------------------------------- |
| 知識 | 知っていること     | パスワード、メール認証コード、バックアップコード                     |
| 所有 | 所持しているもの   | SMS 認証コード、認証アプリ OTP、ハードウェア OTP（セキュリティキー） |
| 生体 | 自分自身であること | 指紋や顔認証などのバイオメトリクス                                   |

MFA フローでは、最初の要素とは異なる属性カテゴリ（知識 / 所有 / 生体）から 2 番目の要素を使用することで、単一チャネルの侵害に対するセキュリティが強化されます。なお、Logto では 1FA と 2FA で異なる属性カテゴリを強制しませんが、同じメールまたは SMS 認証コード方式をサインイン方法（1FA）と MFA 要素（2FA）の両方で使用することはできません。

## なぜ MFA が必要なのか？ \{#why-do-we-need-an-mfa}

MFA は、特に B2B や B2E サービスにおいて不可欠なセキュリティ対策です。今日のデジタル環境で広く採用されている理由は複数あります：

- **アカウントハッキング**：不正なアカウントアクセスは依然として重大なセキュリティ脅威です。しかし、MFA は強力な保護を提供し、特にパスワード漏洩によるアカウントハックの 99.9% を効果的に防ぎます。パスワードレスログイン、強力なパスワードポリシー、パスワードマネージャー、攻撃対策などと組み合わせることで、コスト効率よくセキュリティを強化できます。
- **SaaS の普及**：多くの企業が従業員や機密データ・資産を保護するために MFA を導入しています。LastPass の調査によると、世界の企業の 57% が MFA を利用しており、前年から 12% 増加しています。
- **規制遵守**：MFA は、GDPR や NIST などのデータ保護規制への準拠を支援し、ユーザーデータの安全性を確保します。

## Logto のサポート \{#logto-support}

Logto では、ワンクリックで MFA を有効化でき、複雑な設定は不要です。[認証要素の有効化](/end-user-flows/mfa/configure-mfa) のクイックガイドから始めましょう。

**サポートされている MFA 要素**：

- [パスキー (WebAuthn)](/end-user-flows/mfa/webauthn)：セキュリティキーや生体認証を使ってパスワードレス体験を実現します。
- [認証アプリ OTP](/end-user-flows/mfa/authenticator-app-otp)：Google Authenticator や Authy などの認証アプリで生成される時限ワンタイムパスワード（TOTP）を利用します。
- [SMS 認証](/end-user-flows/mfa/sms-mfa)：SMS メッセージでワンタイムコード（認証コード）を送信して認証します。
- [メール認証](/end-user-flows/mfa/email-mfa)：メールでワンタイムコード（認証コード）を送信して認証します。
- [バックアップコード](/end-user-flows/mfa/backup-codes)：緊急時アクセス用の使い捨てバックアップコードを生成します。

**関連する MFA 機能**：

- [信頼済みデバイス](/end-user-flows/mfa/trusted-devices)：信頼されたブラウザで、時間制限付きかつ取り消し可能な認証情報により、繰り返し MFA を求められることを回避できます。ユーザーは、対象となるサインインまたはサインアップフローの最後に、別ページの **このデバイスを信頼する** でオプトインできます。
