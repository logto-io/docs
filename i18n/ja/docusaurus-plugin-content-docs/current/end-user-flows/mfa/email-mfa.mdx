# MFA 用メール認証 (Email verification for MFA)

Logto は、登録済みメールアドレスにワンタイム認証コードを送信することでアカウントのセキュリティを強化する、メールベースの多要素認証 (多要素認証 (MFA)) 機能をサポートしています。メール MFA は第 2 の認証要素として機能し、他の MFA 要素（TOTP、パスキー、バックアップコードなど）と組み合わせて、柔軟な二要素認証オプションを提供できます。

## 概念 (Concepts) \{#concepts}

メール認証は、最も普及している MFA 方法の一つです。メールアカウントの広範な普及を活用し、一時的なワンタイム認証コードをユーザーのメール受信箱に直接配信します。追加のソフトウェアインストールが必要なアプリベースの認証器とは異なり、メール MFA は既存のメールインフラを利用するため、ほぼすべてのインターネットユーザーがウェブブラウザ、メールクライアント、またはモバイルアプリを通じて即座に利用できます。特別なハードウェアや追加設定は不要で、メールアカウントさえあればすぐに利用可能です。

## MFA 用メール認証の設定 (Configure email verification for MFA) \{#configure-email-verification-for-mfa}

**ステップ 1: メールコネクターとテンプレートの設定**

{/* prettier-ignore */}
1. <CloudLink to="/connectors/passwordless">コンソール > コネクター > メール・SMS コネクター</CloudLink> に移動します
2. 適切なメールコネクター（SendGrid、Mailgun など）を選択します
3. 接続パラメーターを設定します
4. MFA 用の [メールテンプレート](/connectors/email-connectors/email-templates) を、専用の usageType で設定します：

   - MFA 検証用には `MfaVerification` usageType
   - MFA バインド用には `BindMfa` usageType
   - ヒント: [Logto Email Service](/connectors/email-connectors/built-in-email-service) には組み込みメールテンプレートが用意されています

5. プロバイダーごとのセットアップ手順は [メールコネクター](/connectors/email-connectors) を参照してください

**ステップ 2: MFA 用メールを有効化**

1. <CloudLink to="/mfa">コンソール > 多要素認証 (MFA)</CloudLink> に移動します
2. 「メール認証コード」要素を有効にします。メール MFA は他の MFA 要素（TOTP、パスキー、SMS、バックアップコード）と組み合わせて利用することを推奨します（単一要素依存の低減のため）。
3. **メール/SMS 2段階認証** で、どのユーザーがメール MFA を持つか選択します。詳細は [誰がメール MFA を持つか](#who-has-email-mfa) を参照してください。
4. 希望する MFA ポリシー（任意、適応型、必須）を設定します
5. 設定変更を保存します

:::note 重要な利用上の注意

1. **サインイン方法の制限**：メール認証コードは [サインイン方法 (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in) と MFA 要素 (2FA) の両方として同時に利用できません。メール実装ごとに 1 つの認証フローを選択してください。

2. **サインアップ方法の互換性**：メール認証コードはサインアップ方法と MFA の両方で同時に利用できます。Logto は選択した MFA ポリシーに基づき、同じメールアドレスで 2 回メール認証を要求しないようエンドユーザー登録フローを最適化します。

3. **パスワードリカバリーとの互換性**：メール認証コードは [パスワードを忘れた場合](/end-user-flows/sign-up-and-sign-in/reset-password) と MFA の両方で同時利用できますが、この組み合わせは **推奨されません**。この構成では、ユーザーがパスワードリセット用メール認証を利用してパスワードを再設定し、その新しいパスワードで一次認証 (1FA) を行い、続けて同じメール方式で MFA 検証を行うことで MFA を回避できる可能性があるため、MFA のセキュリティ効果が低下します。

:::

## 誰がメール MFA を持つか (Who has email MFA) \{#who-has-email-mfa}

メール MFA コードは常にユーザーの主メールアドレスに送信されます。<CloudLink to="/mfa">多要素認証 (MFA)</CloudLink> ページの **メール/SMS 2段階認証** 設定で、どのユーザーがメール MFA を持つかを決定します：

- **認証済みメールまたは電話番号を持つすべてのユーザー**：主メールアドレスを持つすべてのユーザーが、設定不要でメール MFA を持ちます。
- **設定したユーザーのみ**：メール MFA を設定したユーザーのみが利用できます。認証済みメールでサインアップしたユーザーでも自動的にメール MFA にはなりませんので、メールを MFA オプションの一つとして提供しつつ、全ユーザーへの強制登録を避けられます。ユーザーは MFA セットアップフロー、[アカウントセンター](/end-user-flows/account-settings/by-account-center-ui)、または [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa) で設定できます。管理者は [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) を通じてユーザーの追加・削除が可能です。

この設定は [SMS MFA](/end-user-flows/mfa/sms-mfa) にも適用されます。デフォルトやモード切替時の挙動については [メールと SMS MFA 登録](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment) を参照してください。

:::note
**認証済みメールまたは電話番号を持つすべてのユーザー** の場合、主メールアドレスのみでメール MFA を持つユーザーにはメール MFA レコードが保存されないため、`GET /api/my-account/mfa-verifications`、`GET /api/users/{userId}/mfa-verifications`、`user.mfaVerificationFactors`（カスタム JWT クレームや `PostSignIn` アクション）には表示されません。
:::

## メール MFA セットアップフロー (Email MFA setup flows) \{#email-mfa-setup-flows}

MFA セットアッププロンプトは、ユーザー登録時またはサインイン後に表示されます（設定した [MFA ポリシー](/end-user-flows/mfa/configure-mfa#global-mfa-configuration) による）。

メール MFA セットアップフローは以下の要素に影響されます：

- **MFA 主要素の数**：主要な MFA 要素が複数ある場合、ユーザーはどれを設定するか選択する必要があります。主要要素とはバックアップコード以外の MFA 方法です。
- **バックアップコード有効化**：有効化されている場合、主要 MFA 要素の設定後にバックアップコードが自動生成され、ユーザーに保存を促します。
- **サインアップ識別子の設定**：メールアドレスが [サインアップ識別子](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier) として使われ、登録時にメール認証コードで既に認証済みの場合
  - **認証済みメールまたは電話番号を持つすべてのユーザー** では、そのメールが自動的に MFA 要素としてバインドされ、追加認証は不要です。他の主要要素がある場合、UI に「別の 2段階認証を追加」オプションが表示され（スキップ可能）、MFA が有効であることが明示されます。
  - **設定したユーザーのみ** では、メールは他の要素と同様にマスクされたアドレスで提示されます。ユーザーが選択した場合、または唯一の主要要素である場合、Logto は登録時の認証を利用してセットアップするため、2 回目のコード送信はありません。
- **既存ユーザーデータ**：既存ユーザーがサインイン後に MFA を設定する場合、まず一次認証を完了し、その後 MFA セットアップに進みます。アカウントに既に認証済み主メールアドレスがある場合：
  - **認証済みメールまたは電話番号を持つすべてのユーザー** では、上記サインアップ識別子の場合と同様の挙動です。
  - **設定したユーザーのみ** では、メールはマスクされたアドレスで提示されます。ユーザーが選択した場合、または唯一の主要要素である場合、そのアドレスに認証コードが送信され、ユーザーがコードを入力するとメール MFA がセットアップされます。

以下は、よくあるメール MFA バインドシナリオ 3 例です。

### シナリオ 1: メールアドレスを MFA のみに利用（典型的なフロー） \{#scenario-1-email-address-only-used-for-mfa-typical-flow}

メールアドレスがサインアップ識別子でなく、MFA のみで利用する場合は、標準セットアップ手順に従います：

- メール MFA 要素が 1 つだけの場合、その要素のセットアップ UI を直接表示します。
- 主要 MFA 要素が複数ある場合、「MFA をセットアップ」リストページを表示し、ユーザーにどの要素を設定するか選択させます。

**設定したユーザーのみ** の場合も、このシナリオではメールが唯一の主要要素となるため、登録時の認証を利用してセットアップされます。

**設定したユーザーのみ** の場合、ユーザーはまずリストから要素を選択します。メール、SMS、サインインパスキーのみを設定した直後に「別の 2段階認証を追加」プロンプトが表示されます。

## メール MFA 検証フロー (Email MFA verification flows) \{#email-mfa-verification-flows}

メール MFA 有効ユーザーがサインインする際、一次認証 (1FA) を正常に完了した後、第 2 の認証要素 (2FA) としてメール認証コードによる本人確認が求められます。

複数の MFA 要素が利用可能な場合、Logto は [MFA 設定](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) で定められた固定順（パスキー、認証アプリ OTP、SMS 認証コード、メール認証コード、バックアップコード）に従い、最優先要素を直接開きます。最初に認証アプリ OTP など他の要素が表示された場合、ユーザーは **別の方法で認証** をクリックして選択リストを開き、メール認証コードを選ぶこともできます。

**例：**

<details>
  <summary>
    サインイン: `電話番号 + パスワード` | MFA: `メール認証コード / 認証アプリ OTP /
    バックアップコード`
  </summary>
  <img src="/img/assets/email-mfa-verification-flow.png" alt="Email MFA verification flow" />

## エラーハンドリング (Error Handling) \{#error-handling}

1. **メールアドレス未バインド**

   - エラーコード: `session.mfa.mfa_factor_not_enabled`
   - 対応: まずメールアドレスのバインドを案内

2. **認証コード不一致**

   - エラーコード: `verification_code.code_mismatch`
   - 対応: 再入力を促し、試行回数を制限

3. **認証コード有効期限切れ**

   - エラーコード: `verification_code.expired`
   - 対応: 新しい認証コードの再送信を促す

4. **送信レート制限超過**
   - エラーコード: `request.message_rate_limited`（Logto の宛先ごと送信レート制限）、`connector.rate_limit_exceeded`（メールコネクターのレート制限）
   - 対応: 待機時間を表示し、再送信を制限
