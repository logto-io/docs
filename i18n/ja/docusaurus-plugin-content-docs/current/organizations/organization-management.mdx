# 組織の管理

このセクションでは、開発者が Logto Console または Logto Management API を通じて組織を管理する方法について説明します。アプリ内で組織管理者がメンバーをセルフサービスで管理する方法についてではありません。組織体験の開発方法については、[こちらのガイド](/end-user-flows/organization-experience/organization-management) をご覧ください。

## Logto Console で管理する \{#manage-via-logto-console}

### 組織を作成する \{#create-an-organization}

<CloudLink to="/organizations">Console > Organizations</CloudLink> に移動し、「Create
organization」ボタンをクリックします。

### 基本設定 \{#basic-settings}

組織の名前、説明、ロゴ、カスタムデータなど、基本的な属性を設定できます。

### 組織メンバーに MFA を必須にする \{#require-mfa-for-organization-members}

組織のすべてのメンバーに MFA を有効にすることを必須にできます。これは、組織のリソースにアクセスする際にすべてのメンバーが追加の保護層を持つことを保証するセキュリティ対策です。

この機能を有効にするには、組織の詳細ページに移動し、「Multi-factor authentication (MFA)」トグルスイッチをオンにします。

:::note

この機能を正しく動作させるには、[少なくとも 1 つの MFA 方法を有効化](/end-user-flows/mfa) する必要があります。

:::

有効化後、MFA を設定していないメンバーは、MFA をセットアップするまで組織トークンを交換できません。組織トークンがいつ交換されるかの詳細は [認可 (Authorization)](/authorization) を参照してください。

ご注意ください：

- この機能は、ユーザーが組織トークンを交換する際に MFA が設定されているかどうか（`isMfaRequired`）のみを確認します。サインイン時のプロンプトはテナントの MFA ポリシーによって制御されます：**Optional MFA** の場合、**MFA setup prompt for users after organization enables MFA** を **Ask users to set up MFA on next sign-in (non-skippable)** に設定してください。**Adaptive MFA** がテナントレベルで有効な場合、Console はその組織プロンプト設定を非表示にし、リスクルールが発動しない低リスクのサインインでは、MFA 必須組織のメンバーでも MFA 検証が求められません。
- この機能は、アクセス トークン交換時にユーザーへ MFA 検証を強制しません。
- この機能は、ユーザーが利用できる MFA 方法を制限しません。

### ジャストインタイムプロビジョニング \{#just-in-time-provisioning}

[ジャストインタイムプロビジョニング](https://auth.wiki/jit-provisioning) は、ユーザーが初めてアプリにサインインした際に自動的に組織へ追加する仕組みです。Logto では、[エンタープライズシングルサインオン (SSO)](/end-user-flows/enterprise-sso) やメールドメインベースのプロビジョニングでサポートされています。特定のエンタープライズ IdP でサインインした場合や、特定のドメインのメールアドレスを使用した場合など、条件を満たすと自動的に組織へ追加されます。

また、組織に初めて参加するメンバーのデフォルト組織ロールも設定できます。

ジャストインタイムプロビジョニングの詳細や設定方法については、[こちらのセクション](/organizations/just-in-time-provisioning) をご覧ください。

### 組織メンバーの管理 \{#manage-organization-members}

ユーザーは 1 つ以上のロールを持つことができます。組織にメンバーを追加する際、複数のユーザーにロールを一括で割り当てることも可能です。割り当てを空欄のままにすると、追加されたユーザーにはロールが付与されません。

<CloudLink to="/users">Console > User management > User details page</CloudLink> では、そのユーザーがどの組織に所属しているか、どの組織ロールを持っているかを確認できます。

### 組織 M2M アプリケーションの管理 \{#manage-organization-m2m-applications}

マシン間通信アプリケーションも組織に追加できます。[マシン間通信アプリケーションにロールを割り当てる](/organizations/understand-how-organizations-work#organization-m2m-application) ことも、ユーザーにロールを割り当てるのと同様に可能です。

<CloudLink to="/applications">Console > Applications > Application details page</CloudLink> では、そのアプリケーションがどの組織に関連付けられているか、どの組織ロールを持っているかを確認できます。

## Logto Management API で管理する \{#manage-via-logto-management-api}

Logto Console でできることはすべて、[Management API](/integrate-logto/interact-with-management-api) を通じても実行できます。これには以下が含まれますが、これらに限定されません：

1. 組織の作成、削除、編集。
2. 組織テンプレートの管理：組織の権限やロールの作成、削除、編集。
3. 組織へのメンバー追加や削除。
4. ユーザーの組織ロールの割り当てや削除。
5. 組織へのマシン間通信アプリケーションの追加や削除。
6. マシン間通信アプリケーションの組織ロールの割り当てや削除。

Management API を利用して、より多くの組織レベルの体験や管理を実現する方法については、[こちら](/end-user-flows/organization-experience) もご覧ください。

機能の完全な一覧については、[API リファレンス](https://openapi.logto.io/group/endpoint-organizations) をご参照ください。

## 組織データ構造 \{#organization-data-structure}

各組織について、Logto は以下のデータを保存します：

### 組織 ID \{#organization-id}

_organization id_ は各組織の一意の識別子です。組織レベルのサインイン体験や組織トークンの取得に役立ちます。

### 名前 \{#name}

_name_ は組織レベルのサインインをサポートし、必要に応じて組織レベルのプロダクトインターフェースに統合できます。

### 説明 \{#description}

_description_ フィールドには、組織を識別・ラベル付けするためのテキストを追加できます。

### 組織ロゴ \{#organization-logos}

サインイン体験でクライアントの組織ロゴを動的に表示するには、組織設定ページでロゴをアップロードできます。

詳細は [組織固有のロゴ](/customization/match-your-brand/#organization-specific-branding) をご覧ください。

### カスタムデータ \{#custom-data}

_custom data_ は、組織に関する追加情報を保存するための JSON オブジェクトです。アプリケーションに関連する組織固有の設定やメタデータなど、必要な追加情報を保存できます。

### MFA 必須かどうか \{#is-mfa-required}

_isMfaRequired_ は、組織がメンバーに対して組織トークン交換前に MFA 設定を必須とするかどうかを示します。`true` に設定されている場合、Logto は MFA 要素が有効化されていないメンバーへの組織トークン発行を拒否します。該当メンバーのサインイン時 MFA 強制は、テナントの `organizationRequiredMfaPolicy` 設定で個別に制御されます。

詳細は [組織の管理](/organizations/organization-management#require-mfa-for-organization-members) をご覧ください。

### 作成日時 \{#created-at}

_createdAt_ は、組織が作成された日時（タイムゾーン付き）です。

### テナント ID \{#tenant-id}

_tenantId_ は、その組織が属するテナントを識別します。
