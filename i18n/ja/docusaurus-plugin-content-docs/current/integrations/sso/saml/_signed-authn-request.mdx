デフォルトでは、Logto は SAML 認証リクエスト（AuthnRequests）を署名せずに送信します。IdP が署名付き認証リクエストを要求する場合、Logto は生成されたサービスプロバイダー（SP）証明書でリクエストに署名できます。署名の有無はコネクターの **認証リクエストに署名** 設定によって完全に制御されており、Logto は IdP メタデータの `WantAuthnRequestsSigned` フラグを読み取りません。

サインインの中断を避けるため、次の順序で設定してください：

1. コネクターの `Connection` タブで **リクエスト署名証明書** セクションを見つけ、**新しいキーを生成** をクリックします。最初のキーは自動的に有効化され、以降に生成されたキーはローテーション用に無効状態でステージされます。
2. 有効なキーの証明書をダウンロードし、IdP に登録します。
3. **認証リクエストに署名** を有効にして保存します。有効化には有効な署名キーが必要です — キーがない状態で保存しようとすると拒否されます。
4. IdP 側で署名付きリクエストの要求や検証を別途設定できる場合は、今そのオプションを有効にし、サインインフローをテストしてください。

:::warning
両者の設定を同期させてください。証明書を登録する前に **認証リクエストに署名** を有効にしたり、Logto が署名する前に IdP 側で検証を必須にしたりすると、この接続経由のサインインができなくなります。リクエスト署名を検証しない IdP は署名を無視します。
:::

キー管理はトグルとは独立して動作します：

- 有効なキーは最大 1 つで、すべてのリクエストに署名します。キーの操作（生成、有効化、無効化、削除）は即時反映されます。
- ダウンタイムなしで証明書をローテーションするには：新しいキーを生成（無効状態でステージ）、その証明書を IdP に登録し、有効化します — 以前のキーは自動的に無効化され、その後削除できます。
- 有効なキーは削除できません。また、**認証リクエストに署名** が有効な間は無効化できません — 先に署名を無効にしてください。
- トグルをオフにしてもすべてのキーは保持されるため、再度有効化すれば同じ証明書で署名が再開されます — IdP 側での再設定は不要です。

Logto はデフォルトで RSA-SHA256 でリクエストに署名します。RSA-SHA512 を使用する場合は、Logto Management API を通じてコネクター設定の `requestSignatureAlgorithm` を `http://www.w3.org/2001/04/xmldsig-more#rsa-sha512` に設定してください。
