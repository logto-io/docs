# Logto MCP Server

Logto MCP Server はリモート [MCP (Model Context Protocol)](https://modelcontextprotocol.io/) サーバーです。AI アプリケーションに URL を追加し、Logto Cloud アカウントでサインインして、Logto との対話を始めましょう。

:::tip
Logto MCP Server は Logto と [MCP Auth](https://mcp-auth.dev) で構築されています。独自のリモート MCP サーバーを構築したい場合は、[独自のリモート MCP サーバーを構築する](#build-your-own-remote-mcp-server) をご覧ください。
:::

## できること \{#what-you-can-do}

- **プロジェクトに認証 (Authentication) を追加**：AI がフレームワークを自動検出し、Logto アプリケーションを作成し、動作する統合コードを生成します。React、Next.js、Vue、Nuxt、SvelteKit、Express、Go、Python、iOS、Android、Flutter など 38 以上のフレームワークに対応。
- **Logto について質問**：AI が Logto ドキュメントを検索し、出典付きで回答します。

今後、サインイン体験の設定、RBAC や権限管理のベストプラクティスガイド付きサポート、組織による B2B アプリ構築のためのマルチテナンシー設定など、さらに多くの機能が追加予定です。

## AI アプリケーションの接続方法 \{#how-your-ai-application-connects}

Logto MCP Server は、AI アプリケーションがサインイン時に自身を識別するための 2 つの方法をサポートしています。どちらの場合も Logto Cloud で何かを作成する必要はありません。

- **サーバー URL のみ（推奨）**：現在ほとんどの AI アプリケーションは [クライアント ID メタデータドキュメント (CIMD)](/integrate-logto/third-party-applications/dynamic-apps) をサポートしています。アプリケーションは所有する URL をクライアント ID として使用し、Logto はその URL からアプリケーション名やリダイレクト URI を取得します。入力するのはサーバー URL `https://mcp.logto.io` だけです。
- **静的クライアント ID**：CIMD をまだサポートしていないアプリケーションの場合は、公開 OAuth クライアント ID `mcp-client` を入力します。このクライアントはループバックリダイレクト URI（`http://localhost` または `http://127.0.0.1` の任意のポート）を受け付けます。

両方のオプションがある場合は、サーバー URL のみを使用してください。`mcp-client` を使った既存の接続も引き続き利用できるため、再接続の必要はありません。

サーバー URL のみで接続すると、Logto Cloud のサインインページにアプリケーション名とクライアント ID URL のホスト（例：`claude.ai` や `vscode.dev`）が表示された同意画面が表示されます。認可 (Authorization) する前に、ホストが利用中のアプリケーションと一致しているか確認してください。

## AI アプリケーションでの設定方法 \{#set-up-in-your-ai-application}

### Amp \{#amp}

1. [Amp](https://ampcode.com) で **Personal Settings** > **Integrations & MCP** を開き、**Add MCP Server** をクリックします。
2. 名前に `Logto MCP Server`、サーバー URL に `https://mcp.logto.io` を入力します。Amp は認証 (Authentication) 方法を自動検出します。
3. **Connect** をクリックし、Amp のプロンプトに従ってサインインします。
4. Logto Cloud アカウントでサインインし、接続を認可 (Authorization) します。

:::tip
Amp が長時間 **Detecting Authentication** のままの場合は、**Change** をクリックして **OAuth** を選択し、自動認証 (Authentication) 検出をスキップしてください。**Use Your Own OAuth App** の **OAuth Client ID** と **OAuth Client Secret** は空のままにし、**Connect** をクリックしてサインインプロンプトに従ってください。Amp は CIMD をサポートしているため、OAuth アプリの登録や `mcp-client` の入力は不要です。
:::

### Claude Code \{#claude-code}

```bash
claude mcp add --transport http logto https://mcp.logto.io
```

その後、Claude Code で `/mcp` を実行し、`logto` を選択して、ブラウザのログインフローに従い Logto Cloud アカウントで認証 (Authentication) します。シェルで `claude mcp login logto` を実行することもできます。

### Claude (ウェブ・デスクトップ) \{#claude-web-and-desktop}

1. **Customize** > **Connectors** を開き、**Add custom connector** をクリックします。
2. 名前に `Logto MCP Server`、リモート MCP サーバー URL に `https://mcp.logto.io` を入力します。**Advanced settings** の OAuth 設定は空のままにし、**Add** をクリックします。
3. **Connectors** リストで **Logto MCP Server** を見つけて **Connect** をクリックします。
4. Logto Cloud のサインインページにリダイレクトされます。Logto Cloud アカウントでサインインし、接続を認可 (Authorization) します。

コネクターは Claude アカウントに保存されるため、ウェブ版と Claude Desktop の両方で利用できます。

### ChatGPT および Codex \{#chatgpt-and-codex}

1. 左サイドバーで **Plugins** を開き、右上の **Add** > **Add custom MCP server** をクリックします。
2. 名前に `Logto MCP Server` を入力します。**Connection** で **Server URL** を選択し、`https://mcp.logto.io` を入力します。
3. デフォルトの **認証 (Authentication)**（**OAuth**）と **Advanced OAuth settings** をそのままにします。
4. **I understand and want to continue** を選択し、**Create as a plugin** をクリックします。
5. **Connect Logto MCP Server** ダイアログで **Connect Logto MCP Server** をクリックします。Logto Cloud アカウントでサインインし、接続を認可 (Authorization) します。

:::tip
サインイン後に **Logto MCP Server** が **Installed** に表示されない場合は、少し待ってから **Plugins** ページ右上のリフレッシュボタンをクリックしてください。
:::

Codex CLI でもサーバーを追加できます：

```bash
codex mcp add logto --url https://mcp.logto.io
codex mcp login logto
```

ブラウザウィンドウが開きます。Logto Cloud アカウントでサインインして接続してください。ChatGPT デスクトップアプリ、Codex CLI、Codex IDE 拡張はこの設定を共有します。

### Cursor \{#cursor}

Cursor はまだ CIMD をサポートしていないため、静的クライアント ID を使用します。

1. **Customize** > **MCPs** を開くか、`~/.cursor/mcp.json`（グローバル）または `.cursor/mcp.json`（プロジェクト）を開きます。
2. 次の設定を追加します：

   ```json
   {
     "mcpServers": {
       "Logto": {
         "url": "https://mcp.logto.io",
         "auth": {
           "CLIENT_ID": "mcp-client",
           "scopes": ["mcp:all"]
         }
       }
     }
   }
   ```

3. サーバーの横にある **Connect** をクリックします。Logto Cloud のサインインページが表示されます。Logto Cloud アカウントでサインインして接続してください。

サインインは Cursor デスクトップアプリから行ってください。Cursor のウェブ版や Cursor Agents で使用されるウェブコールバックはサポートされていません。

### OpenCode \{#opencode}

1. `opencode.json` ファイルに次の設定を追加します：

   ```json
   {
     "$schema": "https://opencode.ai/config.json",
     "mcp": {
       "Logto": {
         "enabled": true,
         "type": "remote",
         "url": "https://mcp.logto.io"
       }
     }
   }
   ```

2. 次のコマンドを実行して認証 (Authentication) します：
   ```bash
   opencode mcp auth Logto
   ```
   `Logto` は設定ファイル内の MCP サーバー名に対応しています。

ブラウザウィンドウが開きます。Logto Cloud アカウントでサインインして認可 (Authorization)・接続してください。

### VS Code \{#vs-code}

1. コマンドパレット（`Command + Shift + P`）を開き、**MCP: Add Server...** を選択します。
2. サーバータイプとして **HTTP** を選択します。
3. URL に `https://mcp.logto.io` を入力します。ワークスペースにインストールして分離・管理を強化することもできます。
4. VS Code から認証 (Authentication) を求められたら許可してください。Logto Cloud のサインインページにリダイレクトされます。Logto Cloud アカウントでサインインして接続してください。

または、`.vscode/mcp.json` またはユーザーの `mcp.json` にサーバーを追加します：

```json
{
  "servers": {
    "logto": {
      "type": "http",
      "url": "https://mcp.logto.io"
    }
  }
}
```

### Windsurf \{#windsurf}

Windsurf は CIMD サポートを明記していないため、静的クライアント ID で [`mcp-remote`](https://www.npmjs.com/package/mcp-remote) を使用します。

1. コマンドパレット（`Command + Shift + P`）を開き、**Windsurf: MCP Marketplace** を選択します。
2. **Installed MCPs** セクションで右側の設定アイコンをクリックし、MCP 設定ファイルを開きます。
3. 次の [設定](https://docs.windsurf.com/windsurf/cascade/mcp#mcp_config-json) を追加します：

   ```json
   {
     "mcpServers": {
       "Logto": {
         "command": "npx",
         "args": [
           "mcp-remote",
           "https://mcp.logto.io",
           "--allow-http",
           "--static-oauth-client-info",
           "{ \"client_id\": \"mcp-client\", \"scope\": \"mcp:all\" }",
           "--resource",
           "https://mcp.logto.io/"
         ]
       }
     }
   }
   ```

Logto Cloud のサインインページが自動的に表示されます。Logto Cloud アカウントでサインインして接続してください。

### その他の MCP クライアント \{#other-mcp-clients}

Logto MCP Server は、OAuth 認可 (Authorization) をサポートする任意の MCP クライアントで動作します：

- **クライアントが CIMD をサポートしている場合**：MCP サーバー URL `https://mcp.logto.io` のみ入力してください。クライアントが他の情報をサーバーから自動取得します。
- **それ以外の場合**：次の設定を使用してください。
  - **MCP サーバー URL:** `https://mcp.logto.io`
  - **OAuth クライアント ID:** `mcp-client`（クライアントシークレット不要）
  - **リダイレクト URI:** `http://localhost:<port>/callback` などのループバックアドレス
  - **リソース:** `https://mcp.logto.io/`（クライアントが必要とする場合）
  - **スコープ:** `mcp:all`（クライアントが必要とする場合）

Logto MCP Server は Dynamic Client Registration (DCR) をサポートしていません。AI アプリケーション開発者の場合は、[クライアント ID メタデータドキュメントを公開](/integrate-logto/third-party-applications/dynamic-apps#publish-a-client-id-metadata-document) すれば、Logto 側での設定なしで接続できます。それが難しい場合は、[お問い合わせ](https://logto.io/contact) からアプリケーションの詳細をご連絡ください。

## 独自のリモート MCP サーバーを構築する \{#build-your-own-remote-mcp-server}

Logto MCP Server は Logto と [MCP Auth](https://mcp-auth.dev) で構築されています。認証 (Authentication) 機能付きで独自のリモート MCP サーバーを構築したい場合は、次のリソースをご覧ください：

- [Remote MCP server in action: a new entry point for SaaS products in the AI era](https://blog.logto.io/remote-mcp-server-in-action)
- [Discord に参加](https://discord.gg/fUQmaFyAam)：リモート MCP サーバー構築の知見やベストプラクティスを共有
- [MCP Auth](https://mcp-auth.dev)：MCP サーバーに本番運用レベルの認証 (Authentication) を追加するために必要なすべて。仕様書を読むのに何週間も費やしたり、複雑な配線をする必要はありません。
