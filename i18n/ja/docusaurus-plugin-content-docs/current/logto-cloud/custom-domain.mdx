# カスタムドメイン

:::note
サービス公開後にドメインを変更すると、アプリケーションコードや各種連携が旧ドメインを参照し続けるため、トラブルの原因となる場合があります。スムーズな移行のため、**本番テナント作成時にカスタムドメインを設定することを推奨**します。
:::

Logto テナントには、デフォルトで無料のドメイン `{{tenant-id}}.app.logto` が付与されます。しかし、`auth.example.com` のようなカスタムドメインを利用することで、ユーザー体験やブランド認知を向上させることができます。

カスタムドメインは、以下の用途で利用されます：

- [サインイン・登録ページ](/end-user-flows/sign-up-and-sign-in) の URL
- [ソーシャルコネクター](/connectors/social-connectors) や [エンタープライズ SSO コネクター](/connectors/enterprise-connectors) のコールバック URI
- [パスキー](/end-user-flows/mfa/webauthn) および [パスキーサインイン](/end-user-flows/sign-up-and-sign-in/passkey-sign-in) 関連の URL（パスキー連携後にドメインを変更すると、MFA やパスキーサインインが利用できなくなる場合があります）
- アプリケーション連携用の [SDK エンドポイント](/integrate-logto/application-data-structure#openid-provider-configuration-endpoint)
- サードパーティプラットフォーム（WeChat、Apple、その他静的ファイル設置が必要なサービス等）向けのドメイン所有権確認ファイル

## 複数カスタムドメインのサポート \{#multiple-custom-domains}

Logto では、**1 テナントに対して複数のカスタムドメイン** を設定できるようになりました。これにより、複数のブランドドメインからサインインページへアクセス可能です。

**プランごとの上限：**

- **開発テナント**：2 つまで無料でカスタムドメイン追加可能（テスト用途）
- **フリープラン**：1 つまで無料でカスタムドメイン追加可能
- **プロプラン**：1 つまで標準で追加可能、アドオンで最大 10 個まで追加可能
- **エンタープライズプラン**：10 個以上や特別な要件の場合は [お問い合わせ](https://logto.io/contact) ください

詳細は [Logto 料金表](https://logto.io/pricing) をご覧ください。

**複数カスタムドメインの活用例：**

- 地域・ロケール・アプリケーション・組織・トップレベルドメインごとに異なるドメインを利用
- サインイン前後で一貫したブランド体験を維持し、信頼性を向上
- [カスタム UI](/customization) により、地域やブランドごとに異なる認証体験を提供

## Console でカスタムドメインを設定する \{#configure-custom-domains-in-console}

Logto Console で新しいカスタムドメインを追加する手順は以下の通りです：

1. <CloudLink to="/tenant-settings/domains">Console > 設定 > ドメイン</CloudLink> へ移動します。
2. 「カスタムドメインを追加」セクションで、サブドメイン（例：`auth.example.com`、`auth.us.example.com`）を入力し、「ドメインを追加」をクリックします。

   <img src="/img/assets/custom-domain-section.png" alt="Add domain" />

3. テーブル内の **CNAME** 値 `domains.logto.app` をコピーし、ドメインの DNS プロバイダーでレコードを追加します。

   <img src="/img/assets/custom-domain-processing.png" alt="Custom domain processing" />

4. 認証および SSL 証明書の発行を待ちます。
   1. カスタムドメインが追加されるまで 10 秒ごとに自動でレコードを検証します。入力したドメイン名や DNS レコードが正しいことを確認してください。
   2. 検証は通常数分で完了しますが、DNS プロバイダーによっては最大 24 時間かかる場合があります。処理中は他の画面に移動しても問題ありません。

複数のカスタムドメインを追加する場合は、上記手順をドメインごとに繰り返してください。

## ドメイン所有権確認ファイル \{#domain-verification-files}

一部のサードパーティプラットフォームでは、OAuth や SSO などの連携前に、ドメイン所有権を証明するためのテキストまたは JSON ファイルの設置が求められます。Logto のカスタムドメインは Logto Cloud を指しているため、独自サーバーにファイルをアップロードできませんが、Logto 側でファイルをホスティングできます。

カスタムドメインが **アクティブ** になった後、<CloudLink to="/tenant-settings/domains">Console > 設定 > ドメイン</CloudLink> で該当ドメインカードを開き、**ドメイン所有権確認ファイル** セクションからファイルの追加・更新・削除が可能です。

**対応パス**

- 拡張子付きのルート直下ファイル（例：`/MP_verify_xxx.txt`、`/apple-developer-domain-association.txt`）
- `/.well-known/` 配下のパス（例：`/.well-known/apple-developer-domain-association.txt`）

パスセグメントには英数字・ドット・ハイフン・アンダースコアのみ使用可能です。`/.well-known/` 以外のネストされたパスは非対応です。

**制限事項**

- 1 カスタムドメインあたり **10** ファイルまで
- 1 ファイルあたり最大 **16,384** 文字
- コンテンツタイプ：プレーンテキスト（`text/plain`）または JSON（`application/json`）

保存後、Logto はカスタムドメインへの `GET` および `HEAD` リクエストに対して完全一致でファイルを返します。例：

```
https://auth.example.com/MP_verify_xxx.txt
https://auth.example.com/.well-known/apple-developer-domain-association.txt
```

既存の Logto ルートが優先されます。他の Logto ハンドラーと競合しない場合のみ、確認ファイルが配信されます。

## トラブルシューティング \{#troubleshooting}

<details>
<summary>

### SSL 証明書の問題 \{#ssl-certificate-issues}

</summary>

カスタムドメイン設定時に SSL 証明書の問題が発生した場合、DNS 設定の CAA レコードが原因の可能性があります。CAA レコードは、どの認証局（CA）が証明書を発行できるかを指定します。CAA レコードを利用している場合は、Logto で証明書を発行できるよう "letsencrypt.org" と "pki.goog" の両方を許可してください。

CAA レコードに関連する SSL 証明書の問題の解決方法は、[Cloudflare のドキュメント](https://developers.cloudflare.com/ssl/edge-certificates/caa-records/) を参照してください。

</details>

<details>
<summary>

### 「The hostname is associated with a held zone」エラー \{#the-hostname-is-associated-with-a-held-zone-error}

</summary>

カスタムドメイン追加時に「The hostname is associated with a held zone, please contact the owner to have the hold removed」というエラーが表示される場合、そのドメインがすでに Cloudflare のゾーンに登録されており、「Zone Hold」状態になっています。詳細は [Cloudflare のドキュメント](https://developers.cloudflare.com/fundamentals/setup/account/account-security/zone-holds/) をご覧ください。

この問題を解決するには、ゾーンホールドを解除する必要があります。解除方法は上記リンクを参照してください。

</details>

<details>
<summary>

### Cloudflare 管理ドメインでの「Connection timed out (Error code 522)」\{#cloudflare-522-timeout}

</summary>

ドメインが Cloudflare で管理されている場合、CNAME レコードの Cloudflare プロキシを無効にしてください。

</details>

<details>
<summary>

### カスタムドメイン設定後の「Redirect URI does not match」エラー \{#redirect-uri-mismatch}

</summary>

カスタムドメイン追加後に「redirect URI does not match」エラーが発生した場合、SDK 設定のエンドポイントをカスタムドメインに更新する必要があります。

**「プライマリドメイン」について：**

Logto には「プライマリドメイン」設定はありません。カスタムドメイン追加後も、カスタムドメインとデフォルトの `{tenant-id}.logto.app` ドメインの両方が有効です。SDK の `endpoint` パラメーターで指定したドメインが認証フローで利用されます。

**解決方法：**

SDK 初期化時の `endpoint` パラメーターをカスタムドメインに更新してください：

```typescript
const client = new LogtoClient({
  endpoint: 'https://auth.example.com', // カスタムドメインを指定
  appId: 'your-app-id',
  // ... その他のオプション
});
```

また、<CloudLink to="/applications">Console → アプリケーション</CloudLink> で登録済みのリダイレクト URI が利用するドメインと一致しているか確認してください。

**注意:** Logto はカスタムドメイン用の SSL 証明書を自動で発行・管理します。独自に証明書を用意する必要はありません。

</details>

## カスタムドメインの利用 \{#use-custom-domains}

設定が完了すると、カスタムドメイン名とデフォルトの Logto ドメイン名の両方がテナントで利用可能になります。ただし、カスタムドメイン名を有効化するには追加設定が必要です。

:::note

本記事では、カスタムドメインを `auth.example.com` と仮定します。

:::

### アプリケーション向け SDK エンドポイントの更新 \{#updating-the-sdk-endpoint-for-applications}

Logto SDK の初期化コードで、エンドポイントのドメイン名をカスタムドメインに変更してください。

```typescript
const client = new LogtoClient({
  ...,// その他のオプション
  endpoint: 'https://auth.example.com',
});
```

<CloudLink to="/applications">Console > アプリケーション</CloudLink> のアプリ詳細ページで「エンドポイント
&
資格情報」セクションまでスクロールし、ドメインのドロップダウンを切り替えて、アプリ設定用のエンドポイントを確認・コピーできます。

### その他アプリケーションの認証エンドポイント変更 \{#modifying-auth-endpoints-for-other-applications}

Logto SDK を利用していないアプリケーションの場合も、認証エンドポイントのドメインを更新する必要があります。

認証エンドポイントは以下の well-known URL で確認できます：

```
https://auth.example.com/oidc/.well-known/openid-configuration
```

### ソーシャルコネクターのリダイレクト URI 更新 \{#updating-social-connector-redirect-uris}

[ソーシャルコネクター](/connectors/social-connectors) は OIDC/OAuth プロトコルを利用しています。カスタムドメイン経由でサインインする場合、リダイレクト URI も自動的にカスタムドメインが利用されます。ソーシャルプロバイダーの開発者コンソールでリダイレクト URI を更新してください。

**手順：**

1. <CloudLink to="/connectors/social">Console > コネクター > ソーシャルコネクター</CloudLink> で該当コネクターを選択
2. コネクター詳細に表示されるリダイレクト URI をコピー（Logto は設定済みカスタムドメインごとに全てのリダイレクト URI を表示します）
3. このリダイレクト URI をソーシャルプロバイダーの開発者コンソール（Google、GitHub、Facebook など）に追加

**複数カスタムドメインの場合：**

- 設定した全カスタムドメイン分のリダイレクト URI を追加してください。どのドメインからアクセスしてもソーシャルログインが動作します。
- デフォルトの Logto ドメイン（`*.logto.app`）も引き続き有効です。必要に応じて追加してください。
- GitHub コネクターの場合、GitHub Apps を利用してください（複数リダイレクト URI 対応）。OAuth Apps は 1 つのリダイレクト URI のみ対応です。

### OIDC ベースのエンタープライズ SSO コネクターのリダイレクト URI 更新 \{#updating-oidc-enterprise-sso-redirect-uris}

[OIDC ベースのエンタープライズコネクター](/connectors/enterprise-connectors) もソーシャルコネクターと同様の手順です。

**手順：**

1. <CloudLink to="/enterprise-sso">Console > エンタープライズ SSO</CloudLink> で該当 OIDC
   コネクターを選択
2. コネクター詳細からリダイレクト URI をコピー（設定済みカスタムドメインごとに全て表示されます）
3. アイデンティティプロバイダー (IdP) の設定でリダイレクト URI を更新

**複数カスタムドメインの場合：** 全てのリダイレクト URI を IdP に追加してください。これにより、どのドメインでもエンタープライズ SSO が利用可能になります。

### SAML ベースのエンタープライズ SSO コネクターの ACS URL 更新 \{#updating-saml-enterprise-sso-acs-urls}

[SAML ベースのエンタープライズコネクター](/connectors/enterprise-connectors) では、リダイレクト URI の代わりに Assertion Consumer Service (ACS) URL を利用します。

**手順：**

1. <CloudLink to="/enterprise-sso">Console > エンタープライズ SSO</CloudLink> で該当 SAML
   コネクターを選択
2. 「IdP で設定」セクションでドメインのドロップダウンを切り替え、カスタムドメインを選択
3. 対応する ACS URL をコピー
4. SAML アイデンティティプロバイダーの設定に ACS URL を追加

**重要:** 選択したドメインが、SSO 認証後のリダイレクト先となります。アプリケーションが SAML レスポンスを受け取るドメインに合わせて設定してください。

### MFA・サインイン用パスキー \{#passkey-for-mfa}

[多要素認証 (MFA) 用パスキー](/end-user-flows/mfa/webauthn) および [パスキーサインイン](/end-user-flows/sign-up-and-sign-in/passkey-sign-in) は、登録時のドメインに紐付けられます。パスキーを利用するには、登録したのと同じドメインでサインインする必要があります。

現時点の制限：Logto はドメインをまたいだパスキー認証に未対応です。たとえば `auth.us.example.com` でパスキー登録した場合、そのパスキーは `auth.us.example.com` でのみ MFA 検証やパスキーサインインに利用できます。他のカスタムドメインでは利用できません。

同一ドメインでサインインを提供する他システムへパスキーを移行したい場合は、[Management API でエクスポート](/end-user-flows/mfa/webauthn#export-passkeys) してください。
