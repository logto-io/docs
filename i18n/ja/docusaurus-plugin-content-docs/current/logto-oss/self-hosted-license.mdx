# セルフホスト型ライセンス

セルフホスト型ライセンスは、[Logto セルフホスト型プラン](https://logto.io/self-hosted-plans) の有料機能を独自の Logto OSS インスタンスでアンロックする署名付きキーです。ライセンスがない場合、Logto OSS は従来通りの動作となります。

:::note
ライセンスはセルフホスト型 Logto OSS 専用です。Logto Cloud では、機能は [テナントのプラン](/logto-cloud/billing-and-pricing) に含まれており、ライセンスエンドポイントは利用できません。
:::

## ライセンスでアンロックされる機能 \{#what-a-license-unlocks}

セルフホスト型 Pro ライセンスをインストールすると、インスタンスで以下の機能が利用可能になります：

| 機能                                                                                | ライセンスなしの場合                     | ライセンスありの場合                                                                               |
| ----------------------------------------------------------------------------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------- |
| [Logto ブランディングの非表示](/customization/match-your-brand#hide-logto-branding) | 「Powered by Logto」が常に表示されます。 | 非表示にできます。                                                                                 |
| [独自 UI の持ち込み](/customization/bring-your-ui) およびカスタム CSP ソース        | 利用できません。                         | [独自ストレージの設定](#set-up-storage-for-bring-your-ui) でサインイン UI をアップロードできます。 |
| コンソールメンバーと招待                                                            | 利用できません。                         | コンソールにメンバーを招待し、**テナント設定 > メンバー** でロールを管理できます。                 |
| コンソールの必須 MFA                                                                | オプションの MFA のみ。                  | すべてのコンソールメンバーに MFA 設定を必須化できます（**テナント設定 > 設定**）。                 |
| [SAML アプリ](/integrate-logto/saml-app)                                            | 最大 3 つまで。                          | SAML アプリ数に制限なし。                                                                          |

このリストにない機能は、ライセンスによる影響を受けません。

## ライセンスの取得 \{#get-a-license}

[セルフホスト型プランページ](https://logto.io/self-hosted-plans) からライセンスをリクエストしてください。Logto から同じライセンスに対して 2 つのキーが提供されます：

- **本番用キー**：サブスクリプションでカバーされる本番環境のデプロイに使用します。注文書に特別な記載がない限り、各サブスクリプションは 1 つの本番デプロイをカバーします。
- **非本番用キー**：同じ本番デプロイをサポートする開発・テスト・ステージング環境用に使用します。これらのデプロイは本番トラフィックを処理してはいけません。

どちらのキーも同じ機能とクォータをアンロックします。2 つのキーがあるからといって、本番デプロイを 2 つ運用できるわけではありません。利用許諾は [セルフホスト型サブスクリプション規約](https://logto.io/terms/self-hosted) および注文書に従います。

インストールしたキーによって、どの種類のデプロイかを Logto に伝えます。Logto は技術的な検証は行わないため、デプロイに合ったキーをインストールしてください。

## ライセンスのインストール \{#install-a-license}

ライセンスはコンソールまたは Management API からインストールできます。いずれの場合も、Logto はインスタンス上で署名を検証し、不正・改ざん・期限切れのキーは拒否します。

### コンソールでのインストール \{#in-console}

1. **コンソール > テナント設定 > ライセンス** に移動します。
2. ライセンスキーを貼り付けて **ライセンスをインストール** をクリックします。

インストール後、ページにライセンスの詳細が表示されます。別のキー（例：非本番用から本番用、または新規発行キー）に切り替える場合は **ライセンスを置き換え** をクリックしてください。

### Management API の利用 \{#using-the-management-api}

[Logto Management API](/integrate-logto/interact-with-management-api) 用のアクセス トークンで、`PUT /api/systems/license` にキーを送信します：

```bash
curl -X PUT 'https://your-logto-endpoint/api/systems/license' \
  -H 'Authorization: Bearer <access_token>' \
  -H 'Content-Type: application/json' \
  -d '{ "license": "<your_license_key>" }'
```

成功時は `204 No Content` を返します。失敗時は以下の通りです：

- `400` および `license.invalid_key`：Logto による署名がない、または改ざんされたキー。
- `400` および `license.expired_key`：有効期限切れのキー。新しいキーを取得して再インストールしてください。
- `501`：Logto Cloud 上で動作している場合。

インストール済みの内容を確認するには、`GET /api/systems/license` を送信します。プラン・環境・権利・有効期限・リフレッシュ状況が返されます。キー自体は返されず、未インストール時は `404` です。詳細なリクエスト・レスポンススキーマは [Management API リファレンス](https://openapi.logto.io) を参照してください。

### 複数インスタンスの場合 \{#multiple-instances}

ライセンスは Logto データベースに保存されるため、同じデータベースを共有するすべての Logto インスタンスで 1 回だけインストールすれば OK です。

## リフレッシュと猶予期間 \{#refresh-and-grace-period}

Logto はライセンス署名をローカルで検証するため、アプリケーションへのサインインは Logto への接続に依存せず、リフレッシュ失敗でサインイントラフィックが止まることはありません。

更新やキャンセルを反映するため、インスタンスは Logto Cloud と通信します：

- **週次チェックイン**：最後の正常なリフレッシュから 7 日以上経過すると、リクエスト処理の一環としてバックグラウンドでライセンスをリフレッシュします。失敗時は後で再試行（最大 1 時間に 1 回）。インストール直後は即時リフレッシュされます。
- **30 日間の猶予**：リフレッシュに失敗した場合（例：インターネットに接続できない等）、最後の正常なリフレッシュから 30 日間は機能が維持されます。その後は OSS デフォルトに戻ります。
- **リフレッシュ拒否**：サブスクリプションキャンセル等でリフレッシュが拒否された場合、ライセンスページに理由が表示されます。猶予期間は最後の正常なリフレッシュからカウントされます。

リフレッシュはインスタンスから `https://cloud.logto.io` へのアウトバウンド HTTPS リクエストです。ファイアウォール越しの場合はこの宛先を許可してください。

### インスタンスが送信する内容 \{#what-your-instance-sends}

リフレッシュリクエストには以下のみが含まれます：

- ライセンスキー（`licenseId` で識別）
- `deploymentId`：ライセンス初回インストール時に生成されるランダム識別子。データベースに保存され、同じ DB を使う全インスタンスで共有・不変です（ライセンス置き換え時も同じ）。
- Logto バージョン
- デプロイの利用状況：月間アクティブユーザー数、月間アクセス トークン数、テナント数（[利用状況レポートを無効化](#turn-off-usage-reporting) していない場合）

利用状況は合計値のみで、個人情報は含みません。Logto はホスト名・ドメイン・設定・その他データを収集しません。このデータはライセンスの有効性維持と、プランの [利用上限](#usage-limits) との比較に使われます。詳細は [セルフホスト型サブスクリプション規約](https://logto.io/terms/self-hosted) の 10.2 節を参照してください。挙動はオープンソースで、[`LicenseReader.ts`](https://github.com/logto-io/logto/blob/master/packages/core/src/license/LicenseReader.ts) をご覧ください。

### 利用状況レポートの無効化 \{#turn-off-usage-reporting}

リフレッシュを実行する可能性のある、**すべての** データベース共有 Logto インスタンスでこの環境変数を設定してください：

```bash
SELF_HOSTED_LICENSE_USAGE_REPORTING_DISABLED=1
```

利用状況なしでもリフレッシュは実行され、上限超過時はコンソールで警告が表示されます。

## 利用上限 \{#usage-limits}

各プランには利用上限があります。強制されることはなく、上限超過でサインインがブロックされたり機能が停止することはありません。代わりにコンソールにバナーが表示されます。

| 指標                    | 本番用キー                                  | 非本番用キー |
| ----------------------- | ------------------------------------------- | ------------ |
| 月間アクティブユーザー  | Self-hosted Pro は 50,000、または注文書記載 | 無制限       |
| 本番デプロイ数          | 1                                           | 無制限       |
| 月間アクセス トークン数 | 無制限                                      | 50,000       |

本番デプロイは、過去 15 日以内にライセンスをリフレッシュした場合にアクティブと見なされます。

上限超過時は、[セルフホスト型サブスクリプション規約](https://logto.io/terms/self-hosted) の 4.2 節に従い、30 日以内にプランアップグレードまたは利用削減について Logto へご連絡ください。

### 利用状況ステートメントの取得 \{#get-a-usage-statement}

Logto から利用状況ステートメントの提出を求められた場合、[Logto Management API](/integrate-logto/interact-with-management-api) 用のアクセス トークンで `GET /api/systems/license/usage-statement` を送信してください。直近 12 か月分の月間アクティブユーザー数とアクセス トークン数がデータベースから返されます。

## ライセンスの有効期限 \{#license-expiration}

ライセンスは 1 年間有効で、**有効期限** がその終了日です。

- **更新時**：インスタンス側で特別な操作は不要です。更新後最初のリフレッシュで新しいキーに置き換わり、有効期限が 1 年延長されます。ページに直近の過去日が数日間表示されることがありますが、機能はその間も利用可能です。
- **未更新時**：期間終了後のリフレッシュは拒否されます。機能は 30 日間の猶予期間終了まで利用でき、その後は OSS デフォルトに戻ります（ライセンス未インストール時と同様）。ライセンスページに説明バナーと実施日が表示されます。
- **猶予期間終了時**：再度機能をアンロックするには新しいキーをインストールしてください。必要な場合はライセンス取得時の連絡チャネルから Logto へご連絡ください。

### 機能が無効化された場合の挙動 \{#what-happens-when-features-are-turned-off}

OSS デフォルトへの復帰は、ライセンスで作成したものを削除しません：

- **Logto ブランディングの非表示**：「Powered by Logto」マークが再表示されます。設定は保存されており、再度ライセンスをインストールすれば適用されます。
- **SAML アプリ**：4 つ目以降も残りますが、上限未満になるまで新規作成できません。
- **必須 MFA**：常にオフにできます。ライセンスなしで再度オンにはできません。
- **独自 UI・カスタム CSP・コンソール招待**：該当機能が必要な新規変更はできませんが、既存データは保持されます。

## 独自 UI 用ストレージの設定 \{#set-up-storage-for-bring-your-ui}

Logto Cloud では、Bring your UI のアセットは Logto がホストします。独自インスタンスでは、設定したオブジェクトストレージに保存されます。Logto はアップロードを解凍し、そこにファイルを保存・配信します。

[ファイルストレージプロバイダー](/logto-oss/file-storage-provider) と同じ JSON 構造で `experienceBlobsProvider` システム設定を指定します。例：S3 互換ストレージの場合

```bash
pnpm logto db system set experienceBlobsProvider '{"provider":"S3Storage","accessKeyId":"my-access-key-id","accessSecretKey":"my-secret-access-key","bucket":"logto-sie","endpoint":"https://s3.us-east-2.amazonaws.com"}'
```

設定変更後は Logto を再起動してください。その後、[Bring your UI](/customization/bring-your-ui#upload-your-custom-ui-assets) に従い、コンソールからアセットをアップロードします。

## コンソールメンバーへの招待メール \{#invitation-emails-for-console-members}

コンソール招待は、デフォルトテナントのメールコネクター経由でメール送信されます。メンバー招待前に [メールコネクターの設定](/connectors/email-connectors) を済ませてください。
