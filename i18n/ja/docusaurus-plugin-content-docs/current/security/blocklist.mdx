# ブロックリスト

## メール許可リストとブロックリスト \{#email-blocklist}

メール許可リストとブロックリストの設定を使用して、新規アカウント登録やアカウント連携に利用できるメールアドレスを制御できます。Logto は、有効化されているすべてのルールを満たさないメールアドレスを拒否し、スパムアカウントの軽減や全体的なアカウントセキュリティの向上に役立ちます。

<CloudLink to="/security/blocklist"> コンソール > セキュリティ > ブロックリスト </CloudLink>
でメール許可リストとブロックリストの設定を行えます。

### カスタムメール許可リスト \{#custom-email-allowlist}

カスタムメール許可リストを利用して、新規サインアップや新たに連携されるメールを承認済みアドレスのみに制限できます。許可リストにエントリーがない場合は無効化されます。1 件以上のエントリーがある場合、メールアドレスは少なくとも 1 つのエントリーに一致する必要があります：

| エントリータイプ           | 例                 | 一致するもの                                            |
| -------------------------- | ------------------ | ------------------------------------------------------- |
| 完全一致メール             | `foo@example.com`  | `foo@example.com` のみ                                  |
| ドメイン                   | `@example.com`     | ドメインが正確に `example.com` のすべてのメールアドレス |
| ローカル部ワイルドカード   | `foo*@example.com` | `foo1@example.com` や `foo.bar@example.com` など        |
| サブドメインワイルドカード | `@*.example.com`   | `user@team.example.com` などサブドメインからのメール    |

一致判定は大文字小文字を区別しません。`@*.example.com` のようなワイルドカードサブドメインエントリーは、ルートドメイン `example.com` には一致しません。ルートドメインとそのサブドメインの両方を許可するには、`@example.com` と `@*.example.com` の両方を追加してください。

許可リストはブロックリストの例外リストではありません。許可リストに一致するメールでも、使い捨てメール、サブアドレッシング、カスタムブロックリストルールなど、すべての有効なブロックリストチェックを通過する必要があります。

### 使い捨てメールアドレスのブロック \{#block-disposable-email-addresses}

これは **クラウド専用** 機能です。有効化すると、システムは提供されたメールアドレスのドメインを既知の使い捨てメールドメインリストと自動的に照合します。リストに該当する場合、リクエストは拒否されます。使い捨てメールドメインリストは、効果を維持するため定期的に更新されます。

### メールサブアドレッシングのブロック \{#block-email-subaddressing}

メールサブアドレッシングとは、プラス記号（+）の後に追加文字を付けてメールアドレスのバリエーションを作成できる機能です（例：user+tag@example.com）。この機能は、悪意のあるユーザーによってブロックリスト制限を回避するために悪用される可能性があります。メールサブアドレッシングのブロック機能を有効にすると、サブアドレス形式を利用したサインアップやアカウント連携の試みはすべて拒否されます。

### カスタムメールブロックリスト \{#custom-email-blocklist}

ブロックしたいメールアドレスやドメインのリストを指定して、カスタムメールブロックリストを作成できます。これらのエントリーに一致するサインアップやアカウント連携の試みは、システムによって拒否されます。ブロックリストは、完全なメールアドレスとドメインの両方の一致をサポートします。

例えば、`@example.com` をブロックリストに追加すると、そのドメインのすべてのメールアドレスがブロックされます。同様に、`foo@example.com` を追加すると、そのメールアドレスのみがブロックされます。

また、ローカル部やドメインに `*` をワイルドカードとして使用できます。例えば、`foo*@example.com` は `foo1@example.com` や `foo.bar@example.com` などをブロックし、`@*.example.com` は `user@team.example.com` などサブドメインからのアドレスをブロックします。ワイルドカードルールも、メールアドレスまたはドメインエントリーの形式に従う必要があり、一致判定は大文字小文字を区別しません。ルートドメインとそのサブドメインの両方をブロックするには、`@example.com` と `@*.example.com` の両方を追加してください。

:::note

メール許可リストとブロックリストのルールは、[新規ユーザー登録](/end-user-flows/sign-up-and-sign-in/sign-up)、[ソーシャルサインイン時のメール連携](/end-user-flows/sign-up-and-sign-in/social-sign-in#collect-sign-up-identifiers)、[Account API](/end-user-flows/account-settings/by-account-api#update-or-link-new-email) 経由でのメール連携や更新時に適用されます。既存ユーザーは、すでにアカウントに連携されているメールアドレスで引き続きサインインできます。

- 管理者は <CloudLink to="/users">コンソール > ユーザー管理</CloudLink> で手動でユーザーを追加したり、[Management API](https://openapi.logto.io/operation/operation-createuser) を利用することで「制限をバイパス」できます。例：サブアドレスメールがブロックされている場合でも、そのメールでユーザーを作成可能です。
- 既存アカウントをブロックするには、<CloudLink to="/users">コンソール > ユーザー管理</CloudLink> で削除または停止してください。

:::
