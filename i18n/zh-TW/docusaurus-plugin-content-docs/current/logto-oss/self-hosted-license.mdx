# 自架授權

自架授權是一組簽署過的金鑰，可於你的 Logto OSS 實例上解鎖 [Logto 自架方案](https://logto.io/self-hosted-plans)的付費功能。沒有授權時，Logto OSS 的行為與以往完全相同。

:::note
授權僅適用於自架 Logto OSS。於 Logto Cloud 上，功能屬於你的 [租戶方案](/logto-cloud/billing-and-pricing)的一部分，且不提供授權端點。
:::

## 授權可解鎖的功能 \{#what-a-license-unlocks}

Self-hosted Pro 授權可於你的實例解鎖以下功能：

| 功能                                                                       | 無授權時                       | 有授權時                                                                  |
| -------------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------- |
| [隱藏 Logto 品牌標示](/customization/match-your-brand#hide-logto-branding) | 一律顯示「Powered by Logto」。 | 你可以選擇隱藏。                                                          |
| [自帶 UI](/customization/bring-your-ui) 與自訂 CSP 來源                    | 不可用。                       | 可將自訂登入 UI 上傳至[自有儲存空間](#set-up-storage-for-bring-your-ui)。 |
| Console 成員與邀請                                                         | 不可用。                       | 可邀請成員加入 Console，並於 **租戶設定 > 成員** 管理其角色。             |
| Console 強制 MFA                                                           | 僅可選擇性啟用 MFA。           | 可要求所有 Console 成員必須設定 MFA，於 **租戶設定 > 設定** 中啟用。      |
| [SAML 應用程式](/integrate-logto/saml-app)                                 | 最多 3 個 SAML 應用程式。      | SAML 應用程式數量無上限。                                                 |

未列於此表的功能不受授權影響。

## 取得授權 \{#get-a-license}

請透過 [自架方案頁面](https://logto.io/self-hosted-plans)申請授權。Logto 會提供你兩組相同授權的金鑰：

- **正式環境金鑰**：用於訂閱所涵蓋的正式部署。除非訂單另有說明，每份訂閱僅涵蓋一個正式部署。
- **非正式環境金鑰**：用於支援同一正式部署的開發、測試與預備環境。這些部署不得處理正式流量。

兩組金鑰解鎖相同功能與配額。擁有兩組金鑰不代表可運行兩個正式部署。你的使用權限受 [自架訂閱條款](https://logto.io/terms/self-hosted)及訂單約束。

你安裝的金鑰會告知 Logto 部署類型。Logto 不會技術性驗證，請安裝符合部署類型的金鑰。

## 安裝授權 \{#install-a-license}

你可以在 Console 或透過 Management API 安裝授權。無論哪種方式，Logto 都會於你的實例上驗證金鑰簽章，若金鑰無效、遭竄改或已過期則拒絕安裝。

### 於 Console 安裝 \{#in-console}

1. 前往 **Console > 租戶設定 > 授權**。
2. 貼上你的授權金鑰並點擊 **安裝授權**。

安裝後，頁面會顯示授權詳細資訊。若需切換金鑰（例如從非正式環境金鑰切換至正式環境金鑰，或安裝新發行的金鑰），請點擊 **更換授權**。

### 使用 Management API 安裝 \{#using-the-management-api}

將金鑰傳送至 `PUT /api/systems/license`，並附上 [Logto Management API](/integrate-logto/interact-with-management-api) 的存取權杖：

```bash
curl -X PUT 'https://your-logto-endpoint/api/systems/license' \
  -H 'Authorization: Bearer <access_token>' \
  -H 'Content-Type: application/json' \
  -d '{ "license": "<your_license_key>" }'
```

成功請求會回傳 `204 No Content`。失敗情境如下：

- 若金鑰未經 Logto 簽署或已被修改，回傳 `400` 與 `license.invalid_key`。
- 若金鑰已過期，回傳 `400` 與 `license.expired_key`。請取得新金鑰並重新安裝。
- 若 Logto 執行於 Logto Cloud，回傳 `501`。

查詢已安裝授權，請發送 `GET /api/systems/license`。回應內容包含授權方案、環境、權益、到期日與刷新狀態，不會回傳金鑰本身，若未安裝授權則回傳 `404`。完整請求與回應格式請參閱 [Management API 文件](https://openapi.logto.io)。

### 多實例部署 \{#multiple-instances}

授權儲存在 Logto 資料庫中，因此共用同一資料庫的所有 Logto 實例僅需安裝一次授權。

## 刷新與寬限期 \{#refresh-and-grace-period}

Logto 於本地驗證授權簽章，因此登入應用程式時不需連線至 Logto，且刷新失敗不會阻擋登入流量。

為同步續約與取消資訊，你的實例會與 Logto Cloud 檢查：

- **每週檢查**：距離上次成功刷新超過 7 天時，Logto 會於處理請求時於背景刷新授權。若刷新失敗，稍後會重試，每小時最多一次。新安裝授權時會立即刷新。
- **30 天寬限期**：若刷新失敗（如無法連線網際網路），功能仍可於上次成功刷新後 30 天內正常運作。之後，實例將回復為 OSS 預設狀態。
- **被拒絕的刷新**：若 Logto 拒絕刷新授權（如訂閱已取消），授權頁面會顯示原因。寬限期仍自上次成功刷新起算。

刷新為從你的實例發出的 HTTPS 請求，目標為 `https://cloud.logto.io`。若實例位於防火牆後，請允許此目的地。

### 實例傳送的資訊 \{#what-your-instance-sends}

刷新請求僅包含：

- 你的授權金鑰，用於以 `licenseId` 識別授權。
- `deploymentId`：首次安裝授權時產生的隨機識別碼，儲存在資料庫中，所有共用該資料庫的實例皆共用，且更換授權時不會變更。
- Logto 版本。
- 部署的使用量統計：每月活躍使用者、每月存取權杖，以及租戶數量，除非你[關閉使用量回報](#turn-off-usage-reporting)。

使用量統計僅為總數，不含個人資料。Logto 不會收集主機名稱、網域、設定或其他任何資料。Logto 僅用於維持授權有效，並與方案[使用量限制](#usage-limits)比對。詳見 [自架訂閱條款](https://logto.io/terms/self-hosted)第 10.2 條。此行為為開源，請參閱 [`LicenseReader.ts`](https://github.com/logto-io/logto/blob/master/packages/core/src/license/LicenseReader.ts)。

### 關閉使用量回報 \{#turn-off-usage-reporting}

請於**所有**共用資料庫的 Logto 實例設置此環境變數，因為任一實例皆可能執行刷新：

```bash
SELF_HOSTED_LICENSE_USAGE_REPORTING_DISABLED=1
```

刷新仍會執行，但不包含使用量統計。若超過限制，Console 仍會顯示警告。

## 使用量限制 \{#usage-limits}

每個方案皆有使用量限制。這些限制**不會強制執行**：超過限制不會阻擋登入或關閉任何功能，Console 僅會顯示提示。

| 指標           | 正式環境金鑰                            | 非正式環境金鑰 |
| -------------- | --------------------------------------- | -------------- |
| 每月活躍使用者 | Self-hosted Pro 為 50,000，或依訂單為準 | 無限制         |
| 正式部署數量   | 1                                       | 無限制         |
| 每月存取權杖   | 無限制                                  | 50,000         |

正式部署若於過去 15 天內刷新過授權，則視為活躍。

若超過限制，請於 30 天內聯繫 Logto 升級方案或降低使用量，詳見 [自架訂閱條款](https://logto.io/terms/self-hosted)第 4.2 條。

### 取得使用量報表 \{#get-a-usage-statement}

若 Logto 要求提供使用量報表，請以 [Logto Management API](/integrate-logto/interact-with-management-api) 的存取權杖發送 `GET /api/systems/license/usage-statement`。回應內容為過去 12 個月每月的活躍使用者與存取權杖數，資料來源為你的資料庫。

## 授權到期 \{#license-expiration}

授權涵蓋一年期，**到期日**即該期間結束日。

- **續約時**，你的實例無需任何操作。續約後的下一次刷新會自動以新金鑰取代現有金鑰，有效期再延一年。頁面顯示的日期可能會有幾天延遲，功能期間仍可正常使用。
- **未續約時**，期間結束後刷新會被拒絕。功能於 30 天寬限期結束前仍可使用，之後實例回復為 OSS 預設狀態，等同未安裝授權。授權頁面會顯示說明與發生日期。
- **若已過寬限期**，請安裝新金鑰以重新解鎖功能。如需新金鑰，請透過原取得授權的管道聯繫 Logto。

### 功能關閉時會發生什麼事 \{#what-happens-when-features-are-turned-off}

回復為 OSS 預設狀態不會刪除你以授權建立的任何資料：

- **隱藏 Logto 品牌標示**：會再次顯示「Powered by Logto」。你的設定會被保留，日後安裝授權後自動套用。
- **SAML 應用程式**：超過 3 個的應用程式仍會保留，但無法新增新應用程式，直到數量低於限制。
- **強制 MFA**：你隨時可以關閉。無授權時無法再次啟用。
- **自帶 UI、自訂 CSP 與 Console 邀請**：無法進行需此功能的新變更，既有資料會保留。

## 設定自帶 UI 的儲存空間 \{#set-up-storage-for-bring-your-ui}

於 Logto Cloud 上，自帶 UI 資產由 Logto 託管。於自架實例，需自行設定物件儲存空間。Logto 會解壓縮你的上傳並將檔案儲存於該處，並從該處提供服務。

請以與 [檔案儲存供應商](/logto-oss/file-storage-provider) 相同的 JSON 結構設定 `experienceBlobsProvider` 系統設定，例如 S3 相容儲存空間：

```bash
pnpm logto db system set experienceBlobsProvider '{"provider":"S3Storage","accessKeyId":"my-access-key-id","accessSecretKey":"my-secret-access-key","bucket":"logto-sie","endpoint":"https://s3.us-east-2.amazonaws.com"}'
```

更改設定後請重啟 Logto。接著依照 [自帶 UI 上傳資產](/customization/bring-your-ui#upload-your-custom-ui-assets) 於 Console 上傳資產。

## Console 成員邀請郵件 \{#invitation-emails-for-console-members}

Console 邀請郵件會透過預設租戶的 email 連接器發送。請先[設定 email 連接器](/connectors/email-connectors)再邀請成員。
