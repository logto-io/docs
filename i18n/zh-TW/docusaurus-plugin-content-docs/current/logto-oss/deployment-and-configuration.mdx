# 部署與設定

在前一篇文章中，我們介紹了[快速開始使用 Logto](/logto-oss/get-started-with-oss)的基礎知識。本篇將深入探討，聚焦於生產環境下的最佳實踐與詳細設定步驟。

## 環境變數 \{#environment-variables}

我們在 demo（`docker-compose.yml`）中使用了一組預設產生的環境變數，你應該替換為自己的設定，並在多個 Logto 實例間保持一致。

你可以直接設定環境變數，或將 `.env` 檔案放在 Logto 專案根目錄。如果你用 Docker 測試，請查看映像檔在 `/etc/logto` 產生的 `.env`。

### 基本必備 \{#essentials}

- `DB_URL` Logto 資料庫的 [Postgres DSN](https://www.postgresql.org/docs/14/libpq-connect.html#id-1.7.3.8.3.6)。
- `DATABASE_STATEMENT_TIMEOUT`（v1.36.0+）PostgreSQL 的 `statement_timeout`，單位為毫秒。請使用數字字串（如 `5000`），或對 PgBouncer/RDS Proxy 使用 `DISABLE_TIMEOUT`。詳見[設定說明](/concepts/core-service/configuration/)。
- `PORT` Logto 監聽的埠號，預設為 `3001`。
- `ENDPOINT` 可指定自訂網域的 URL 作為生產環境端點（如 `ENDPOINT=https://logto.domain.com`）。這也會影響 [OIDC 簽發者識別碼 (Issuer Identifier)](https://openid.net/specs/openid-connect-core-1_0.html#IssuerIdentifier) 的值。

**啟用管理主控台 (Admin Console)**

- `ADMIN_PORT` Logto 管理主控台監聽的埠號，預設為 `3002`。
- `ADMIN_ENDPOINT` 可指定自訂網域的 URL 作為生產環境端點（如 `ADMIN_ENDPOINT=https://admin.domain.com`）。這也會影響管理主控台的 Redirect URI 值。

**停用管理主控台 (Admin Console)**

- `ADMIN_DISABLE_LOCALHOST` 設為 `1` 或 `true` 可關閉管理主控台的埠號。若未設定 `ADMIN_ENDPOINT`，將完全停用管理主控台。

更多環境變數細節，請參閱[設定說明](/concepts/core-service/configuration/)。

**啟用 Secret Vault**

- 若要使用 [Secret Vault](/secret-vault)，需將 `SECRET_VAULT_KEK` 設為你的 Key Encryption Key (KEK) 的 base64 編碼字串。這用於加密 Secret Vault 中的 Data Encryption Key (DEK)。建議使用 AES-256（32 bytes）。範例：`crypto.randomBytes(32).toString('base64')`。

### 對外 HTTP 代理 \{#outbound-http-proxy}

如果你的自架 Logto 實例必須透過 HTTP 代理存取外部服務（如社交連接器 API 或 CAPTCHA 供應商），請啟用環境代理支援並設定標準代理變數。

例如，在 Docker Compose 設定中為 Logto 服務新增以下環境變數：

```yaml
services:
  logto:
    image: ghcr.io/logto-io/logto:latest
    environment:
      NODE_USE_ENV_PROXY: '1'
      HTTP_PROXY: http://proxy.example.com:3128
      HTTPS_PROXY: http://proxy.example.com:3128
      NO_PROXY: localhost,127.0.0.1,::1,postgres,.internal.example.com
```

- `NODE_USE_ENV_PROXY=1` 啟用環境代理支援。
- `HTTP_PROXY` 指定 HTTP 請求的代理。
- `HTTPS_PROXY` 指定 HTTPS 請求的代理。代理 URL 本身可用 HTTP 或 HTTPS。
- `NO_PROXY` 以逗號分隔的主機清單，這些主機將直接連線。請包含所有不應經過代理的內部 HTTP 端點。

請注意，這些代理設定不一定對所有對外請求都生效。

### HTTPS \{#https}

你可以直接用 Node.js 提供 HTTPS 服務，或在 Node.js 前方設置 HTTPS 代理 / 負載平衡器。詳見[啟用 HTTPS](/concepts/core-service/configuration/#enabling-https)。

### 反向代理 \{#reverse-proxy}

若你想在伺服器上使用反向代理（如 Nginx 或 Apache），需在代理設定中分別對應 3001 與 3002 埠。假設你使用 Nginx，Logto 驗證端點運行於 3001 埠，管理主控台運行於 3002 埠，請在 nginx.conf 中加入以下設定：

將 `TRUST_PROXY_HEADER=1` 設定給 Logto 以信任轉發標頭。`Host` 與 `X-Forwarded-Host` 請皆用 `$http_host`，以保留公開 URL 的非標準埠。

```
server {
  listen 443 ssl;
  server_name <your_endpoint_url>; // 例如 auth.your-domain.com
  ...

  location / {
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_pass http://127.0.0.1:3001;
  }

  ssl_certificate <path-to-your-certificate-for-auth-endpoint>;
  ssl_certificate_key <path-to-your-certificate-key-for-auth-endpoint>
  ...
}
```

然後為管理主控台加入類似設定：

```
server {
  listen 443 ssl;
  server_name <your_admin_endpoint_url>; // 例如 admin.your-domain.com
  ...

  location / {
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_pass http://127.0.0.1:3002;
  }

  ssl_certificate <path-to-your-certificate-for-admin-endpoint>;
  ssl_certificate_key <path-to-your-certificate-key-for-admin-endpoint>
  ...
}
```

重新載入 Nginx 設定以套用最新變更：

```
nginx -s reload
```

一切就緒。打開瀏覽器並造訪 `https://admin.your-domain.com`，你應該能看到 Logto 歡迎頁面。

## 容器化 \{#containerization}

在生產環境中，你可以用 Docker 將 Logto 容器化。專案根目錄有 Dockerfile。如果你想運行多個 Logto 實例（例如在 Kubernetes 叢集部署 Logto），還需額外步驟。

### 資料庫初始化 \{#database-setup}

準備一個 Postgres 資料庫給 Logto。強烈建議使用 Logto CLI 初始化資料庫。

```bash
npm run cli db seed -- --swe
```

詳見 [Logto CLI](/logto-oss/using-cli)。

:::tip 離線或隔離網路安裝

若你的部署環境無法連線至 `api.pwnedpasswords.com`，請在 `logto init` 或 `npm run cli db seed` 時加上 `--disable-admin-pwned-password-check`，避免首次管理員註冊時卡在 Have I Been Pwned 漏洞檢查。詳見[離線部署初始化說明](/logto-oss/using-cli#seed-for-air-gapped-or-offline-deployments)。

:::

### 共用連接器資料夾 \{#shared-connectors-folder}

預設情況下，Logto 會在 `core` 資料夾根目錄下建立 `connectors` 資料夾。官方 Docker 映像已內建官方連接器，若僅用官方連接器則無需共用。

若你需要映像中未包含的連接器（如自訂連接器），建議多個 Logto 實例共用該資料夾。將 `packages/core/connectors` 資料夾掛載到容器，並執行 `npm run cli connector add -- --official` 以部署官方連接器，再將自訂連接器加入同一資料夾。掛載 volume 會隱藏映像內建連接器，因此需重新加入官方連接器，這需要能存取 npm registry。

以下為 Kubernetes 的最小範例 `deployment`：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: logto
  namespace: default
spec:
  selector:
    matchLabels:
      app: logto
  template:
    metadata:
      labels:
        app: logto
    spec:
      volumes:
        - name: connectors
          emptyDir: {}
      initContainers:
        - image: ghcr.io/logto-io/logto
          command:
            - /bin/sh
          args:
            - '-c'
            - 'npm run cli connector add -- --official'
          name: init
          volumeMounts:
            - name: connectors
              mountPath: /etc/logto/packages/core/connectors
      containers:
        - image: ghcr.io/logto-io/logto
          name: logto
          volumeMounts:
            - name: connectors
              mountPath: /etc/logto/packages/core/connectors
```

此範例中，我們建立一個空目錄作為 volume 並掛載到容器。然後在 init container 執行 `npm run cli connector add -- --official` 下載連接器。最後，每個 container 都會共用同一個已含官方連接器的資料夾。

:::note

這僅為 yaml 範例，實際運行 Logto 時需正確設定環境變數。

:::

在生產環境中，你可以將 "empty dir" volume 換成持久化 volume，並用自己的方式執行 "init" 任務，只要你知道自己在做什麼！

### 資料庫變更 (alteration) \{#database-alteration}

與連接器類似，資料庫變更需在單一實例執行。你可以用 job 執行變更腳本。

非互動執行時需設 `CI=true` 環境變數。

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: alteration
spec:
  template:
    spec:
      containers:
        - name: alteration
          image: ghcr.io/logto-io/logto
          imagePullPolicy: Always
          env:
            - name: CI
              value: 'true'
            - name: DB_URL
              value: postgresql://user:password@localhost:5432/logto
          command:
            - /bin/sh
          args:
            - '-c'
            - 'npm run alteration deploy latest'
      restartPolicy: Never
```

關於 alteration 指令詳見 [資料庫變更 (Database alteration)](/logto-oss/using-cli/database-alteration/)。
