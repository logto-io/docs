# 備用代碼 (Backup codes)

## 概念 \{#concepts}

備用代碼（又稱為恢復代碼，Recovery code）是一種一次性使用的多重要素驗證 (MFA, Multi-factor authentication) 備援驗證碼，當使用者的主要驗證因素（如驗證器應用程式或硬體權杖）無法使用時，作為備用方案。

遺失備用代碼可能導致帳號恢復困難。因此，建議在啟用備用代碼前，先設定額外的主要驗證因素，並將其設為優先。

Logto 會在使用者設定額外驗證因素後，自動產生 10 組備用代碼。每組代碼僅能使用一次。使用者可透過 [預建帳號中心介面 (Account Center UI)](/end-user-flows/account-settings/by-account-center-ui)（`/account/backup-codes/regenerate`）、使用 [Account API](/end-user-flows/account-settings/by-account-api#manage-backup-codes) 建立的自訂自助介面，或透過 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 的管理工具，在現有代碼用盡前重新產生新的一組代碼。

## 設定 MFA 備用代碼 \{#configure-backup-codes-for-mfa}

1. 前往 <CloudLink to="/mfa">主控台 > 多重要素驗證 (Multi-factor authentication)</CloudLink>
2. 啟用「備用代碼 (Backup Codes)」因素。備用代碼不能作為唯一的 MFA 因素，必須與其他主要 MFA 因素（通行密鑰、驗證器應用程式、簡訊、電子郵件）搭配使用。
3. 設定你偏好的 MFA 政策（選用、自適應或強制）
4. 儲存你的設定變更

## 設定備用代碼管理 \{#configure-backup-codes-management}

使用者可透過 [預建帳號中心介面 (Account Center UI)](/end-user-flows/account-settings/by-account-center-ui)（`/account/backup-codes/manage` 與 `/account/backup-codes/regenerate`）檢視與重新產生備用代碼。你也可以利用 Account API 建立自訂帳號管理介面，讓使用者檢視、重新產生或移除備用代碼。這讓使用者能直接從你的應用程式帳號設定頁管理其恢復選項。

詳細實作步驟與 API 端點，請參閱 [透過 Account API 管理帳號設定](/end-user-flows/account-settings/by-account-api#manage-backup-codes)。

## 備用代碼設定流程 \{#backup-codes-setup-flows}

由於備用代碼屬於次要 MFA 因素，僅能在成功設定主要 MFA 因素後啟用。系統會自動產生 10 組備用代碼並顯示給使用者，使用者可安全下載或複製。使用者必須手動確認備用代碼，才能完成 MFA 設定流程。

若啟用 **備用代碼 (Backup codes)**，且使用者已有其他啟用的因素但沒有剩餘未用備用代碼，Logto 會在登入時提示使用者產生並儲存新的一組備用代碼，例如：

- 先前產生的備用代碼已全部用完。
- 你在使用者已註冊主要 MFA 因素後才啟用 **備用代碼 (Backup codes)**。

對於既有使用者的登入，只有在驗證 MFA 挑戰（或以通行密鑰登入）後才會重新提示；若登入流程跳過 MFA 驗證（如受信任裝置、低風險 [自適應 MFA (Adaptive MFA)](/end-user-flows/mfa/adaptive-mfa) 登入，或使用者略過 **選用 MFA (Optional MFA)**），則不會在登入中途提示綁定新備用代碼。一般 [企業級單一登入 (Enterprise SSO)](/end-user-flows/enterprise-sso) 登入也會略過 MFA 設定提示，除非透過 `acr_values` 明確要求 MFA。

## 備用代碼驗證流程 \{#backup-codes-verification-flow}

備用代碼可作為主要 MFA 因素無法使用時的緊急驗證方式。每組代碼僅能使用一次，驗證成功後即失效。

**驗證優先順序：**

- **優先提示主要因素**：若使用者已設定其他 MFA 因素，會先提示主要因素（通行密鑰、TOTP、簡訊、電子郵件）。
- **切換至備用代碼**：若主要因素無法使用，使用者可點選「嘗試其他驗證方式」切換至備用代碼。
- **僅剩備用代碼時**：若所有主要因素皆已刪除，備用代碼成為唯一驗證選項。登入時成功以備用代碼通過 MFA 驗證後，Logto 會自動提示使用者設定新的主要因素。
