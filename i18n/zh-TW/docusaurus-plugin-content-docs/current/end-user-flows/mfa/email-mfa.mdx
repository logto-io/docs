# MFA 電子郵件驗證

Logto 支援以電子郵件為基礎的多重要素驗證 (MFA, Multi-factor authentication) 功能，透過向使用者註冊的電子郵件地址發送一次性驗證碼來提升帳號安全性。電子郵件 MFA 作為第二驗證因素，可以與其他 MFA 因素（如 TOTP、通行密鑰、備用代碼）結合，為使用者提供彈性的雙重驗證選項。

## 概念 \{#concepts}

電子郵件驗證是最普及的 MFA 方法之一。它利用電子郵件帳號的廣泛可用性，將臨時的一次性驗證碼直接發送到使用者的電子郵件信箱。與需要額外安裝軟體的應用程式型驗證器不同，電子郵件 MFA 利用現有的電子郵件基礎設施，幾乎所有網際網路使用者都能透過瀏覽器、郵件客戶端或行動應用程式存取。因此，除了擁有電子郵件帳號外，使用者無需額外硬體或設定即可立即使用。

## 設定 MFA 電子郵件驗證 \{#configure-email-verification-for-mfa}

**步驟 1：設定電子郵件連接器與範本**

1. 前往 <CloudLink to="/connectors/passwordless">控制台 > 連接器 > 電子郵件與簡訊連接器</CloudLink>
2. 選擇合適的電子郵件連接器（SendGrid、Mailgun 等）
3. 設定連線參數
4. 為 MFA 設定 [電子郵件範本](/connectors/email-connectors/email-templates) 與專用用途類型：

   - `MfaVerification` 用於 MFA 驗證
   - `BindMfa` 用於綁定 MFA
   - 小提示：[Logto 電子郵件服務](/connectors/email-connectors/built-in-email-service) 提供內建電子郵件範本

5. 參考 [電子郵件連接器](/connectors/email-connectors) 取得各供應商的詳細設定說明

**步驟 2：啟用 MFA 電子郵件驗證**

1. 前往 <CloudLink to="/mfa">控制台 > 多重要素驗證</CloudLink>
2. 啟用「電子郵件驗證碼」因素。建議將電子郵件 MFA 與其他 MFA 因素（TOTP、通行密鑰、簡訊、備用代碼）結合使用，以降低單一因素依賴。
3. 在 **電子郵件 / 簡訊兩步驟驗證** 中，選擇哪些使用者擁有電子郵件 MFA。詳見 [誰擁有電子郵件 MFA](#who-has-email-mfa)。
4. 設定你偏好的 MFA 政策（選用、自適應或強制）
5. 儲存設定變更

:::note 重要使用注意事項

1. **登入方法限制**：電子郵件驗證碼不可同時作為 [登入方法 (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in) 與 MFA 因素 (2FA) 使用。每個電子郵件實作請選擇一種驗證流程。

2. **註冊方法相容性**：電子郵件驗證碼可同時用於註冊方法與 MFA。Logto 會根據你選擇的 MFA 政策最佳化終端使用者註冊流程，避免對同一電子郵件地址重複驗證。

3. **密碼重設相容性**：雖然電子郵件驗證碼可同時用於 [忘記密碼](/end-user-flows/sign-up-and-sign-in/reset-password) 與 MFA，但**不建議**這樣配置。此組合會降低 MFA 的安全性，因為使用者可能透過忘記密碼的電子郵件驗證重設密碼，然後用新密碼進行主驗證 (1FA)，再用相同電子郵件方法進行 MFA 驗證，進而繞過 MFA。

:::

## 誰擁有電子郵件 MFA \{#who-has-email-mfa}

電子郵件 MFA 驗證碼一律發送到使用者的主要電子郵件地址。<CloudLink to="/mfa">多重要素驗證</CloudLink>頁面的 **電子郵件 / 簡訊兩步驟驗證** 設定決定哪些使用者擁有電子郵件 MFA：

- **所有擁有已驗證電子郵件或電話號碼的使用者**：所有擁有主要電子郵件地址的使用者都自動擁有電子郵件 MFA，無需額外設定。
- **僅已設定的使用者**：只有主動設定電子郵件 MFA 的使用者才擁有。以已驗證電子郵件註冊的使用者不會自動獲得電子郵件 MFA，因此你可以將電子郵件作為 MFA 選項之一，而不必讓每位使用者都啟用。使用者可在 MFA 設定流程、[帳號中心](/end-user-flows/account-settings/by-account-center-ui) 或透過 [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa) 設定。管理員可透過 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 為使用者新增或移除。

此設定同樣適用於 [簡訊 MFA](/end-user-flows/mfa/sms-mfa)。預設值與切換模式時的行為，請參閱 [電子郵件與簡訊 MFA 註冊](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment)。

:::note
若選擇 **所有擁有已驗證電子郵件或電話號碼的使用者**，僅因主要電子郵件地址而擁有電子郵件 MFA 的使用者不會有儲存的電子郵件 MFA 記錄，因此不會出現在 `GET /api/my-account/mfa-verifications`、`GET /api/users/{userId}/mfa-verifications` 或 `user.mfaVerificationFactors`（自訂 JWT 宣告與 `PostSignIn` Actions）中。
:::

## 電子郵件 MFA 設定流程 \{#email-mfa-setup-flows}

MFA 設定提示可能出現在使用者註冊時或登入後，取決於你設定的 [MFA 政策](/end-user-flows/mfa/configure-mfa#global-mfa-configuration)。

電子郵件 MFA 設定流程會受到以下因素影響：

- **MFA 主要因素數量**：若有多個主要因素，使用者必須選擇一個進行設定。主要因素指除備用代碼外的 MFA 方法。
- **啟用備用代碼**：啟用時，設定主要 MFA 因素後會自動產生備用代碼，並提示使用者儲存。
- **註冊識別子設定**：電子郵件地址作為 [註冊識別子](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier) 且使用者已於註冊時以電子郵件驗證碼驗證。
  - 若選擇 **所有擁有已驗證電子郵件或電話號碼的使用者**，系統會自動將該電子郵件綁定為 MFA 因素，無需再次驗證。若有其他主要因素，UI 會顯示「新增另一個兩步驟驗證」選項（可略過），同時明確顯示 MFA 已啟用。
  - 若選擇 **僅已設定的使用者**，電子郵件會像其他因素一樣顯示（遮蔽地址）。當使用者選擇或僅有此主要因素時，Logto 會直接用註冊時的驗證完成設定，不會再發送第二組驗證碼。
- **現有使用者資料**：現有使用者登入後設定 MFA，需先完成主驗證，再進行 MFA 設定。若帳號已有已驗證的主要電子郵件地址：
  - 若選擇 **所有擁有已驗證電子郵件或電話號碼的使用者**，設定流程與上述註冊識別子情境相同。
  - 若選擇 **僅已設定的使用者**，電子郵件會以遮蔽地址顯示。當使用者選擇或僅有此主要因素時，Logto 會發送驗證碼到該地址，使用者輸入後即完成電子郵件 MFA 設定。

以下為三種常見電子郵件 MFA 綁定情境。

### 情境 1：電子郵件僅用於 MFA（典型流程） \{#scenario-1-email-address-only-used-for-mfa-typical-flow}

當電子郵件地址不是註冊識別子，僅用於 MFA 時，請依標準設定流程：

- 若僅有一個電子郵件 MFA 因素，直接顯示該因素設定 UI。
- 若有多個主要 MFA 因素，顯示「設定 MFA」列表頁，讓使用者選擇要設定的因素。

若選擇 **僅已設定的使用者**，使用者需先從列表選擇因素。當僅設定電子郵件、簡訊或登入通行密鑰為唯一因素時，會出現「新增另一個兩步驟驗證」提示。

## 電子郵件 MFA 驗證流程 \{#email-mfa-verification-flows}

啟用電子郵件 MFA 的使用者登入時，完成主驗證 (1FA) 後，會被提示以電子郵件驗證碼作為第二驗證因素 (2FA) 驗證身分。

若有多個 MFA 因素，Logto 會依 [MFA 設定](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) 中的固定順序（通行密鑰、驗證器應用程式 OTP、簡訊驗證碼、電子郵件驗證碼、備用代碼）直接開啟最高優先權因素。若先提示如驗證器應用程式 OTP，使用者可點選 **嘗試其他驗證方式** 開啟選擇列表，改選電子郵件驗證碼。

## 錯誤處理 \{#error-handling}

1. **電子郵件地址未綁定**

   - 錯誤代碼：`session.mfa.mfa_factor_not_enabled`
   - 處理方式：引導使用者先綁定電子郵件地址

2. **驗證碼錯誤**

   - 錯誤代碼：`verification_code.code_mismatch`
   - 處理方式：提示使用者重新輸入，限制重試次數

3. **驗證碼過期**

   - 錯誤代碼：`verification_code.expired`
   - 處理方式：提示使用者重新取得驗證碼

4. **發送頻率超限**
   - 錯誤代碼：`request.message_rate_limited`（Logto 單一收件人發送頻率限制）或 `connector.rate_limit_exceeded`（電子郵件連接器頻率限制）
   - 處理方式：顯示等待時間，限制重發次數
