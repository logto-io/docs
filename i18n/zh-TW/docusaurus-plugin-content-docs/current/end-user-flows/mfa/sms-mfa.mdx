# MFA 的簡訊驗證 (SMS verification for MFA)

Logto 支援基於簡訊的多重要素驗證 (MFA, Multi-factor authentication) 功能，透過向使用者註冊的手機號碼發送一次性驗證碼來提升帳號安全性。簡訊 MFA 作為第二驗證因素，可與其他 MFA 因素（如 TOTP、通行密鑰、備用碼）結合，為使用者提供彈性的雙重驗證選項。

## 概念 \{#concepts}

簡訊驗證（SMS verification），又稱手機號碼驗證，是最容易取得的 MFA 方法之一。它利用手機的普及性，直接將臨時的一次性驗證碼透過簡訊發送到使用者裝置。與需要額外安裝軟體的應用程式型驗證器不同，簡訊 MFA 利用每支手機都具備的訊息傳送基礎設施，讓使用者無需額外設定即可立即使用。

## 設定 MFA 的簡訊驗證 \{#configure-sms-verification-for-mfa}

**步驟 1：設定簡訊連接器與範本**

1. 前往 <CloudLink to="/connectors/passwordless">控制台 > 連接器 > 電子郵件與簡訊連接器</CloudLink>
2. 選擇合適的簡訊連接器（Twilio、SMS Aero 等）
3. 設定連線參數
4. 針對 MFA 設定專用用途的簡訊範本
   - `MfaVerification` usageType 用於 MFA 驗證
   - `BindMfa` usageType 用於綁定 MFA
5. 測試連接器功能，確保訊息可正常發送
6. 參考 [簡訊連接器](/connectors/sms-connectors) 取得各供應商的詳細設定說明

**步驟 2：啟用 MFA 的簡訊驗證**

1. 前往 <CloudLink to="/mfa">控制台 > 多重要素驗證</CloudLink>
2. 啟用「簡訊驗證碼」因素。建議與其他 MFA 因素（TOTP、通行密鑰、備用碼）搭配使用，以降低單一因素依賴。
3. 在 **電子郵件 / 簡訊兩步驟驗證** 中，選擇哪些使用者擁有簡訊 MFA。詳見 [誰擁有簡訊 MFA](#who-has-sms-mfa)。
4. 設定你偏好的 MFA 政策（選用、自適應或強制）
5. 儲存設定變更

:::note 重要使用注意事項

1. **登入方式限制**：簡訊驗證碼不可同時作為 [登入方式 (1FA)](/end-user-flows/sign-up-and-sign-in/sign-in) 與 MFA 因素 (2FA) 使用。每個簡訊驗證實作請選擇一種驗證流程。

2. **註冊方式相容性**：簡訊驗證碼可同時用於註冊方式與 MFA。Logto 會根據你選擇的 MFA 政策最佳化終端使用者註冊流程，避免同一手機號碼需重複簡訊驗證。

3. **密碼重設相容性**：雖然簡訊驗證碼可同時用於 [忘記密碼](/end-user-flows/sign-up-and-sign-in/reset-password) 與 MFA，但**不建議**這樣配置。此組合會降低 MFA 的安全性，因為使用者可能透過忘記密碼的簡訊驗證重設密碼，然後用新密碼進行主驗證 (1FA)，再用相同簡訊方式進行 MFA 驗證。

:::

## 誰擁有簡訊 MFA \{#who-has-sms-mfa}

簡訊 MFA 驗證碼一律發送到使用者的主要手機號碼。<CloudLink to="/mfa">多重要素驗證</CloudLink>頁面的 **電子郵件 / 簡訊兩步驟驗證** 設定決定哪些使用者擁有簡訊 MFA：

- **所有擁有已驗證電子郵件或手機號碼的使用者**：所有擁有主要手機號碼的使用者都自動擁有簡訊 MFA，無需額外設定。
- **僅設定過的使用者**：只有主動設定簡訊 MFA 的使用者才擁有。以已驗證手機號碼註冊的使用者不會自動啟用簡訊 MFA，因此你可以將簡訊作為 MFA 選項之一，而不需讓每位使用者都啟用。使用者可在 MFA 設定流程、[帳號中心](/end-user-flows/account-settings/by-account-center-ui) 或透過 [Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa) 設定。管理員可透過 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 為使用者新增或移除。

此設定同樣適用於 [電子郵件 MFA](/end-user-flows/mfa/email-mfa)。關於預設值與切換模式時的行為，請參閱 [電子郵件與簡訊 MFA 註冊](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment)。

:::note
若選擇 **所有擁有已驗證電子郵件或手機號碼的使用者**，僅因主要手機號碼而擁有簡訊 MFA 的使用者不會有儲存的簡訊 MFA 記錄，因此不會出現在 `GET /api/my-account/mfa-verifications`、`GET /api/users/{userId}/mfa-verifications` 或 `user.mfaVerificationFactors`（自訂 JWT 宣告與 `PostSignIn` Actions）中。
:::

## 簡訊 MFA 設定流程 \{#sms-mfa-setup-flows}

MFA 設定提示可在使用者註冊時或登入後出現，具體時機取決於你設定的 [MFA 政策](/end-user-flows/mfa/configure-mfa#global-mfa-configuration)。

簡訊 MFA 設定流程會受到以下因素影響：

- **MFA 主要因素數量**：若有多個主要因素，使用者需選擇一個進行設定。主要因素指除備用碼外的 MFA 方法。
- **啟用備用碼**：啟用時，主要 MFA 因素設定完成後會自動產生備用碼，並提示使用者儲存。
- **註冊識別項設定**：手機號碼作為 [註冊識別項](/end-user-flows/sign-up-and-sign-in/sign-up#set-up-the-sign-up-identifier) 並於註冊時已用簡訊驗證碼驗證。
  - 若選擇 **所有擁有已驗證電子郵件或手機號碼的使用者**，系統會自動將該號碼綁定為 MFA 因素，無需再次驗證。若有其他主要因素，UI 會顯示「新增另一個兩步驟驗證」選項（可略過），並明確標示已啟用 MFA。
  - 若選擇 **僅設定過的使用者**，手機號碼會像其他因素一樣提供（以遮蔽號碼顯示）。當使用者選擇該因素，或僅有此主要因素時，Logto 會直接用註冊時的驗證完成設定，不會再發送第二組驗證碼。
- **既有使用者資料**：既有使用者登入後設定 MFA，需先完成主驗證，再進行 MFA 設定。若帳號已有已驗證的主要手機號碼：
  - **所有擁有已驗證電子郵件或手機號碼的使用者**，設定流程與上述註冊識別項情境相同。
  - **僅設定過的使用者**，手機號碼會以遮蔽號碼顯示。當使用者選擇該因素，或僅有此主要因素時，Logto 會發送驗證碼到該號碼，使用者輸入後即完成簡訊 MFA 設定。

以下為三種常見簡訊 MFA 綁定情境。

### 情境 1：手機號碼僅用於 MFA（典型流程） \{#scenario-1-phone-number-only-used-for-mfa-typical-flow}

當手機號碼不是註冊識別項，僅用於 MFA 時，請依標準設定流程：

- 若僅有一個簡訊 MFA 因素，直接顯示該因素的設定 UI。
- 若有多個主要 MFA 因素，顯示「設定 MFA」列表頁，讓使用者選擇要設定的因素。

若選擇 **僅設定過的使用者**，使用者需先從列表選擇因素。當僅設定簡訊、電子郵件或登入通行密鑰為唯一因素時，會出現「新增另一個兩步驟驗證」提示。

## 簡訊 MFA 驗證流程 \{#sms-mfa-verification-flows}

啟用簡訊 MFA 的使用者登入時，完成主驗證 (1FA) 後，會被提示以簡訊驗證碼作為第二驗證因素 (2FA) 驗證身分。

若有多個 MFA 因素，Logto 會依 [MFA 設定](/end-user-flows/mfa/configure-mfa#mfa-verification-flow) 中的固定順序（通行密鑰、驗證器 App OTP、簡訊驗證碼、電子郵件驗證碼、備用碼）直接開啟最高優先順序的因素。若優先提示如驗證器 App OTP，使用者可點選 **嘗試其他驗證方式** 開啟選擇清單，改選簡訊驗證碼。

## 錯誤處理 \{#error-handling}

1. **手機號碼未綁定**

   - 錯誤碼：`session.mfa.mfa_factor_not_enabled`
   - 處理方式：引導使用者先綁定手機號碼

2. **驗證碼錯誤**

   - 錯誤碼：`verification_code.code_mismatch`
   - 處理方式：提示使用者重新輸入，限制重試次數

3. **驗證碼過期**

   - 錯誤碼：`verification_code.expired`
   - 處理方式：提示使用者重新取得驗證碼

4. **發送頻率超限**
   - 錯誤碼：`request.message_rate_limited`（Logto 單一收件人發送頻率限制）或 `connector.rate_limit_exceeded`（簡訊連接器頻率限制）
   - 處理方式：顯示等待時間，限制重發
