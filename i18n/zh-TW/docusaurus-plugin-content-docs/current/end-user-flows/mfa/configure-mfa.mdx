# 設定多重要素驗證 (MFA, Multi-factor authentication)

## 在 Logto 設定 MFA \{#configure-mfa-settings-in-logto}

Logto 提供彈性的多重要素驗證 (MFA) 設定選項，以滿足不同的安全需求。你可以在全域層級為所有使用者設定 MFA，或針對多租戶應用程式按組織啟用。

### 全域 MFA 設定 \{#global-mfa-configuration}

依照下列步驟，於使用者的 Logto 登入流程啟用 MFA：

1. 前往：<CloudLink to="/mfa">Console > Multi-factor auth</CloudLink>。
2. 啟用你希望提供給使用者的驗證因子。
   1. 主要因子：
      - [Passkeys (WebAuthn)](/end-user-flows/mfa/webauthn)：高安全性的選擇，適合支援裝置生物辨識或安全金鑰等網頁產品，確保強大防護。
      - [Authenticator App OTP](/end-user-flows/mfa/authenticator-app-otp)：最常見且廣泛接受的方法。使用如 Google Authenticator 或 Authy 等驗證器應用程式產生的 TOTP（基於時間的一次性密碼）。
      - [SMS 驗證](/end-user-flows/mfa/sms-mfa)：透過簡訊將一次性驗證碼發送至使用者註冊的手機號碼，適合偏好行動裝置驗證且不需額外應用程式的使用者。
      - [Email 驗證](/end-user-flows/mfa/email-mfa)：將一次性驗證碼發送至使用者註冊的電子郵件信箱，適用於所有平台與裝置的使用者。
   2. 備用因子：
      - [備用代碼](/end-user-flows/mfa/backup-codes)：當使用者無法驗證上述任何主要因子時，作為備用選項。啟用此選項可降低使用者存取失敗的阻力。
   3. 若啟用 SMS 或 Email 驗證，請於 **Email/SMS 2-step verification** 選擇哪些使用者適用。詳見 [Email 與 SMS MFA 註冊](#email-and-sms-mfa-enrollment)。
3. 從下拉選單選擇 **Require MFA** 政策。此政策控制使用者在登入時必須完成 MFA 的時機：
   - **Optional MFA**（_Optional MFA: 讓使用者自行決定是否啟用 MFA 以提升帳戶安全_）：讓使用者自行決定是否啟用 MFA。使用者可於登入時略過 MFA 設定，並於自助帳戶設定頁面稍後設定。詳見 [如何實作帳戶設定頁](/end-user-flows/account-settings/)。
   - **Adaptive MFA**（_Adaptive MFA: 僅於登入風險較高時要求 MFA（如新國家 / 長時間未登入）_）：僅於登入行為異常時要求 MFA，讓低風險登入流程更順暢，疑似風險登入則加強驗證。Logto 會評估內建情境風險規則（新國家、地理速度、長時間未登入、不可信 IP 等）。此模式需已啟用至少一種 MFA 因子，僅適用於終端使用者登入流程，且不依賴裝置指紋。詳見 [Adaptive MFA](/end-user-flows/mfa/adaptive-mfa) 以瞭解規則門檻、Edge Header 前置需求與 Webhook 細節。
   - **Mandatory MFA**（_Mandatory MFA: 所有使用者每次登入都必須完成 MFA_）：所有使用者每次登入都必須完成 MFA。尚未設定 MFA 的使用者需先完成設定才能繼續。
   - 選擇 **Optional MFA** 時，可設定 **MFA 設定提示** 政策：
     - **不提示使用者設定 MFA**：登入或註冊時不會提示使用者設定 MFA。
     - **註冊時提示使用者設定 MFA（可略過，僅提示一次）**：新使用者於註冊時會被提示設定 MFA，現有使用者於下次登入時看到提示。可略過且不再出現。
     - **註冊後下次登入時提示使用者設定 MFA（可略過，僅提示一次）**：新使用者於註冊後下次登入時會被提示設定 MFA，現有使用者於下次登入時看到提示。可略過且不再出現。
   - 選擇 **Adaptive MFA** 時，僅支援兩種不可略過的 **MFA 設定提示** 政策（**不提示使用者設定 MFA** 不可用）：
     - **註冊時提示使用者設定 MFA（不可略過）**：新使用者於註冊時必須完成 MFA 設定，現有未設定 MFA 的使用者於下次登入時必須完成。
     - **註冊後下次登入時提示使用者設定 MFA（不可略過）**：新使用者於註冊後下次登入時必須完成 MFA 設定，現有未設定 MFA 的使用者於下次登入時必須完成。

當 **Optional MFA** 且啟用設定提示時（`註冊時提示使用者設定 MFA（可略過，僅提示一次）` 或 `註冊後下次登入時提示使用者設定 MFA（可略過，僅提示一次）`），Logto 會先顯示標題為 `開啟兩步驟驗證` 的啟用 MFA 確認頁。使用者可選擇 `啟用兩步驟驗證` 進行 MFA 綁定，或略過提示完成本次登入 / 註冊流程而不啟用 MFA。在 **Adaptive MFA** 或 **Mandatory MFA** 下，使用者會直接進入 MFA 因子綁定，不會看到 `開啟兩步驟驗證` 確認頁。

:::tip
若你需要在使用者略過 MFA 註冊後再次提示，請重設其略過狀態，讓下次登入時顯示設定畫面。管理員可透過 Management API（`PATCH /api/users/{userId}/logto-configs`），開發者可於自助流程呼叫 Account API（`PATCH /api/my-account/logto-configs`）。[Management API 參考文件](https://openapi.logto.io/operation/operation-updateuserlogtoconfigs) · [Account API 參考文件](https://openapi.logto.io/operation/operation-updatelogtoconfig)
:::

### Email 與 SMS MFA 註冊 \{#email-and-sms-mfa-enrollment}

Email 與 SMS 驗證碼會發送至使用者的主要電子郵件與主要手機號碼。**Email/SMS 2-step verification** 設定決定哪些使用者擁有這些因子。此選項於啟用 SMS 或 Email 驗證碼因子時出現，並同時適用於兩者。

- **所有擁有已驗證 Email 或手機號碼的使用者**：所有有主要 Email 的使用者自動擁有 Email MFA，有主要手機號碼的使用者自動擁有 SMS MFA，無需額外設定。以已驗證 Email 或手機號碼註冊的使用者即已擁有該因子。
- **僅有自行設定的使用者**：只有在 MFA 設定流程中驗證過代碼的使用者才擁有 Email 或 SMS MFA，可於 [Account Center](/end-user-flows/account-settings/by-account-center-ui)、[Account API](/end-user-flows/account-settings/by-account-api#manage-email-and-sms-mfa) 或管理員透過 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 新增。僅有已驗證 Email 或手機號碼並不會自動啟用 MFA，因此你可以將 Email 或 SMS 作為 MFA 選項之一，而不需讓每位使用者都註冊。

新租戶預設為 **僅有自行設定的使用者**。較早建立的租戶則維持 **所有擁有已驗證 Email 或手機號碼的使用者**，直到你變更。於 Management API，此設定為 [sign-in experience](https://openapi.logto.io/operation/operation-updatesigninexp) 的 `mfa.verificationCodeEnrollment`，值為 `Implicit` 或 `Explicit`。更新 `mfa` 物件時若省略 `verificationCodeEnrollment`，將重設為 `Implicit`。

Logto 會記錄每次 Email 或 SMS MFA 設定，無論哪種模式。紀錄儲存的是選擇而非地址：當使用者更換或移除主要 Email 或手機號碼時仍保留，若無主要地址則忽略。日後新增新地址時會再次生效。

**切換模式**

切換立即生效，不會更動任何使用者資料。Console 會要求你確認。

- **切換為僅有自行設定的使用者**：未設定 Email 或 SMS MFA 的使用者將不再自動擁有。僅以 Email 或手機號碼作為唯一因子的使用者，將被視為未啟用 MFA：登入時不會要求驗證，僅於政策要求或提示時才需設定。Logto 不會自動註冊任何人。若需保留特定使用者的 Email 或 SMS MFA，請於切換前透過 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) 新增。
- **切換為所有擁有已驗證 Email 或手機號碼的使用者**：所有有主要 Email 或手機號碼的使用者再次自動擁有 Email 或 SMS MFA，包括未曾設定過的使用者。

### 組織層級 MFA 設定 \{#organization-level-mfa-configuration}

對於支援 [組織 (Organizations)](/organizations) 的多租戶架構產品，大多數情況下你不需要求所有使用者啟用 MFA。你可以按組織啟用 MFA，根據每個客戶需求量身打造。請參考 [要求組織成員啟用 MFA](/organizations/organization-management#require-mfa-for-organization-members) 開始設定。

當 **Require MFA** 下拉選單選擇 **Optional MFA** 時，Console 會顯示 **組織啟用 MFA 後提示成員設定 MFA** 設定。設為 **下次登入時提示成員設定 MFA（不可略過）**，即可讓啟用 MFA 的組織成員於下次登入時必須完成 MFA 設定且不可略過。（此設定於選擇 **Adaptive MFA** 或 **Mandatory MFA** 時會隱藏且不儲存。）

於 **Adaptive MFA** 下，觸發不到任何風險規則的低風險登入，即使使用者已啟用個人 **Require MFA setup** 或屬於 `isMfaRequired` 組織，也不會要求 MFA 驗證。

### 建議新增另一個 MFA 因子 \{#suggest-adding-another-mfa-factor}

於 <CloudLink to="/mfa">Console > Multi-factor authentication</CloudLink>，**建議新增另一個 MFA 因子** 開關（預設啟用，由 Sign-in Experience API 的 `mfa.skipAdditionalBindingSuggestion` 控制）會在下列情況於註冊或登入時提示使用者新增 MFA 因子：

- 使用者唯一的 MFA 因子為登入時使用的 Email、手機號碼或 Passkey，且
- 租戶已啟用至少一種其他 MFA 因子。

使用者可略過此提示。略過後，Logto 會於使用者的 `logtoConfig` 儲存 `mfa.additionalBindingSuggestionSkipped: true`，未來登入時不再顯示。你可透過 [Account API](/end-user-flows/account-settings/by-account-api) 更新或重設此旗標（`PATCH /api/my-account/logto-configs`，內容 `{ "mfa": { "additionalBindingSuggestionSkipped": false } }`；注意 `GET /api/my-account/logto-configs` 與 `GET /api/users/{userId}/logto-configs` 不會回傳此欄位）。

### 個別使用者 MFA 要求 \{#per-user-mfa-requirement}

管理員可針對單一使用者強制要求 MFA 設定，無論租戶的 **Optional MFA** 提示設定為何：

- **於 Console**：前往 <CloudLink to="/users">Console > User management</CloudLink>，選擇使用者，於 **Multi-factor authentication** 區塊啟用 **Require MFA setup**。
- **透過 Management API**：呼叫 `PATCH /api/users/{userId}/logto-configs`，內容 `{ "mfa": { "required": true } }`（查詢則用 `GET /api/users/{userId}/logto-configs`）。詳見 [Management API 管理帳戶設定](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management)。

終端使用者無法透過 Account API（`PATCH /api/my-account/logto-configs`）修改 `mfa.required`；自助客戶端僅可於 `GET /api/my-account/mfa-settings` 讀取 `required` 欄位。

當個別使用者 `mfa.required` 為 `true` 時，該使用者必須設定至少一個 MFA 因子才能完成登入，且不可略過。在 **Optional MFA** 下，即使使用者啟用 `skipMfaOnSignIn` 或設為 `enabled: false`，登入時仍需 MFA 驗證。在 **Adaptive MFA** 下，觸發不到任何風險規則的低風險登入仍不會要求 MFA 驗證。

## MFA 使用者流程 \{#mfa-user-flow}

### MFA 設定流程 \{#mfa-set-up-flow}

啟用 MFA 後，使用者可能於登入或註冊時被提示設定 MFA。僅於 **Require MFA** 政策選擇 **Optional MFA** 時可略過此設定流程。

1. **造訪登入或註冊頁面**：使用者前往登入或註冊頁。
2. **完成登入或註冊**：於登入或註冊流程中完成身分驗證。
   - 若選擇 **Optional MFA** 且啟用設定提示，Logto 會先顯示 `開啟兩步驟驗證` 確認頁，使用者可略過 MFA 設定或點選 `啟用兩步驟驗證` 繼續。
   - 在 **Adaptive MFA** 或 **Mandatory MFA** 下，使用者會直接進入 MFA 因子綁定，無法略過設定，也不會看到 `開啟兩步驟驗證` 頁面。
3. **設定 MFA 主要因子**：提示使用者設定主要 MFA 因子（Passkey、Authenticator app OTP、SMS 代碼或 Email 代碼）。
   - 若啟用多種主要因子，使用者可選擇偏好選項。
   - 若主要因子與註冊識別碼相同（如 SMS 或 Email），則已預先驗證，無需再次驗證：
     - **所有擁有已驗證 Email 或手機號碼的使用者**，該因子已屬於使用者，直接進入下一步（如「新增另一個兩步驟驗證」或「儲存備用因子」）。
     - **僅有自行設定的使用者**，該因子如同其他因子提供，設定時不會再發送第二組驗證碼。詳見 [Email 與 SMS MFA 註冊](#email-and-sms-mfa-enrollment)。
   - 若於 **Require MFA** 政策選擇 **Optional MFA**，可點選「略過」按鈕略過此步驟。
4. **設定 MFA 備用因子**：若啟用 **備用代碼**，於成功設定主要驗證因子後，提示使用者儲存備用代碼。系統會自動產生備用代碼，使用者可下載並妥善保存。使用者需手動確認備用代碼以完成 MFA 設定流程。

### MFA 驗證流程 \{#mfa-verification-flow}

已設定 MFA 的使用者於登入時會被提示以已設定的 MFA 因子驗證身分。驗證因子依 Logto MFA 設定與使用者設定而定。

若使用 [Passkey 登入](/end-user-flows/sign-up-and-sign-in/passkey-sign-in)，Logto 會略過額外的 MFA 驗證步驟，因為登入所用的 Passkey 本身即為 WebAuthn MFA 因子。

- 若使用者僅有一個可用 MFA 因子，將直接驗證該因子。
- 若有多個可用 MFA 因子，Logto 會依固定優先順序排序並直接開啟第一個可用因子：
  1. **Passkey (WebAuthn)**
  2. **Authenticator app OTP (TOTP)**
  3. **SMS 驗證碼**
  4. **Email 驗證碼**
  5. **備用代碼**
- 若有兩種以上 MFA 因子可用，驗證頁會顯示 **嘗試其他驗證方式** 連結，讓使用者開啟方法選單並切換至其他可用因子（若啟用，也包含一次性備用代碼）。

<img src="/img/assets/verify-mfa.png" alt="MFA 驗證流程" />

### 登入綁定規則與豁免 \{#sign-in-binding-rules-and-exemptions}

設計 MFA 流程時請留意下列行為：

- **備用代碼再次提示**：啟用 **備用代碼** 且使用者已有其他啟用的 MFA 因子時，若所有備用代碼已用完或啟用備用代碼於首次註冊後，Logto 會於登入時提示產生並儲存新一組備用代碼。
- **登入時綁定新因子需已驗證因子**：於 `SignIn` 互動中，若使用者已有 MFA 因子，綁定新因子（包含儲存新備用代碼或「建議新增另一個 MFA 因子」提示）需先完成 MFA 驗證挑戰（或以 Passkey 登入或企業級單一登入 (Enterprise SSO)）。略過 MFA 驗證的登入（如 [受信任裝置](/end-user-flows/mfa/trusted-devices)、未觸發規則的低風險 [Adaptive MFA](/end-user-flows/mfa/adaptive-mfa) 登入、或使用者略過 **Optional MFA**（`skipMfaOnSignIn` / `enabled: false`））無法於該次登入流程綁定新 MFA 因子。這些情境下，使用者可於 Account Center 或 [Account API](/end-user-flows/account-settings/by-account-api) 事後新增因子。
- **企業級單一登入 (Enterprise SSO) 豁免**：透過 [企業級單一登入 (Enterprise SSO)](/end-user-flows/enterprise-sso) 登入或註冊時，該次互動會略過租戶 MFA 驗證與 MFA 設定提示（除非客戶端明確要求 MFA，如 `acr_values` 設為 `urn:logto:acr:mfa`）。
- **忘記密碼豁免**：[忘記密碼](/end-user-flows/sign-up-and-sign-in/reset-password) 流程會略過 MFA 驗證與 MFA 設定提示。

## MFA 管理 \{#mfa-management}

除了登入 / 註冊時的初始設定外，使用者可透過自助帳戶中心管理 MFA 設定，靈活綁定或解除 MFA 因子。

### 建立帳戶中心 \{#building-an-account-center}

你可利用 Logto 的 [Account API](/end-user-flows/account-settings/by-account-api) 建立完整帳戶中心，讓使用者：

- **綁定新 MFA 因子**：新增驗證器 App、Passkey 或重新產生備用代碼
- **解除現有 MFA 因子**：移除不再使用的 MFA 方法
- **檢視目前 MFA 狀態**：查看目前已設定哪些 MFA 因子

### 登入後 MFA 設定提示 \{#post-login-mfa-setup-prompts}

對於註冊時不強制 MFA 的應用程式，你可實作智慧提示鼓勵使用者設定 MFA：

- **條件式提示**：根據使用者行為或帳戶價值顯示 MFA 設定建議
- **安全儀表板**：顯示安全分數，啟用 MFA 後分數提升
- **漸進式導引**：將 MFA 設定納入逐步強化安全性的流程

詳見 [Account API](/end-user-flows/account-settings/by-account-api) 以瞭解如何實作這些模式。

### 於 Console 管理使用者 MFA \{#manage-users-mfa-in-console}

於 <CloudLink to="/user">Console > User management</CloudLink>，管理員可有效管理使用者 MFA 設定：

- **檢視使用者 MFA 狀態**：查看每位使用者啟用哪些 MFA 因子。若 Email 或 SMS 因子僅因使用者有已驗證 Email 或手機號碼而生效，或使用者設定但因因子停用而不生效，會有提示標記。
- **移除使用者 MFA**：逐一移除已儲存的 MFA 因子。隱含的 Email 或 SMS 驗證碼因子無法直接於此表移除，啟用 Passkey 登入時，Passkey (WebAuthn) 因子需於同一使用者詳情頁的 **Passkeys** 區塊管理。

若需為使用者新增 Email 或 SMS MFA，請使用 [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management)。

### 常見問題 \{#faqs}

<details>
<summary>
### 管理員移除使用者現有 MFA 因子時會發生什麼事？ \{#what-happens-when-administrators-remove-users-existing-mfa-factors}
</summary>
當管理員移除使用者所有主要 MFA 因子（Passkey、Authenticator app OTP、SMS 或 Email）後，使用者下次登入時會出現以下情境：

**情境 1：無任何 MFA 因子**

- 若完全沒有 MFA 因子（包含無備用代碼），且 [MFA 政策](#global-mfa-configuration) 要求 MFA，使用者可直接登入且無需 MFA 驗證，並會立即被提示再次設定 MFA。

**情境 2：仍有備用代碼**

- 若仍有備用代碼可用，使用者登入時需先以備用代碼驗證。
- 成功驗證後，會被提示設定新的主要 MFA 因子。
- 是否可略過此設定，取決於你設定的 MFA 政策。
