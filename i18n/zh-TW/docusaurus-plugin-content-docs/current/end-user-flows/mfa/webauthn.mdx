# Passkeys（WebAuthn）

[Passkey](https://auth.wiki/passkey) 提供比傳統密碼更安全且更友善的替代方案。Passkey 利用公開金鑰加密技術，將使用者裝置、服務網域與使用者 ID 綁定，有效防止釣魚與密碼攻擊。它相容於多種裝置或瀏覽器，並允許使用者透過生物辨識與硬體安全功能進行便利的驗證。 [WebAuthn](https://auth.wiki/webauthn) 則提供 API，讓網站能實作 passkey。

Logto 支援將 passkeys（WebAuthn）用於 [多重要素驗證 (MFA, Multi-Factor Authentication)](/end-user-flows/mfa/configure-mfa) 以及 [passkey 登入](/end-user-flows/sign-up-and-sign-in/passkey-sign-in)。同一組底層 WebAuthn 憑證可依據租戶設定於兩者間重複使用。

## 概念 \{#concepts}

客戶通常認識 Passkeys 而非 WebAuthn，那麼兩者有什麼關係？又該如何使用？讓我們來釐清這些概念：

- **Passkeys**：Passkey 是一種基於 FIDO、具備防釣魚能力的憑證，用來取代密碼。它採用非對稱公開金鑰加密技術以提升安全性。Passkey 可以是硬體憑證或安全金鑰，例如 USB 或藍牙裝置。由於「Passkeys」是呈現給使用者的驗證方式名稱，建議於產品端顯示此名稱。
- **WebAuthn**：WebAuthn 是由 W3C 與 FIDO 聯盟制定的 JavaScript API，讓網頁應用程式能以 FIDO2 標準進行驗證。Passkeys 是 WebAuthn 支援的其中一種驗證方式。在 Logto Console 中，這項整合專業稱為「WebAuthn」。

WebAuthn 提供多元的驗證器（authenticator）供使用者選擇，分為本地與雲端兩種類型：

- **平台驗證器（Platform authenticator, Internal authenticator）**：綁定於單一且特定裝置作業系統，例如電腦、筆電、手機或平板，僅能在該裝置上以生物辨識或裝置密碼授權，驗證速度快。例如 macOS 或 iOS 上以 Touch ID、Face ID 或裝置密碼驗證的 iCloud Keychain；Windows Hello 則可用臉部辨識、指紋或 PIN。
- **漫遊驗證器（Roaming authenticator, External authenticator, Cross-platform authenticator）**：為獨立、可攜式的裝置或軟體應用程式，如硬體安全金鑰或智慧型手機。需透過 USB 連接或開啟 NFC、藍牙。漫遊驗證器不限於單一裝置或瀏覽器，彈性更高。

想深入了解 WebAuthn 的原理與流程，請參閱我們的部落格文章：[WebAuthn 與 Passkeys 101](https://blog.logto.io/web-authn-and-passkey-101/) 及 [整合 WebAuthn 前你該知道的事](https://blog.logto.io/webauthn-base-knowledge/)。

## 設定 MFA 的 passkeys 驗證 \{#configure-passkeys-verification-for-mfa}

1. 前往 <CloudLink to="/mfa">Console > 多重要素驗證 (Multi-factor authentication)</CloudLink>
2. 啟用「Passkeys（WebAuthn）」驗證因子。建議與其他 MFA 因子（TOTP、簡訊、備用碼）搭配使用，以降低單一因子依賴。
3. 設定你偏好的 MFA 政策（必填或選填）
4. 儲存設定變更

:::tip
若同一使用者以 [passkey 登入](/end-user-flows/sign-up-and-sign-in/passkey-sign-in)，Logto 會略過額外的 MFA 驗證步驟。因為 passkey 登入已滿足 WebAuthn 驗證需求。
:::

:::note 注意限制

實作 WebAuthn 時，請留意以下限制：

1. **平台與瀏覽器限制**：Logto 目前尚未支援原生應用程式的 WebAuthn。此外，WebAuthn 驗證器的可用性取決於瀏覽器與裝置能力（[查詢支援列表](https://caniuse.com/?search=webauthn)）。因此，WebAuthn 並非唯一的多重要素驗證 (MFA) 選項，否則你需自行控管哪些瀏覽器與裝置可存取產品。
2. **網域限制**：更換網域會導致使用者無法透過原有 WebAuthn 帳號驗證。Passkeys 綁定於當前網頁的特定網域，無法跨網域使用。
3. **裝置限制**：遺失裝置可能導致帳號無法存取，特別是僅依賴「本裝置」平台驗證器的情境。建議提供多種驗證因子以提升存取彈性。

:::

## 設定 passkeys 管理 \{#configure-passkeys-management}

你可以利用 Account API 建立自訂帳號管理介面，讓使用者新增、檢視、重新命名與移除 passkeys。這有助於打造個人化帳號中心，並支援跨裝置備份情境。

詳細實作步驟與 API 端點，請參閱 [透過 Account API 管理帳號設定](/end-user-flows/account-settings/by-account-api#link-a-new-webauthn-passkey)。

## 匯出 passkeys \{#export-passkeys}

你可以透過 [Management API](/integrate-logto/interact-with-management-api) 匯出 Logto 為使用者儲存的 WebAuthn 憑證。匯出後可將 passkeys 移轉至同一網域下支援 WebAuthn 的其他系統，讓使用者持續以現有 passkey 登入。

呼叫 [`GET /api/users/{userId}/mfa-verifications`](https://openapi.logto.io/operation/operation-listusermfaverifications) 並將 `includeWebAuthnCredentials` 查詢參數設為 `true`：

```bash
curl "https://[tenant-id].logto.app/api/users/{userId}/mfa-verifications?includeWebAuthnCredentials=true" \
  -H 'authorization: Bearer <management-api-access-token>'
```

回應中的每筆 WebAuthn 項目都包含儲存的憑證：

```json
[
  {
    "id": "wv9m3k2x7p1q",
    "createdAt": "2026-10-12T08:31:24.000Z",
    "lastUsedAt": "2026-11-02T06:15:09.000Z",
    "type": "WebAuthn",
    "agent": "Mozilla/5.0 (Macintosh) ...",
    "name": "MacBook",
    "rpId": "auth.example.com",
    "credentialId": "Ab3dY0n9Kq2LwX8mR4sT1uV6zE",
    "publicKey": "pQECAyYgASFYIOrE5x...",
    "counter": 0,
    "transports": ["internal", "hybrid"]
  }
]
```

| 欄位           | 說明                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| `credentialId` | WebAuthn 憑證 ID，base64url 編碼。                                           |
| `publicKey`    | 憑證公開金鑰（COSE 格式），base64url 編碼。                                  |
| `counter`      | Logto 觀察到的該憑證最後簽章計數（`signCount`）。許多 passkey 永遠回報 `0`。 |
| `transports`   | 註冊時驗證器回報的傳輸方式，如 `internal`、`hybrid` 或 `usb`。               |
| `rpId`         | 憑證註冊時的 Relying Party ID（網域）。                                      |
| `createdAt`    | 憑證註冊時間。                                                               |
| `lastUsedAt`   | 憑證最後一次用於驗證使用者的時間。                                           |

若未帶入 `includeWebAuthnCredentials`，回應將省略 `credentialId`、`publicKey`、`counter`、`transports` 與 `rpId`。其他 MFA 因子則維持不變。此參數亦適用於唯讀 Management API 存取，因為憑證 ID 與公開金鑰無法用於登入。

匯入憑證至其他系統時請注意：

- **維持相同網域。** Passkey 僅適用於註冊時的 Relying Party ID。其他系統必須以匯出的 `rpId` 作為 WebAuthn Relying Party ID，亦即於該網域提供登入頁，例如你的 [自訂網域](/logto-cloud/custom-domain)。
- **處理無 `rpId` 的憑證。** 在 Logto 開始記錄 Relying Party ID 前註冊、且未再使用過的憑證，將沒有 `rpId`。它們綁定於註冊當下的登入頁網域，可能與你目前的自訂網域不同。
- **對應使用者識別。** Logto 以 Logto 使用者 ID 的 UTF-8 位元組作為 WebAuthn `userHandle`。Passkey 登入時，驗證器會回傳此值，因此其他系統需將其對應至遷移後的使用者。
- **保留計數器。** 將 `counter` 作為憑證目前的簽章計數儲存，以便其他系統持續偵測複製的驗證器。

## Passkey 設定流程 \{#passkey-setup-flows}

Passkeys 規範要求使用者必須主動點擊當前頁面的按鈕以啟動驗證元件。因此，無論是設定或驗證流程，皆應將使用者導向起始頁以啟動 WebAuthn。

## Passkey 驗證流程 \{#passkey-verification-flows}

當使用者已設定多種 MFA 方法（包含 passkey）時，passkey 會因其安全性與便利性，在第一個畫面作為推薦的 MFA 驗證方式。使用者可點擊下方「嘗試其他驗證方式」切換至其他驗證方法。詳情請參閱 [設定 MFA](/end-user-flows/mfa/configure-mfa#mfa-verification-flow)。

若使用者以 [passkey 登入](/end-user-flows/sign-up-and-sign-in/passkey-sign-in) 完成登入，而非輸入其他第一因子，Logto 之後不會再要求額外 MFA 步驟。因為 passkey 本身即視為 WebAuthn MFA 因子。
