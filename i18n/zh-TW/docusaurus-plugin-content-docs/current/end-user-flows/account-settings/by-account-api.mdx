# 透過 Account API 管理帳戶設定

## 什麼是 Logto Account API \{#what-is-logto-account-api}

Logto Account API 是一套完整的 API，讓終端使用者可以直接透過 API 存取帳戶，而無需經過 Management API。重點如下：

- 直接存取：Account API 讓終端使用者能直接存取並管理自己的帳戶資料，無需透過 Management API 中繼。
- 使用者資料與身分管理：使用者可管理個人資料與安全設定，包括電子郵件、手機、密碼、社交連結、MFA 因子，並可從 Secret Vault 取得企業級單一登入 (SSO) 聯邦權杖。
- 全域存取控制：管理員可對存取設定進行完整、全域的控管，並可自訂每個欄位。
- 無縫授權 (Authorization)：授權 (Authorization) 變得前所未有地簡單！只需使用 `client.getAccessToken()` 取得 Logto 的不透明權杖 (Opaque token)，並以 `Bearer <access_token>` 附加於 Authorization 標頭即可。

透過 Logto Account API，你可以打造如個人資料頁等自訂帳戶管理系統，並與 Logto 完整整合。

常見應用場景如下：

- 取得使用者資料
- 更新使用者資料
- 更新使用者密碼
- 更新使用者身分（含電子郵件、手機、社交連結）
- 管理 MFA 因子（驗證方式）
- 管理使用者工作階段
- 管理使用者授權應用程式（授權記錄）

想瞭解更多可用 API，請參閱 [Logto Account API Reference](https://openapi.logto.io/group/endpoint-my-account) 與 [Logto Verification API Reference](https://openapi.logto.io/group/endpoint-verifications)。

:::note

SSO 帳戶檢視與帳戶刪除功能目前僅能透過 Logto Management API 實現（Account API 不支援連結或解除連結企業級單一登入 (SSO) 身分，只能取得已連結 SSO 身分的 Secret Vault 權杖）。詳見 [透過 Management API 管理帳戶設定](/end-user-flows/account-settings/by-management-api)。

:::

## 如何啟用 Account API \{#how-to-enable-account-api}

前往 <CloudLink to="/sign-in-experience/account-center">Console > 登入與帳戶 > 帳戶中心</CloudLink>。

Account API 預設為關閉，因此其存取控制設定為鎖定。切換 **啟用 Account API** 以開啟功能。

啟用後，可設定 **近期驗證 (Recent authentication)** 時間窗（1 至 120 分鐘，預設 10 分鐘），以及識別資訊、個人資料、第三方權杖存取的每欄位權限。每個欄位支援 `Off`、`ReadOnly` 或 `Edit`，預設為 `Off`。

1. **安全性欄位**：
   - 包含：主要電子郵件、主要手機、社交身分、密碼、通行密鑰 (passkeys)、MFA、多重存取權杖 (personal access tokens)。
   - 敏感操作需來自第一方應用程式的近期使用者驗證——access token 的 `acr` 必須符合 `urn:logto:acr:1fa`，且在設定的近期驗證時間窗內（詳見 [OIDC 進階驗證 (step-up authentication)](/end-user-flows/step-up-authentication#account-api-and-account-center)）。
   - 若要將 WebAuthn 通行密鑰用於 MFA，請將前端應用程式網域加入 **WebAuthn 相關來源 (Related Origins)**，以便帳戶中心與登入體驗共用通行密鑰。詳見 [連結新 WebAuthn 通行密鑰](#link-a-new-webauthn-passkey)。
2. **個人資料欄位**：
   - 包含：使用者名稱、姓名、大頭貼、[profile](/user-management/user-data#profile)（其他標準個人資料屬性）、[自訂資料](/user-management/user-data#custom-data)。
   - 終端使用者可直接編輯，僅 `username` 需近期驗證。
3. **Secret vault**：
   - 對於 OIDC 或 OAuth 社交與企業連接器，Logto [Secret Vault](/secret-vault/federated-token-set) 會在驗證後安全儲存第三方 access token 與重新整理權杖 (refresh token)。應用程式可直接呼叫外部 API（如同步 Google Calendar 事件），無需再次提示使用者登入。啟用 Account API 後即可自動取得權杖。
4. **工作階段管理**：
   - 啟用後，使用者可檢視並管理所有啟用中的工作階段，包括裝置資訊與上次登入時間，也可撤銷特定裝置的工作階段以登出。
   - `Sessions` 欄位權限同時控制使用者授權應用程式（授權記錄）API（檢視與撤銷授權）。
   - 存取工作階段與授權管理需與安全性欄位相同的近期驗證。

## 如何存取 Account API \{#how-to-access-account-api}

:::note
為確保 access token 具備正確權限，請在 Logto 設定中正確配置對應的權限範圍 (Scope)。

例如，`POST /api/my-account/primary-email` 需配置 `email` 權限範圍；`POST /api/my-account/primary-phone` 需配置 `phone` 權限範圍。

```ts
import { type LogtoConfig, UserScope } from '@logto/js';

const config: LogtoConfig = {
  // ...其他選項
  // 根據需求加入適當的權限範圍
  scopes: [
    UserScope.Email, // 用於 `{POST,DELETE} /api/my-account/primary-email` API
    UserScope.Phone, // 用於 `{POST,DELETE} /api/my-account/primary-phone` API
    UserScope.CustomData, // 管理自訂資料
    UserScope.Address, // 管理地址
    UserScope.Identities, // 用於身分與 MFA 相關 API
    UserScope.Profile, // 管理使用者個人資料
    UserScope.Sessions, // 管理使用者工作階段與應用程式授權
  ],
};
```

:::

### 取得存取權杖 (Access token) \{#fetch-an-access-token}

在應用程式中設置 SDK 後，可使用 `client.getAccessToken()` 方法取得存取權杖。此權杖為不透明權杖 (Opaque token)，可用於存取 Account API。

若未使用官方 SDK，請在存取權杖請求 `/oidc/token` 時將 `resource` 設為空字串。

### 使用存取權杖存取 Account API \{#access-account-api-using-access-token}

與 Account API 互動時，請將存取權杖以 Bearer 格式（`Bearer YOUR_TOKEN`）放入 HTTP 標頭的 `Authorization` 欄位。

以下為取得使用者帳戶資訊的範例：

```bash
curl https://[tenant-id].logto.app/api/my-account \
  -H 'authorization: Bearer <access_token>'
```

## 管理基本帳戶資訊 \{#manage-basic-account-information}

### 取得使用者帳戶資訊 \{#retrieve-user-account-information}

可透過 [`GET /api/my-account`](https://openapi.logto.io/operation/operation-getprofile) 端點取得使用者資料。

```bash
curl https://[tenant-id].logto.app/api/my-account \
  -H 'authorization: Bearer <access_token>'
```

回應內容如下：

```json
{
  "id": "...",
  "username": "...",
  "name": "...",
  "avatar": "..."
}
```

回應欄位會依帳戶中心設定而有所不同。

### 更新基本帳戶資訊 \{#update-basic-account-information}

基本帳戶資訊包含使用者名稱、姓名、大頭貼、自訂資料及其他個人資料。

要更新 **username、name、avatar、customData**，可使用 [`PATCH /api/my-account`](https://openapi.logto.io/operation/operation-updateprofile) 端點。

```bash
curl -X PATCH https://[tenant-id].logto.app/api/my-account \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"username":"...","name":"...","avatar":"..."}'
```

要更新其他個人資料（如 **familyName、givenName、middleName、nickname、profile（個人頁面網址）、website、gender、birthdate、zoneinfo、locale、address**），可使用 [`PATCH /api/my-account/profile`](https://openapi.logto.io/operation/operation-updateotherprofile) 端點。

```bash
curl -X PATCH https://[tenant-id].logto.app/api/my-account/profile \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"familyName":"...","givenName":"..."}'
```

## 管理識別資訊與其他敏感資料 \{#manage-identifiers-and-other-sensitive-information}

出於安全考量，敏感的 Account API 操作需來自第一方應用程式的近期使用者驗證：access token 必須帶有 `acr` 且符合 `urn:logto:acr:1fa`，且 `auth_time` 在租戶設定的 **近期驗證** 時間窗內（預設 600 秒 / 10 分鐘，可設定 60 至 7,200 秒）。

若 access token 不含 `urn:logto:acr:1fa` 或已超過時間窗，Account API 會回傳 `401 Unauthorized`，並帶有 RFC 9470 `WWW-Authenticate` 標頭（`error="insufficient_user_authentication"`，`acr_values="urn:logto:acr:1fa"`，`max_age="<window>"`）。請依此參數啟動 [OIDC 進階驗證 (step-up authentication)](/end-user-flows/step-up-authentication#account-api-and-account-center) 並以新權杖重試。

:::note
綁定**新**電子郵件、手機、社交身分或 WebAuthn 通行密鑰時，也需透過 Verification API 驗證新識別資訊或因子所有權，並於請求內容帶入 `newIdentifierVerificationRecordId`，詳見下方各節。
:::

### 更新使用者密碼 \{#update-users-password}

要更新使用者密碼，可使用 [`POST /api/my-account/password`](https://openapi.logto.io/operation/operation-updatepassword) 端點。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/password \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"password":"..."}'
```

:::tip
如同註冊時設定密碼，透過 Account API 設定的密碼也必須符合你在 <CloudLink to="/security/password-policy">Console > 安全性 > 密碼政策</CloudLink> 設定的 [密碼政策](/security/password-policy)。若密碼不符，Logto 會回傳詳細驗證結果與錯誤訊息。
:::

### 更新或連結新電子郵件 \{#update-or-link-new-email}

:::note
使用此方法前，需先[設定電子郵件連接器](/connectors/email-connectors/)，並確認已配置 `BindNewIdentifier` 範本。
:::

要更新或連結新電子郵件，需先驗證該電子郵件的所有權。

呼叫 [`POST /api/verifications/verification-code`](https://openapi.logto.io/operation/operation-createverificationbyverificationcode) 端點請求驗證碼。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/verification-code \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"identifier":{"type":"email","value":"..."}}'
```

回應中會有 `verificationId`，並會收到驗證碼於該電子郵件信箱，請用於驗證。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/verification-code/verify \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"identifier":{"type":"email","value":"..."},"verificationId":"...","code":"..."}'
```

驗證通過後，即可呼叫 [`PATCH /api/my-account/primary-email`](https://openapi.logto.io/operation/operation-updateprimaryemail) 更新使用者電子郵件，並於請求內容帶入 `verificationId` 作為 `newIdentifierVerificationRecordId`。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/primary-email \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"email":"...","newIdentifierVerificationRecordId":"<verification_record_id_from_new_email>"}'
```

:::tip
如同註冊時收集的電子郵件，透過 Account API 連結的電子郵件也必須通過你在 <CloudLink to="/security/blocklist">Console > 安全性 > 封鎖清單</CloudLink> 設定的 [封鎖清單](/security/blocklist) 驗證。若違反政策，Logto 會拒絕請求並回傳詳細錯誤。
:::

### 移除使用者電子郵件 \{#remove-the-users-email}

要移除使用者電子郵件，可使用 [`DELETE /api/my-account/primary-email`](https://openapi.logto.io/operation/operation-deleteprimaryemail) 端點。

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/primary-email \
  -H 'authorization: Bearer <access_token>'
```

### 管理手機 \{#manage-phone}

:::note
使用此方法前，需先[設定簡訊連接器](/connectors/sms-connectors/)，並確認已配置 `BindNewIdentifier` 範本。
:::

與更新電子郵件類似，可使用 [`PATCH /api/my-account/primary-phone`](https://openapi.logto.io/operation/operation-updateprimaryphone) 端點更新或連結新手機，並可用 [`DELETE /api/my-account/primary-phone`](https://openapi.logto.io/operation/operation-deleteprimaryphone) 端點移除使用者手機。

### 連結新社交連結 \{#link-a-new-social-connection}

要連結新社交連結，需先透過 [`POST /api/verifications/social`](https://openapi.logto.io/operation/operation-createverificationbysocial) 取得授權網址。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/social \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"connectorId":"...","redirectUri":"...","state":"..."}'
```

- `connectorId`：對應 [社交連接器](/connectors/social-connectors/) 的 ID。
- `redirectUri`：使用者授權應用程式後的導向網址，需於此網址架設網頁並接收回調。
- `state`：授權後回傳的狀態，為防止 CSRF 攻擊的隨機字串。

回應中會有 `verificationRecordId`，請妥善保存。

使用者授權應用程式後，會於 `redirectUri` 收到帶有 `state` 參數的回調。接著可用 [`POST /api/verifications/social/verify`](https://openapi.logto.io/operation/operation-verifyverificationbysocial) 端點驗證社交連結。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/social/verify \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"connectorData":"...","verificationRecordId":"..."}'
```

`connectorData` 為社交連接器授權後回傳的資料，需於回調頁解析 `redirectUri` 的查詢參數並包裝為 JSON 作為 `connectorData` 欄位值。

最後，可用 [`POST /api/my-account/identities`](https://openapi.logto.io/operation/operation-adduseridentities) 端點連結社交帳號。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/identities \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"newIdentifierVerificationRecordId":"<verification_record_id_from_social>"}'
```

### 移除社交連結 \{#remove-a-social-connection}

要移除社交連結，可使用 [`DELETE /api/my-account/identities`](https://openapi.logto.io/operation/operation-deleteidentity) 端點。

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/identities/[connector_target_id] \
  -H 'authorization: Bearer <access_token>'
```

### 連結新 WebAuthn 通行密鑰 \{#link-a-new-webauthn-passkey}

:::note
請先[啟用 MFA 與 WebAuthn](/end-user-flows/mfa)。
:::

:::note
WebAuthn 通行密鑰寫入端點（`POST /api/my-account/mfa-verifications` 並帶 `type: "WebAuthn"`、`PATCH /api/my-account/mfa-verifications/{verificationId}/name`、`DELETE /api/my-account/mfa-verifications/{verificationId}`）受帳戶中心設定的 `passkey` 欄位控管，若未設定則回退至 `mfa` 欄位。讀取 `GET /api/my-account/mfa-verifications` 則需 `mfa` 欄位設為 `ReadOnly` 或 `Edit`。
:::

**步驟 1：將前端應用程式來源加入相關來源**

WebAuthn 通行密鑰綁定於特定主機名稱（RP ID, Relying Party ID）。僅於該 RP ID 的來源託管的應用程式可註冊或驗證通行密鑰。

由於前端應用程式與 Logto 驗證頁面網域不同，需於 **相關來源 (Related Origins)** 設定允許跨來源通行密鑰操作。

**Logto 如何決定 RP ID：**

- **預設情境**：僅使用 Logto 預設網域 `https://[tenant-id].logto.app` 時，RP ID 為 `[tenant-id].logto.app`
- **自訂網域**：若已設定 [自訂網域](/logto-cloud/custom-domain)（如 `https://auth.example.com`），RP ID 為 `auth.example.com`

**設定相關來源：**

可用 [`PATCH /api/account-center`](https://openapi.logto.io/operation/operation-updateaccountcentersettings) 端點新增前端應用程式來源。例如帳戶中心運行於 `https://account.example.com`：

```bash
curl -X PATCH https://[tenant-id].logto.app/api/account-center \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"webauthnRelatedOrigins":["https://account.example.com"]}'
```

:::note

WebAuthn 最多支援 5 個唯一 eTLD+1 標籤作為相關來源。eTLD+1（有效頂級網域加一標籤）為可註冊的網域部分。例如：

- `https://example.com`、`https://app.example.com`、`https://auth.example.com` 算作**一個**標籤（`example.com`）
- `https://shopping.com`、`https://shopping.co.uk`、`https://shopping.co.jp` 也算作**一個**標籤（`shopping`）
- `https://example.com` 與 `https://another.com` 算作**兩個**標籤

若需支援超過 5 個不同網域，請參閱 [Related Origin Requests](https://passkeys.dev/docs/advanced/related-origins/) 文件。

:::

**步驟 2：請求新註冊選項**

使用 [`POST /api/verifications/web-authn/registration`](https://openapi.logto.io/operation/operation-generatewebauthnregistrationoptions) 端點請求註冊新通行密鑰。Logto 允許每個帳戶註冊多把通行密鑰。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/web-authn/registration \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

回應如下：

```json
{
  "registrationOptions": "...",
  "verificationRecordId": "...",
  "expiresAt": "..."
}
```

**步驟 3：於本地瀏覽器註冊通行密鑰**

以 [`@simplewebauthn/browser`](https://simplewebauthn.dev/) 為例，可用 `startRegistration` 函式於本地瀏覽器註冊通行密鑰。

```ts
import { startRegistration } from '@simplewebauthn/browser';

// ...
const response = await startRegistration({
  optionsJSON: registrationOptions, // 步驟 1 伺服器回傳資料
});
// 儲存 response 以供後續使用
```

**步驟 4：驗證通行密鑰註冊**

使用 [`POST /api/verifications/web-authn/registration/verify`](https://openapi.logto.io/operation/operation-verifywebauthnregistration) 端點驗證通行密鑰註冊。

此步驟會驗證認證器產生的加密簽章，確保通行密鑰合法產生且傳輸過程未被竄改。

```bash
curl -X POST https://[tenant-id].logto.app/api/verifications/web-authn/registration/verify \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"payload":"...","verificationRecordId":"..."}'
```

- `payload`：步驟 2 本地瀏覽器回傳資料
- `verificationRecordId`：步驟 1 伺服器回傳的驗證記錄 ID

**步驟 5：連結通行密鑰**

最後，可用 [`POST /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-addmfaverification) 端點將通行密鑰連結至使用者帳戶。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"type":"WebAuthn","newIdentifierVerificationRecordId":"..."}'
```

- `type`：MFA 因子型別（`WebAuthn`、`Totp` 或 `BackupCode`，此處用 `WebAuthn`）
- `newIdentifierVerificationRecordId`：步驟 2 伺服器回傳的驗證記錄 ID

### 管理現有 WebAuthn 通行密鑰 \{#manage-existing-webauthn-passkeys}

要管理現有 WebAuthn 通行密鑰，可用 [`GET /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-getmfaverifications) 端點取得目前通行密鑰與其他 MFA 驗證因子。

```bash
curl https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>'
```

回應如下：

```json
[
  {
    "id": "...",
    "type": "WebAuthn",
    "name": "...",
    "agent": "...",
    "createdAt": "...",
    "lastUsedAt": "..."
  }
]
```

- `id`：驗證因子 ID
- `type`：驗證因子型別（`WebAuthn`、`Totp`、`BackupCode`、`EmailVerificationCode`、`PhoneVerificationCode`）。`EmailVerificationCode` 與 `PhoneVerificationCode` 僅在使用者[設定 Email 或 SMS MFA](#manage-email-and-sms-mfa) 時出現。
- `name`：通行密鑰名稱，選填（僅 `WebAuthn`）
- `agent`：通行密鑰的 user agent（僅 `WebAuthn`）
- `createdAt`：驗證因子建立時間
- `lastUsedAt`：驗證因子最後使用時間，選填（僅 `WebAuthn`）
- `remainCodes`：剩餘未用備用碼數量，選填（僅 `BackupCode`）

更新通行密鑰名稱可用 [`PATCH /api/my-account/mfa-verifications/{verificationId}/name`](https://openapi.logto.io/operation/operation-updatemfaverificationname) 端點：

```bash
curl -X PATCH https://[tenant-id].logto.app/api/my-account/mfa-verifications/{verificationId}/name \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"name":"..."}'
```

刪除通行密鑰可用 [`DELETE /api/my-account/mfa-verifications/{verificationId}`](https://openapi.logto.io/operation/operation-deletemfaverification) 端點：

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/mfa-verifications/{verificationId} \
  -H 'authorization: Bearer <access_token>'
```

### 連結新 TOTP \{#link-a-new-totp}

:::note
請先[啟用 MFA 與 TOTP](/end-user-flows/mfa)。
:::

:::note
使用此方法前，需於[帳戶中心設定](#how-to-enable-account-api)啟用 `mfa` 欄位。
:::

**步驟 1：產生 TOTP 密鑰**

使用 [`POST /api/my-account/mfa-verifications/totp-secret/generate`](https://openapi.logto.io/operation/operation-generatetotpsecret) 端點產生 TOTP 密鑰。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications/totp-secret/generate \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

回應如下：

```json
{
  "secret": "..."
}
```

**步驟 2：將 TOTP 密鑰顯示給使用者**

用此密鑰產生 QR code 或直接顯示給使用者，讓其加入驗證器 App（如 Google Authenticator、Microsoft Authenticator、Authy）。

QR code URI 格式如下：

```
otpauth://totp/[Issuer]:[Account]?secret=[Secret]&issuer=[Issuer]
```

範例：

```
otpauth://totp/YourApp:user@example.com?secret=JBSWY3DPEHPK3PXP&issuer=YourApp
```

**步驟 3：綁定 TOTP 因子**

使用者將密鑰加入驗證器 App 後，需驗證並綁定至帳戶。使用 [`POST /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-addmfaverification) 端點綁定 TOTP 因子。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"type":"Totp","secret":"..."}'
```

- `type`：必須為 `Totp`
- `secret`：步驟 1 產生的 TOTP 密鑰

:::note
每位使用者僅能有一組 TOTP 因子。若已存在，重複新增會回傳 422 錯誤。
:::

### 取代現有 TOTP \{#replace-an-existing-totp}

若使用者已設定 TOTP 因子，可用 [`PUT /api/my-account/mfa-verifications/totp`](https://openapi.logto.io/operation/operation-createorreplacetotpmfaverification) 端點以新密鑰取代，這是冪等操作，會移除舊 TOTP 並綁定新密鑰。

:::note
使用此方法前，需於[帳戶中心設定](#how-to-enable-account-api)啟用 `mfa` 欄位。
:::

**步驟 1：產生新 TOTP 密鑰**

使用 [`POST /api/my-account/mfa-verifications/totp-secret/generate`](https://openapi.logto.io/operation/operation-generatetotpsecret) 端點產生新密鑰，並依 [連結新 TOTP](#link-a-new-totp) 步驟顯示給使用者。

**步驟 2：取代 TOTP 因子**

```bash
curl -X PUT https://[tenant-id].logto.app/api/my-account/mfa-verifications/totp \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"secret":"...","code":"..."}'
```

- `secret`：步驟 1 產生的新 TOTP 密鑰
- `code`：由新密鑰產生的 TOTP 驗證碼，用於確認綁定

### 管理 Email 與 SMS MFA \{#manage-email-and-sms-mfa}

:::note
請先[啟用 MFA 與 Email 或 SMS 驗證碼因子](/end-user-flows/mfa)。
:::

:::note
使用此方法前，需於[帳戶中心設定](#how-to-enable-account-api)啟用 `mfa` 欄位。
:::

Email 與 SMS MFA 驗證碼會發送至使用者主要電子郵件與主要手機。設定因子即記錄使用者選擇，地址本身則透過 [更新或連結新電子郵件](#update-or-link-new-email) 與 [管理手機](#manage-phone) 管理。

是否需設定這些因子取決於 [Email 與 SMS MFA 註冊](/end-user-flows/mfa/configure-mfa#email-and-sms-mfa-enrollment) 設定。選擇 **僅設定者可用** 時，僅設定者可用於 MFA；選擇 **所有有驗證過 Email 或手機者** 時，仍會記錄設定，方便日後切換模式時保留因子。

**設定 Email 或 SMS MFA**

使用 [`POST /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-addmfaverification) 端點：

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"type":"EmailVerificationCode"}'
```

- `type`：`EmailVerificationCode` 為 Email MFA，`PhoneVerificationCode` 為 SMS MFA

:::note

- 使用者必須有主要電子郵件（Email MFA）或主要手機（SMS MFA），否則會回傳 422 錯誤。
- 每位使用者每種因子僅能設定一次，重複設定會回傳 422 錯誤。

:::

**移除 Email 或 SMS MFA**

先用 [`GET /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-getmfaverifications) 端點查詢 `type` 為 `EmailVerificationCode` 或 `PhoneVerificationCode` 的驗證，再用 [`DELETE /api/my-account/mfa-verifications/{verificationId}`](https://openapi.logto.io/operation/operation-deletemfaverification) 端點刪除：

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/mfa-verifications/{verificationId} \
  -H 'authorization: Bearer <access_token>'
```

移除因子不會影響使用者的主要電子郵件或手機。

### 管理備用碼 (Backup codes) \{#manage-backup-codes}

:::note
請先[啟用 MFA 與備用碼](/end-user-flows/mfa)。
:::

:::note
使用此方法前，需於[帳戶中心設定](#how-to-enable-account-api)啟用 `mfa` 欄位。
:::

**步驟 1：產生新備用碼**

使用 [`POST /api/my-account/mfa-verifications/backup-codes/generate`](https://openapi.logto.io/operation/operation-generatemyaccountbackupcodes) 端點產生一組 10 組備用碼。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications/backup-codes/generate \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

回應如下：

```json
{
  "codes": ["...", "...", "..."]
}
```

**步驟 2：將備用碼顯示給使用者**

在綁定備用碼前，請將備用碼顯示給使用者，並提醒：

- 立即下載或抄寫這些備用碼
- 妥善保存於安全處
- 每組備用碼僅能使用一次
- 若失去主要 MFA 方法，這些備用碼是最後救援手段

建議以清楚、易複製的格式顯示，並可提供下載（如文字檔或 PDF）。

**步驟 3：綁定備用碼至帳戶**

使用 [`POST /api/my-account/mfa-verifications`](https://openapi.logto.io/operation/operation-addmfaverification) 端點綁定備用碼至帳戶。

```bash
curl -X POST https://[tenant-id].logto.app/api/my-account/mfa-verifications \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"type":"BackupCode","codes":["...","...","..."]}'
```

- `type`：必須為 `BackupCode`
- `codes`：前一步產生的備用碼陣列

:::note

- 每位使用者僅能有一組備用碼。若全部用完，需重新產生並綁定新備用碼。
- 備用碼不能是唯一 MFA 因子。使用者必須已設定驗證器 App（`Totp`）或通行密鑰（`WebAuthn`）；僅有 Email 或 SMS 驗證碼不符合要求。
- 每組備用碼僅能使用一次。

:::

**檢視現有備用碼**

要檢視現有備用碼及其使用狀態，可用 [`GET /api/my-account/mfa-verifications/backup-codes`](https://openapi.logto.io/operation/operation-getbackupcodes) 端點：

```bash
curl https://[tenant-id].logto.app/api/my-account/mfa-verifications/backup-codes \
  -H 'authorization: Bearer <access_token>'
```

回應如下：

```json
{
  "codes": [
    {
      "code": "...",
      "usedAt": null
    },
    {
      "code": "...",
      "usedAt": "2024-01-15T10:30:00.000Z"
    }
  ]
}
```

- `code`：備用碼
- `usedAt`：該備用碼使用時間，未使用則為 `null`

### 管理兩步驟驗證設定 \{#manage-2-step-verification-settings}

:::note
使用這些方法前，需於[帳戶中心設定](#how-to-enable-account-api)啟用 `mfa` 欄位。
:::

終端使用者可針對帳戶開啟或關閉兩步驟驗證。常見情境如：使用者已設定 MFA 因子（如通行密鑰），但僅想用於登入而非額外驗證——關閉兩步驟驗證後，登入時可略過 MFA 提示，MFA 因子仍保留。此設定由每位使用者的 `skipMfaOnSignIn` 控制。

**取得目前 MFA 設定**

使用 [`GET /api/my-account/mfa-settings`](https://openapi.logto.io/operation/operation-getmfasettings) 端點取得目前兩步驟驗證設定。

```bash
curl https://[tenant-id].logto.app/api/my-account/mfa-settings \
  -H 'authorization: Bearer <access_token>'
```

回應如下：

```json
{
  "skipMfaOnSignIn": false,
  "enabled": true,
  "required": false
}
```

- `skipMfaOnSignIn`：使用者是否選擇登入時略過 MFA 驗證提示
- `enabled`（選填）：該使用者是否啟用 MFA 驗證（舊帳戶未有此欄位，Logto 會在有可用因子時視為啟用）
- `required`（唯讀）：MFA 是否為租戶政策（如**強制**或**自適應 MFA**不可略過）、個人或組織強制要求，若為 true，`skipMfaOnSignIn` 與 `enabled: false` 無效

**更新 MFA 設定**

要啟用或停用兩步驟驗證，可用 [`PATCH /api/my-account/mfa-settings`](https://openapi.logto.io/operation/operation-updatemfasettings) 端點。

```bash
curl -X PATCH https://[tenant-id].logto.app/api/my-account/mfa-settings \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"skipMfaOnSignIn":true}'
```

- `skipMfaOnSignIn`：設為 `true` 則登入時略過兩步驟驗證提示，設為 `false` 則啟用
- `enabled`（選填）：設為 `true` 或 `false` 以更新是否啟用 MFA 驗證。回應會帶回更新後的 `skipMfaOnSignIn`、`enabled` 與唯讀 `required` 欄位

:::note
`skipMfaOnSignIn` 與 `enabled: false` 僅於 MFA 政策為**選用**且未被個人或組織強制要求時生效（透過 `organizationRequiredMfaPolicy`）。若 MFA 為**強制**或被個人/組織要求，兩者皆無效且必須執行 MFA（`required` 為 `true`）。自適應 MFA 下，`required` 亦為 `true`，兩者無效，但僅於風險規則觸發時提示 MFA 驗證。
:::

### 管理使用者工作階段 \{#manage-user-sessions}

**列出啟用中的工作階段**

要列出使用者啟用中的工作階段，可用 [`GET /api/my-account/sessions`](https://openapi.logto.io/operation/operation-getsessions) 端點。

:::note

- 需有 `UserScope.Sessions` 權限範圍
- 帳戶中心設定的 `Sessions` 欄位需設為 `ReadOnly` 或 `Edit`

:::

```bash
curl https://[tenant-id].logto.app/api/my-account/sessions \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

**依 session ID 撤銷工作階段**

要撤銷特定工作階段，可用 [`DELETE /api/my-account/sessions/{sessionId}`](https://openapi.logto.io/operation/operation-deletesessionbyid) 端點。

:::note

- 需有 `UserScope.Sessions` 權限範圍
- 帳戶中心設定的 `Sessions` 欄位需設為 `Edit`
  :::

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/sessions/{sessionId} \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

可選查詢參數：

- `revokeGrantsTarget`：可選，指定撤銷授權目標：
  - `all`：撤銷該 session 相關的所有授權
  - `firstParty`：僅撤銷第一方應用程式授權（建議大多數情境，僅撤銷自家 app 存取權，保留第三方 app 授權，提升體驗）
  - 未指定：預設僅撤銷未含 `offline_access` 權限範圍的授權，通常即撤銷該 session 的非 refresh token 授權

### 管理使用者授權應用程式（授權記錄） \{#manage-user-authorized-apps-grants}

當使用者需於帳戶設定頁檢視與撤銷授權應用程式時，可用授權記錄 API。

:::note

- 授權記錄 API 權限模型與工作階段 API 相同
- 需有 `UserScope.Sessions` 權限範圍
- 帳戶中心設定的 `Sessions` 欄位需啟用：
  - `ReadOnly` 或 `Edit` 可列出授權
  - `Edit` 可撤銷授權

:::

**列出啟用中的應用程式授權**

要列出目前使用者啟用中的應用程式授權，可用 [`GET /api/my-account/grants`](https://openapi.logto.io/operation/operation-getgrants) 端點。

```bash
curl https://[tenant-id].logto.app/api/my-account/grants \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

可選查詢參數：

- `appType=firstParty`：僅回傳第一方應用程式授權
- `appType=thirdParty`：僅回傳第三方應用程式授權
- 不帶 `appType`：回傳所有啟用中的授權

```bash
curl "https://[tenant-id].logto.app/api/my-account/grants?appType=thirdParty" \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

**依授權 ID 撤銷應用程式授權**

要撤銷特定應用程式授權，可用 [`DELETE /api/my-account/grants/{grantId}`](https://openapi.logto.io/operation/operation-deletegrantbyid) 端點。

```bash
curl -X DELETE https://[tenant-id].logto.app/api/my-account/grants/{grantId} \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json'
```

撤銷授權後，該授權下已發出的不透明權杖 (Opaque tokens) 與重新整理權杖 (Refresh tokens) 皆會失效。
