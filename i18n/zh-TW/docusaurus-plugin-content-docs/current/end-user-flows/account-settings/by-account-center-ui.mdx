# 透過預建帳號中心 UI 管理帳號設定

## 什麼是預建帳號中心 UI \{#what-is-the-prebuilt-account-center-ui}

Logto 提供一套預建的帳號中心 UI，為終端使用者提供現成的帳號設定管理頁面。這個預建 UI 由 Logto 託管，處理常見的帳號管理任務，包括：

- 檢視與編輯使用者個人檔案（姓名、大頭貼、自訂檔案欄位）
- 更新電子郵件地址與手機號碼
- 更新使用者名稱
- 設定或更新密碼
- 管理社交連結（連結與解除連結社交帳號）
- 管理 MFA 設定（TOTP 驗證器 App、通行密鑰、備用代碼）
- 開關兩步驟驗證
- 管理活躍工作階段與已授權應用程式

預建帳號中心 UI 設計上可與你的應用程式無縫整合，提供一致的使用者體驗，無需你自行開發帳號管理頁面。

## 使用預建 UI 的好處 \{#benefits-of-using-the-prebuilt-ui}

- **零開發成本**：現成可用的頁面，開箱即用
- **一致體驗**：外觀與 Logto 登入體驗一致
- **內建安全性**：所有驗證流程與安全措施自動處理
- **自動更新**：新功能與安全性改進自動獲得

## 可用頁面 \{#available-pages}

預建帳號中心 UI 提供以下頁面，全部可透過你的 Logto 租戶端點下的 `/account` 路徑存取：

| Path                                 | 說明                                             |
| ------------------------------------ | ------------------------------------------------ |
| `/account/profile`                   | 使用者個人檔案頁（姓名、大頭貼、自訂檔案欄位）   |
| `/account/security`                  | 安全性設定總覽（兩步驟驗證、社交帳號、工作階段） |
| `/account/email`                     | 更新或移除主要電子郵件地址                       |
| `/account/phone`                     | 更新或移除主要手機號碼                           |
| `/account/username`                  | 更新使用者名稱                                   |
| `/account/password`                  | 設定或更新密碼                                   |
| `/account/passkey/add`               | 新增通行密鑰（WebAuthn）                         |
| `/account/passkey/manage`            | 檢視與管理現有通行密鑰                           |
| `/account/authenticator-app`         | 設定 TOTP 驗證器 App                             |
| `/account/authenticator-app/replace` | 更換現有 TOTP 驗證器 App                         |
| `/account/backup-codes/generate`     | 產生新的備用代碼                                 |
| `/account/backup-codes/manage`       | 檢視與管理備用代碼                               |

例如，若你的租戶端點為 `https://example.logto.app`，則電子郵件更新頁面位於 `https://example.logto.app/account/email`。

## 如何使用預建 UI \{#how-to-use-the-prebuilt-ui}

### 步驟 1：啟用 Account API \{#step-1-enable-account-api}

預建帳號中心 UI 依賴 Account API。請前往 <CloudLink to="/sign-in-experience/account-center">Console > 登入與帳號 > 帳號中心</CloudLink> 並啟用 Account API。

根據需求設定欄位權限：

- 欄位設為 `Edit` 允許使用者修改
- 欄位設為 `ReadOnly` 僅允許檢視
- 欄位設為 `Off` 則完全隱藏

#### 設定個人檔案欄位 \{#configure-profile-fields}

帳號中心會顯示 **個人檔案** 頁面，讓終端使用者檢視與管理個人資訊。若要控制哪些個人檔案欄位出現在此頁：

1. 確認 **姓名**、**大頭貼**、**個人檔案** 或 **自訂資料** 欄位權限已設為 `Edit` 或 `ReadOnly`（在帳號安全 / 使用者個人檔案區段）。
2. 在 **整合預建 UI** 卡片中，從個人檔案欄位選擇器新增你想顯示的欄位。這些欄位來自 [收集使用者個人檔案](/end-user-flows/collect-user-profile) 使用的同一欄位目錄——任何在那裡定義的欄位也可顯示於帳號中心。
3. 拖曳排序欄位順序。

只有同時列於個人檔案欄位 **且** 權限非 `Off` 的欄位才會出現在個人檔案頁。

### 步驟 2：從你的應用程式連結到預建頁面 \{#step-2-link-to-prebuilt-pages}

要使用預建帳號中心 UI，你需要將使用者從你的應用程式導向對應的 Logto 頁面。有兩種方式：

#### 方式 A：直接連結並帶上 redirect 參數 \{#approach-a-direct-linking}

在你的應用程式中加入連結，將使用者導向預建頁面。加上 `redirect` 查詢參數，讓使用者完成操作後返回你的應用程式：

```
https://[tenant-id].logto.app/account/email?redirect=https://your-app.com/settings
```

當使用者完成電子郵件更新後，會被導回 `https://your-app.com/settings`。若使用者用返回鍵離開頁面，也會回到同一網址。

#### 方式 B：嵌入於你的帳號設定流程 \{#approach-b-embedding}

你可以將預建頁面整合進你現有的帳號設定流程：

1. 在應用程式的帳號設定頁顯示使用者目前資訊
2. 提供「編輯」或「更新」按鈕，連結到對應的預建頁面
3. 使用者完成或離開操作後，會被導回你的應用程式

實作範例：

```tsx
function AccountSettings() {
  const tenantEndpoint = 'https://example.logto.app';
  const redirectUrl = encodeURIComponent(window.location.href);

  return (
    <div>
      <h2>Account Settings</h2>

      <div>
        <span>Email: user@example.com</span>
        <a href={`${tenantEndpoint}/account/email?redirect=${redirectUrl}`}>Update Email</a>
      </div>

      <div>
        <span>Password: ••••••••</span>
        <a href={`${tenantEndpoint}/account/password?redirect=${redirectUrl}`}>Change Password</a>
      </div>

      <div>
        <span>MFA: Not configured</span>
        <a href={`${tenantEndpoint}/account/authenticator-app?redirect=${redirectUrl}`}>
          Set up Authenticator
        </a>
      </div>
    </div>
  );
}
```

### 步驟 3：處理返回應用程式的情境 \{#step-3-handle-success-redirects}

使用者在完成操作或用返回鍵離開時都會回到你的 `redirect` URL，且網址相同。不要僅以返回作為操作成功的依據；請改為重新取得最新使用者資料，例如透過 [Account API](/end-user-flows/account-settings/by-account-api)。

若要在操作完成後明確提示使用者，可在帳號中心 URL 加上 `show_success=true`。帳號中心會在操作後顯示成功頁，並於使用者點擊 **完成** 時返回你的 `redirect` URL：

```
https://[tenant-id].logto.app/account/password?redirect=https://your-app.com/settings&show_success=true
```

## 支援的 URL 參數 \{#supported-url-parameters}

你可以在任何帳號中心 URL 後加上下列查詢參數，以調整體驗：

| 參數           | 說明                                                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `redirect`     | 使用者完成操作或用返回鍵離開時要導回的絕對網址。僅接受 `http(s)` 開頭的網址。                                                           |
| `show_success` | 設為 `true` 時，帳號中心會在操作後顯示成功頁，並於使用者點擊 **完成** 時返回你的 `redirect` URL。未設時則直接返回。                     |
| `identifier`   | 預先填入目標頁（`/account/email`、`/account/phone`、`/account/username`）的識別欄位。當你已知使用者識別資訊時，便於從應用程式深層連結。 |
| `ui_locales`   | 以空格分隔的 BCP-47 語言標籤清單（如 `fr-CA fr en`），控制帳號中心 UI 語言。若省略則回退至使用者瀏覽器語言。                            |

範例——深層連結到電子郵件更新頁，預填目前電子郵件並顯示法文 UI：

```
https://[tenant-id].logto.app/account/email?identifier=user@example.com&ui_locales=fr&redirect=https://your-app.com/settings
```

:::note
`identifier` 值會在登入導向前暫存於 session storage，並於目標頁首次使用後消耗。
:::

## 帳號刪除連結 \{#account-deletion-link}

帳號中心本身不直接處理帳號刪除。你可以設定一個 **帳號刪除 URL**，指向你自有的刪除流程（通常由 [Management API](/end-user-flows/account-settings/by-management-api) 支援）。設定後，帳號中心安全性頁面會出現 **刪除你的帳號** 項目，並連結至你的網址。

設定方式：前往 <CloudLink to="/sign-in-experience/account-center">Console > 登入與帳號 > 帳號中心</CloudLink>，填寫 **帳號刪除 URL** 欄位。你也可以透過 Management API 更新：

```bash
curl -X PATCH https://[tenant-id].logto.app/api/account-center \
  -H 'authorization: Bearer <access_token>' \
  -H 'content-type: application/json' \
  --data-raw '{"deleteAccountUrl":"https://your-app.com/delete-account"}'
```

留空（或將 `deleteAccountUrl` 設為 `null`）即可隱藏帳號刪除項目。

## 社交連結回呼網址 \{#social-connection-callback-url}

從帳號中心連結社交帳號時，會使用連接器的回呼網址：

```
https://[your-tenant-endpoint]/callback/{connectorId}
```

其中 `{connectorId}` 為社交連接器的 ID。這就是 <CloudLink to="/connectors/social">Console > 連接器 > 社交連接器</CloudLink> 詳細頁顯示的 **Callback URI**，你需在 [設定連接器](/connectors/social-connectors/) 時向社交服務註冊。

## 安全性考量 \{#security-considerations}

預建帳號中心 UI 內建多項安全措施：

- **OIDC 提升驗證（step-up authentication）**：敏感變更（電子郵件、手機、使用者名稱、密碼、社交帳號、MFA、工作階段、受信任裝置）需於租戶設定的 **近期驗證** 時間窗（預設 `10` 分鐘，可於 <CloudLink to="/sign-in-experience/account-center">Console > 登入與帳號 > 帳號中心</CloudLink> 設定，範圍 `1` 至 `120` 分鐘）內完成 `urn:logto:acr:1fa` 或更高等級驗證。若使用者剛以合格方式登入或註冊則不需額外驗證；若登入不具 `1fa`（如社交登入）或已超過時間窗，帳號中心會自動執行 [OIDC 提升驗證](/end-user-flows/step-up-authentication) 並繼續原操作。
- **驗證碼**：電子郵件與手機號碼更新需驗證新地址／號碼的驗證碼
- **工作階段驗證**：所有操作都會驗證使用者工作階段，防止未授權存取

## 客製化選項 \{#customization-options}

預建帳號中心 UI 會繼承你的登入體驗設定品牌，包括：

- 標誌與配色
- 深色／淺色模式
- 語言設定

### 自訂 CSS \{#custom-css}

你可以進一步透過自訂 CSS 客製帳號中心 UI 外觀。前往 <CloudLink to="/sign-in-experience/account-center">Console > 登入與帳號 > 帳號中心</CloudLink>，在 **自訂 CSS** 編輯器中新增你的 CSS。

預建帳號中心 UI 在主要 UI 元素（版面容器、頁首、區塊、卡片等）上提供以 `logto_ac-` 為前綴的穩定 CSS 類名，方便你精確覆蓋預設樣式，無需擔心版本間類名變動。

範例：

```css
/* 隱藏 Logto 簽名 */
.logto_ac-logto-signature {
  display: none;
}

/* 客製安全性區塊卡片 */
.logto_ac-security-card {
  border-radius: 12px;
}
```

若你需要超越預建 UI 與自訂 CSS 的客製化，請考慮使用 [Account API](/end-user-flows/account-settings/by-account-api) 自行打造專屬帳號管理頁面。
