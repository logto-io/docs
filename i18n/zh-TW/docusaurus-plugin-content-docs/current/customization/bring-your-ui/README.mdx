# 自訂你的 UI

除了預設的 UI 客製化選項外，Logto 允許你自帶 UI，完全取代內建的登入體驗介面。此功能讓你可以上傳包含自訂 UI 資產（HTML、CSS、JavaScript、圖片等）的 zip 檔，並將其託管於 [Logto Cloud](https://cloud.logto.io) 伺服器，作為租戶使用者的 [登入體驗](/end-user-flows#authentication-flows)。

:::note

此功能要求你的自訂 UI 必須相容於單頁應用程式（SPA, Single Page Application），並建議始終使用正式版建置以獲得最佳效能。

:::

## 在 Logto Console 體驗自訂 UI 功能 \{#explore-the-custom-ui-feature-in-logto-console}

### 使用官方專案快速開始 \{#get-started-with-official-project}

最快建立自訂登入 UI 的方式是複製 [Logto experience 專案](https://github.com/logto-io/logto/tree/master/packages/experience)。這是 Logto 內建的登入體驗 UI，涵蓋所有功能並遵循 Logto 最佳實踐。你可以根據需求進行自訂。

檢出程式碼後，只需執行以下指令建置專案：

```bash
pnpm install && pnpm build
```

:::note

整個 Logto 專案為 [pnpm monorepo](https://pnpm.io/workspaces)，若你想單獨執行 experience 套件（不使用 pnpm），請將 `package.json` 中的 `workspace:` _依賴改為具體版本號（如 `^1.0.0`）。_

:::

建置完成後，所有編譯後的資產會在 `dist` 目錄下。請將 `dist` 目錄壓縮成 ZIP 檔，稍後即可上傳至 Logto Cloud。

### 自訂 UI 資產要求 \{#custom-ui-assets-requirements}

上傳自訂 UI 資產前，請確保符合以下要求：

- 上傳資產需打包為單一 zip 檔。
- zip 檔根目錄需包含 `index.html` 檔案。
- zip 檔大小不得超過 20MB。
- zip 檔內單一檔案不得超過 10MB。
- zip 檔內檔案總數不得超過 200 個。

### 上傳你的自訂 UI 資產 \{#upload-your-custom-ui-assets}

:::note

在正式環境使用此功能時請謹慎，因為會立即影響使用者的登入體驗。

:::

1. 前往 <CloudLink to="/sign-in-experience/branding">Console > Sign-in & account > Branding > Bring your UI</CloudLink>。
2. 點擊選擇或拖曳你在前一步建立的 zip 檔，系統會自動開始上傳。
3. 上傳完成後，儲存變更，你的自訂 UI 會立即生效。
4. 使用自訂登入 UI 時，「Sign-in preview」視窗會停用。不過，你仍可點擊「[Live preview](/customization/live-preview)」按鈕，在新開的瀏覽器分頁測試自訂登入頁面。

### 設定自訂 CSP 來源 \{#configure-custom-csp-sources}

Logto 會對自訂 UI 頁面套用 Content Security Policy（CSP）標頭。若你的自訂 UI 需載入第三方腳本或連接外部服務，請在 <CloudLink to="/sign-in-experience/branding">Console > Sign-in & account > Branding > Bring your UI</CloudLink> 新增額外來源。

你可以設定：

- `script-src`：允許 JavaScript 模組或腳本來源，例如 CAPTCHA、分析或標籤管理服務。
- `connect-src`：允許 `fetch`、XMLHttpRequest、EventSource 及 WebSocket 連線的網路端點。

範例：

```json
{
  "scriptSrc": ["https://scripts.example.com"],
  "connectSrc": ["https://api.example.com", "wss://events.example.com"]
}
```

兩者皆請使用 HTTPS 來源。`connect-src` 也接受 WebSocket 連線的 `wss://` 來源。Logto 僅在你的自訂 UI 資產啟用時，才會將這些來源附加至現有安全性政策。

### 設定 Cross-Origin-Opener-Policy 標頭 \{#configure-the-cross-origin-opener-policy-header}

預設情況下，Logto 不會傳送 `Cross-Origin-Opener-Policy`（COOP）標頭，因此以彈出視窗開啟登入頁的應用程式仍可透過 `window.opener` 通訊。若你的應用程式不會以彈出視窗登入，可以將自訂登入 UI 與其他瀏覽器視窗隔離。在 <CloudLink to="/sign-in-experience/branding">Console > Sign-in & account > Branding > Bring your UI</CloudLink> 的 **Cross-Origin-Opener-Policy** 選擇政策：

| 選項                       | 傳送標頭                                               | 效果                                                                                     |
| -------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 未設定（無標頭）           | 無                                                     | 預設值。所有基於彈出視窗的整合皆可正常運作。                                             |
| `same-origin-allow-popups` | `Cross-Origin-Opener-Policy: same-origin-allow-popups` | 切斷開啟登入頁的視窗。自訂 UI 開啟的彈出視窗只要停留在其他網站，仍保有 `window.opener`。 |
| `same-origin`              | `Cross-Origin-Opener-Policy: same-origin`              | 也會切斷自訂 UI 開啟的彈出視窗。                                                         |

你也可以透過 [update sign-in experience](https://openapi.logto.io/operation/operation-updatesigninexp) Management API 設定 `crossOriginOpenerPolicy` 欄位。可用值有 `unsafe-none`（預設，不傳送標頭）、`same-origin-allow-popups` 與 `same-origin`。

:::warning

選擇政策前，請檢查你的應用程式與自訂 UI 如何使用彈出視窗：

- 以彈出視窗開啟登入頁並依賴 `window.opener` 的應用程式（例如透過 `postMessage` 接收結果），在啟用任一政策後將無法運作。若有此類應用，請維持預設值，或先改為導向式登入流程。
- 自訂 UI 開啟的彈出視窗，一旦導回自訂 UI（如社交登入回呼頁），將失去 `window.opener`。若彈出視窗停留在其他網站並從那裡傳送結果（如第三方登入彈窗），在 `same-origin-allow-popups` 下仍可運作。若設為 `same-origin`，彈窗一開啟即失去 `window.opener`。

如需設定，建議優先選擇 `same-origin-allow-popups`。

:::

Logto 僅在你的自訂 UI 資產被服務時才傳送該標頭。內建登入頁、`/oidc/*` 頁面與 Account Center（`/account`）皆不會傳送 COOP 標頭，因此安全性掃描工具在這些頁面上仍可能報告缺少該標頭。

## 開發你的自訂 UI \{#develop-your-custom-ui}

### 與 Experience API 互動 \{#interact-with-experience-api}

你的自訂 UI 需與 [Experience API](https://openapi.logto.io/group/endpoint-experience) 互動，以執行登入、註冊、重設密碼、綁定社交帳號、啟用 MFA 等多種操作。建議參考我們的 [Experience API 設計 RFC](https://github.com/logto-io/rfcs/blob/master/draft/0004-experience-api.md)，其中提供完整技術規格與範例，有助於理解使用者流程與實作細節。

你也需要透過 [sign-in Experience API endpoint](https://openapi.logto.io/operation/operation-getsigninexperienceconfig) 取得其他登入體驗設定，例如品牌色、公司標誌、favicon、密碼政策、本地化語言字串，甚至自訂 CSS。

### 啟用 CAPTCHA 時的處理方式 \{#handle-captcha-when-enabled}

Logto 內建登入體驗會自動處理 CAPTCHA。若你的租戶啟用 Bring your UI 並啟用 CAPTCHA 機器人防護，你的自訂 UI 必須在呼叫 `PUT /api/experience` 前完成前端 CAPTCHA 整合。

請將驗證服務回傳的 provider token 作為 `captchaToken`，放入 `PUT /api/experience` 請求主體。詳細整合方式請參考各服務提供者指南：

- [reCAPTCHA Enterprise 與 Bring your UI](/security/captcha/recaptcha-enterprise#bring-your-ui)
- [Cloudflare Turnstile 與 Bring your UI](/security/captcha/turnstile#bring-your-ui)
- [GeeTest 與 Bring your UI](/security/captcha/geetest#bring-your-ui)
- [Friendly Captcha 與 Bring your UI](/security/captcha/friendly-captcha#bring-your-ui)
- [Cap 與 Bring your UI](/security/captcha/cap#bring-your-ui)

### 範例專案 \{#sample-projects}

我們提供多個範例專案，協助你快速理解並實作自訂 UI。詳情請參閱 [Logto Experience project](https://github.com/logto-io/experience-samples) GitHub 倉庫。

此外，我們將持續推出更多簡化且情境導向的範例專案，涵蓋最常見的使用情境，敬請期待後續更新！

### 本地開發與除錯 \{#local-development-and-debugging}

針對本地開發與除錯，我們提供 Logto Tunnel CLI 工具，可用於：

- 將本機 Experience API 請求代理至 Logto Cloud 端點。
- 在本地測試你的自訂 UI 實作。

這讓你能在上傳至 Logto Cloud 前，於本地測試與除錯自訂 UI。

詳情請參閱 [本地除錯與測試自訂 UI](/customization/bring-your-ui/debug-and-test-your-custom-ui-locally/)。

## 使用 CLI 上傳自訂 UI 資產 \{#upload-your-custom-ui-assets-using-the-cli}

除了透過 Console 上傳外，你也可以使用 Logto CLI 上傳自訂 UI 資產，這對自動化部署流程特別有用。

詳情請參閱 [使用 CLI 上傳自訂 UI 資產](/customization/bring-your-ui/upload-custom-ui-assets-using-cli/)。

## 還原為 Logto 內建登入體驗 \{#restore-to-logto-built-in-sign-in-experience}

若你希望還原為 Logto 內建登入體驗，只需點擊 Bring your UI 卡片上的刪除按鈕。儲存變更後，登入體驗 UI 即會回復為 Logto 預設樣式。
