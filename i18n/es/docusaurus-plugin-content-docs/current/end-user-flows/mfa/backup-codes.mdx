# Códigos de respaldo

## Conceptos \{#concepts}

Los códigos de respaldo, también conocidos como código de recuperación, son códigos de un solo uso para la autenticación multifactor (MFA), que actúan como respaldo en caso de que los factores de autenticación principales del usuario (por ejemplo, aplicación autenticadora o token de hardware) no estén disponibles.

Perderlos puede generar desafíos para la recuperación de la cuenta. Por lo tanto, se recomienda configurar un factor principal adicional antes de habilitar los códigos de respaldo, dándole prioridad.

Logto genera automáticamente 10 códigos de respaldo para los usuarios una vez que configuran un factor adicional. Cada código es de un solo uso. Los usuarios pueden regenerar un nuevo conjunto de códigos a través de la [interfaz preconstruida del Centro de Cuenta](/end-user-flows/account-settings/by-account-center-ui) (`/account/backup-codes/regenerate`), una interfaz de autoservicio personalizada construida con la [Account API](/end-user-flows/account-settings/by-account-api#manage-backup-codes), o herramientas de administración usando la [Management API](/end-user-flows/account-settings/by-management-api#user-mfa-settings-management) antes de agotar todos los códigos existentes.

## Configurar códigos de respaldo para MFA \{#configure-backup-codes-for-mfa}

1. Navega a <CloudLink to="/mfa">Consola > Autenticación multifactor</CloudLink>
2. Habilita el factor "Códigos de respaldo". Los códigos de respaldo no pueden usarse como el único factor de MFA. Es obligatorio usar los códigos de respaldo en combinación con otros factores principales de MFA (passkeys, aplicación autenticadora, SMS, correo electrónico).
3. Configura tu política de MFA preferida (opcional, adaptativa o obligatoria)
4. Guarda los cambios de configuración

## Configurar la gestión de códigos de respaldo \{#configure-backup-codes-management}

Los usuarios pueden ver y regenerar sus códigos de respaldo usando la [interfaz preconstruida del Centro de Cuenta](/end-user-flows/account-settings/by-account-center-ui) (`/account/backup-codes/manage` y `/account/backup-codes/regenerate`). También puedes usar la Account API para construir interfaces personalizadas de gestión de cuentas donde los usuarios puedan ver, regenerar y eliminar sus códigos de respaldo. Esto permite a los usuarios gestionar sus opciones de recuperación directamente desde la configuración de cuenta de tu aplicación.

Para pasos de implementación detallados y endpoints de API, consulta [Configuración de cuenta por Account API](/end-user-flows/account-settings/by-account-api#manage-backup-codes).

## Flujos de configuración de códigos de respaldo \{#backup-codes-setup-flows}

Debido a que los códigos de respaldo son un factor secundario de MFA, solo pueden configurarse después de que se haya configurado correctamente un factor principal de MFA. Se mostrará al usuario un grupo de 10 códigos de respaldo generados automáticamente, que podrá descargar y copiar de forma segura. El usuario debe confirmar manualmente los códigos de respaldo para completar el proceso de configuración de MFA.

Logto también solicita al usuario durante el inicio de sesión que genere y guarde un nuevo conjunto de códigos de respaldo si **Códigos de respaldo** están habilitados y el usuario ya tiene otro factor activo pero no le quedan códigos de respaldo sin usar; por ejemplo:

- Se han utilizado todos los códigos de respaldo generados previamente.
- Habilitaste **Códigos de respaldo** después de que el usuario ya hubiera registrado su factor principal de MFA.

Durante el inicio de sesión de un usuario existente, este recordatorio solo ocurre después de que el usuario verifica un desafío de MFA (o inicia sesión con una passkey); los inicios de sesión que omiten la verificación de MFA (como un dispositivo de confianza, un inicio de sesión de [MFA adaptativa](/end-user-flows/mfa/adaptive-mfa) de bajo riesgo, o cuando el usuario omite la **MFA opcional**) no solicitan vincular nuevos códigos de respaldo a mitad del inicio de sesión, y los inicios de sesión normales de [SSO empresarial](/end-user-flows/enterprise-sso) omiten los recordatorios de configuración de MFA a menos que se solicite explícitamente MFA mediante `acr_values`.

## Flujo de verificación de códigos de respaldo \{#backup-codes-verification-flow}

Los códigos de respaldo sirven como autenticación de emergencia cuando los factores principales de MFA no están disponibles. Cada código solo puede usarse una vez y se invalida tras una verificación exitosa.

**Prioridad de verificación:**

- **Primero los factores principales**: Cuando los usuarios tienen otros factores de MFA configurados, se solicitan primero los factores principales (passkeys, TOTP, SMS, correo electrónico).
- **Acceso a códigos de respaldo**: Los usuarios pueden cambiar a los códigos de respaldo haciendo clic en "Probar otro método de verificación" si los factores principales no están disponibles.
- **Escenario de respaldo**: Si se eliminan todos los factores principales, los códigos de respaldo se convierten en la única opción de verificación. Tras una verificación exitosa de MFA mediante códigos de respaldo durante el inicio de sesión, Logto solicita automáticamente a los usuarios que configuren un nuevo factor principal.
