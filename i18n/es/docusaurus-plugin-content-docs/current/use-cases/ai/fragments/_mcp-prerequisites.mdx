## Requisitos previos \{#prerequisites}

- Un tenant de [Logto Cloud](https://cloud.logto.io) (o autogestionado)
- Entorno Node.js >= 20

### Entendiendo la arquitectura \{#understanding-the-architecture}

- **Servidor MCP**: El servidor que expone herramientas y recursos a los clientes MCP. Siguiendo la [última especificación de MCP](https://modelcontextprotocol.io/specification/latest/basic/authorization), actúa como un servidor de recursos OAuth 2.0 que valida los tokens de acceso emitidos por Logto.
- **Cliente MCP**: Un cliente utilizado para iniciar el flujo de autenticación y probar la integración. {<b>{props.isThirdParty ? 'El agente de IA de terceros se utilizará como cliente en esta guía.' : "Usaremos VS Code (con soporte MCP integrado) como cliente en esta guía."}</b>}
- **Logto**: Funciona como el proveedor de OpenID Connect (servidor de autorización), gestiona las identidades de los usuarios y emite tokens de acceso JWT ligados a la audiencia para tu servidor MCP.

Un diagrama de secuencia no normativo ilustra el flujo general del proceso:

    Client->>Server: Solicitud MCP (sin token)

    Client->>Logto: Redirige a Logto para autenticación
    Logto->>Logto: El usuario se autentica
    ${props.isThirdParty ? 'Logto->>Logto: El usuario autoriza (consiente) los alcances<br/>al agente de IA de terceros' : ''}

    Client->>Logto: Intercambia el código por un token de acceso<br/>(con el parámetro resource)
    Logto->>Client: Devuelve token de acceso (JWT, ligado a la audiencia)
    Client->>Server: Solicitud MCP con token de acceso
    Server->>Server: Verifica el token de acceso contra el JWKS de Logto<br/>(firma, emisor, audiencia, expiración)
    Server->>Client: Devuelve respuesta de la herramienta`}
