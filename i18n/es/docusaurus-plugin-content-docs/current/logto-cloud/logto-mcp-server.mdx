# Logto MCP Server

Logto MCP Server es un servidor remoto de [MCP (Model Context Protocol)](https://modelcontextprotocol.io/). Añade la URL a tu aplicación de IA, inicia sesión con tu cuenta de Logto Cloud y comienza a interactuar con Logto.

:::tip
Logto MCP Server está construido con Logto y [MCP Auth](https://mcp-auth.dev). Si quieres construir tu propio servidor remoto MCP, consulta [Construye tu propio servidor remoto MCP](#build-your-own-remote-mcp-server).
:::

## Qué puedes hacer \{#what-you-can-do}

- **Añade autenticación a tu proyecto**: La IA detecta tu framework, crea una aplicación Logto y genera el código de integración funcional. Soporta más de 38 frameworks incluyendo React, Next.js, Vue, Nuxt, SvelteKit, Express, Go, Python, iOS, Android, Flutter y más.
- **Haz preguntas sobre Logto**: La IA busca en la documentación de Logto y te da respuestas con fuentes.

Próximamente habrá más capacidades, incluyendo configuración de la experiencia de inicio de sesión, gestión de RBAC y permisos con guía de mejores prácticas, configuración multi-tenancy para construir aplicaciones B2B con organizaciones, y más.

## Cómo se conecta tu aplicación de IA \{#how-your-ai-application-connects}

Logto MCP Server admite dos formas para que una aplicación de IA se identifique al iniciar sesión. No necesitas crear nada en Logto Cloud para ninguna de las dos.

- **Solo URL del servidor (recomendado)**: La mayoría de las aplicaciones de IA ahora soportan [documentos de metadatos de client ID (CIMD)](/integrate-logto/third-party-applications/dynamic-apps). La aplicación usa una URL que posee como su client ID, y Logto lee el nombre de la aplicación y los URIs de redirección desde esa URL. Solo tienes que ingresar la URL del servidor `https://mcp.logto.io`.
- **Client ID estático**: Para aplicaciones que aún no soportan CIMD, ingresa el client ID público de OAuth `mcp-client`. Este cliente acepta URIs de redirección loopback (`http://localhost` o `http://127.0.0.1` con cualquier puerto).

Si tu aplicación tiene ambas opciones, usa solo la URL del servidor. Las conexiones existentes que usan `mcp-client` seguirán funcionando, por lo que no necesitas reconectarlas.

Cuando te conectas solo con la URL del servidor, la página de inicio de sesión de Logto Cloud muestra una pantalla de consentimiento con el nombre de la aplicación y el host de la URL del client ID, como `claude.ai` o `vscode.dev`. Verifica que el host coincida con la aplicación que estás usando antes de autorizar.

## Configuración en tu aplicación de IA \{#set-up-in-your-ai-application}

### Claude Code \{#claude-code}

```bash
claude mcp add --transport http logto https://mcp.logto.io
```

Luego, ejecuta `/mcp` en Claude Code, selecciona `logto` y sigue el flujo de inicio de sesión en el navegador para autenticarte con tu cuenta de Logto Cloud. También puedes ejecutar `claude mcp login logto` en tu terminal.

### Claude (web y escritorio) \{#claude-web-and-desktop}

1. Abre **Customize** > **Connectors** y haz clic en **Add custom connector**.
2. Ingresa el nombre `Logto MCP Server` y la URL del servidor remoto MCP: `https://mcp.logto.io`. Deja vacía la configuración de OAuth en **Advanced settings** y haz clic en **Add**.
3. En la lista de **Connectors**, busca **Logto MCP Server** y haz clic en **Connect**.
4. Serás redirigido a la página de inicio de sesión de Logto Cloud. Inicia sesión con tu cuenta de Logto Cloud y autoriza la conexión.

Los conectores se guardan en tu cuenta de Claude, por lo que están disponibles tanto en Claude web como en Claude Desktop.

### Codex \{#codex}

```bash
codex mcp add logto --url https://mcp.logto.io
codex mcp login logto
```

Se abrirá una ventana del navegador. Inicia sesión con tu cuenta de Logto Cloud para conectar. La aplicación de escritorio ChatGPT, Codex CLI y la extensión Codex IDE comparten esta configuración.

### Cursor \{#cursor}

Cursor aún no soporta CIMD, por lo que utiliza el client ID estático.

1. Abre **Customize** > **MCPs**, o abre `~/.cursor/mcp.json` (global) o `.cursor/mcp.json` (proyecto).
2. Añade la siguiente configuración:

   ```json
   {
     "mcpServers": {
       "Logto": {
         "url": "https://mcp.logto.io",
         "auth": {
           "CLIENT_ID": "mcp-client",
           "scopes": ["mcp:all"]
         }
       }
     }
   }
   ```

3. Haz clic en **Connect** junto al servidor. Aparecerá una página de inicio de sesión de Logto Cloud. Inicia sesión con tu cuenta de Logto Cloud para conectar.

Inicia sesión desde la aplicación de escritorio Cursor. El callback web usado por Cursor en la web y Cursor Agents no es compatible.

### OpenCode \{#opencode}

1. Añade la siguiente configuración a tu archivo `opencode.json`:

   ```json
   {
     "$schema": "https://opencode.ai/config.json",
     "mcp": {
       "Logto": {
         "enabled": true,
         "type": "remote",
         "url": "https://mcp.logto.io"
       }
     }
   }
   ```

2. Ejecuta el siguiente comando para autenticarte:
   ```bash
   opencode mcp auth Logto
   ```
   Ten en cuenta que `Logto` corresponde al nombre del servidor MCP en tu archivo de configuración.

Se abrirá una ventana del navegador. Inicia sesión con tu cuenta de Logto Cloud para autorizar y conectar.

### VS Code \{#vs-code}

1. Abre la paleta de comandos (`Command + Shift + P`) y selecciona **MCP: Add Server...**.
2. Elige **HTTP** como tipo de servidor.
3. Ingresa la URL: `https://mcp.logto.io`. Puedes elegir instalarlo en tu espacio de trabajo para mejor aislamiento y gestión.
4. Cuando VS Code solicite autenticación, permítelo. Serás redirigido a la página de inicio de sesión de Logto Cloud. Inicia sesión con tu cuenta de Logto Cloud para conectar.

Alternativamente, añade el servidor a `.vscode/mcp.json` o a tu `mcp.json` de usuario:

```json
{
  "servers": {
    "logto": {
      "type": "http",
      "url": "https://mcp.logto.io"
    }
  }
}
```

### Windsurf \{#windsurf}

Windsurf no documenta soporte para CIMD, así que usa [`mcp-remote`](https://www.npmjs.com/package/mcp-remote) con el client ID estático.

1. Abre la paleta de comandos (`Command + Shift + P`) y selecciona **Windsurf: MCP Marketplace**.
2. En la sección **Installed MCPs**, haz clic en el icono de configuración a la derecha para abrir el archivo de configuración MCP.
3. Añade la siguiente [configuración](https://docs.windsurf.com/windsurf/cascade/mcp#mcp_config-json):

   ```json
   {
     "mcpServers": {
       "Logto": {
         "command": "npx",
         "args": [
           "mcp-remote",
           "https://mcp.logto.io",
           "--allow-http",
           "--static-oauth-client-info",
           "{ \"client_id\": \"mcp-client\", \"scope\": \"mcp:all\" }",
           "--resource",
           "https://mcp.logto.io/"
         ]
       }
     }
   }
   ```

Aparecerá automáticamente una página de inicio de sesión de Logto Cloud. Inicia sesión con tu cuenta de Logto Cloud para conectar.

### Otros clientes MCP \{#other-mcp-clients}

Logto MCP Server funciona con cualquier cliente MCP que soporte autorización OAuth:

- **Si tu cliente soporta CIMD**: Ingresa solo la URL del servidor MCP `https://mcp.logto.io`. El cliente descubre todo lo demás desde el servidor.
- **De lo contrario**: Usa la siguiente configuración.
  - **URL del servidor MCP:** `https://mcp.logto.io`
  - **OAuth client ID:** `mcp-client` (sin client secret)
  - **Redirect URI:** una dirección loopback, como `http://localhost:<port>/callback`
  - **Resource:** `https://mcp.logto.io/` (si tu cliente lo requiere)
  - **Scope:** `mcp:all` (si tu cliente lo requiere)

Logto MCP Server no soporta Dynamic Client Registration (DCR). Si eres desarrollador de aplicaciones de IA, [publica un documento de metadatos de client ID](/integrate-logto/third-party-applications/dynamic-apps#publish-a-client-id-metadata-document) para tu aplicación y podrá conectarse sin ninguna configuración en Logto. Si eso no es posible, [contáctanos](https://logto.io/contact) con los detalles de tu aplicación.
